📖 What is an Array?

An array is a fixed-size, contiguous block of memory that holds elements of the same type. When you write int[] arr = new int[5] in Java, the JVM reserves 5×4 = 20 bytes of contiguous heap memory, all zeroed out. The address of arr[0] is some base address B, and arr[i] is at B + i×4. This is why random access is O(1) — you don't search; you calculate.

Array: int[] arr = {10, 20, 30, 40, 50} Memory layout (contiguous): ┌──────┬──────┬──────┬──────┬──────┐ │ 10 │ 20 │ 30 │ 40 │ 50 │ └──────┴──────┴──────┴──────┴──────┘ [0] [1] [2] [3] [4] ↑ Base address B addr(arr[i]) = B + i × 4 → O(1) access!

📐 What are 2D Arrays?

A 2D array is an array of arrays — a table with rows and columns. In Java, int[][] matrix = new int[3][4] creates 3 separate 1D arrays, each of size 4. The rows are NOT necessarily contiguous in memory (unlike C's 2D arrays), because each row is an independent object on the heap.

int[][] grid = new int[3][4] → 3 rows, 4 columns grid[0] → [ 0 | 0 | 0 | 0 ] ← one int[] object on heap grid[1] → [ 0 | 0 | 0 | 0 ] ← another int[] object grid[2] → [ 0 | 0 | 0 | 0 ] ← another int[] object Accessing grid[r][c]: • grid[r] → gets the r-th row array O(1) • [c] → gets the c-th element O(1) Traversal: row by row is cache-friendly ✓ column by column is NOT ✗
💡
2D Array Patterns you must know:
• Row/Column traversal: nested for loops
• Diagonal traversal: elements where i == j (main) or i + j == n-1 (anti-diagonal)
• Transpose: swap grid[i][j] ↔ grid[j][i]
• Spiral order: shrinking boundary: top/bottom/left/right
• 2D Prefix Sum: O(1) submatrix sum queries (covered in this lecture)

🧵 What is a String in Java? — The Deep Dive

In Java, a String is an immutable sequence of char values. Internally, it is backed by a char[] (before Java 9) or a byte[] with a coder flag (Java 9+ compact strings). "Immutable" means once a String object is created, it cannot be changed — ever. Any operation that appears to "modify" a string actually creates a brand new String object.

String s = "hello"; s = s + " world"; // What ACTUALLY happens: Step 1: Create new object "hello world" (new heap allocation) Step 2: Point s to the new object Step 3: "hello" is now UNREFERENCED → eligible for GC If done 1000 times in a loop: → 1000 new String objects created! → O(1+2+3+...+N) = O(N²) time ← The String concatenation trap
⚠️
The StringBuilder Fix: StringBuilder is a mutable buffer. It holds a resizable char[] array internally and appends directly — no new objects. Use StringBuilder inside any loop that builds a string.

Complexity comparison:
String += char in a loop → O(N²) time
StringBuilder.append(char) in a loop → O(N) time, O(1) amortised per append

📊 Prefix Sums — A First Look

👀
Preview — covered fully in Lecture 26. This section shows the core idea so you can use it on the simplest problems in this lecture. Lecture 26 (Prefix Sums & Difference Arrays) is the full treatment: 2D grids, counting subarrays with a given sum using a hash map, difference arrays for range updates, and prefix XOR.

Imagine your bank account. To find out how much you spent between Wednesday and Friday, you do not add up three days of receipts — you take your running total on Friday and subtract the running total on Tuesday. That running total is a prefix sum: build it once in O(n), and every “sum from here to there” question is a single subtraction.

Building and Using It

i 0 1 2 3 4
a[i] (daily spending) 3 1 4 1 5
P[i] (total so far) 3 4 8 9 14
📐 Pseudocode · Prefix Sums — Build Once, Query in O(1) 
function buildPrefix(a):
    P ← new list of length(a)
    P[0] ← a[0]
    for i from 1 to length(a) - 1:
        P[i] ← P[i - 1] + a[i]          // total so far = previous total + today
    return P

function rangeSum(P, L, R):             // sum of a[L..R], both ends included
    if L = 0: return P[R]
    return P[R] - P[L - 1]

// Example: spending on days 1..3 = P[3] - P[0] = 9 - 3 = 6  (1 + 4 + 1 ✓)

The L = 0 case is the classic edge case: there is no P[−1]. Lecture 26 shows the tidy fix — an extra 0 at the front of the array — along with the grid version of the same trick.

🎒 Kadane's Algorithm — Maximum Subarray

If you're looking for the largest possible sum from a contiguous chunk of an array, checking every chunk takes O(n³). Kadane's algorithm finds the answer in a blazingly fast O(N) single pass!

2.1 The "Reset" Philosophy

Kadane’s works on a simple intuition: If my past is dragging me down (negative sum), I must drop the baggage and start fresh!

At every step, you must make a greedy choice: Do I append the current number to the existing subarray chain, OR do I cut ties and start a brand-new subarray at this exact number?

Let's dry run the array: [-2, 1, -3, 4] [ -2 ] -> currentMax = -2. [ 1 ] -> Do I append 1 to -2 (gives -1)? Or start fresh at 1? (1 > -1. Start fresh!) currentMax = 1 [ -3 ] -> Do I append -3 to 1 (gives -2)? Or start fresh at -3? (-2 > -3. Keep the chain!) currentMax = -2 [ 4 ] -> Do I append 4 to -2 (gives 2)? Or start fresh at 4? (4 > 2. Drop the baggage!) currentMax = 4 Global Max recorded during this trip: 4
📐 Pseudocode · Maximum Subarray (Kadane) 
function maxSubArray(nums):
    currentMax ← nums[0]
    globalMax ← nums[0]

    for i from 1 to length(nums) - 1:
        // keep extending the running subarray, or start fresh at nums[i]?
        currentMax ← max(nums[i], currentMax + nums[i])
        globalMax ← max(globalMax, currentMax)
    return globalMax
// Seed with nums[0], not 0 — otherwise an all-negative array returns 0.
🌟
Extensions: You can apply Kadane's logic to find the Max Product Subarray (track both minProduct and maxProduct) or the Best Time to Buy & Sell Stock (track the minPrice).

🗳️ Boyer-Moore Majority Vote

Find the element appearing more than ⌊n/2⌋ times, in a single pass using constant memory. The trick is to pair off every occurrence of the candidate with one occurrence of something else. A true majority element outnumbers everything else combined, so it is the only value that can survive all the cancellations.

📐 Pseudocode · Majority Element 
// A true majority outnumbers everything else combined,
// so it survives every cancellation.
candidate ← none
count     ← 0

for x in nums:
    if count = 0:
        candidate ← x        // nothing left to cancel — adopt x
        count     ← 1
    else if x = candidate:
        count ← count + 1     // a vote for
    else:
        count ← count - 1     // a vote against — they cancel

return candidate

// If a majority is NOT guaranteed, verify in a second pass:
// count occurrences of candidate; it must exceed n / 2.
TimeO(n) — one pass
SpaceO(1)
💡
Generalises to ⌊n/3⌋
At most two values can appear more than ⌊n/3⌋ times, so keep two candidates and two counters, then verify both at the end (LC 229). With k counters the same cancellation argument finds every element appearing more than ⌊n/(k+1)⌋ times.

🚩 Dutch National Flag (Three-Way Partition)

Invented by Edsger Dijkstra, the DNF approach sorts 0s, 1s, and 2s in a single pass using O(1) space. It maintains 4 strictly defined zones using 3 pointers: low, mid, and high.

  • 0 to low - 1: Confirmed 0s zone.
  • low to mid - 1: Confirmed 1s zone.
  • mid to high: UNEXPLORED zone.
  • high + 1 to N - 1: Confirmed 2s zone.
📐 Pseudocode · Sort Colors 
function sortColors(nums):
    low ← 0;  mid ← 0;  high ← length(nums) - 1
    while mid ≤ high:
        if nums[mid] = 0:
            swap(nums, low, mid);  low ← low + 1;  mid ← mid + 1
        else if nums[mid] = 1:
            mid ← mid + 1
        else:
            swap(nums, mid, high);  high ← high - 1   // mid stays: new value is unseen

🔄 The Reversal Algorithm (In-Place)

Rotating an array by K steps in O(1) space using three strategic mirror flips.

🔄
The Trick: To rotate [1, 2, 3, 4, 5] by K=2:
  1. Reverse whole: [5, 4, 3, 2, 1]
  2. Reverse first K: [4, 5, 3, 2, 1]
  3. Reverse rest: [4, 5, 1, 2, 3]
📐 Pseudocode · Array Rotation 
// Rotate right by k using three reversals — O(n) time, O(1) space
function rotate(nums, k):
    n ← length(nums)
    k ← k mod n
    reverse(nums, 0, n - 1)        // [1,2,3,4,5], k=2 → [5,4,3,2,1]
    reverse(nums, 0, k - 1)        //                  → [4,5,3,2,1]
    reverse(nums, k, n - 1)        //                  → [4,5,1,2,3]

🔤 Frequency Arrays vs HashMaps

HashMaps can be slow for constant character sets like lowercase English letters. A flat int[26] array is the absolute fastest way to count frequencies.

📐 Pseudocode · Anagram Check 
count ← array of 0, size 26
for c in s:
    count[c - 'a'] ← count[c - 'a'] + 1   // letter → slot 0..25

🧵 String Immutability

Strings in many languages are immutable. Operations like s += "abc" create brand new objects, leading to O(N²) time when done in loops.

⚠️
The Trap: Never use += on a String inside a loop. Always use StringBuilder for high-performance mutations.

🔑 Rolling Hash — A First Look

👀
Preview — covered fully in Lecture 39. Rabin-Karp and rolling hashes belong with the other string-matching algorithms (KMP, the Z-function, Manacher) in Lecture 39. This section only plants the idea, because it is the same “reuse the last answer” move you just saw with prefix sums.

Suppose you want to know whether a short pattern appears inside a long text. Comparing the pattern against every position character by character costs O(n × m). The trick is to turn each window of the text into a single number — a fingerprint — and compare numbers instead. The clever part is that when the window slides one step right, the new fingerprint can be computed from the old one in O(1): remove the character leaving on the left, and add the one arriving on the right.

📐 Pseudocode · Sliding a Fingerprint One Step 
// Treat a window of m characters as an m-digit number in base B.
// Moving right: drop the leftmost digit, shift everything, add a new digit.

hash ← hash - text[i - 1] × B^(m - 1)     // remove the character leaving
hash ← hash × B + text[i + m - 1]         // shift, then add the one arriving

// Real implementations also take "mod" a large prime at every step so the
// number stays small. Lecture 39 covers that, and what to do when two
// different windows happen to share a fingerprint.

🌀 2D Boundary Traversals

Navigating matrices in orders like Spiral or Zigzag is easiest when using 4 dynamic, shrinking walls: top, bottom, left, and right.

📐 Pseudocode · Spiral Matrix 
while top ≤ bottom and left ≤ right:
    // walk the top wall left → right,     then top ← top + 1
    // walk the right wall top → bottom,   then right ← right - 1
    // walk the bottom wall right → left,  then bottom ← bottom - 1
    // walk the left wall bottom → top,    then left ← left + 1

Problem 01 · Reversal Trick
Rotate Array
🔗 LC 189 - Rotate Array
Medium Three Reversals Amazon · Microsoft · Google
›
Problem

Rotate the array to the right by k steps, in place. k may be larger than the array's length.

nums = [1,2,3,4,5,6,7], k = 3 → [5,6,7,1,2,3,4]
Hints
▶Hint 1 — a nudge

Copying into a second array is easy. What must you do to k first, and can you avoid the extra array?

▶Hint 2 — the key idea

Reduce k mod n. Then reverse the whole array, reverse the first k elements, and reverse the rest.

Solution

Reversing flips the order, so reversing the whole array puts the last k elements in front — backwards. Reversing each of the two blocks fixes them internally. Three linear passes, no extra array. The alternative — cyclic replacements with a gcd-sized loop count — is O(1) space too but far easier to get wrong.

▶Full solution
📐 Pseudocode · Reverse Three Times 
function rotate(nums, k):
    n ← length(nums)
    k ← k mod n                     // rotating by n changes nothing
    reverse(nums, 0, n - 1)         // whole array
    reverse(nums, 0, k - 1)         // first k
    reverse(nums, k, n - 1)         // the rest

function reverse(a, lo, hi):
    while lo < hi:
        swap a[lo], a[hi]
        lo ← lo + 1;  hi ← hi - 1

// [1,2,3,4,5,6,7], k = 3
// reverse all   -> [7,6,5,4,3,2,1]
// reverse 0..2  -> [5,6,7,4,3,2,1]
// reverse 3..6  -> [5,6,7,1,2,3,4]
TimeO(n)
SpaceO(1)
Problem 02 · Kadane's
Maximum Subarray Sum
🔗 LC 53 - Maximum Subarray
Medium Google · Amazon · LinkedIn · Microsoft Dynamic Programming
›
Problem

Find the contiguous subarray with the largest sum.

Hints
▶Hint 1 — a nudge

At each index, decide whether the subarray you are building is still worth keeping.

▶Hint 2 — the key idea

Kadane: current = max(x, current + x), best = max(best, current). Seed best with the first element so all-negative input works.

Solution

Walk the array once, keeping current, the best sum of a subarray that ends here. Extending is only worth it while current is positive — once it turns negative it can only drag the next element down, so start again from that element. best records the largest current ever seen, which is why it is seeded with the first element rather than 0 (an all-negative array must still return its largest value).

▶Full solution
📐 Pseudocode · Kadane's Algorithm 
function maxSubArray(nums):
    current ← nums[0]
    best ← nums[0]                       // never seed with 0 — all-negative input

    for i from 1 to length(nums) - 1:
        current ← max(nums[i], current + nums[i])   // extend, or restart here
        best ← max(best, current)
    return best

// [-2,1,-3,4,-1,2,1,-5,4]
// current: -2, 1, -2, 4, 3, 5, 6, 1, 5
// best:    -2, 1,  1, 4, 4, 5, 6, 6, 6  ← answer 6 (subarray [4,-1,2,1])
TimeO(n)
SpaceO(1)
Problem 03 · Prefix Products
Product of Array Except Self
🔗 LC 238
Medium Amazon · Meta · Microsoft Prefix/Suffix
›
Problem

Given an integer array nums, return an output array where output[i] equals the product of all elements except nums[i]. Solve without division in O(N) time.

Input: [1, 2, 3, 4] Output: [24, 12, 8, 6] ↑ ↑ ↑ ↑ 2×3×4 1×3×4 1×2×4 1×2×3
Hints
▶Hint 1 — a nudge

Division is banned. What is the answer at index i, in words?

▶Hint 2 — the key idea

Everything to the left times everything to the right. One left-to-right pass builds prefixes into the output, one right-to-left pass multiplies in the suffixes — O(1) extra space.

Solution

output[i] = (product of everything LEFT of i) × (product of everything RIGHT of i). Make two passes: left-to-right to fill prefix products, then right-to-left multiplying in suffix products. No division needed, works even with zeros.

▶Full solution
📐 Pseudocode · O(N) time O(1) extra 
function productExceptSelf(nums):
    n ← length(nums)
    out ← array of size n

    // Pass 1: out[i] = product of everything LEFT of i
    out[0] ← 1
    for i from 1 to n - 1:
        out[i] ← out[i-1] × nums[i-1]

    // Pass 2: multiply in the product of everything RIGHT of i
    right ← 1
    for i from n-1 down to 0:
        out[i] ← out[i] × right
        right ← right × nums[i]
    return out
// [1,2,3,4]: after pass 1 out = [1,1,2,6]
// pass 2: i=3 → 6×1=6, i=2 → 2×4=8, i=1 → 1×12=12, i=0 → 1×24=24 ✓
TimeO(N)
SpaceO(1) extra
Problem 04 · Two Index Walk
Merge Strings Alternately
🔗 LC 1768 - Merge Strings Alternately
Easy Two Pointers (Same Direction) Amazon · Google
›
Problem

Merge two strings by alternating their characters, starting with word1. When one string runs out, append the rest of the other.

word1 = "abc", word2 = "pqrs" → "apbqcrs"
Hints
▶Hint 1 — a nudge

One index per string, and a single loop that runs while either index is still in range.

▶Hint 2 — the key idea

Append word1[i] when i is in range, then word2[j] when j is in range, and advance both. The tail falls out of the same loop.

Solution

The trap is writing two loops and a special case for the leftover. One loop with two independent bounds checks handles both strings of any lengths. Build the answer in a StringBuilder: appending to an immutable String inside a loop would copy the whole string each time, turning O(n) into O(n²).

▶Full solution
📐 Pseudocode · Alternate and Drain 
function mergeAlternately(word1, word2):
    i ← 0;  j ← 0
    out ← empty string builder
    while i < length(word1) or j < length(word2):
        if i < length(word1):
            append word1[i] to out;  i ← i + 1
        if j < length(word2):
            append word2[j] to out;  j ← j + 1
    return out

// "abc" + "pqrs" -> a p b q c r, then the leftover s -> "apbqcrs"
TimeO(n + m)
SpaceO(n + m)
Problem 05 · Prefix Sum
Find Pivot Index
🔗 LC 724 - Find Pivot Index
Easy Running Total Amazon · Google · Meta
›
Problem

Find the leftmost index where the sum of everything to its left equals the sum of everything to its right. Return -1 if there is none.

nums = [1, 7, 3, 6, 5, 6] → 3   (1+7+3 = 5+6)
Hints
▶Hint 1 — a nudge

If you know the total and the sum on the left, do you need another loop for the right side?

▶Hint 2 — the key idea

Total first. Then walk left to right keeping left; the right sum is total - left - nums[i]. Compare, then add nums[i] to left.

Solution

One precomputed total turns a nested O(n²) scan into a single pass. The ordering matters: compare before adding the current element, because the pivot itself belongs to neither side. Negative numbers are fine here — unlike sliding windows, prefix sums do not care about signs.

▶Full solution
📐 Pseudocode · Total Minus Left 
function pivotIndex(nums):
    total ← sum(nums)
    left ← 0
    for i from 0 to length(nums) - 1:
        right ← total - left - nums[i]     // exclude the pivot itself
        if left = right: return i
        left ← left + nums[i]
    return -1

// [1,7,3,6,5,6]: i=3 -> left = 11, right = 22 - 11 - 6 = 5 + 6 = 11
TimeO(n)
SpaceO(1)
Problem 06 · One-Pass Greedy
Best Time to Buy and Sell Stock
🔗 LC 121 - Best Time to Buy and Sell Stock
Easy Track the Minimum So Far Amazon · Google · Meta
›
Problem

Given daily prices, buy on one day and sell on a later day for the largest profit. Return 0 if no profit is possible.

prices = [7, 1, 5, 3, 6, 4] → 5   (buy at 1, sell at 6)
Hints
▶Hint 1 — a nudge

For a fixed selling day, which buying day is best? Do you need to search for it?

▶Hint 2 — the key idea

Sweep left to right keeping the smallest price seen so far. At each day, the best profit ending today is price - minSoFar.

Solution

Every pair of days is a candidate, but you never need the inner loop: as you move right, the best buy day is always the cheapest day you have already passed. One variable carries that fact forward, so the sweep is O(n) with O(1) memory — the same “carry one fact forward” idea as Kadane's algorithm.

▶Full solution
📐 Pseudocode · Min So Far 
function maxProfit(prices):
    minPrice ← +infinity
    best ← 0
    for price in prices:
        if price < minPrice: minPrice ← price       // cheapest day so far
        else: best ← max(best, price - minPrice)    // sell today
    return best

// [7,1,5,3,6,4]: min = 7,1,1,1,1,1 -> profits 0,0,4,2,5,3 -> 5
TimeO(n)
SpaceO(1)
Problem 07 · Frequency Array
Valid Anagram
🔗 LC 242
Easy Amazon · Meta · Bloomberg Freq Array
›
Problem

Return true if string t is an anagram of s (same characters, same frequencies, any order).

s="anagram", t="nagaram" → true s="rat", t="car" → false
Hints
▶Hint 1 — a nudge

Two strings are anagrams exactly when their letter counts match.

▶Hint 2 — the key idea

int[26], increment for one string, decrement for the other, check all zeros. Compare lengths first as an early exit.

Solution

Use int[26]: increment on each char of s, decrement on t. If all entries are 0 at end → anagram. This is faster than HashMap since char - 'a' maps each letter to 0–25 in O(1).

▶Full solution
📐 Pseudocode · int[26] Counter 
function isAnagram(s, t):
    if length(s) ≠ length(t): return false
    count ← array of 0, size 26
    for i from 0 to length(s) - 1:
        count[s[i] - 'a'] ← count[s[i] - 'a'] + 1
        count[t[i] - 'a'] ← count[t[i] - 'a'] - 1
    for c in count:
        if c ≠ 0: return false
    return true
TimeO(N)

Longest Common Prefix
🔗 LC 14

Problem

Find the longest common prefix string among an array of strings. Return "" if none.

["flower","flow","flight"] → "fl" ["dog","racecar","car"] → ""
Hints
▶Hint 1 — a nudge

You could compare the strings pairwise, but there is a simpler scan.

▶Hint 2 — the key idea

Vertical scan: compare character i of every string, stop at the first mismatch or the first string that ends. No sorting needed.

Solution

Vertical scan: for each column index c, check if all strings share the same character. The first mismatch (or a string that ends) is the answer boundary. Return strs[0].substring(0, c).

▶Full solution
📐 Pseudocode · Vertical Scan 
function longestCommonPrefix(strs):
    for c from 0 to length(strs[0]) - 1:
        ch ← strs[0][c]
        for i from 1 to length(strs) - 1:
            if c = length(strs[i]) or strs[i][c] ≠ ch:
                return strs[0][0 .. c-1]     // first mismatch ends the prefix
    return strs[0]
// ["flower","flow","flight"]: c=0 'f' ✓  c=1 'l' ✓  c=2 'o' ≠ 'i' → "fl" ✓
TimeO(S) total chars
SpaceO(1)
