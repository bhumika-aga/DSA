Intervals & Sweep Line

“Stop thinking about intervals. Think about the moments they start and stop — then walk the timeline once.”

📚 Lecture 21 of 38 Phase 3 — Core Patterns ⏱ 4 days 🎯 18 problems 💼 Google · Amazon · Microsoft · Uber
🌍
Why does this topic matter?
Meetings, bookings, flights, buildings, ranges of a genome — whenever something has a start and an end, an interview question is close behind. Almost all of them collapse to the same three moves: sort the intervals, or turn them into events and sort those, or mark the ends and sweep. Lecture 9 gave you sorting and Lecture 19 gave you the difference array; this lecture is where both of them become one technique.
By the end of this lecture you can
  • Write the overlap test correctly, including the touching-endpoint case
  • Choose between sorting by start and sorting by end, and say why
  • Convert intervals into +1 / -1 events and sweep them
  • Pick between an event sweep, a difference array and a heap of active items
  • Solve skyline and rectangle-union problems with a sweep and coordinate compression

📏 What Overlap Actually Means

Almost every interval bug starts here. Two intervals a and b overlap when each one starts before the other ends:

📐 Pseudocode · The Overlap Test 
function overlaps(a, b):
    return a.start < b.end and b.start < a.end

// [1, 5] and [5, 9]:  1 < 9 and 5 < 5 → false. They only touch.
// [1, 5] and [4, 9]:  1 < 9 and 4 < 5 → true.  One hour of clash.

// If the problem says touching counts as overlapping
// (a meeting ending at 5 blocks one starting at 5), use ≤ instead.
⚠️
Decide closed or half-open once, at the start. [1, 5) — the room is free again at 5 — is the convention most scheduling problems use, and it makes touching intervals compatible. Rooms, flights and calendars usually work that way; a “days covered” question usually does not. Write the choice down before you write the comparison, because every < and ≤ in the solution follows from it.

What to Sort By

Sort by Use it for Why
start ascending merging, inserting, counting rooms intervals arrive in timeline order, so one pass can extend or close the current group
end ascending keeping the most non-overlapping intervals finishing early leaves the most room for whatever comes next
start ↑, then end ↓ removing covered intervals a longer interval is seen before the shorter one it swallows
the events, not the intervals maximum concurrency, skyline, area only the moments where something changes matter

🧱 Merge, Insert, Cover

The starting family: sort by start, then walk once, keeping the interval you are currently building.

📐 Pseudocode · Merge Overlapping Intervals 
function merge(intervals):
    sort intervals by start ascending
    out ← empty list

    for iv in intervals:
        if out is empty or out.last().end < iv.start:
            out.append(iv)                       // a clean gap: start a new one
        else:
            out.last().end ← max(out.last().end, iv.end)   // extend, never shrink
    return out

// [[1,3],[2,6],[8,10]] → [1,3] extends to [1,6]; 8 > 6 → new → [[1,6],[8,10]]
🛑
The max is not optional. Sorting by start says nothing about the ends, so [1, 9] can be followed by [2, 3]. Assigning end = iv.end instead of taking the maximum silently shrinks the merged interval — a bug that passes the small examples and fails the real tests.

Insert is the same walk with the list already sorted: copy everything ending before the new interval, absorb everything that overlaps it, then copy the rest — O(n) with no sort at all. Remove covered changes only the sort: with start ascending and end descending, an interval is covered exactly when its end is no larger than the largest end seen so far.

🎯 Greedy by End Time

A different question: not “how do these fit together?” but “how many can I keep?” Sorting by end answers it in one pass.

📐 Pseudocode · Maximum Non-Overlapping Intervals 
function maxNonOverlapping(intervals):
    sort intervals by end ascending
    kept ← 0
    lastEnd ← -infinity

    for iv in intervals:
        if iv.start ≥ lastEnd:      // no clash with the one we kept
            kept ← kept + 1
            lastEnd ← iv.end
    return kept

// Removals needed = total − kept.
// Arrows to burst balloons = kept, with the same loop and ≥ → >.
🧠
Why earliest end wins. Whatever you pick, the only thing that matters afterwards is when it frees up. Among all compatible choices, the one finishing earliest leaves at least as much room as any other — so it is never wrong to take it. An exchange argument makes it formal: swap any optimal solution's first interval for the earliest-ending one and it stays valid.

⏱ The Event Sweep

Now the trick that names the lecture. Stop treating an interval as one object. Split it into two moments on a timeline: +1 when it starts, -1 when it ends. Sort every moment, walk them in order, and keep a running count.

📐 Pseudocode · Maximum Concurrency (Minimum Rooms) 
function maxConcurrent(intervals):
    events ← empty list
    for iv in intervals:
        events.append((iv.start, +1))
        events.append((iv.end,   -1))

    sort events by time; // ties: -1 before +1, so touching intervals share a room

    running ← 0;  best ← 0
    for (time, delta) in events:
        running ← running + delta
        best ← max(best, running)
    return best

// [[0,30],[5,10],[15,20]]
// events: (0,+1) (5,+1) (10,-1) (15,+1) (20,-1) (30,-1)
// running: 1, 2, 1, 2, 1, 0 → best = 2 rooms
⚠️
The tie-break is the whole problem. At the same timestamp, does a meeting ending at 10 free the room for one starting at 10? If yes, process -1 first. If the problem counts them as overlapping, process +1 first. Getting this backwards gives an answer that is off by exactly one room on the tests with touching intervals.

Sweep vs Difference Array

A difference array (Lecture 19) is the same idea when the timeline is small and dense: instead of sorting events, write +1 and -1 straight into an array indexed by time, then prefix-sum it. Which one to reach for:

Difference array Event sweep
Coordinates small integers (stops, days, years) huge, sparse or non-integer
Cost O(n + range) O(n log n) — the sort dominates
Gives you the value at every position the value at every point of change
Typical question Car Pooling, Corporate Flight Bookings minimum rooms, skyline, area union
🧠
Coordinate compression is the bridge. When timestamps are up to 10⁹ but there are only 10⁴ intervals, collect the endpoints, sort them, and use their positions as indices. A huge sparse timeline becomes a small dense one, and the difference array works again.

🌅 Sweep Line Proper

A true sweep line adds a second structure: as the line moves left to right, something has to remember what is currently open, in sorted order. A heap or a multiset does that job.

The Skyline

📐 Pseudocode · Skyline — Sweep + Max-Heap 
// Each building (left, right, height) becomes two events.
events ← for each building: (left, -height) and (right, +height)
sort events by x; // ties: starts before ends, taller first — negative heights sort that way

active ← multiset containing 0        // ground level is always available
prevMax ← 0;  out ← empty list

for (x, h) in events:
    if h < 0: active.insert(-h)       // a building starts
    else: active.remove(h)            // a building ends

    curMax ← active.maximum()
    if curMax ≠ prevMax:              // the roofline changed here
        out.append((x, curMax))
        prevMax ← curMax
return out
⚠️
Removing from a heap. A plain binary heap cannot delete an arbitrary element. Either use an ordered multiset, or use lazy deletion: keep a “to remove” count per height and discard stale tops before reading the maximum. That detail is what makes this problem Hard rather than Medium.

Rectangle Union

Area works the same way in two dimensions. Sweep a vertical line across the x-coordinates; between two consecutive events the covered height does not change, so the area contributed is covered height × x gap. Recomputing that height from the currently open y-intervals is just an interval merge — the first thing in this lecture, used as a subroutine inside the last.

📐 Pseudocode · Union of Rectangle Areas 
xs ← all distinct x-coordinates of all rectangles, sorted
total ← 0

for each adjacent pair (x1, x2) in xs:
    open ← y-intervals of rectangles that span [x1, x2]
    covered ← total length of merge(open)      // merge, then sum the lengths
    total ← total + covered × (x2 - x1)

return total mod 1000000007

// O(n²) with a merge per strip, which is fine for n ≤ 200.
// A segment tree over compressed y-coordinates brings it to O(n log n).

⚠️ Complexity & The Classic Bugs

Technique Time Space Answers
Sort + one pass (merge, insert, cover) O(n log n) O(n) the combined intervals
Greedy by end time O(n log n) O(1) how many fit without clashing
Event sweep O(n log n) O(n) concurrency at every point of change
Difference array O(n + range) O(range) the value at every position
Sweep + heap / multiset O(n log n) O(n) skyline, area union, active extremes
Bug Symptom Fix
Wrong tie-break at equal timestamps Off by one room, or touching intervals merged Decide closed vs half-open first, then order the events
Assigning the end instead of taking the max Merged intervals silently shrink end = max(end, iv.end)
Sorting by start for a “keep the most” question Greedy picks a long interval and blocks two short ones Sort by end for maximum count
Difference array over huge coordinates Out of memory, or a timeout Compress the coordinates, or sweep the events instead
Deleting from a binary heap Stale heights reappear in the skyline Use a multiset, or lazy deletion with a removal count
Forgetting the final open interval The last group never reaches the output Flush after the loop, or append a sentinel event
💡
How to spot it in an interview. Anything with a start and an end: meetings, bookings, flights, buildings, appointments, ranges of days. Then pick by the question — “combine them” means sort by start; “how many can I keep” means sort by end; “how many at once” means sweep the events.

Problem 01 · Greedy by End
Non-overlapping Intervals
🔗 LC 435 - Non-overlapping Intervals
Medium Greedy by End Time Amazon · Google · Meta
›
Problem

Return the minimum number of intervals to remove so that the rest do not overlap. Touching endpoints are allowed.

intervals = [[1,2],[2,3],[3,4],[1,3]] → 1  (remove [1,3])
Hints
▶Hint 1 — a nudge

Removing the fewest is the same as keeping the most. Which interval is always safe to keep first?

▶Hint 2 — the key idea

Sort by end. Keep an interval whenever its start is at least the last kept end; the answer is the total minus the number kept.

Solution

Sorting by start is the trap: a long interval can be chosen first and block two short ones. Sorting by end means each choice frees the timeline as early as possible, and an exchange argument shows that is never worse. Touching is allowed here, so the test is start ≥ lastEnd.

▶Full solution
📐 Pseudocode · Keep the Most 
function eraseOverlapIntervals(intervals):
    sort intervals by end ascending
    kept ← 0
    lastEnd ← -infinity

    for iv in intervals:
        if iv.start ≥ lastEnd:        // touching is fine here
            kept ← kept + 1
            lastEnd ← iv.end
    return length(intervals) - kept

// [[1,2],[2,3],[3,4],[1,3]] sorted by end: [1,2] [1,3] [2,3] [3,4]
// keep [1,2] → keep [2,3] → keep [3,4] → kept = 3 → remove 1 ✓
TimeO(n log n)
SpaceO(1)
Problem 02 · Build the Intervals
Partition Labels
🔗 LC 763 - Partition Labels
Medium Intervals from Last Occurrence Amazon · Google · Meta
›
Problem

Split a string into as many parts as possible so that each letter appears in at most one part. Return the part sizes.

s = "ababcbacadefegdehijhklij" → [9, 7, 8]
Hints
▶Hint 1 — a nudge

There are no intervals in the input. Can you make one for each letter?

▶Hint 2 — the key idea

Each letter owns the interval from its first to its last occurrence. Walk the string extending the current part to the furthest last-occurrence seen; cut when the position reaches it.

Solution

The insight is manufacturing the intervals: letter c occupies [first(c), last(c)], and a valid part must contain every interval it touches. That turns the problem into merging, which one pass does without ever building the list — the running maximum of last[c] is the merged end.

▶Full solution
📐 Pseudocode · Running Furthest End 
function partitionLabels(s):
    last ← map from letter to its final index in s

    out ← empty list
    start ← 0;  end ← 0
    for i from 0 to length(s) - 1:
        end ← max(end, last[s[i]])       // this part must stretch at least this far
        if i = end:                     // nothing inside reaches further
            out.append(end - start + 1)
            start ← i + 1
    return out

// "ababcbacadefegde...": a ends at 8, b at 5, c at 7 → first cut at 8 → size 9 ✓
TimeO(n)
SpaceO(1) — 26 letters
Problem 03 · Sort Tie-Break
Remove Covered Intervals
🔗 LC 1288 - Remove Covered Intervals
Medium Sort by Start, End Descending Amazon · Google
›
Problem

An interval is covered when another interval contains it. Return how many intervals remain after removing every covered one.

intervals = [[1,4],[3,6],[2,8]] → 2  ([3,6] is covered by [2,8])
Hints
▶Hint 1 — a nudge

Sort by start. What goes wrong when two intervals share the same start?

▶Hint 2 — the key idea

Break ties with the end descending, so the longer one comes first. Then an interval is covered exactly when its end is at most the largest end seen so far.

Solution

With that sort order, every interval starts at or after the one before it, so only the end matters. Keep a running maxEnd: if the current end is no bigger, this interval sits inside an earlier one. The tie-break is essential — without it, [1,4] before [1,8] would make the longer interval look covered.

▶Full solution
📐 Pseudocode · Running Max End 
function removeCoveredIntervals(intervals):
    sort by start ascending, and by end DESCENDING on ties
    remaining ← 0
    maxEnd ← -infinity

    for iv in intervals:
        if iv.end > maxEnd:          // reaches past everything so far → not covered
            remaining ← remaining + 1
            maxEnd ← iv.end
    return remaining

// [[1,4],[2,8],[3,6]] → keep [1,4] (max=4), keep [2,8] (max=8),
// [3,6]: 6 ≤ 8 → covered → 2 ✓
TimeO(n log n)
SpaceO(1)
Problem 04 · Sweep + Heap
Maximum Number of Events That Can Be Attended
🔗 LC 1353 - Maximum Number of Events That Can Be Attended
Medium Day Sweep + Min-Heap Amazon · Google · Microsoft
›
Problem

Each event spans [start, end] and you may attend one event per day, on any day within its range. Return the maximum number of events you can attend.

events = [[1,2],[2,3],[3,4],[1,2]] → 4
Hints
▶Hint 1 — a nudge

Events are no longer atomic — you pick a single day inside each. Walk the days instead of the events.

▶Hint 2 — the key idea

On each day, add every event that has started to a min-heap keyed on end day, drop the ones already expired, and attend the one that ends soonest.

Solution

Greedy by end time again, but now it must be decided day by day, because an event only becomes available when its start arrives. Sorting the events by start lets you feed the heap as the day advances; the heap always offers the most urgent event still attendable. Expired entries are dropped from the top before choosing.

▶Full solution
📐 Pseudocode · Advance the Day, Feed the Heap 
function maxEvents(events):
    sort events by start ascending
    heap ← empty min-heap of end days
    i ← 0;  attended ← 0

    for day from 1 to the largest end day:
        while i < length(events) and events[i].start = day:
            heap.push(events[i].end);  i ← i + 1     // now available

        while heap is not empty and heap.peek() < day:
            heap.popMin()                            // too late, gone

        if heap is not empty:
            heap.popMin();  attended ← attended + 1  // attend the most urgent
    return attended
TimeO(n log n)
SpaceO(n)
Problem 05 · Sweep Line
The Skyline Problem
🔗 LC 218 - The Skyline Problem
Hard Event Sweep + Multiset Google · Amazon · Meta
›
Problem

Given buildings as [left, right, height], return the skyline: the list of points where the visible roofline changes.

buildings = [[2,9,10],[3,7,15],[5,12,12]] → [[2,10],[3,15],[7,12],[12,0]]
Hints
▶Hint 1 — a nudge

The outline only changes where a building starts or ends. What do you need to know at each of those x-positions?

▶Hint 2 — the key idea

The tallest building currently open. Keep the open heights in a multiset: insert on a start event, remove on an end event, and emit a point whenever the maximum changes.

Solution

The sweep is easy; the bookkeeping is the exam. Two details decide correctness. First the tie order at equal x: starts before ends, and among starts the taller first, so a taller building replacing a shorter one emits one point rather than dipping to ground. Encoding a start as a negative height makes the default sort do both. Second, removal: binary heaps cannot delete from the middle, so use an ordered multiset or lazy deletion with a pending-removal count.

▶Full solution
📐 Pseudocode · Sweep + Active Heights 
function getSkyline(buildings):
    events ← empty list
    for (left, right, height) in buildings:
        events.append((left, -height))      // negative marks a start
        events.append((right, +height))

    sort events                             // by x, then by the signed height

    active ← multiset containing 0          // ground is always open
    prevMax ← 0;  out ← empty list

    for (x, h) in events:
        if h < 0: active.insert(-h)
        else: active.remove(h)

        curMax ← active.maximum()
        if curMax ≠ prevMax:
            out.append((x, curMax))
            prevMax ← curMax
    return out
TimeO(n log n)
SpaceO(n)
Problem 06 · 2D Sweep
Rectangle Area II
🔗 LC 850 - Rectangle Area II
Hard Sweep + Coordinate Compression Google · Amazon
›
Problem

Given axis-aligned rectangles, return the total area they cover, counting overlaps once. Answer modulo 109+7.

rectangles = [[0,0,2,2],[1,0,2,3],[1,0,3,1]] → 6
Hints
▶Hint 1 — a nudge

Between two consecutive x-coordinates, does the covered height ever change?

▶Hint 2 — the key idea

No — so sweep the distinct x values, and for each strip merge the y-intervals of the rectangles that span it. Area is covered height × strip width.

Solution

Two lecture ideas stack here. The sweep reduces a 2D problem to a sequence of 1D ones, and each 1D question is the interval merge from the start of this lecture. Take the modulus only at the end of each strip’s contribution, and keep the running total in 64-bit. With n ≤ 200 the O(n²) version is comfortable; a segment tree over compressed y-coordinates is the O(n log n) upgrade.

▶Full solution
📐 Pseudocode · Strip by Strip 
function rectangleArea(rectangles):
    xs ← sorted distinct x-coordinates of every rectangle
    total ← 0

    for each adjacent pair (x1, x2) in xs:
        open ← empty list
        for (rx1, ry1, rx2, ry2) in rectangles:
            if rx1 ≤ x1 and rx2 ≥ x2:       // spans this whole strip
                open.append((ry1, ry2))

        covered ← 0;  lastEnd ← -infinity
        for (y1, y2) in sort(open) by y1:      // merge as you go
            lo ← max(y1, lastEnd)
            if y2 > lo: covered ← covered + (y2 - lo)
            lastEnd ← max(lastEnd, y2)

        total ← total + covered × (x2 - x1)
    return total mod 1000000007
TimeO(n²)
SpaceO(n)
