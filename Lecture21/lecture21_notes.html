Graphs I — Representation, BFS & DFS

“Almost every graph question is one of two walks. Pick the right one and the rest is bookkeeping.”

📚 Lecture 21 of 45 Phase 2 — Core Data Structures ⏱ 5 days 🎯 16 problems 💼 Google · Amazon · Meta · Microsoft
🌍
Why does this topic matter?
A graph is just “things, and which of them are connected” — friends on a social network, cities joined by roads, board positions one move apart. Trees were graphs with a promise (no cycles, one parent); real graphs drop that promise, and the only new skill you need is a visited set to stop yourself walking in circles. Get the two traversals down here and the next two lectures are just those walks with a priority queue or a counter bolted on.
By the end of this lecture you can
  • Choose between an adjacency list, matrix and edge list, and say why
  • Write BFS and DFS from memory and say what each is good for
  • Use BFS to find the shortest path on an unweighted graph
  • Detect a cycle in both an undirected and a directed graph
  • See the graph in a problem that never uses the word

📈 Graph Representations

A graph G = (V, E) has V vertices (nodes) and E edges. How you store it determines the complexity of every operation.

Representation Space Check Edge List Neighbours Best For
Adjacency List O(V + E) O(degree) O(degree) Sparse graphs (most interview problems)
Adjacency Matrix O(V²) O(1) O(V) Dense graphs, Floyd-Warshall
Edge List O(E) O(E) O(E) Kruskal's MST (sort edges)

Adjacency List in Java

📐 Pseudocode · Graph Representation 
// Adjacency list: one bucket of neighbours per node.
// O(V + E) space — always prefer it unless the graph is dense.
adj ← array of V empty lists

for each edge (u, v) in edges:
    adj[u].append(v)
    adj[v].append(u)        // omit this line for a DIRECTED graph

// Weighted? store pairs: adj[u].append( (v, weight) )
// A grid is an implicit graph: the neighbours of (r,c) are
// (r+1,c) (r-1,c) (r,c+1) (r,c-1) — no adjacency list needed.

Grid as Implicit Graph

📌
Grid problems ARE graph problems. Each cell (r,c) is a node. Edges go to the 4 (or 8) adjacent cells. You never need to build an explicit adjacency list — just use the 4-direction delta array. Lecture 17 works through the grid versions (Number of Islands, Rotting Oranges, 01 Matrix, Pacific Atlantic Water Flow); here the same traversals run on explicit graphs.

dirs = [(1,0), (-1,0), (0,1), (0,-1)]

🌊 BFS — Breadth-First Search

BFS visits nodes level by level. Because it expands the closest nodes first, it guarantees shortest path in an unweighted graph. Use a Queue and a visited set/array.

🎯 BFS Recognition Signal

"Shortest path", "minimum steps", "minimum moves", "fewest hops" in an unweighted graph or grid → reach for BFS first. If edges have weights, switch to Dijkstra's.

Single-Source BFS Template

📐 Pseudocode · BFS — Shortest Path (unweighted) 
// BFS visits nodes in order of distance, so the FIRST time you
// reach a node is along a shortest path. Only true when every
// edge costs the same.
queue ← [start]
visited ← { start }        // mark on PUSH, never on pop
dist ← 0

while queue not empty:
    size ← length(queue)     // one full ring at distance = dist
    repeat size times:
        node ← queue.popFront()
        if node = target: return dist

        for nb in adj[node]:
            if nb not in visited:
                visited.add(nb)
                queue.pushBack(nb)
    dist ← dist + 1

return unreachable

// Multi-source (rotting oranges, nearest exit): push EVERY source
// before the loop starts, all at distance 0.

// Time: O(V + E)  Space: O(V)
TimeO(V + E)
SpaceO(V)

Multi-Source BFS

When multiple starting nodes all exist at distance 0, seed them all into the queue at once before the BFS loop begins. This avoids running BFS from each source separately.

📐 Pseudocode · Multi-Source BFS (Rotting Oranges pattern) 
// Seed ALL rotten oranges at time 0
q ← empty queue
for every cell (r, c):
    if grid[r][c] = 2: q.enqueue((r, c, 0))       // (row, col, time)

maxTime ← 0
while q is not empty:
    (r, c, t) ← q.dequeue()
    maxTime ← max(maxTime, t)
    for (dr, dc) in [(1,0), (-1,0), (0,1), (0,-1)]:
        nr ← r + dr;  nc ← c + dc
        if 0 ≤ nr < rows and 0 ≤ nc < cols and grid[nr][nc] = 1:
            grid[nr][nc] ← 2                       // mark visited by overwriting
            q.enqueue((nr, nc, t + 1))

📃 DFS — Depth-First Search

DFS explores as deep as possible before backtracking. Use it when you need connectivity, paths, cycles, or component labelling. Can be written recursively or iteratively (explicit stack).

🎯 DFS Recognition Signal

"Connected components", "number of islands", "can you reach X from Y", "all paths", "cycle exists" → DFS. Also: any problem where you need to explore an entire region (flood fill, island area).

DFS Template + Connected Components

📐 Pseudocode · DFS — Connected Components 
// Count how many separate islands the graph falls into.
visited ← empty set
components ← 0

for node in all nodes:
    if node not in visited:
        components ← components + 1
        dfs(node)

function dfs(node):
    visited.add(node)
    for nb in adj[node]:
        if nb not in visited: dfs(nb)

// Deep graph? recursion will overflow the stack. Swap in an explicit
// stack: push start, then pop-mark-push-neighbours in a loop.

// Time: O(V + E)  Space: O(V) for visited + the recursion stack
⚠
Stack overflow on large inputs: Java's default stack handles ~10k–30k recursive calls. For n > 104, convert to iterative DFS using an explicit Deque<Integer> stack.

🔁 Cycle Detection

Directed Graph — 3-Color DFS

Track three states per node: 0 = unvisited, 1 = in current DFS path (grey), 2 = fully processed (black). If during DFS you reach a grey node, you found a back edge → cycle.

📐 Pseudocode · Directed Cycle Detection (3-color) 
color ← array of V, all WHITE     // WHITE = unvisited, GREY = in progress, BLACK = done

function hasCycle(adj, V):
    for i from 0 to V - 1:
        if color[i] = WHITE and dfs(adj, i): return true
    return false

function dfs(adj, node):
    color[node] ← GREY                        // on the current path
    for nei in adj[node]:
        if color[nei] = GREY: return true      // back edge = cycle
        if color[nei] = WHITE and dfs(adj, nei): return true
    color[node] ← BLACK                       // fully explored
    return false

Undirected Graph — Parent-Skip DFS

In undirected graphs the edge u↔v appears in both directions. When doing DFS from u via edge to v, skip the edge back to u (the parent). If you still reach an already-visited node, it's a cycle.

📐 Pseudocode · Undirected Cycle Detection (parent-skip) 
function dfs(adj, node, parent, vis):
    vis[node] ← true
    for nei in adj[node]:
        if not vis[nei]:
            if dfs(adj, nei, node, vis): return true
        else if nei ≠ parent:          // visited AND not the edge we came from
            return true
    return false
📌
BFS-based cycle detection (undirected): Also works — track parent per node in the BFS queue. But the DFS parent-skip is cleaner in interviews. For directed graphs, BFS-based is Kahn's algorithm (cycle = not all nodes processed).

⚠️ Complexity & Classic Bugs

The costs worth quoting in an interview first, then the mistakes that most often break code that looks correct. Every row in the second table is a bug someone has shipped.

Operation Cost Note
Build an adjacency list O(V + E) time and space
Adjacency matrix O(V²) space, O(1) edge check Only for small or dense graphs
BFS or DFS O(V + E)
Cycle detection O(V + E)
BFS over states O(states × moves) Implicit graphs
Bug Symptom Fix
No visited set Infinite loop on the first cycle Mark nodes as visited
BFS marking visited when dequeuing Nodes enqueued many times; wrong distances Mark when enqueuing
An undirected edge added in one direction Traversal misses nodes Add both directions
Only starting from node 0 Misses disconnected parts Loop over every node, start from each unvisited one
Undirected cycle check without a parent Every edge looks like a cycle Ignore the edge back to the parent
Directed cycle check with only visited / unvisited False cycles, or missed ones Use three states: unvisited, on the path, finished
Nodes numbered 1..n in arrays of size n Off-by-one crash Size arrays n + 1

💪 In-Lecture Practice Problems

Four problems: two where the graph is handed to you, and two where you have to notice it is a graph at all.

Problem 01 · LC 752
Open the Lock
Medium Shortest Path, Unweighted Google · Amazon · Microsoft
▶
Problem

A lock has four wheels showing digits 0-9 that wrap around. From "0000", each move turns one wheel one step. Return the fewest moves to reach target without ever showing a string in deadends, or -1.

deadends = ["0201","0101","0102","1212","2002"], target = "0202" → 6
Hints
▶Hint 1 — a nudge

Nothing here looks like a graph — but what are the nodes, and what are the edges?

▶Hint 2 — the key idea

Each 4-digit string is a node with exactly 8 neighbours (each wheel up or down). Plain BFS from "0000", skipping deadends and states you have already reached.

Solution

The graph is never built — neighbours are generated on demand, which is what “implicit graph” means. BFS visits states in order of distance, so the first time you reach the target you have the fewest moves. Mark states visited when you enqueue them, not when you pop, or the same state enters the queue many times.

▶Full solution
📐 Pseudocode · BFS over States 
function openLock(deadends, target):
    dead ← set of deadends
    if "0000" in dead: return -1
    if target = "0000": return 0

    queue ← ["0000"]
    visited ← {"0000"}
    steps ← 0

    while queue is not empty:
        steps ← steps + 1
        repeat queue.size times:            // one whole ring = one move
            state ← queue.popFront()
            for each of the 8 neighbours nb of state:   // each wheel ±1, wrapping
                if nb in dead or nb in visited: continue
                if nb = target: return steps
                visited.add(nb)             // mark on push, never on pop
                queue.pushBack(nb)
    return -1
TimeO(10⁴ × 8)
SpaceO(10⁴)
Problem 02 · LC 1319
Number of Operations to Make Network Connected
Medium DFS over an Adjacency List Amazon · Google · Meta
▶
Problem

You have n computers and a list of cables. You may unplug any cable and re-plug it between two other computers. Return the fewest moves to connect every computer, or -1 if it is impossible.

n = 6, connections = [[0,1],[0,2],[0,3],[1,2],[1,3]] → 2
Hints
▶Hint 1 — a nudge

How many cables does it take, at minimum, to connect n computers?

▶Hint 2 — the key idea

With fewer than n - 1 cables it is impossible. Otherwise count the connected components: joining c components takes c - 1 moves, and spare cables always exist.

Solution

Two separate ideas. First the counting argument: a connected graph on n nodes needs at least n - 1 edges, so fewer means -1. Then the graph work: count components with DFS (or Union-Find, in Lecture 31) and the answer is components - 1. Every extra edge inside a component is a spare you can move.

▶Full solution
📐 Pseudocode · Count Components 
function makeConnected(n, connections):
    if length(connections) < n - 1: return -1      // not enough cables

    adj ← adjacency list of n empty lists
    for (a, b) in connections:
        adj[a].append(b)
        adj[b].append(a)

    visited ← array of n, all false
    components ← 0
    for node from 0 to n - 1:
        if not visited[node]:
            components ← components + 1
            dfs(adj, node, visited)
    return components - 1                          // one move joins two components

function dfs(adj, node, visited):
    visited[node] ← true
    for nb in adj[node]:
        if not visited[nb]: dfs(adj, nb, visited)
TimeO(V + E)
SpaceO(V + E)
Problem 03 · Traversal + Memory
Clone Graph
🔗 LC 133 - Clone Graph
Medium DFS/BFS + HashMap Google · Amazon · Meta
›
Problem

Given a reference to a node in a connected undirected graph, return a deep copy of the whole graph.

adjList = [[2,4],[1,3],[2,4],[1,3]] → an identical, independent graph
Hints
▶Hint 1 — a nudge

A plain DFS would loop forever on a cycle. What do you need to remember as you walk?

▶Hint 2 — the key idea

A map from original node to its copy. Check the map before recursing — that is both your visited set and your result.

Solution

The lesson is that in a graph, “visited” and “already built” are the same question, and one hash map answers both. Create the copy and put it in the map before recursing into neighbours, or a cycle sends you round forever. This create-then-register order is the same discipline you use in any graph DFS: mark, then explore.

▶Full solution
📐 Pseudocode · Map Original → Copy 
function cloneGraph(node):
    if node = null: return null
    seen ← empty map                       // original → copy

    function dfs(cur):
        if cur in seen: return seen[cur]   // visited AND built

        copy ← new Node(cur.val)
        seen[cur] ← copy                   // register BEFORE recursing

        for nb in cur.neighbours:
            copy.neighbours.append(dfs(nb))
        return copy

    return dfs(node)

// Registering after the loop instead would revisit cur through its own
// neighbour and recurse forever.
TimeO(V + E)
SpaceO(V)
Problem 04 · Implicit Graph
Word Ladder
🔗 LC 127 - Word Ladder
Hard BFS on an Implicit Graph Amazon · Google · Meta
›
Problem

Transform beginWord into endWord one letter at a time, where every intermediate word must be in the word list. Return the number of words in the shortest such sequence, or 0.

beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log","cog"] → 5
Hints
▶Hint 1 — a nudge

Nobody handed you a graph. What are the nodes, and when is there an edge between two of them?

▶Hint 2 — the key idea

Nodes are words; two words are joined if they differ in exactly one letter. Shortest path on an unweighted graph is plain BFS.

Solution

The whole difficulty is seeing the graph that is not there. Once nodes are words and edges are one-letter changes, this is the shortest path on an unweighted graph, which is BFS and nothing cleverer. The second trap is how you find neighbours: comparing every pair is O(n²·L), while generating all 26 × L single-letter variants of the current word and testing each against a hash set is far cheaper for realistic inputs.

▶Full solution
📐 Pseudocode · Words as Nodes, BFS for Shortest 
function ladderLength(beginWord, endWord, wordList):
    dict ← hash set of wordList
    if endWord not in dict: return 0

    queue ← [beginWord];  seen ← {beginWord};  steps ← 1

    while queue is not empty:
        repeat queue.size times:          // one whole level
            word ← queue.popFront()
            if word = endWord: return steps

            for i from 0 to length(word) - 1:
                for c from 'a' to 'z':
                    next ← word with position i replaced by c
                    if next in dict and next not in seen:
                        seen.add(next);  queue.pushBack(next)
        steps ← steps + 1

    return 0                                  // endWord unreachable
TimeO(n · L · 26)
SpaceO(n · L)
