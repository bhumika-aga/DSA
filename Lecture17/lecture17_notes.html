Graphs

“A graph is nodes connected by edges. BFS finds the shortest path; DFS finds connectivity. Everything else — Dijkstra, topological sort, MST — is built on top of those two primitives.”

📚 Lecture 17 of 38 Phase 2 — Core Data Structures ⏱ 12 days 🎯 30 problems 💼 Google · Meta · Amazon · Microsoft · Uber
🌍
Why does this topic matter?
Graphs are the single largest topic in FAANG interviews by problem count. Nearly every system can be modelled as a graph — social networks, maps, dependency resolution, state machines. The good news: 95% of all graph interview problems use exactly two primitives — BFS and DFS. Learn to recognise which one to reach for and every other algorithm (Dijkstra, Kahn's, Kruskal's) is just a variation.
By the end of this lecture you can
  • Understand graph representations (adjacency list, matrix, edge list) and trade-offs
  • Master BFS for shortest path in unweighted graphs
  • Master DFS for connectivity, cycle detection, and topological sort
  • Apply Dijkstra's and Bellman-Ford for weighted shortest paths
  • Build minimum spanning trees with Kruskal's and Prim's
🔗
How it connects: BFS is the level-order traversal you already know from trees (Lecture 15), but on a general graph with cycles you must track visited[]. Dijkstra's uses the min-heap from Lecture 16. Kruskal's MST needs Union-Find, taught properly in Lecture 24. After Graphs, Dynamic Programming on DAGs and interval scheduling both rely on topological order.

📈 Graph Representations

A graph G = (V, E) has V vertices (nodes) and E edges. How you store it determines the complexity of every operation.

Representation Space Check Edge List Neighbours Best For
Adjacency List O(V + E) O(degree) O(degree) Sparse graphs (most interview problems)
Adjacency Matrix O(V²) O(1) O(V) Dense graphs, Floyd-Warshall
Edge List O(E) O(E) O(E) Kruskal's MST (sort edges)

Adjacency List in Java

📐 Pseudocode · Graph Representation 
// Adjacency list: one bucket of neighbours per node.
// O(V + E) space — always prefer it unless the graph is dense.
adj ← array of V empty lists

for each edge (u, v) in edges:
    adj[u].append(v)
    adj[v].append(u)        // omit this line for a DIRECTED graph

// Weighted? store pairs: adj[u].append( (v, weight) )
// A grid is an implicit graph: the neighbours of (r,c) are
// (r+1,c) (r-1,c) (r,c+1) (r,c-1) — no adjacency list needed.

Grid as Implicit Graph

📌
Grid problems ARE graph problems. Each cell (r,c) is a node. Edges go to the 4 (or 8) adjacent cells. You never need to build an explicit adjacency list — just use the 4-direction delta array. This covers: Number of Islands, Rotting Oranges, 01 Matrix, Pacific Atlantic Water Flow.

int[][] dirs = {{1,0},{-1,0},{0,1},{0,-1}};

🌊 BFS — Breadth-First Search

BFS visits nodes level by level. Because it expands the closest nodes first, it guarantees shortest path in an unweighted graph. Use a Queue and a visited set/array.

🎯 BFS Recognition Signal

"Shortest path", "minimum steps", "minimum moves", "fewest hops" in an unweighted graph or grid → reach for BFS first. If edges have weights, switch to Dijkstra's.

Single-Source BFS Template

📐 Pseudocode · BFS — Shortest Path (unweighted) 
// BFS visits nodes in order of distance, so the FIRST time you
// reach a node is along a shortest path. Only true when every
// edge costs the same.
queue ← [start]
visited ← { start }        // mark on PUSH, never on pop
dist ← 0

while queue not empty:
    size ← length(queue)     // one full ring at distance = dist
    repeat size times:
        node ← queue.popFront()
        if node = target: return dist

        for nb in adj[node]:
            if nb not in visited:
                visited.add(nb)
                queue.pushBack(nb)
    dist ← dist + 1

return unreachable

// Multi-source (rotting oranges, nearest exit): push EVERY source
// before the loop starts, all at distance 0.

// Time: O(V + E)  Space: O(V)
TimeO(V + E)
SpaceO(V)

Multi-Source BFS

When multiple starting nodes all exist at distance 0, seed them all into the queue at once before the BFS loop begins. This avoids running BFS from each source separately.

📐 Pseudocode · Multi-Source BFS (Rotting Oranges pattern) 
// Seed ALL rotten oranges at time 0
q ← empty queue
for every cell (r, c):
    if grid[r][c] = 2: q.enqueue((r, c, 0))       // (row, col, time)

maxTime ← 0
while q is not empty:
    (r, c, t) ← q.dequeue()
    maxTime ← max(maxTime, t)
    for (dr, dc) in [(1,0), (-1,0), (0,1), (0,-1)]:
        nr ← r + dr;  nc ← c + dc
        if 0 ≤ nr < rows and 0 ≤ nc < cols and grid[nr][nc] = 1:
            grid[nr][nc] ← 2                       // mark visited by overwriting
            q.enqueue((nr, nc, t + 1))

📃 DFS — Depth-First Search

DFS explores as deep as possible before backtracking. Use it when you need connectivity, paths, cycles, or component labelling. Can be written recursively or iteratively (explicit stack).

🎯 DFS Recognition Signal

"Connected components", "number of islands", "can you reach X from Y", "all paths", "cycle exists" → DFS. Also: any problem where you need to explore an entire region (flood fill, island area).

DFS Template + Connected Components

📐 Pseudocode · DFS — Connected Components 
// Count how many separate islands the graph falls into.
visited ← empty set
components ← 0

for node in all nodes:
    if node not in visited:
        components ← components + 1
        dfs(node)

function dfs(node):
    visited.add(node)
    for nb in adj[node]:
        if nb not in visited: dfs(nb)

// Deep graph? recursion will overflow the stack. Swap in an explicit
// stack: push start, then pop-mark-push-neighbours in a loop.

// Time: O(V + E)  Space: O(V) for visited + the recursion stack
⚠
Stack overflow on large inputs: Java's default stack handles ~10k–30k recursive calls. For n > 104, convert to iterative DFS using an explicit Deque<Integer> stack.

🔁 Cycle Detection

Directed Graph — 3-Color DFS

Track three states per node: 0 = unvisited, 1 = in current DFS path (grey), 2 = fully processed (black). If during DFS you reach a grey node, you found a back edge → cycle.

📐 Pseudocode · Directed Cycle Detection (3-color) 
color ← array of V, all WHITE     // WHITE = unvisited, GREY = in progress, BLACK = done

function hasCycle(adj, V):
    for i from 0 to V - 1:
        if color[i] = WHITE and dfs(adj, i): return true
    return false

function dfs(adj, node):
    color[node] ← GREY                        // on the current path
    for nei in adj[node]:
        if color[nei] = GREY: return true      // back edge = cycle
        if color[nei] = WHITE and dfs(adj, nei): return true
    color[node] ← BLACK                       // fully explored
    return false

Undirected Graph — Parent-Skip DFS

In undirected graphs the edge u↔v appears in both directions. When doing DFS from u via edge to v, skip the edge back to u (the parent). If you still reach an already-visited node, it's a cycle.

📐 Pseudocode · Undirected Cycle Detection (parent-skip) 
function dfs(adj, node, parent, vis):
    vis[node] ← true
    for nei in adj[node]:
        if not vis[nei]:
            if dfs(adj, nei, node, vis): return true
        else if nei ≠ parent:          // visited AND not the edge we came from
            return true
    return false
📌
BFS-based cycle detection (undirected): Also works — track parent per node in the BFS queue. But the DFS parent-skip is cleaner in interviews. For directed graphs, BFS-based is Kahn's algorithm (cycle = not all nodes processed).

▶ Topological Sort

A topological order of a DAG lists every node before all nodes it points to. Only valid on Directed Acyclic Graphs. If a cycle exists, no topological order exists. Use case: course prerequisites, build dependency order, task scheduling.

Kahn's Algorithm (BFS-based) — Recommended

💡
Intuition: A node with in-degree 0 has no dependencies — process it first. After removing it, some neighbours lose a dependency (in-degree drops). If their in-degree reaches 0, they're ready. Repeat. If the output order has fewer than V nodes, there was a cycle.
📐 Pseudocode · Topological Sort (Kahn's) 
// Repeatedly take a node nothing depends on. If you can't empty
// the graph, what is left is a cycle.
indeg ← count of incoming edges for every node
queue ← every node with indeg = 0
order ← empty list

while queue not empty:
    node ← queue.popFront()
    order.append(node)

    for nb in adj[node]:
        indeg[nb] ← indeg[nb] - 1
        if indeg[nb] = 0: queue.pushBack(nb)

if length(order) ≠ V: return CYCLE_DETECTED
return order

// Time: O(V + E)  Space: O(V)

DFS-based Topological Sort

After fully processing a node (all descendants done), push it onto a stack. Reverse the stack for the order. Equivalent to Kahn's but DFS-native — useful when you already have DFS in the solution.

📐 Pseudocode · DFS Topo Sort (post-order + stack) 
stack ← empty stack
visited ← array of V, all false

function dfs(node):
    visited[node] ← true
    for nei in adj[node]:
        if not visited[nei]: dfs(nei)
    stack.push(node)                 // push AFTER all neighbours are done

// Call dfs(i) for every unvisited i, then read the stack top-to-bottom

⚙ Dijkstra's Algorithm

Dijkstra finds the shortest path in a weighted graph with non-negative edges. It is essentially BFS with a min-heap instead of a plain queue, always processing the node with the currently known shortest distance.

🎯 Dijkstra Recognition Signal

"Shortest path", "minimum cost/time/effort" and edges have non-negative weights → Dijkstra. Weights are negative? → Bellman-Ford. K-stops constraint? → Modified Bellman-Ford (DP with relaxation limit).

📐 Pseudocode · Dijkstra's Shortest Path 
// Weighted, non-negative edges. Always expand the closest unfinished
// node — a min-heap keeps that cheap.
dist ← array of infinity, length V
dist[src] ← 0
heap ← min-heap holding (0, src) ordered by distance

while heap not empty:
    (d, node) ← heap.extractMin()
    if d > dist[node]: continue     // a stale copy — skip it

    for (nb, w) in adj[node]:
        if d + w < dist[nb]:
            dist[nb] ← d + w
            heap.insert((dist[nb], nb))

return dist

// Negative edges? Dijkstra is WRONG — use Bellman-Ford.
// All weights 0 or 1? A deque beats the heap (0-1 BFS).

// Time: O((V + E) log V)  Space: O(V)
📌
The “stale entry” check is critical. Java's PriorityQueue does not support decrease-key, so when you find a shorter path you push a new entry rather than updating the old one. Old (larger) entries remain in the heap. The check if (d > dist[node]) continue discards them when they eventually pop.
TimeO((V+E) log V)
SpaceO(V + E)
ConstraintNon-negative weights only

🔴 Bellman-Ford

Bellman-Ford relaxes all edges V−1 times. Works with negative weights. A V-th relaxation pass that still improves a distance indicates a negative cycle. Slower than Dijkstra but more general.

📐 Pseudocode · Bellman-Ford 
function bellmanFord(edges, V, src):
    dist ← array of V, all ∞
    dist[src] ← 0

    repeat V - 1 times:                    // V-1 rounds
        for (u, v, w) in edges:
            if dist[u] ≠ ∞ and dist[u] + w < dist[v]:
                dist[v] ← dist[u] + w

    // Optional V-th pass: anything that still improves means a negative cycle
    for (u, v, w) in edges:
        if dist[u] ≠ ∞ and dist[u] + w < dist[v]:
            report "negative cycle reachable from src"
    return dist

// Time: O(V × E)  Space: O(V)
// In fixed-width integers use a large finite INF (e.g. MAX ÷ 2) so dist[u] + w can't overflow
💡
LC 787 “Cheapest Flights Within K Stops”: Use Bellman-Ford limited to K+1 rounds instead of V−1. Copy dist at the start of each round to avoid using the same round's updates within the same round (the “temp array” trick).
TimeO(V × E)
SpaceO(V)
HandlesNegative weights

🔳 Floyd-Warshall

Floyd-Warshall computes all-pairs shortest paths in O(V3) time. Works with negative weights (no negative cycles). Use only when V is small (≤ 300) and you need distances between every pair of nodes.

🎯 Floyd-Warshall Recognition Signal

"Shortest path between all pairs", "transitive closure", "can i reach j?" for every pair, or small V (≤ 300) with negative weights → Floyd-Warshall. Single source? Use Dijkstra or Bellman-Ford instead.

📐 Pseudocode · Floyd-Warshall All-Pairs Shortest Path 
// dist[i][j] = shortest distance from i to j
dist ← V × V matrix, all ∞
for i from 0 to V - 1: dist[i][i] ← 0
for (u, v, w) in edges: dist[u][v] ← w

// Try every intermediate node k
for k from 0 to V - 1:
    for i from 0 to V - 1:
        for j from 0 to V - 1:
            if dist[i][k] < ∞ and dist[k][j] < ∞:
                dist[i][j] ← min(dist[i][j], dist[i][k] + dist[k][j])

// Negative cycle: if dist[i][i] < 0 for any i, a negative cycle exists
// Time: O(V³)  Space: O(V²)
⚠
Overflow guard: Use INF = 1e9 (not Integer.MAX_VALUE) to avoid overflow when computing dist[i][k] + dist[k][j]. The guard if (dist[i][k] < INF) also protects you.
TimeO(V³)
SpaceO(V²)
HandlesNegative weights

🌳 Minimum Spanning Tree (MST)

An MST connects all V nodes using exactly V−1 edges with the minimum total weight. Two classic algorithms, both greedily build the MST.

Algorithm Strategy Data Structure Time Best When
Kruskal's Sort edges, add if no cycle Union-Find O(E log E) Sparse graphs
Prim's Grow MST from a node, always add cheapest reachable edge Min-Heap O(E log V) Dense graphs

Kruskal's Algorithm

📐 Pseudocode · Kruskal's Minimum Spanning Tree 
// Sort every edge cheapest first; keep an edge only if it joins
// two components that were not already connected.
sort edges by weight ascending
dsu ← disjoint-set over V nodes
total ← 0; used ← 0

for (w, u, v) in edges:
    if dsu.find(u) ≠ dsu.find(v):    // different components — safe
        dsu.union(u, v)
        total ← total + w
        used ← used + 1
        if used = V - 1: break       // a spanning tree has V-1 edges

if used < V - 1: return GRAPH_NOT_CONNECTED
return total

// The disjoint-set find, with path compression:
function find(parent, x):
    if parent[x] ≠ x: parent[x] ← find(parent, parent[x])   // point straight at the root
    return parent[x]

Prim's Algorithm

📐 Pseudocode · Prim's MST (min-heap) 
function prim(adj, V):
    inMST ← array of V, all false
    pq ← min-heap of (edgeWeight, node), starting with (0, 0)   // start from node 0
    cost ← 0
    while pq is not empty:
        (w, node) ← pq.popMin()
        if inMST[node]: continue        // already joined by a cheaper edge
        inMST[node] ← true
        cost ← cost + w
        for (nei, weight) in adj[node]:
            if not inMST[nei]: pq.push((weight, nei))
    return cost

// Time: O(E log V)  Space: O(V + E)

🌸 Bipartite Graphs

A graph is bipartite if its nodes can be split into two groups such that every edge crosses between groups (no edge within a group). Equivalently: the graph is 2-colorable, equivalently: contains no odd-length cycle.

📌
Check: BFS 2-coloring. Assign alternating colors (0/1) during BFS. If you ever try to color a node the same color as its neighbour, the graph is not bipartite.
📐 Pseudocode · Bipartite Check (BFS coloring) 
function isBipartite(graph):
    n ← length(graph)
    color ← array of n, all -1          // -1 = uncolored, otherwise 0 or 1

    for start from 0 to n - 1:           // the graph may be disconnected
        if color[start] ≠ -1: continue
        color[start] ← 0
        q ← queue containing start
        while q is not empty:
            node ← q.dequeue()
            for nei in graph[node]:
                if color[nei] = -1:
                    color[nei] ← 1 - color[node]    // opposite color
                    q.enqueue(nei)
                else if color[nei] = color[node]:
                    return false                    // conflict
    return true

🔣 Tarjan's Bridge Finding

A bridge is an edge whose removal disconnects the graph. Tarjan's algorithm finds all bridges in O(V + E) using two DFS arrays: disc[] (discovery time) and low[] (lowest discovery time reachable from the subtree without using the parent edge).

💡
Key insight: Edge (u, v) is a bridge when the subtree rooted at v cannot "look back" past u without this edge. Formally: low[v] > disc[u]. If low[v] ≤ disc[u], there is a back-edge in the subtree that bypasses the edge — removing it won't disconnect anything.
📐 Pseudocode · Tarjan's Bridge Finding (LC 1192) 
disc ← array of n, all -1     // discovery time
low ← array of n              // earliest discovery time reachable from the subtree
timer ← 0
bridges ← empty list

function criticalConnections(n, connections):
    adj ← undirected adjacency list built from connections
    for i from 0 to n - 1:
        if disc[i] = -1: dfs(adj, i, -1)
    return bridges

function dfs(adj, u, parent):
    disc[u] ← timer;  low[u] ← timer;  timer ← timer + 1
    for v in adj[u]:
        if v = parent: continue                 // skip the edge we came from
        if disc[v] = -1:                        // tree edge — recurse
            dfs(adj, v, u)
            low[u] ← min(low[u], low[v])
            if low[v] > disc[u]:                // v can't reach u or above without this edge
                append (u, v) to bridges
        else:                                   // back edge — update low
            low[u] ← min(low[u], disc[v])

// Time: O(V + E)  Space: O(V)
📌
Multigraph caveat: The parent-skip if (v == parent) fails when there are parallel edges (e.g., two edges between u and v). For multigraphs, track the parent edge index instead of the parent node.
TimeO(V + E)
SpaceO(V)

🎯 Pattern Decision Guide

Signal in Problem Pattern Key Tool
"Shortest path" — unweighted / unit weight BFS Queue + visited[]
"Shortest path" — weighted, non-negative Dijkstra Min-heap PQ
"Shortest path" — negative weights or K-stop limit Bellman-Ford Edge list, V−1 rounds
"Connected components", "number of islands" DFS flood fill visited[] + recursive DFS
"Course prerequisites", "task order", "dependency" Topological Sort Kahn's (in-degree) or DFS post-order
"Can you complete all courses" = detect cycle in directed graph Cycle Detection 3-color DFS or Kahn's (idx < n)
"Minimum cost to connect all nodes" MST Kruskal's (edges) or Prim's (heap)
"Two groups", "no conflict", "bipartite" BFS 2-coloring color[] alternating
"All-pairs shortest path" (small V) Floyd-Warshall 3-loop DP, O(V³)
✅
The 4-question framework for any graph problem:
1. What are the nodes? (cells, words, courses, …)
2. What are the edges? (adjacent cells, one-letter diff, prerequisite, …)
3. Directed or undirected? Weighted?
4. What am I computing? (shortest path, reachability, order, connectivity)

💪 In-Lecture Practice Problems

Problem 01 · LC 200
Number of Islands
Medium DFS Flood Fill Amazon · Google · Meta · Microsoft
▶
Problem

Given a 2D grid of '1' (land) and '0' (water), count the number of islands. An island is surrounded by water and connected horizontally/vertically.

Input: [["1","1","0"],["0","1","0"],["0","0","1"]] Output: 2
Hints
▶Hint 1 — a nudge

Each island is a connected component; the grid is the graph.

▶Hint 2 — the key idea

Scan every cell; on an unvisited '1', increment the count and flood-fill the component away. Sinking it to '0' is your visited marker.

Solution

DFS from each unvisited '1', marking all connected land cells as '0' (sinking the island). Each time you start a new DFS, increment the count. The grid itself acts as the visited array.

▶
Solution
📐 Pseudocode · LC 200 
function numIslands(grid):
    count ← 0
    for every cell (r, c):
        if grid[r][c] = '1':
            dfs(grid, r, c)
            count ← count + 1
    return count

function dfs(g, r, c):
    if r, c out of bounds or g[r][c] ≠ '1': return
    g[r][c] ← '0'                          // sink it
    dfs(g, r+1, c);  dfs(g, r-1, c);  dfs(g, r, c+1);  dfs(g, r, c-1)
TimeO(m×n)
SpaceO(m×n)
Problem 02 · LC 994
Rotting Oranges
Medium Multi-Source BFS Amazon · Google · Meta
▶
Problem

Grid contains 0 (empty), 1 (fresh orange), 2 (rotten). Each minute a rotten orange rots adjacent fresh oranges. Return the minimum minutes to rot all, or -1 if impossible.

Input: [[2,1,1],[1,1,0],[0,1,1]] Output: 4
Hints
▶Hint 1 — a nudge

Rot spreads outward one ring per minute, from every rotten orange simultaneously.

▶Hint 2 — the key idea

Multi-source BFS: enqueue every rotten orange before the loop, then count completed levels. Afterwards, any remaining fresh orange means return -1.

Solution

Seed all initially rotten oranges into the BFS queue at time 0. BFS propagates one level (= one minute) per round. After BFS completes, if any 1 remains in the grid, return -1.

▶
Solution
📐 Pseudocode · LC 994 
function orangesRotting(grid):
    q ← empty queue;  fresh ← 0;  mins ← 0
    for every cell (r, c):
        if grid[r][c] = 2: q.enqueue((r, c))
        else if grid[r][c] = 1: fresh ← fresh + 1
    while q is not empty and fresh > 0:
        mins ← mins + 1
        repeat q.size times:                 // one minute = one BFS level
            (r, c) ← q.dequeue()
            for each of the 4 neighbours (nr, nc):
                if in bounds and grid[nr][nc] = 1:
                    grid[nr][nc] ← 2
                    fresh ← fresh - 1
                    q.enqueue((nr, nc))
    if fresh = 0: return mins
    return -1
TimeO(m×n)
SpaceO(m×n)
Problem 03 · LC 207
Course Schedule
Medium Topological Sort / Cycle Detection Amazon · Google · Meta · Microsoft
▶
Problem

There are n courses (0 to n-1). prerequisites[i] = [a, b] means you must take b before a. Return true if it is possible to finish all courses.

Input: n=2, prerequisites=[[1,0]] Output: true Input: n=2, prerequisites=[[1,0],[0,1]] Output: false (cycle)
Hints
▶Hint 1 — a nudge

'Can I finish?' is really asking whether the prerequisite graph has a cycle.

▶Hint 2 — the key idea

Kahn's algorithm: repeatedly remove nodes with in-degree 0. If you cannot process all V nodes, the leftovers form a cycle.

Solution

Build a directed graph. A cycle means a course depends on itself (directly or indirectly) — impossible. Run Kahn's BFS: if the number of processed nodes equals n, no cycle.

▶
Solution
📐 Pseudocode · LC 207 
function canFinish(n, prerequisites):
    adj ← n empty lists;  indeg ← array of n, all 0
    for (course, pre) in prerequisites:
        adj[pre].append(course)             // pre must come before course
        indeg[course] ← indeg[course] + 1
    q ← every node with indeg = 0
    done ← 0
    while q is not empty:
        node ← q.dequeue()
        done ← done + 1
        for nei in adj[node]:
            indeg[nei] ← indeg[nei] - 1
            if indeg[nei] = 0: q.enqueue(nei)
    return done = n                          // anything left is stuck in a cycle
TimeO(V+E)
SpaceO(V+E)
Problem 04 · LC 743
Network Delay Time
Medium Dijkstra Google · Amazon · Uber
▶
Problem

Weighted directed graph with n nodes. Signal starts from node k. Return the time for all nodes to receive the signal, or -1 if any node is unreachable.

Input: times=[[2,1,1],[2,3,1],[3,4,1]], n=4, k=2 Output: 2
Hints
▶Hint 1 — a nudge

Edges have weights, so BFS is wrong. All weights are positive, so you have a choice.

▶Hint 2 — the key idea

Dijkstra with a min-heap. The answer is the maximum over all shortest distances; if any node is unreachable, return -1.

Solution

Dijkstra from node k. Answer = max(dist[]). If any dist remains infinity, return -1. Classic single-source shortest path on a weighted graph.

▶
Solution
📐 Pseudocode · LC 743 
function networkDelayTime(times, n, k):
    adj ← n + 1 empty lists                 // nodes are 1-indexed
    for (u, v, w) in times: adj[u].append((v, w))
    dist ← array of n + 1, all ∞;  dist[k] ← 0
    pq ← min-heap of (distance, node), starting with (0, k)
    while pq is not empty:
        (d, node) ← pq.popMin()
        if d > dist[node]: continue          // stale
        for (nei, w) in adj[node]:
            if dist[node] + w < dist[nei]:
                dist[nei] ← dist[node] + w
                pq.push((dist[nei], nei))
    ans ← 0
    for i from 1 to n:
        if dist[i] = ∞: return -1            // some node never hears the signal
        ans ← max(ans, dist[i])
    return ans
TimeO((V+E) log V)
SpaceO(V+E)
Problem 05 · LC 1584
Min Cost to Connect All Points
Medium MST — Prim's Google · Amazon · Meta
▶
Problem

Given n points on a 2D plane, return the minimum cost to connect all points. Cost of connecting two points = Manhattan distance. All pairs are implicitly edges.

Input: [[0,0],[2,2],[3,10],[5,2],[7,0]] Output: 20
Hints
▶Hint 1 — a nudge

Every pair of points is connectable, so this is a complete weighted graph.

▶Hint 2 — the key idea

Minimum spanning tree over Manhattan distances. Prim's with a min-heap is O(n² log n) and avoids materialising all n² edges; Kruskal's with union-find also works.

Solution

MST on a complete graph where edge weight = Manhattan distance. Prim's is efficient here: maintain a min-heap of (cost, node). The inMST[] flag replaces the visited check. Greedily add the cheapest reachable edge.

▶
Solution
📐 Pseudocode · LC 1584 
function minCostConnectPoints(pts):
    n ← length(pts)
    inMST ← array of n, all false
    minDist ← array of n, all ∞;  minDist[0] ← 0
    pq ← min-heap of (distance, index), starting with (0, 0)
    cost ← 0
    while pq is not empty:
        (d, i) ← pq.popMin()
        if inMST[i]: continue
        inMST[i] ← true
        cost ← cost + d
        for j from 0 to n - 1:              // dense graph: every point is a neighbour
            if inMST[j]: continue
            dj ← |pts[i].x - pts[j].x| + |pts[i].y - pts[j].y|   // Manhattan distance
            if dj < minDist[j]:
                minDist[j] ← dj
                pq.push((dj, j))
    return cost
TimeO(n² log n)
SpaceO(n)
