Glossary

“Every word this course uses, in plain English.”

💡
Met a word you do not know? Look it up here. Each definition is deliberately short — enough to keep reading — and links to the lecture where the idea is taught properly.

A

Adjacency list
A way to store a graph: for each node, a list of the nodes it connects to. Uses space proportional to nodes plus edges. Lecture 21 →
Algorithm
A precise, step-by-step method for solving a problem that always finishes. Lecture 1 →
Amortised cost
The average cost per operation over a long sequence, when most operations are cheap and a few are expensive. Adding to a growable list is O(1) amortised. Lecture 1 →
Array
A fixed-length row of items stored side by side, so any item can be read instantly by its position (index). Lecture 11 →
Articulation point
A node whose removal, together with its edges, splits a connected graph into pieces. Found in one DFS using discovery and low times. Lecture 40 →
Auxiliary space
The extra memory an algorithm uses beyond its input. When interviewers say “space complexity” they usually mean this. Lecture 1 →

B

Backtracking
Building a solution one choice at a time and undoing the last choice when it leads nowhere: choose, explore, un-choose. Lecture 24 →
Balanced BST
A binary search tree that keeps its height around log n after every insert and delete, usually with rotations, so every operation stays O(log n). AVL and red-black trees are the classic kinds. Lecture 41 →
Base case
The input small enough that a recursive function answers it directly, without calling itself. Every recursion needs one. Lecture 8 →
BFS (breadth-first search)
Exploring a graph level by level with a queue: first every neighbour, then every neighbour’s neighbour. Finds shortest paths when all edges cost the same. Lecture 21 →
Big-O
A label for how an algorithm’s work grows as its input grows. O(n) means doubling the input roughly doubles the work. Lecture 1 →
Binary search
Finding a target in sorted data by checking the middle and throwing away the half that cannot contain it. O(log n). Lecture 13 →
Binary search tree (BST)
A binary tree where every value in a node’s left subtree is smaller than it and every value in its right subtree is larger. Lecture 19 →
Binary tree
A tree in which every node has at most two children, called left and right. Lecture 18 →
Bitmask
An integer used as a row of on/off switches, one bit per item — a compact way to store a set of up to about 20 items. Lecture 9 →
Brute force
The simplest solution that is obviously correct, usually by trying every possibility. Always the first thing to state. Lecture 2 →

C

Cache
A small, fast store that keeps copies of recently or frequently used data so the next request for it is quick. It can be out of date, so it needs a rule for when to refresh or evict. Lecture 43 →
Call stack
The pile of unfinished function calls waiting in memory. Each call adds a frame; returning removes it. Lecture 5 →
Collision
When two different keys produce the same hash value and land in the same bucket of a hash table. Lecture 16 →
Comparator
A rule that tells a sort how to order two items: negative, zero or positive. Lecture 6 →
Cycle
A path in a graph that returns to where it started. Lecture 21 →

D

DAG
A directed acyclic graph: edges have a direction and there are no cycles. Exactly the graphs that have a topological order. Lecture 22 →
Depth
How many edges separate a node from the root of its tree. Lecture 18 →
Deque
A double-ended queue: add and remove at both the front and the back in O(1). Lecture 15 →
DFS (depth-first search)
Exploring a graph by going as deep as possible down one path before backing up. Uses recursion or a stack. Lecture 21 →
Difference array
An array that records where changes start and stop, so many range updates can be applied in one final pass. Lecture 26 →
Dijkstra's algorithm
Finds the shortest paths from one node when every edge weight is zero or positive, by always settling the closest unsettled node next with a priority queue. Lecture 22 →
Divide and conquer
Splitting a problem into independent smaller parts, solving each, then combining the answers. Merge sort is the classic example. Lecture 30 →
Dynamic programming (DP)
Solving a problem by solving overlapping subproblems once each and storing their answers, instead of recomputing them. Lecture 32 →

E

Edge
A connection between two nodes of a graph. It can have a direction and a weight. Lecture 21 →
Edge case
An unusual input — empty, a single item, very large, all equal — where correct-looking code often breaks. Lecture 3 →
Expected value
The average result of a random process over many repeats: each outcome times its probability, added up. The expected value of a sum is the sum of the expected values. Lecture 42 →

F

Fenwick tree
A compact structure that keeps prefix sums up to date as values change, in O(log n) per operation. Also called a binary indexed tree. Lecture 37 →

G

GCD
Greatest common divisor: the largest number that divides two numbers exactly. Found quickly with Euclid’s algorithm. Lecture 10 →
Graph
A set of nodes (vertices) and connections between them (edges). Road maps, social networks and dependencies are all graphs. Lecture 21 →
Greedy algorithm
An algorithm that makes the locally best choice at every step and never reconsiders. Correct only when you can prove that choice is safe. Lecture 29 →
Grundy number
A number given to each game position: the smallest non-negative value not reachable in one move (the mex). Zero means the player to move loses; independent games combine by XOR. Lecture 42 →

H

Hash function
A function that turns a key into a number used to pick a storage slot. Equal keys must give equal numbers. Lecture 16 →
Hash map
A structure storing key → value pairs with average O(1) insert and lookup. Java’s HashMap. Lecture 16 →
Hash set
A collection of distinct items with average O(1) “is this present?” checks. Java’s HashSet. Lecture 16 →
Heap
A tree-shaped structure that always keeps the smallest (or largest) item at the top, with O(log n) insert and remove. Lecture 20 →
Height
The number of edges on the longest path from a node down to a leaf. The height of a tree is the height of its root. Lecture 18 →

I

Immutable
Cannot be changed after it is created. Java strings are immutable; “changing” one really builds a new one. Lecture 11 →
In-place
Working inside the input’s own memory using only O(1) extra space, instead of building a copy. Lecture 1 →
Inclusion–exclusion
A counting rule for overlapping groups: add the single groups, subtract every pair, add back every triple, and so on, so nothing is counted twice. Lecture 42 →
Index
The position of an item in an array or list. In Java, and in this course, positions start at 0. Lecture 11 →
Invariant
A statement that stays true at every step of a loop. Checking it is one of the fastest ways to find a bug. Lecture 3 →
Iterator
An object that hands out the items of a collection one at a time through hasNext() and next(), often doing the work lazily as each item is requested. Lecture 43 →

K

KMP (Knuth–Morris–Pratt)
A string-search algorithm that finds a pattern in a text in O(n + m) by precomputing, for each prefix of the pattern, how far it can fall back after a mismatch. Lecture 39 →

L

Lazy deletion
Marking or ignoring outdated entries instead of removing them straight away, and discarding them only when they reach the front — the usual way to “update” a heap. Lecture 43 →
Leaf
A tree node with no children. Lecture 18 →
Linked list
A chain of nodes, each holding a value and a reference to the next node. Fast to insert into, slow to index. Lecture 14 →
Load balancer
A server that spreads incoming requests across several identical servers so no single one is overloaded. Lecture 45 →
LRU cache
A cache that, when full, evicts the least recently used item. Built from a HashMap plus a doubly linked list so get and put are both O(1). Lecture 16 →

M

Matrix exponentiation
Computing the n-th term of a linear recurrence by writing one step as a matrix and raising it to the n-th power with repeated squaring, in O(k³ log n). Lecture 42 →
Max flow
The largest amount that can travel from a source to a sink through a network of capacity-limited edges. It always equals the capacity of the cheapest cut separating them. Lecture 40 →
Memoisation
Storing the answer to each function call the first time it is computed, so repeated calls return it instantly. Lecture 8 →
Minimum spanning tree (MST)
The cheapest set of edges that connects every node of a weighted graph without forming a cycle. Lecture 23 →
Mo's algorithm
A way to answer many offline range queries fast by sorting them into blocks so that moving from one query's range to the next adds or removes only a few elements. Lecture 38 →
Modular inverse
The number you multiply by to “divide” under a modulus. Modulo a prime p, the inverse of a is a to the power p − 2. Lecture 42 →
Modulo
The remainder after division, written mod or %. Used to keep huge numbers small. Lecture 10 →
Monotonic stack
A stack kept in sorted order: when a new item breaks the order, the items it beats are popped and have found their answer. Lecture 27 →
Multiset
A collection like a set that can hold the same value more than once. In Java it is usually faked with a TreeMap from value to count. Lecture 41 →

N

Nim
A game with several piles where a move takes any number of stones from one pile. The player to move loses exactly when the XOR of the pile sizes is 0. Lecture 42 →
Node
One item in a linked list, tree or graph, holding a value and links to other nodes. Lecture 14 →

O

Off-by-one error
Being wrong by exactly one: looping once too often, stopping one early, or reading one past the end. Lecture 3 →
Overflow
When a number grows past the largest value its type can hold and silently wraps round to a wrong, often negative, value. Lecture 3 →

P

Prefix sum
A running total: the sum of everything up to each position. Turns any range-sum question into one subtraction. Lecture 26 →
Priority queue
A queue that always hands out the most important item next rather than the oldest. Usually built on a heap. Lecture 20 →
Pruning
Abandoning a branch of a search as soon as it is clear it cannot lead to a valid answer. Lecture 24 →
Pseudocode
Plain, precise steps written in a small notation that is not any real programming language. Every algorithm in this course is written in it. Lecture 1 →

Q

Queue
A first-in, first-out (FIFO) line: items are added at the back and removed from the front. Lecture 15 →

R

Recursion
A function that solves a problem by calling itself on a smaller version of the same problem. Lecture 8 →
Reference
A value that points to where an object lives in memory, rather than being the object itself. Lecture 5 →
Rolling hash
A hash of a window of text that can be updated in O(1) as the window slides one character, used by Rabin-Karp to compare substrings quickly. Lecture 39 →
Rotation
A local rearrangement of three pointers in a binary search tree that lifts a child above its parent without changing the in-order order. Balanced trees use it to fix their shape. Lecture 41 →

S

Segment tree
A tree of subtotals over ranges of an array, supporting range queries and updates in O(log n). Lecture 37 →
Shortest path
The route between two nodes with the smallest total edge weight. Found with BFS, Dijkstra or Bellman-Ford depending on the weights. Lecture 22 →
Skip list
A sorted linked list with extra “express” levels chosen by coin flips, giving O(log n) expected search, insert and delete without any rotations. Lecture 41 →
Sliding window
A range of an array that moves along it, updated by adding what enters and removing what leaves instead of recomputing. Lecture 25 →
Space complexity
How the memory an algorithm needs grows with the size of its input. Lecture 1 →
Spaced repetition
Re-solving a problem after growing gaps — for example 1, 7 and 30 days — so it moves into long-term memory. Lecture 44 →
Sqrt decomposition
Splitting an array into about √n blocks with a summary per block, so range queries and updates cost about O(√n). Lecture 38 →
Stable sort
A sort that keeps equal items in the order they were already in. Lecture 12 →
Stack
A last-in, first-out (LIFO) pile: you add and remove only at the top. Lecture 15 →
STAR method
A way to answer behavioural questions: Situation, Task, Action, Result — with most of the time spent on what you did. Lecture 45 →
Strongly connected component (SCC)
In a directed graph, a largest group of nodes where every node can reach every other by following the arrows. Found with Kosaraju's or Tarjan's algorithm. Lecture 40 →
Sweep line
Processing events in time (or position) order while keeping a running state, such as the number of meetings in progress. Lecture 28 →

T

Tabulation
Filling a dynamic-programming table from the smallest subproblems upward, with loops instead of recursion. Lecture 32 →
Time complexity
How the running time of an algorithm grows with the size of its input, written in Big-O. Lecture 1 →
Topological sort
An ordering of a directed acyclic graph’s nodes in which every edge points forward — any order that respects the dependencies. Lecture 22 →
Trace table
A table of every variable’s value after each step of a loop, filled in by hand to check code without running it. Lecture 3 →
Tree
A connected graph with no cycles, usually drawn with one root at the top and children below. Lecture 18 →
TreeMap
Java's sorted map, built on a red-black tree. Besides get and put, it answers neighbour questions such as floorKey and ceilingKey in O(log n). TreeSet is the same without values. Lecture 41 →
Trie
A tree of letters where words that start the same share the same path. Makes prefix lookups fast. Lecture 36 →
Two pointers
Two positions moving through the data — often from both ends, or one fast and one slow — to avoid a nested loop. Lecture 25 →

U

UMPIRE
A six-stage plan for a coding interview: Understand, Match, Plan, Implement, Review, Evaluate. Lecture 45 →
Union-find
A structure that tracks which items belong to the same group and can merge groups, in almost O(1) per operation. Also called disjoint set union (DSU). Lecture 31 →

V

Vertex
Another word for a node in a graph. Lecture 21 →

W

Worst case
The input that makes an algorithm do the most work. Interview complexity questions mean the worst case unless they say otherwise. Lecture 1 →
