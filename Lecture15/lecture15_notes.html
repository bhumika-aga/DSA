Trees — Binary Trees & BST

“Everything is just recursion on a node. Trust the function for the subtrees, combine at the root.”

📚 Lecture 15 of 38 Phase 2 — Core Data Structures ⏱ 10 days 🎯 45 problems 💼 Google · Amazon · Meta · Microsoft · Apple
🌍
Why does this topic matter?
Trees appear in roughly 25–30% of all FAANG on-site rounds. Google in particular is famous for tree problems. More importantly, trees are the first non-linear data structure you encounter — they force you to think recursively, which is the fundamental skill underlying graphs, dynamic programming, and almost everything that follows. Once you truly understand trees, you understand recursion.
By the end of this lecture you can
  • Master all traversals (pre, in, post, level-order, Morris traversal)
  • Think recursively — every tree problem is root + left sub-problem + right sub-problem
  • Leverage BST property for O(log n) operations
  • Solve path-sum, ancestor, construction, and serialization problems

📚 Before We Start — The Recursive Leap of Faith

Every tree function follows one template: assume that solve(node.left) and solve(node.right) already return the correct answer for their subtrees. Your only job is to combine those two answers with the current node to produce the answer for the whole tree. This is called the recursive leap of faith — trust the function.

You have been doing this implicitly since Lecture 5 (Recursion). Every recursive call stack is a tree. Now you make it explicit with actual tree nodes and pointers.

🔗
How it connects: This lecture builds on Lecture 5 (Recursion) and Lecture 12 (Stacks & Queues). You will use a stack for iterative DFS and a queue for BFS level-order. Trees are the prerequisite for Lecture 16 (Heaps), Lecture 17 (Graphs), and the ordered-structure problems in Lecture 34.

🧰 Tree Anatomy

Build the mental model before writing a single line of code:

Tree Vocabulary — Memorise These 
          1          ← Root (no parent)
        /   \
       2     3       ← Internal nodes (have children)
      / \     \
     4   5     6    ← Leaf nodes (no children)

 Node 1: depth = 0, height = 2
 Node 2: depth = 1, height = 1
 Node 4: depth = 2, height = 0  (leaf)

 Tree height   = longest root-to-leaf path = 2
 Subtree of 2  = the entire tree rooted at node 2

 Full BT    : every node has 0 or 2 children
 Complete BT: all levels full except last (left-filled)
 Perfect BT : all internal nodes 2 children, all leaves same depth
 Balanced BT: |height(left) - height(right)| <= 1 at EVERY node
 BST        : left < root < right at EVERY node

🟊 Pattern 1 — DFS Traversals (Pre / In / Post)

The foundational tree pattern. Everything else builds on top of this. The three orders all use the same recursive skeleton — only the position of the “process root” step changes:

Pattern Skeleton

Base case: if node is null → return
Preorder : process root → left → right
Inorder : left → process root → right
Postorder : left → right → process root

📐 Pseudocode · The Three DFS Orders 
// Same walk, three different moments to do the work.
function dfs(node):
    if node = null: return

    visit(node)        // PRE-order  — root, left, right
    dfs(node.left)
    visit(node)        // IN-order   — left, root, right  (sorted, for a BST)
    dfs(node.right)
    visit(node)        // POST-order — left, right, root  (children first)

// Keep exactly ONE visit() line. Which one you keep is the whole choice:
//   pre  -> you need the root before its children (clone, serialise)
//   in   -> you need sorted order (BST validation, kth smallest)
//   post -> you need child answers before the root (height, delete, sizes)

Iterative Traversals (No Recursion)

📐 Pseudocode · Iterative Preorder + Inorder 
// Iterative Preorder — push RIGHT first, then LEFT (so left is processed first)
function preorderIterative(root):
    res ← empty list
    if root = null: return res
    stack ← [root]
    while stack is not empty:
        n ← stack.pop()
        append n.val to res                      // visit ROOT immediately
        if n.right ≠ null: stack.push(n.right)   // right first → processed last
        if n.left ≠ null: stack.push(n.left)
    return res

// Iterative Inorder — go left until null, pop and visit, then go right
function inorderIterative(root):
    res ← empty list
    stack ← empty stack
    curr ← root
    while curr ≠ null or stack is not empty:
        while curr ≠ null:
            stack.push(curr)
            curr ← curr.left
        curr ← stack.pop()
        append curr.val to res
        curr ← curr.right
    return res

// Time O(n), Space O(h). Key trick for preorder: push RIGHT before LEFT.
📊
Dry Run — All 3 orders on this tree:
1 / \ 2 3 / 4 Preorder (Root→L→R) : 1 2 4 3 ← use for: clone tree, serialize, prefix Inorder (L→Root→R) : 4 2 1 3 ← use for: BST sorted output, kth smallest Postorder (L→R→Root) : 4 2 3 1 ← use for: delete tree, height, evaluate expression Iterative inorder — stack state trace: curr=1 → push 1, go left curr=2 → push 2, go left curr=4 → push 4, go left curr=null → pop 4, visit 4, curr=4.right=null curr=null → pop 2, visit 2, curr=2.right=null curr=null → pop 1, visit 1, curr=1.right=3 curr=3 → push 3, go left curr=null → pop 3, visit 3, curr=3.right=null ✓ Result: [4, 2, 1, 3]

🌟 Pattern 2 — BFS Level-Order

Use a queue. Process the tree one level at a time. Any problem mentioning “by level,” “row,” or “right side view” is Pattern 2.

📌
The Critical Trick: Snapshot int size = q.size() before the inner loop. This locks in how many nodes are in the current level. As you add children mid-loop, the queue grows, but you only process size nodes per level.
📐 Pseudocode · BFS Level-Order 
// Fixing the level size before the inner loop is what separates
// one level from the next.
if root = null: return empty
queue ← [root]
levels ← empty list

while queue not empty:
    size ← length(queue)      // <-- snapshot THIS level
    level ← empty list

    repeat size times:
        node ← queue.popFront()
        level.append(node.value)
        if node.left  ≠ null: queue.pushBack(node.left)
        if node.right ≠ null: queue.pushBack(node.right)

    levels.append(level)

return levels

// Variants built on this template:
//   Right side view   → last element of each level
//   Zigzag traversal  → alternate direction per level (add to front on odd levels)
//   Average of levels → sum ÷ size per level
📊
Dry Run — Level-Order on tree [1, 2, 3, 4]:
1 / \ 2 3 / 4 Queue=[1] size=1 → visit 1, enqueue 2,3 Level 0: [1] Queue=[2,3] size=2 → visit 2 (enqueue 4), visit 3 Level 1: [2,3] Queue=[4] size=1 → visit 4, no children Level 2: [4] Queue=[] done ✓ Result: [[1], [2,3], [4]] Right side view = last of each level = [1, 3, 4]

🎮 Pattern 3 — Height Recursion (Bottom-Up)

The function returns a number to its caller. Root combines left & right results. This is postorder DFS where each call computes something useful for its parent.

📐 Pseudocode · Max Depth + Balanced Check 
// Height recursion — children compute FIRST (postorder), the parent uses both results.
function maxDepth(n):
    if n = null: return 0
    lh ← maxDepth(n.left)
    rh ← maxDepth(n.right)
    return 1 + max(lh, rh)

// Balanced tree — use -1 as a sentinel for "unbalanced", O(n) single pass:
function isBalanced(root):
    return check(root) ≠ -1

function check(n):
    if n = null: return 0
    lh ← check(n.left);   if lh = -1: return -1
    rh ← check(n.right);  if rh = -1: return -1
    if |lh - rh| > 1: return -1
    return 1 + max(lh, rh)
📚
Dry Run — maxDepth on [3, 9, 20, null, null, 15, 7]:
3 / \ 9 20 / \ 15 7 Call-stack unwind (children resolve before parent): maxDepth(9) → lh=0, rh=0 → 1+max(0,0) = 1 maxDepth(15) → lh=0, rh=0 → 1+max(0,0) = 1 maxDepth(7) → lh=0, rh=0 → 1+max(0,0) = 1 maxDepth(20) → lh=1, rh=1 → 1+max(1,1) = 2 maxDepth(3) → lh=1, rh=2 → 1+max(1,2) = 3 ✓

🏆 Pattern 4 — Global State via Local Traversal

The answer lives in a class-level variable updated during DFS. The function's return value is a helper value, not the final answer. This trips up beginners the most.

📐 Pseudocode · Diameter of Binary Tree (LC 543) 
// Global state pattern: the recursion RETURNS a helper value (height)
// but UPDATES a global answer (diameter) at every node.
maxD ← 0                               // global answer

function diameterOfBinaryTree(root):
    dfs(root)
    return maxD

function dfs(n):                       // returns HEIGHT, not diameter
    if n = null: return 0
    lh ← dfs(n.left)
    rh ← dfs(n.right)
    maxD ← max(maxD, lh + rh)          // diameter through THIS node
    return 1 + max(lh, rh)             // height handed back to the parent

// Diameter at a node = leftHeight + rightHeight (edges through it)
// We check EVERY node as a potential "peak" of the diameter path
💡
Same pattern solves Binary Tree Maximum Path Sum (LC 124). Return the max gain from one branch; update global with leftGain + node.val + rightGain. Once you understand Pattern 4, LC 124 is a 10-line solution.
📐 Pseudocode · Binary Tree Maximum Path Sum (LC 124) — Hard 
maxSum ← -∞                           // global: reset per problem instance

function maxPathSum(root):
    gain(root)
    return maxSum

// gain(n) = the most this subtree can add to a path going UP to its parent
function gain(n):
    if n = null: return 0
    lGain ← max(0, gain(n.left))         // ignore negative branches
    rGain ← max(0, gain(n.right))
    maxSum ← max(maxSum, lGain + n.val + rGain)   // path THROUGH this node
    return n.val + max(lGain, rGain)     // can only go ONE direction up

// Why max(0, gain)? A negative subtree hurts the path — better to skip it.
// Why return only ONE side? A path going up can't branch — the parent picks one.
📊
Dry Run — Diameter of [1,2,3,4,5] (answer=3):
1 / \ 2 3 / \ 4 5 ⚠ dfs() returns HEIGHT; global maxD stores DIAMETER Call-stack unwind (postorder): dfs(4) → lh=0,rh=0 → maxD=max(0,0+0)=0 → return 1 dfs(5) → lh=0,rh=0 → maxD=max(0,0+0)=0 → return 1 dfs(2) → lh=1,rh=1 → maxD=max(0,2) → return 2 dfs(3) → lh=0,rh=0 → maxD=max(2,0)=2 → return 1 dfs(1) → lh=2,rh=1 → maxD=max(2,3) → return 3 Answer: maxD=3 ✓ (path: 4→2→1→3)

🆕 Pattern 5 — The BST Property

For every node in a BST, all values in its left subtree are strictly less, and all values in its right subtree are strictly greater.

📐 Pseudocode · BST Operations 
// The BST rule: everything in the left subtree < node < everything in the right
function search(node, val):
    while node ≠ null:
        if val = node.val: return node          // found
        if val < node.val: node ← node.left
        else: node ← node.right
    return null

// Insert:   same walk as search until null, place the new node there
// Validate: pass (min, max) bounds down; every node needs min < val < max
// Inorder:  always produces a sorted sequence ← the key BST insight
⚠️
Classic Mistake — Wrong BST validation: Checking only node.left.val < node.val < node.right.val at each node is wrong. You must pass a valid range [min, max] down the tree. Going left narrows the max; going right narrows the min. Start the bounds at ±∞ (in Java, use Long bounds) so a node holding the smallest or largest possible integer isn't wrongly rejected.
📐 Pseudocode · Validate BST + Kth Smallest 
// Validate BST — range propagation:
function isValidBST(root):
    return check(root, -∞, +∞)

function check(n, lo, hi):
    if n = null: return true
    if n.val ≤ lo or n.val ≥ hi: return false
    return check(n.left, lo, n.val) and check(n.right, n.val, hi)
    // going left narrows the max; going right narrows the min

// Kth Smallest — inorder = sorted, count as you go:
k ← the requested rank;  result ← none
function kth(n):
    if n = null or result is set: return
    kth(n.left)
    k ← k - 1
    if k = 0:
        result ← n.val
        return
    kth(n.right)

BST Insert & Delete

📐 Pseudocode · BST Insert (LC 701) + Delete (LC 450) 
// INSERT: navigate like search until a null spot, place the node there
function insertIntoBST(root, val):
    if root = null: return TreeNode(val)
    if val < root.val: root.left ← insertIntoBST(root.left, val)
    else: root.right ← insertIntoBST(root.right, val)
    return root                  // return root so the parent's pointer stays valid

// DELETE: 3 cases
// Case 1: leaf node    → return null
// Case 2: one child    → return that child
// Case 3: two children → copy the inorder successor up, delete the successor below
function deleteNode(root, key):
    if root = null: return null
    if key < root.val: root.left ← deleteNode(root.left, key)
    else if key > root.val: root.right ← deleteNode(root.right, key)
    else:
        if root.left = null: return root.right       // Cases 1 and 2
        if root.right = null: return root.left
        succ ← root.right
        while succ.left ≠ null: succ ← succ.left      // leftmost = successor
        root.val ← succ.val                           // copy value up
        root.right ← deleteNode(root.right, succ.val) // delete the old successor
    return root

// Time O(h): O(log n) for a balanced BST, O(n) worst case (skewed)

🌐 Pattern 6 — Lowest Common Ancestor (LCA)

The LCA of two nodes p and q is the deepest node that is an ancestor of both. It is the first node where they “split” in the tree.

📐 Pseudocode · LCA Binary Tree (LC 236) + BST (LC 235) 
// Binary Tree — works for any tree:
function lca(n, p, q):
    if n = null or n = p or n = q: return n
    l ← lca(n.left, p, q)
    r ← lca(n.right, p, q)
    if l ≠ null and r ≠ null: return n     // split here → this IS the LCA
    if l ≠ null: return l
    return r                               // whichever side found something

// BST — exploit the ordering (simpler):
function lcaBST(n, p, q):
    if p.val < n.val and q.val < n.val: return lcaBST(n.left, p, q)
    if p.val > n.val and q.val > n.val: return lcaBST(n.right, p, q)
    return n                               // split point → LCA
📌
Dry Run — LCA(root=3, p=5, q=1) on [3,5,1,6,2,0,8]:
3 / \ 5 1 / \ / \ 6 2 0 8 lca(3, p=5, q=1): left = lca(5, p=5, q=1) → node==p → return 5 ◄ found p right = lca(1, p=5, q=1) → node==q → return 1 ◄ found q both non-null → split point → return 3 ✓ Key: once both sides return non-null, the current node IS the LCA.

🧵 Morris Traversal — O(1) Space

Every traversal so far has cost O(h) memory — the call stack, or an explicit stack. Morris traversal gets in-order out of a tree in O(1) extra space by borrowing the null right pointers of leaf nodes as temporary threads back up the tree, then putting them back. Every node is visited at most twice, so it is still O(n) time.

📐 Pseudocode · Morris In-order Traversal 
// In-order traversal with NO recursion and NO stack.
// Idea: temporarily point each predecessor's right pointer back
// at its successor, so you can climb back up without a stack.
cur ← root

while cur ≠ null:
    if cur.left = null:
        visit(cur)
        cur ← cur.right
    else:
        // find the rightmost node of the left subtree
        pred ← cur.left
        while pred.right ≠ null and pred.right ≠ cur:
            pred ← pred.right

        if pred.right = null:
            pred.right ← cur      // 1st visit: thread it, go left
            cur ← cur.left
        else:
            pred.right ← null     // 2nd visit: unthread, restore tree
            visit(cur)
            cur ← cur.right
TimeO(n) — each edge walked at most twice SpaceO(1)
⚠️
It mutates the tree while it runs
Between the threading and the unthreading, the tree is temporarily not a tree — it has cycles. The algorithm always restores it, but never run it concurrently with anything else reading the tree, and never on a structure you must not modify.

🏗️ Building a Tree from its Traversals

One traversal is never enough to rebuild a tree — but two are, as long as one of them is in-order. Preorder (or postorder) tells you which node is the root; in-order tells you where that root splits the remaining nodes into a left group and a right group. Recurse on the two groups.

📐 Pseudocode · Build from Preorder + Inorder 
// preorder tells you WHICH node is the root.
// inorder tells you WHERE that root splits left from right.
position ← map from value → index in inorder
p ← 0                     // cursor into preorder

function build(lo, hi):        // inorder range [lo, hi]
    if lo > hi: return null

    node ← Node(preorder[p])
    p ← p + 1
    mid ← position[node.value]

    node.left  ← build(lo, mid - 1)   // must come first: p is shared
    node.right ← build(mid + 1, hi)
    return node

return build(0, length(inorder) - 1)
TimeO(n) — the map removes the linear scan SpaceO(n)
💡
The three variants
Preorder + inorder (LC 105) — take roots from the front. Postorder + inorder (LC 106) — take roots from the back and build right before left. Preorder + postorder (LC 889) — only works when every node has 0 or 2 children, and the answer is not unique.

Problem 01 · LC 94
Binary Tree Inorder Traversal
Easy Pattern 1: DFS Traversal Amazon · Microsoft · Google · Meta
▶
Problem

Given the root of a binary tree, return the inorder traversal of its node values (left → root → right).

Input: [1,null,2,3] Output: [1,3,2] Input: [] Output: []
Hints
▶Hint 1 — a nudge

Recursion is three lines. The interview follow-up is always 'now without recursion'.

▶Hint 2 — the key idea

Iterative: push left as far as you can, pop and visit, then move right. The loop condition is curr != null || !stack.isEmpty() — the second half matters when the left spine runs out.

Solution

Pattern 1 — recursive inorder is trivial (3 lines). The real interview ask: can you do it iteratively? Use an explicit stack. Keep going left until null, pop, visit, then move right. The outer while condition curr != null || !stack.isEmpty() covers the case where all left nodes are exhausted but the stack still has nodes to return to.

▶
Solution (Recursive + Iterative)
📐 Pseudocode · LC 94 — Both Approaches 
// Recursive — Pattern 1 in its purest form:
function inorderRecursive(root):
    res ← empty list
    dfs(root, res)
    return res

function dfs(n, res):
    if n = null: return
    dfs(n.left, res)
    append n.val to res       // ROOT (after left)
    dfs(n.right, res)

// Iterative — the classic interview follow-up:
function inorderIterative(root):
    res ← empty list;  stack ← empty stack;  curr ← root
    while curr ≠ null or stack is not empty:
        while curr ≠ null:
            stack.push(curr);  curr ← curr.left
        curr ← stack.pop()
        append curr.val to res
        curr ← curr.right
    return res

// Both: Time O(n), Space O(h) where h = tree height
TimeO(n)
SpaceO(h) stack
Problem 02 · LC 104
Maximum Depth of Binary Tree
Easy Pattern 3: Height Recursion Amazon · Google · LinkedIn
▶
Problem

Given the root of a binary tree, return its maximum depth (nodes along the longest root-to-leaf path).

Input: [3,9,20,null,null,15,7] Output: 3
Hints
▶Hint 1 — a nudge

A node's depth depends only on its children's depths.

▶Hint 2 — the key idea

Post-order: depth(node) = 1 + max(depth(left), depth(right)), with null returning 0.

Solution

Pattern 3. depth(node) = 1 + max(depth(left), depth(right)). Empty tree returns 0. Trust the recursion for both subtrees, just combine.

▶
Full Solution + Complexity
📐 Pseudocode · LC 104 
function maxDepth(root):
    if root = null: return 0
    return 1 + max(maxDepth(root.left), maxDepth(root.right))
// 3 lines. This is the beauty of pattern recognition.
TimeO(n)
SpaceO(h) stack
Problem 03 · LC 102
Binary Tree Level Order Traversal
Medium Pattern 2: BFS Level-Order Amazon · Microsoft · Google · Meta LC 102
▶
Problem

Return the level-order traversal as a list of lists.

Input: [3,9,20,null,null,15,7] Output: [[3],[9,20],[15,7]]
Hints
▶Hint 1 — a nudge

A plain queue mixes the levels together. How do you know where one level ends?

▶Hint 2 — the key idea

Snapshot queue.size() before the inner loop — that is exactly this level's node count. Process that many, then move to the next level.

Solution

Pattern 2. Queue + snapshot int size = q.size() before inner loop separates levels.

▶
Full Solution
📐 Pseudocode · LC 102 
function levelOrder(root):
    res ← empty list
    if root = null: return res
    q ← queue containing root
    while q is not empty:
        size ← q.size                  // snapshot: this many nodes in the level
        level ← empty list
        repeat size times:
            n ← q.dequeue()
            append n.val to level
            if n.left ≠ null: q.enqueue(n.left)
            if n.right ≠ null: q.enqueue(n.right)
        append level to res
    return res
TimeO(n)
SpaceO(w) queue
Problem 04 · LC 543
Diameter of Binary Tree
Easy Pattern 4: Global via Local Google · Meta · Amazon LC 543
▶
Problem

Return the length of the longest path between any two nodes. The path may not pass through the root.

Input: [1,2,3,4,5] Output: 3 (path 4→2→1→3 or 5→2→1→3)
Hints
▶Hint 1 — a nudge

The diameter may not pass through the root at all.

▶Hint 2 — the key idea

Compute height recursively, but at each node also record leftHeight + rightHeight against a global best. Return the height; update the answer as a side effect.

Solution

Pattern 4. Diameter through any node = leftHeight + rightHeight. DFS returns height; global variable tracks the maximum diameter seen at any node.

▶
Full Solution
📐 Pseudocode · LC 543 
maxD ← 0
function diameterOfBinaryTree(root):
    dfs(root)
    return maxD

function dfs(n):
    if n = null: return 0
    l ← dfs(n.left);  r ← dfs(n.right)
    maxD ← max(maxD, l + r)
    return 1 + max(l, r)
TimeO(n)
SpaceO(h)
Problem 05 · LC 98
Validate Binary Search Tree
Medium Pattern 5: BST Property Amazon · Microsoft · Bloomberg · Meta LC 98
▶
Problem

Determine if a binary tree is a valid BST.

Input: [5,1,4,null,null,3,6] Output: false (root is 5 but right child is 4 which is less)
Hints
▶Hint 1 — a nudge

Checking only node vs its two children is the classic wrong answer.

▶Hint 2 — the key idea

Every node must fall inside an inherited (min, max) range: recurse left with max = node.val and right with min = node.val. Use long bounds for Integer.MIN/MAX values.

Solution

Pattern 5. Pass a valid range [lo, hi] down. Going left tightens the upper bound; going right tightens the lower bound. Use Long to avoid Integer.MIN/MAX_VALUE edge cases.

▶
Full Solution
📐 Pseudocode · LC 98 
function isValidBST(root):
    return check(root, -∞, +∞)

function check(n, lo, hi):
    if n = null: return true
    if n.val ≤ lo or n.val ≥ hi: return false
    return check(n.left, lo, n.val) and check(n.right, n.val, hi)
TimeO(n)
SpaceO(h)
Problem 06 · LC 236
Lowest Common Ancestor of a Binary Tree
Medium Pattern 6: LCA Amazon · Google · Meta · Microsoft LC 236
▶
Problem

Find the lowest common ancestor of two nodes p and q in a binary tree.

Input: root=[3,5,1,6,2,0,8], p=5, q=1 Output: 3
Hints
▶Hint 1 — a nudge

If both targets are in different subtrees, the current node is the answer.

▶Hint 2 — the key idea

Recurse both sides. If both return non-null, this node is the LCA; otherwise pass up whichever side is non-null. In a BST you can do better — walk down until the values straddle the node.

Solution

Pattern 6. Return node when null/p/q. If both left and right are non-null → split here → current node IS the LCA. Else bubble up the non-null side.

▶
Full Solution
📐 Pseudocode · LC 236 
function lca(n, p, q):
    if n = null or n = p or n = q: return n
    l ← lca(n.left, p, q)
    r ← lca(n.right, p, q)
    if l ≠ null and r ≠ null: return n
    if l ≠ null: return l
    return r
TimeO(n)
SpaceO(h)
