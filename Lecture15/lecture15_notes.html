Stacks & Queues

"A stack is memory that thinks last-in first-out. A queue is the world — it's fair."

📚 Lecture 15 of 45 Phase 2 — Core Data Structures ⏱ 4 days 🎯 16 problems 💼 Google · Amazon · Microsoft · Meta
🌍
Why does this topic matter?
Stacks and queues are the two most fundamental sequential data structures after arrays and linked lists. Every operating system uses a call stack to manage function invocations — that's why you see "stack overflow" when recursion goes too deep. Every web browser uses a history stack for the back button. Every customer service system uses queues. In interview problems, the monotonic stack pattern alone appears in dozens of FAANG questions, and this lecture gives you a first look at it through Next Greater Element and Daily Temperatures; Lecture 27 covers it in full, together with the deque, which extends the same idea to sliding windows. These are not just data structures — they are thinking tools.
By the end of this lecture you can
  • Understand LIFO (stack) and FIFO (queue) principles and their implementations
  • Master monotonic stack for next greater/smaller element problems
  • Use queues for BFS and level-order traversals
  • Recognise the monotonic stack shape (taught fully in Lecture 27)

📖 Before We Start — The Mental Model

Think of a stack as a pile of plates — you can only add or remove from the top (Last In, First Out = LIFO). Think of a queue as a line at a coffee shop — first person in line is first to be served (First In, First Out = FIFO).

These simple behaviours unlock surprisingly powerful patterns: you can use a stack to reverse order, to match pairs, and to track history. You can use a queue to process things level by level — which is exactly what BFS does on graphs and trees.

🔗
How it connects: Lecture 14 (Linked Lists) showed you how to build singly/doubly linked lists. A stack is just a linked list where you only touch the head. A queue is a linked list where you add at the tail and remove from the head. Lecture 18 (Trees) uses stacks for DFS traversal and queues for BFS level-order traversal — you'll use everything from this lecture there.

📚 Stack Fundamentals — LIFO

🎯
Core Property: Last In, First Out (LIFO). Only the top element is accessible. Three operations — push(x) (add to top), pop() (remove top), peek() (read top without removing) — all O(1).
Stack visualisation — push(1), push(2), push(3): After push(1): [1] ← top After push(2): [2] ← top [1] After push(3): [3] ← top [2] [1] pop() → returns 3. Stack: [2][1] peek()→ returns 2. Stack unchanged: [2][1]

Stack Implementations in Java

Implementation Backed By push pop Notes
ArrayDeque<T> (preferred) Resizable array O(1)* O(1) Fastest, no synchronisation overhead
Stack<T> (legacy) Vector O(1)* O(1) Synchronized — avoid in single-threaded code
LinkedList (as Deque) Doubly linked list O(1) O(1) More GC pressure from node allocation
☕ Java · Stack using ArrayDeque (Gold Standard) 
// ✅ PREFERRED — ArrayDeque used as a stack
Deque<Integer> stack = new ArrayDeque<>();

stack.push(10);          // addFirst(10) — add to top
stack.push(20);
stack.push(30);

stack.peek();            // 30 — read top, do NOT remove
stack.pop();             // 30 — removes and returns top
stack.isEmpty();         // false
stack.size();            // 2

// ❌ AVOID in interviews — legacy, synchronized
Stack<Integer> legacyStack = new Stack<>();
legacyStack.push(10);   // works, but prefer Deque

Java Stack API Quick Reference

☕ Java · Deque as Stack — All Key Methods 
// Push: addFirst / push / offerFirst
stack.push(x);          // throws if capacity exceeded (rare)
stack.offerFirst(x);    // returns false if capacity exceeded

// Pop: removeFirst / pop / pollFirst
stack.pop();             // throws NoSuchElementException if empty
stack.pollFirst();       // returns null if empty — safer for conditionals

// Peek: peekFirst / peek / getFirst
stack.peek();            // null if empty
stack.getFirst();        // throws if empty

// Check
stack.isEmpty();
stack.size();

// ⚠️ Common interview pattern — check before pop:
if (!stack.isEmpty() && stack.peek() < threshold)
    stack.pop();

📈 Monotonic Stack — A Preview

👀
Preview — covered fully in Lecture 27. This section shows the idea through its simplest use, the next greater element, so that you recognise the shape. Lecture 27 (Monotonic Stack & Queue) is the full treatment: the four variants, spans and the histogram, counting contributions, building the best sequence, and monotonic deques.
🎯
What is a Monotonic Stack? A stack that is always kept in a sorted order (either monotonically increasing or decreasing). When a new element arrives that violates the order, we pop elements until the order is restored. Each popped element has "found its answer" — the new element is the answer it was waiting for.

Next Greater Element Pattern

For each element, find the first element to its right that is greater than it. Brute force is O(n²). Monotonic stack solves it in O(n).

Array: [2, 1, 5, 3, 4] NGE: [5, 5, -1, 4, -1] Walk left→right. Maintain a DECREASING stack of indices. i=0, val=2: stack empty → push 0. stack=[0] (vals:[2]) i=1, val=1: 1 ≤ 2 → push 1. stack=[0,1] (vals:[2,1]) i=2, val=5: 5>1 → pop 1, ans[1]=5 5>2 → pop 0, ans[0]=5 stack empty → push 2. stack=[2] (vals:[5]) i=3, val=3: 3 ≤ 5 → push 3. stack=[2,3] (vals:[5,3]) i=4, val=4: 4>3 → pop 3, ans[3]=4 4 ≤ 5 → push 4. stack=[2,4] (vals:[5,4]) End: remaining on stack → NGE = -1. ans[2]=-1, ans[4]=-1 Result: [5, 5, -1, 4, -1] ✓
📐 Pseudocode · Monotonic Stack 
// The stack holds indices whose answer is still unknown, and it stays
// sorted. Pop everything the new element beats — it is their answer.
stack ← empty          // holds INDICES, kept decreasing by value
result ← array of -1, length n

for i from 0 to n - 1:
    while stack not empty and a[stack.top] < a[i]:
        j ← stack.pop()
        result[j] ← a[i]      // a[i] is j's next greater element
    stack.push(i)

// Anything still on the stack has no greater element to its right.
return result

// next SMALLER  -> flip '<' to '>'
// previous ...  -> walk i from n-1 down to 0

🚶 Queue Fundamentals — FIFO

📌
Core Property: First In, First Out (FIFO). Elements enter at the tail (rear) and exit from the head (front). Operations: offer(x) (enqueue), poll() (dequeue), peek() — all O(1).

Queue Implementations in Java

Implementation Use Case Notes
ArrayDeque<T> (preferred) General FIFO Fastest, no null elements
LinkedList<T> When null needed Slower due to GC
PriorityQueue<T> Min/Max ordering NOT FIFO — ordering by priority
ArrayBlockingQueue<T> Thread-safe bounded For multi-threaded use
☕ Java · Queue using ArrayDeque (FIFO) 
// ArrayDeque used as a QUEUE — add at tail, remove from head
Queue<Integer> queue = new ArrayDeque<>();

queue.offer(1);         // enqueue to tail
queue.offer(2);
queue.offer(3);
                         // queue: [1, 2, 3]  (1 is head)
queue.peek();           // → 1  (read head, no remove)
queue.poll();           // → 1  (remove head)
queue.peek();           // → 2
queue.size();           // → 2
queue.isEmpty();        // → false

// BFS template — bread-and-butter queue usage:
while (!queue.isEmpty()) {
    int node = queue.poll();
    // process node
    // add neighbours: queue.offer(neighbour)
}

The Deque — a Queue With Two Doors

A deque (“deck”, double-ended queue) lets you add and remove at both ends in O(1). In Java it is ArrayDeque, and it is the recommended way to get both a stack and a queue — faster than the old Stack class.

👀
Preview — covered fully in Lecture 27. Keep a deque sorted and it answers “what is the maximum of this sliding window?” in O(n) total. That trick — the monotonic deque — is taught with its template and problems in Lecture 27.

🔢 Expression Evaluation — Stack Arithmetic

Evaluating arithmetic expressions is a classic stack application. The key idea: numbers go onto an operand stack; operators control when to compute. Reverse Polish Notation (RPN / postfix) eliminates the need for parentheses — operators come after their operands.

RPN: ["2","1","+","3","*"] → (2+1)*3 = 9 Process token by token: "2" → push 2. stack=[2] "1" → push 1. stack=[2,1] "+" → pop 1, pop 2 → 2+1=3 → push 3. stack=[3] "3" → push 3. stack=[3,3] "*" → pop 3, pop 3 → 3*3=9 → push 9. stack=[9] Result = 9 ✓
📐 Pseudocode · Evaluate Reverse Polish Notation 
function evalRPN(tokens):
    stack ← empty stack
    for t in tokens:
        if t is an operator (+ - × ÷):
            b ← stack.pop()          // popped FIRST = right operand — order matters!
            a ← stack.pop()
            stack.push(apply t to a and b)   // ÷ truncates toward zero
        else:
            stack.push(integer value of t)
    return stack.pop()

Balanced brackets / undo history → Plain Stack

Priority scheduling, top-K → PriorityQueue (Heap)

⚠️ Complexity & Classic Bugs

The costs worth quoting in an interview first, then the mistakes that most often break code that looks correct. Every row in the second table is a bug someone has shipped.

Operation Cost Note
push, pop, peek (ArrayDeque) O(1)
offer, poll (queue) O(1)
Queue built from two stacks O(1) amortised per operation Each item moves at most twice
Stack built from two queues O(n) for push or pop
Evaluate an expression with two stacks O(n)
Bug Symptom Fix
pop or peek on an empty stack Exception, or null then a crash Check isEmpty() first
Using java.util.Stack Slower than necessary Use ArrayDeque
Transferring between the two stacks on every operation O(n) per operation instead of amortised O(1) Only transfer when the output stack is empty
Ignoring operator precedence 2 + 3 × 4 evaluates to 20 Apply operators of higher or equal precedence first
Assuming division rounds down Java's -7 / 2 is −3 Check what the problem expects
Circular queue: full and empty look the same head = tail is ambiguous Track the size separately
A closing bracket with an empty stack Crash instead of “invalid” An empty stack on ) means the string is invalid

💪 In-Lecture Practice Problems

Problem 01 · Plain Stack
Valid Parentheses
🔗 LC 20
Easy Google · Amazon · Meta · Microsoft Stack
›
Problem

Given a string containing only '(', ')', '{', '}', '[', ']', determine if the input string is valid. Open brackets must be closed by the same type bracket and in the correct order.

"()[]{}" → true "([)]" → false "{[]}" → true "[" → false
Hints
▶Hint 1 — a nudge

The most recently opened bracket must close first.

▶Hint 2 — the key idea

Push openers; on a closer, pop and compare. Fail if you pop an empty stack, or if the stack is non-empty at the end.

Solution

Push every open bracket. When you encounter a close bracket, check if the stack's top is the matching open bracket — if not, immediately return false. At the end, the stack must be empty (every open was properly closed).

▶Full solution
📐 Pseudocode · Stack Matching 
function isValid(s):
    stack ← empty stack
    for c in s:
        if c is '(' or '[' or '{':
            stack.push(c)
        else:
            if stack is empty: return false
            top ← stack.pop()
            if top is not the opening partner of c: return false
    return stack is empty

// "{[]}" → push {, push [, ] matches [ pop, } matches { pop, stack empty → true ✓
TimeO(N)
SpaceO(N)
Problem 02 · Design
Min Stack
🔗 LC 155
Medium Amazon · Google · Bloomberg Two-Stack Design
›
Problem

Design a stack that supports push, pop, top, and getMin — all in O(1) time.

push(5)→push(3)→push(7)→getMin()=3→pop()→getMin()=3→pop()→getMin()=5
Hints
▶Hint 1 — a nudge

getMin() must not scan. What if each entry carried its own answer?

▶Hint 2 — the key idea

Push (value, minSoFar) pairs, or keep a parallel stack of minima. The top always holds the current minimum.

Solution

Run two parallel stacks: a main stack for values, and a min-stack where each level records the current minimum at that depth. When you push, also push min(val, minStack.peek()). When you pop, pop both. getMin() is always the top of the min-stack — O(1).

▶Full solution
📐 Pseudocode · Parallel Min-Stack 
record MinStack:
    stack       // the values
    minStack    // minStack.top() = minimum of everything currently in stack

function push(ms, val):
    ms.stack.push(val)
    if ms.minStack is empty: curMin ← val
    else: curMin ← min(val, ms.minStack.top())
    ms.minStack.push(curMin)

function pop(ms):    ms.stack.pop();  ms.minStack.pop()
function top(ms):    return ms.stack.top()
function getMin(ms): return ms.minStack.top()

// push(5): stack=[5], min=[5]
// push(3): stack=[3,5], min=[3,5]
// push(7): stack=[7,3,5], min=[3,3,5]  ← min stays 3
// getMin()=3 ✓   pop() → stack=[3,5], min=[3,5] → getMin()=3 ✓
TimeO(1) all ops
SpaceO(N)
Problem 03 · Monotonic Stack
Daily Temperatures
🔗 LC 739
Medium Amazon · Google · Meta Monotonic Stack
›
Problem

Given daily temperatures, return an array where answer[i] is the number of days you have to wait after day i to get a warmer temperature. If no warmer day exists, put 0.

[73,74,75,71,69,72,76,73] → [1,1,4,2,1,1,0,0]
Hints
▶Hint 1 — a nudge

For each day you want the next warmer day. That is 'next greater element'.

▶Hint 2 — the key idea

Monotonic decreasing stack of indices. When today beats the top, pop it — today is its answer, and the distance is i - poppedIndex.

Solution

This is "Next Greater Element" — the answer for each day is the distance (in indices) to its next greater temperature. Use a monotonic decreasing stack of indices. When a warmer day arrives, pop all cooler days and record the gap.

▶Full solution
📐 Pseudocode · Monotonic Decreasing Stack 
function dailyTemperatures(temps):
    ans ← array of length(temps), filled with 0
    stack ← empty stack                         // indices
    for i from 0 to length(temps) - 1:
        while stack is not empty and temps[stack.top()] < temps[i]:
            j ← stack.pop()
            ans[j] ← i - j                      // days waited = index difference
        stack.push(i)
    return ans            // anything left on the stack keeps 0 (no warmer day)

// [73,74,...]: i=0 push 0. i=1 temp[1]=74 > 73 → pop 0, ans[0]=1-0=1 ✓
TimeO(N)
SpaceO(N)
Problem 04 · Monotonic Stack + HashMap
Next Greater Element I
🔗 LC 496
Easy Amazon · Microsoft · Adobe Mono Stack + HashMap
›
Problem

nums1 is a subset of nums2. For each element in nums1, find its Next Great Element in nums2. Return -1 if none exists.

nums1=[4,1,2], nums2=[1,3,4,2] → [-1,3,-1] (4 has no NGE in nums2; 1's NGE is 3; 2 has no NGE)
Hints
▶Hint 1 — a nudge

Solve it for the whole second array first, then just look answers up.

▶Hint 2 — the key idea

Build a value → nextGreater map with one monotonic-stack pass over nums2, then read off nums1 in O(1) each.

Solution

Pre-compute NGE for every element in nums2 using a monotonic stack and store the results in a HashMap val → NGE. Then answer each query in O(1) from the map. This pattern decouples the "compute" step from the "query" step.

▶Full solution
📐 Pseudocode · Pre-compute NGE then Query 
function nextGreaterElement(nums1, nums2):
    nge ← empty map                     // value → its next greater value
    stack ← empty stack                 // values, decreasing
    for n in nums2:
        while stack is not empty and stack.top() < n:
            nge[stack.pop()] ← n
        stack.push(n)
    // whatever remains on the stack has no greater element

    ans ← array of length(nums1)
    for i from 0 to length(nums1) - 1:
        if nums1[i] in nge: ans[i] ← nge[nums1[i]]
        else: ans[i] ← -1
    return ans
TimeO(M+N)
SpaceO(N)
Problem 05 · Stack Arithmetic
Evaluate Reverse Polish Notation
🔗 LC 150
Medium Amazon · LinkedIn · Meta Stack
›
Problem

Evaluate the value of an arithmetic expression in Reverse Polish Notation (postfix). Valid operators: +, -, *, /. Each operand may be an integer or another expression. Division truncates toward zero.

["2","1","+","3","*"] → 9 ((2+1)*3) ["4","13","5","/","+"] → 6 (4+(13/5))
Hints
▶Hint 1 — a nudge

Postfix notation was designed for exactly one data structure.

▶Hint 2 — the key idea

Push numbers; on an operator pop two and push the result. Order matters for - and /: the second pop is the left operand.

Solution

Process tokens left to right. If a number, push to stack. If an operator, pop two numbers (order matters: b = pop(), a = pop(), then compute a op b) and push the result. The final stack contains the answer.

▶Full solution
📐 Pseudocode · Operand Stack 
function evalRPN(tokens):
    stack ← empty stack
    for t in tokens:
        if t is an operator:
            b ← stack.pop()
            a ← stack.pop()
            stack.push(apply t to a and b)
        else:
            stack.push(integer value of t)
    return stack.pop()
TimeO(N)
SpaceO(N)
Problem 06 · Circular Queue Design
Design Circular Queue
🔗 LC 622
Medium Microsoft · Amazon · Google Array + Two Pointers
›
Problem

Design a circular queue (ring buffer) supporting enQueue, deQueue, Front, Rear, isEmpty, isFull — all O(1).

Circular buffer of capacity 5: Indices: [0] [1] [2] [3] [4] [A] [B] [C] [ ] [ ] ↑head ↑tail(next write) After deQueue(): head=1, B is front After enQueue(D): [A][B][C][D][ ], tail=4 After filling and deQueuing, tail wraps: tail = (tail+1) % capacity
Hints
▶Hint 1 — a nudge

A fixed array plus modular arithmetic beats shifting elements.

▶Hint 2 — the key idea

Keep head, count and a capacity-sized array. Tail is (head + count) % capacity. Storing count avoids the classic full-vs-empty ambiguity.

Solution

Use a fixed-size array, a head pointer, a tail pointer, and a size counter. Advance pointers using % capacity to wrap around. isFull when size == capacity, isEmpty when size == 0.

▶Full solution
📐 Pseudocode · Ring Buffer 
record CircularQueue:
    buf ← array of size k
    head ← 0;  tail ← 0;  size ← 0;  cap ← k

function enQueue(q, val):
    if isFull(q): return false
    q.buf[q.tail] ← val
    q.tail ← (q.tail + 1) mod q.cap          // wrap around
    q.size ← q.size + 1
    return true

function deQueue(q):
    if isEmpty(q): return false
    q.head ← (q.head + 1) mod q.cap
    q.size ← q.size - 1
    return true

function front(q):   if isEmpty(q): return -1 else: return q.buf[q.head]
function rear(q):    if isEmpty(q): return -1 else: return q.buf[(q.tail - 1 + q.cap) mod q.cap]
function isEmpty(q): return q.size = 0
function isFull(q):  return q.size = q.cap
TimeO(1) all ops
SpaceO(K)
