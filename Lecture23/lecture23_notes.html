Divide & Conquer

“Cut the problem in half, solve both halves, and spend all your cleverness on putting them back together.”

📚 Lecture 23 of 38 Phase 3 — Core Patterns ⏱ 4 days 🎯 18 problems 💼 Google · Amazon · Meta · Microsoft
🌍
Why does this topic matter?
Merge sort, quick sort and binary search were all divide and conquer — you just were not asked to say so. This lecture gives the technique its own name and, more usefully, its own arithmetic: the Master Theorem, which reads the running time straight off the recursion. Then it covers the two places the technique earns its keep — selecting without sorting, and counting pairs during a merge.
By the end of this lecture you can
  • Write any divide-and-conquer solution as divide, conquer, combine
  • Apply the Master Theorem to T(n) = a·T(n/b) + f(n) and get the answer in seconds
  • Use QuickSelect for O(n) average selection, and say why it is not O(n log n)
  • Count pairs during a merge without adding to the complexity
  • Split a problem space that is not an array — expressions, constructions, character positions

✂ Divide, Conquer, Combine

Three steps, always in the same order. The interesting one is the third: if combining is cheap the algorithm is fast, and if combining is expensive you may as well not have split.

📐 Pseudocode · The Template 
function solve(problem):
    if problem is small enough:
        return answer directly          // base case — never forget it

    left, right ← split(problem)         // DIVIDE
    a ← solve(left)                      // CONQUER
    b ← solve(right)
    return combine(a, b)                // COMBINE — where the real work lives

// Merge sort: split at the middle, combine = merge two sorted halves.
// Binary search: split at the middle, one side is thrown away, combine = nothing.
🧠
Divide and conquer vs dynamic programming. Both split a problem into smaller ones. The difference is overlap: the halves of a merge sort share nothing, so each is solved once. The subproblems of Fibonacci overlap heavily, so solving each one afresh is exponential — that is where memoisation, and Phase 4, come in.

📏 The Master Theorem

Almost every divide-and-conquer recursion has the same shape: a subproblems, each of size n / b, plus f(n) work to split and combine.

T(n) = a · T(n / b) + f(n)     a = how many subproblems  |  b = how much smaller each one is  |  f(n) = divide + combine

Compare f(n) against nlogba — the total work done by the leaves. Whichever side dominates decides the answer.

The Three Cases

Case When Result Example
Leaves win f(n) grows slower than nlogba Θ(nlogba) naive matrix multiply: 8 halves, O(n²) combine
Tie they grow at the same rate Θ(nlogba log n) merge sort: 2 halves, O(n) merge → O(n log n)
Root wins f(n) grows faster Θ(f(n)) 2 halves, O(n²) combine → O(n²)
Recurrence a, b, f(n) Answer Where you have seen it
T(n) = 2T(n/2) + O(n) 2, 2, n O(n log n) Merge sort, count inversions
T(n) = T(n/2) + O(1) 1, 2, 1 O(log n) Binary search, fast power
T(n) = 2T(n/2) + O(1) 2, 2, 1 O(n) Tree traversal, tree height
T(n) = T(n/2) + O(n) 1, 2, n O(n) QuickSelect (average case)
⚠️
Read the fourth row carefully. T(n) = T(n/2) + O(n) is linear, not O(n log n), because the work halves every level: n + n/2 + n/4 + … < 2n. Recursing into one half instead of both is what makes QuickSelect beat sorting.

🎯 QuickSelect — Selection Without Sorting

You need the k-th smallest element. Sorting gives it in O(n log n), but sorting answers a much harder question than the one asked. QuickSelect partitions around a pivot and then recurses into only the side that can contain the answer.

📐 Pseudocode · QuickSelect 
function quickSelect(nums, k):        // k is a 0-based index into the sorted order
    lo ← 0;  hi ← length(nums) - 1

    while lo < hi:
        p ← partition(nums, lo, hi)      // random pivot: everything < it on the left
        if p = k: return nums[p]
        if p < k: lo ← p + 1            // the answer is to the right
        else: hi ← p - 1                 // the answer is to the left
    return nums[lo]

function partition(nums, lo, hi):      // Lomuto, with a random pivot
    swap nums[random index in lo..hi], nums[hi]
    pivot ← nums[hi];  store ← lo
    for i from lo to hi - 1:
        if nums[i] < pivot:
            swap nums[i], nums[store];  store ← store + 1
    swap nums[store], nums[hi]
    return store
Average Worst Space
Sort, then index O(n log n) O(n log n) O(log n)
Size-k heap O(n log k) O(n log k) O(k)
QuickSelect O(n) O(n²) O(1) iterative
🛑
Always randomise the pivot. With a fixed pivot, a sorted or adversarial input makes every partition remove one element — n + (n−1) + … = O(n²). A random pivot makes that case vanishingly unlikely; the median-of-medians pivot guarantees O(n) worst case but is slower in practice and is a theory answer, not an interview one.

🔢 Counting in the Merge

The second big use. While merging two sorted halves you know something you will never know again: every element still in the left half is before every element in the right half, and both halves are sorted. Pairs can be counted in bulk, for free.

📐 Pseudocode · Count Inversions 
// An inversion is a pair i < j with nums[i] > nums[j].
function sortAndCount(nums, lo, hi):
    if hi - lo ≤ 1: return 0
    mid ← (lo + hi) ÷ 2
    count ← sortAndCount(nums, lo, mid) + sortAndCount(nums, mid, hi)

    // count across the halves BEFORE merging destroys the split
    j ← mid
    for i from lo to mid - 1:
        while j < hi and nums[j] < nums[i]: j ← j + 1
        count ← count + (j - mid)        // this many right elements are smaller

    merge the two halves in place
    return count

// The counting pointer only moves forward, so the extra work is O(n)
// per level — the total stays O(n log n).
🧠
One pattern, many questions. Count of Smaller Numbers After Self, Reverse Pairs, Count of Range Sum and Number of Pairs Satisfying an Inequality are all this loop with a different comparison. Rewrite the condition so it compares one element of the left half with one of the right, and the rest of the code does not change.

🧩 Splitting Something That Is Not an Array

The technique is not about arrays; it is about choosing a split point. The interesting problems are the ones where you have to invent it.

Every Operator Is a Split

📐 Pseudocode · Different Ways to Add Parentheses 
function ways(expr):
    if expr is a plain number: return [value of expr]

    results ← empty list
    for each position i where expr[i] is an operator:
        left ← ways(expr[0 .. i-1])        // everything before the operator
        right ← ways(expr[i+1 .. end])     // everything after it
        for a in left:
            for b in right:
                results.append(apply expr[i] to a and b)
    return results

// "2*3-4*5": splitting at each of the three operators gives every
// possible parenthesisation. Memoise on the substring to avoid re-solving.

Building by Halves

Construction problems run the template backwards: instead of splitting an answer, you split the input and let the recursion build the structure.

Problem The split The combine
Maximum Binary Tree at the largest value make it the root of the two halves
Balance a BST at the middle of the sorted values middle becomes the root
Construct Quad Tree into four equal squares merge four identical leaves into one
Longest Substring with K Repeats at every character that is too rare take the best answer among the pieces
⚠️
The split must always shrink the problem. If a recursive call can receive the same input it was given — an empty range, or a split that puts everything on one side — the recursion never ends. Check the base case and the strict decrease before you run anything.

⚠️ Complexity & The Classic Bugs

Algorithm Recurrence Time Space
Merge sort / count inversions 2T(n/2) + O(n) O(n log n) O(n)
QuickSelect (random pivot) T(n/2) + O(n) expected O(n) average, O(n²) worst O(1)
Binary search / fast power T(n/2) + O(1) O(log n) O(1)
Split at every operator Catalan-many results exponential without memoisation O(n²) memo
Bug Symptom Fix
A split that does not shrink Stack overflow on a two-element input Check that both sides are strictly smaller
Counting after merging Inversion counts far too low Count while the halves are still separate
Fixed pivot in QuickSelect Times out on sorted input Pick the pivot at random
Recursing into both sides of a partition O(n log n) where O(n) was expected Only the side containing k matters
Mid computed as (lo + hi) / 2 Overflow on very large bounds lo + (hi - lo) / 2
No memo on overlapping splits Exponential blow-up on long expressions Cache by the substring or index range
💡
How to spot it in an interview. The answer for the whole can be built from the answers for two halves, and the halves do not depend on each other. Or the question asks for one order statistic rather than the whole order. Or it counts pairs (i, j) with i < j and a comparison — that is a merge sort with a counting line.

Problem 01 · Tree Recursion
Subtree of Another Tree
🔗 LC 572 - Subtree of Another Tree
Easy Divide on the Root Amazon · Google · Meta
›
Problem

Return true if subRoot appears as a subtree of root: some node of root, with all of its descendants, equals subRoot.

root = [3,4,5,1,2], subRoot = [4,1,2] → true   |   subRoot = [4,1,3] → false
Hints
▶Hint 1 — a nudge

Two different questions hide here: “are these two trees identical?” and “does this tree contain that one?”

▶Hint 2 — the key idea

Write isSame(a, b) first. Then the answer is: this node matches, or the left subtree contains it, or the right one does.

Solution

The clean version is two small recursions rather than one clever one. isSame divides on the root and requires both halves to agree; isSubtree divides on the root and requires either half to succeed. Cost is O(n·m) in the worst case, because each of the n nodes may start a comparison — acceptable here, and the reason the serialise-and-search trick exists.

▶Full solution
📐 Pseudocode · Two Recursions 
function isSubtree(root, subRoot):
    if root = null: return false
    if isSame(root, subRoot): return true
    return isSubtree(root.left, subRoot) or isSubtree(root.right, subRoot)

function isSame(a, b):
    if a = null and b = null: return true
    if a = null or b = null: return false
    if a.val ≠ b.val: return false
    return isSame(a.left, b.left) and isSame(a.right, b.right)
TimeO(n × m)
SpaceO(h)
Problem 02 · Split at Every Operator
Different Ways to Add Parentheses
🔗 LC 241 - Different Ways to Add Parentheses
Medium Split the Expression Google · Amazon · Meta
›
Problem

Given an expression of numbers and the operators +, - and *, return every possible result from different ways of grouping it.

expression = "2*3-4*5" → [-34, -14, -10, -10, 10]
Hints
▶Hint 1 — a nudge

Parenthesising means choosing which operator is applied last. What does that choice do to the string?

▶Hint 2 — the key idea

Each operator splits the expression into a left part and a right part. Solve both recursively, then combine every left result with every right result using that operator.

Solution

The split point is the operator applied last, so trying each operator in turn enumerates every grouping exactly once. A number with no operators is the base case. Results multiply, so memoise on the substring (or on the index range) — without it the same sub-expression is recomputed a Catalan number of times.

▶Full solution
📐 Pseudocode · Recurse on Both Sides 
function diffWaysToCompute(expr):
    if expr contains no operator: return [number(expr)]
    if expr in memo: return memo[expr]

    results ← empty list
    for i from 0 to length(expr) - 1:
        if expr[i] is an operator:
            left ← diffWaysToCompute(expr[0 .. i-1])
            right ← diffWaysToCompute(expr[i+1 .. end])
            for a in left:
                for b in right:
                    results.append(apply expr[i] to a, b)

    memo[expr] ← results
    return results
TimeO(Catalan(n))
SpaceO(n²) memo
Problem 03 · Split on a Bad Character
Longest Substring with At Least K Repeating Characters
🔗 LC 395 - Longest Substring with At Least K Repeating Characters
Medium Divide on the Impossible Google · Amazon · Meta
›
Problem

Return the length of the longest substring in which every character appears at least k times.

s = "aaabb", k = 3 → 3  ("aaa")  |   s = "ababbc", k = 2 → 5  ("ababb")
Hints
▶Hint 1 — a nudge

A sliding window struggles here. Instead, look for a character that appears fewer than k times in the whole string.

▶Hint 2 — the key idea

That character can never be inside the answer, so it splits the string. Solve each piece between the bad characters and take the best.

Solution

The insight is negative: find something the answer cannot contain, and use it as the split point. Counting the whole string costs O(n); each recursive call works on strictly shorter pieces. If no character is rare, the whole string is valid and the recursion ends. Depth is bounded by the alphabet size, giving O(26·n).

▶Full solution
📐 Pseudocode · Split at Rare Characters 
function longestSubstring(s, k):
    if length(s) < k: return 0
    count ← frequency of each character in s

    for c in count:
        if count[c] > 0 and count[c] < k:       // c can never be in the answer
            best ← 0
            for piece in split s on c:
                best ← max(best, longestSubstring(piece, k))
            return best

    return length(s)                             // every character is frequent enough

// "ababbc", k=2: 'c' appears once → split into "ababb" → all counts ≥ 2 → 5 ✓
TimeO(26 × n)
SpaceO(26 × depth)
Problem 04 · Build by Halves
Beautiful Array
🔗 LC 932 - Beautiful Array
Medium Construct by Parity Google · Amazon
›
Problem

Return any permutation of 1..n such that for every i < k < j, nums[k] * 2 ≠ nums[i] + nums[j].

n = 5 → [1, 5, 3, 2, 4]  (one valid answer of several)
Hints
▶Hint 1 — a nudge

The forbidden condition needs nums[i] + nums[j] to be even. When is that impossible?

▶Hint 2 — the key idea

Put every odd number before every even number: an odd plus an even is odd, so no middle element can break it. Then recursively build the odd half and the even half.

Solution

The trick is a transformation. If A is beautiful, so are 2A - 1 (all odd) and 2A (all even), and concatenating them keeps the property because cross pairs sum to an odd number. So build the array for ⌈n/2⌉, map it to odds, build for ⌊n/2⌋, map it to evens, and join. Each level halves the size: O(n log n).

▶Full solution
📐 Pseudocode · Odds, Then Evens 
function beautifulArray(n):
    if n = 1: return [1]

    odds ← beautifulArray((n + 1) ÷ 2)     // will become 1, 3, 5, ...
    evens ← beautifulArray(n ÷ 2)          // will become 2, 4, 6, ...

    out ← empty list
    for x in odds: out.append(2 × x - 1)
    for x in evens: out.append(2 × x)
    return out

// An odd + an even is odd, so 2 × middle can never equal it —
// only pairs inside a half can break the rule, and those are beautiful already.
TimeO(n log n)
SpaceO(n)
Problem 05 · Count in the Merge
Number of Pairs Satisfying Inequality
🔗 LC 2426 - Number of Pairs Satisfying Inequality
Hard Merge Sort Counting Google · Amazon
›
Problem

Count pairs i < j with nums1[i] - nums1[j] ≤ nums2[i] - nums2[j] + diff.

nums1 = [3,2,5], nums2 = [2,2,1], diff = 1 → 3
Hints
▶Hint 1 — a nudge

Move everything about i to one side and everything about j to the other.

▶Hint 2 — the key idea

With d[i] = nums1[i] - nums2[i] the condition is d[i] ≤ d[j] + diff. Now count pairs i < j with that relation — a merge sort with a counting line.

Solution

The algebra turns two arrays into one. Then it is the inversion-counting pattern: during the merge, both halves are sorted, so for each left element a single forward pointer finds how many right elements satisfy the inequality, and the count is added in bulk. The pointer never rewinds, so the counting is O(n) per level and the total stays O(n log n).

▶Full solution
📐 Pseudocode · Transform, Then Count 
function numberOfPairs(nums1, nums2, diff):
    d ← array where d[i] = nums1[i] - nums2[i]
    return sortAndCount(d, 0, length(d), diff)

function sortAndCount(d, lo, hi, diff):
    if hi - lo ≤ 1: return 0
    mid ← lo + (hi - lo) ÷ 2
    total ← sortAndCount(d, lo, mid, diff) + sortAndCount(d, mid, hi, diff)

    j ← mid
    for i from lo to mid - 1:
        while j < hi and d[j] + diff < d[i]: j ← j + 1
        total ← total + (hi - j)          // all remaining right elements qualify

    merge d[lo..mid) and d[mid..hi) in place
    return total
TimeO(n log n)
SpaceO(n)
Problem 06 · Divide + Combinatorics
Number of Ways to Reorder Array to Get Same BST
🔗 LC 1569 - Number of Ways to Reorder Array to Get Same BST
Hard Split by the Root Google · Amazon
›
Problem

Given a permutation of distinct values, count how many other orderings build the same binary search tree. Answer modulo 109+7.

nums = [2,1,3] → 1   |   nums = [3,4,5,1,2] → 5
Hints
▶Hint 1 — a nudge

The first value is always the root. What decides which side of the tree each later value goes to?

▶Hint 2 — the key idea

Split the rest into values smaller and larger than the root. Any interleaving of the two sequences builds the same tree, so multiply by the number of interleavings: C(left + right, left).

Solution

Divide and conquer plus one counting fact. Within each side the relative order must be preserved, but the two sides can be shuffled together freely — that is a binomial coefficient. The answer is C(l + r, l) × ways(left) × ways(right), minus one at the very end because the original ordering is not a reordering. Precompute Pascal’s triangle for the coefficients, and keep everything modulo 109+7.

▶Full solution
📐 Pseudocode · Interleavings × Both Sides 
function numOfWays(nums):
    C ← Pascal's triangle up to length(nums)      // binomial coefficients mod 1e9+7
    return (ways(nums) - 1) mod 1000000007

function ways(seq):
    if length(seq) ≤ 2: return 1
    root ← seq[0]
    left ← values of seq[1..] smaller than root      // order preserved
    right ← values of seq[1..] larger than root

    interleavings ← C[length(left) + length(right)][length(left)]
    return interleavings × ways(left) × ways(right) mod 1000000007
TimeO(n²)
SpaceO(n²)
