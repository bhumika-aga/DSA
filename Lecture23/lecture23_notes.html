Graphs III — MST, Bipartite & Bridges

“Not where to go — what holds the whole thing together.”

📚 Lecture 23 of 45 Phase 2 — Core Data Structures ⏱ 4 days 🎯 10 problems 💼 Google · Amazon · Meta · Microsoft
🌍
Why does this topic matter?
The last two lectures moved through a graph. This one asks about its shape. Think of a utility company wiring up a town: they do not care about the route between any two houses, only about the cheapest set of cables that reaches every house — that is a minimum spanning tree. The other two questions here are equally structural: can everyone be split into two groups with no conflicts inside either, and which single link would cut the network in half if it failed?
By the end of this lecture you can
  • Build a minimum spanning tree with Kruskal and with Prim
  • Say which of the two fits a dense graph and which a sparse one
  • Test a graph for bipartiteness by two-colouring it
  • Find every bridge in one DFS using discovery and low-link times
  • Choose the right algorithm from a problem statement

🌳 Minimum Spanning Tree (MST)

An MST connects all V nodes using exactly V−1 edges with the minimum total weight. Two classic algorithms, both greedily build the MST.

Algorithm Strategy Data Structure Time Best When
Kruskal's Sort edges, add if no cycle Union-Find O(E log E) Sparse graphs
Prim's Grow MST from a node, always add cheapest reachable edge Min-Heap O(E log V) Dense graphs

Kruskal's Algorithm

📐 Pseudocode · Kruskal's Minimum Spanning Tree 
// Sort every edge cheapest first; keep an edge only if it joins
// two components that were not already connected.
sort edges by weight ascending
dsu ← disjoint-set over V nodes
total ← 0; used ← 0

for (w, u, v) in edges:
    if dsu.find(u) ≠ dsu.find(v):    // different components — safe
        dsu.union(u, v)
        total ← total + w
        used ← used + 1
        if used = V - 1: break       // a spanning tree has V-1 edges

if used < V - 1: return GRAPH_NOT_CONNECTED
return total

// The disjoint-set find, with path compression:
function find(parent, x):
    if parent[x] ≠ x: parent[x] ← find(parent, parent[x])   // point straight at the root
    return parent[x]

Prim's Algorithm

📐 Pseudocode · Prim's MST (min-heap) 
function prim(adj, V):
    inMST ← array of V, all false
    pq ← min-heap of (edgeWeight, node), starting with (0, 0)   // start from node 0
    cost ← 0
    while pq is not empty:
        (w, node) ← pq.popMin()
        if inMST[node]: continue        // already joined by a cheaper edge
        inMST[node] ← true
        cost ← cost + w
        for (nei, weight) in adj[node]:
            if not inMST[nei]: pq.push((weight, nei))
    return cost

// Time: O(E log V)  Space: O(V + E)

🌸 Bipartite Graphs

A graph is bipartite if its nodes can be split into two groups such that every edge crosses between groups (no edge within a group). Equivalently: the graph is 2-colorable, equivalently: contains no odd-length cycle.

📌
Check: BFS 2-coloring. Assign alternating colors (0/1) during BFS. If you ever try to color a node the same color as its neighbour, the graph is not bipartite.
📐 Pseudocode · Bipartite Check (BFS coloring) 
function isBipartite(graph):
    n ← length(graph)
    color ← array of n, all -1          // -1 = uncolored, otherwise 0 or 1

    for start from 0 to n - 1:           // the graph may be disconnected
        if color[start] ≠ -1: continue
        color[start] ← 0
        q ← queue containing start
        while q is not empty:
            node ← q.dequeue()
            for nei in graph[node]:
                if color[nei] = -1:
                    color[nei] ← 1 - color[node]    // opposite color
                    q.enqueue(nei)
                else if color[nei] = color[node]:
                    return false                    // conflict
    return true

🔣 Tarjan's Bridge Finding

A bridge is an edge whose removal disconnects the graph. Tarjan's algorithm finds all bridges in O(V + E) using two DFS arrays: disc[] (discovery time) and low[] (lowest discovery time reachable from the subtree without using the parent edge).

💡
Key insight: Edge (u, v) is a bridge when the subtree rooted at v cannot "look back" past u without this edge. Formally: low[v] > disc[u]. If low[v] ≤ disc[u], there is a back-edge in the subtree that bypasses the edge — removing it won't disconnect anything.
📐 Pseudocode · Tarjan's Bridge Finding (LC 1192) 
disc ← array of n, all -1     // discovery time
low ← array of n              // earliest discovery time reachable from the subtree
timer ← 0
bridges ← empty list

function criticalConnections(n, connections):
    adj ← undirected adjacency list built from connections
    for i from 0 to n - 1:
        if disc[i] = -1: dfs(adj, i, -1)
    return bridges

function dfs(adj, u, parent):
    disc[u] ← timer;  low[u] ← timer;  timer ← timer + 1
    for v in adj[u]:
        if v = parent: continue                 // skip the edge we came from
        if disc[v] = -1:                        // tree edge — recurse
            dfs(adj, v, u)
            low[u] ← min(low[u], low[v])
            if low[v] > disc[u]:                // v can't reach u or above without this edge
                append (u, v) to bridges
        else:                                   // back edge — update low
            low[u] ← min(low[u], disc[v])

// Time: O(V + E)  Space: O(V)
📌
Multigraph caveat: The parent-skip if (v == parent) fails when there are parallel edges (e.g., two edges between u and v). For multigraphs, track the parent edge index instead of the parent node.
TimeO(V + E)
SpaceO(V)

🎯 Pattern Decision Guide

This guide covers all three graph lectures, not just this one — it is the page to come back to when a new problem turns out to be a graph and you have to pick a tool. Rows marked Lecture 21 or Lecture 22 point back to where that algorithm was taught.

Signal in Problem Pattern Key Tool
"Shortest path" — unweighted / unit weight BFS Queue + visited[]
"Shortest path" — weighted, non-negative Dijkstra Min-heap PQ
"Shortest path" — negative weights or K-stop limit Bellman-Ford Edge list, V−1 rounds
"Connected components", "number of islands" DFS flood fill visited[] + recursive DFS
"Course prerequisites", "task order", "dependency" Topological Sort Kahn's (in-degree) or DFS post-order
"Can you complete all courses" = detect cycle in directed graph Cycle Detection 3-color DFS or Kahn's (idx < n)
"Minimum cost to connect all nodes" MST Kruskal's (edges) or Prim's (heap)
"Two groups", "no conflict", "bipartite" BFS 2-coloring color[] alternating
"All-pairs shortest path" (small V) Floyd-Warshall 3-loop DP, O(V³)
✅
The 4-question framework for any graph problem:
1. What are the nodes? (cells, words, courses, …)
2. What are the edges? (adjacent cells, one-letter diff, prerequisite, …)
3. Directed or undirected? Weighted?
4. What am I computing? (shortest path, reachability, order, connectivity)

⚠️ Complexity & Classic Bugs

The costs worth quoting in an interview first, then the mistakes that most often break code that looks correct. Every row in the second table is a bug someone has shipped.

Operation Cost Note
Kruskal O(E log E) Sorting dominates
Prim with a heap O(E log V)
Bipartite check O(V + E)
Tarjan's bridges O(V + E) One DFS
Eulerian path (Hierholzer) O(E)
Bug Symptom Fix
Kruskal without a cycle check The result is not a tree Union-find; skip edges inside one set
Prim on a disconnected graph Stops early with a wrong total Check that every node was reached
Bipartite check from node 0 only Misses other components Start from every uncoloured node
Tarjan skipping every visited neighbour Misses back edges Skip only the edge you arrived on
Updating low with low[v] on a back edge Wrong articulation points Use disc[v] for back edges
Hierholzer building the path forwards The path comes out in the wrong order Build it backwards, then reverse
Assuming the MST is unique Arguing about “the” answer It is unique only when all weights differ

💪 In-Lecture Practice Problems

Three problems on structure: the cheapest way to connect everything, the edges that everything depends on, and splitting a graph in two.

Problem 01 · LC 1584
Min Cost to Connect All Points
Medium MST — Prim's Google · Amazon · Meta
▶
Problem

Given n points on a 2D plane, return the minimum cost to connect all points. Cost of connecting two points = Manhattan distance. All pairs are implicitly edges.

Input: [[0,0],[2,2],[3,10],[5,2],[7,0]] Output: 20
Hints
▶Hint 1 — a nudge

Every pair of points is connectable, so this is a complete weighted graph.

▶Hint 2 — the key idea

Minimum spanning tree over Manhattan distances. Prim's with a min-heap is O(n² log n) and avoids materialising all n² edges; Kruskal's with union-find also works.

Solution

MST on a complete graph where edge weight = Manhattan distance. Prim's is efficient here: maintain a min-heap of (cost, node). The inMST[] flag replaces the visited check. Greedily add the cheapest reachable edge.

▶Full solution
📐 Pseudocode · LC 1584 
function minCostConnectPoints(pts):
    n ← length(pts)
    inMST ← array of n, all false
    minDist ← array of n, all ∞;  minDist[0] ← 0
    pq ← min-heap of (distance, index), starting with (0, 0)
    cost ← 0
    while pq is not empty:
        (d, i) ← pq.popMin()
        if inMST[i]: continue
        inMST[i] ← true
        cost ← cost + d
        for j from 0 to n - 1:              // dense graph: every point is a neighbour
            if inMST[j]: continue
            dj ← |pts[i].x - pts[j].x| + |pts[i].y - pts[j].y|   // Manhattan distance
            if dj < minDist[j]:
                minDist[j] ← dj
                pq.push((dj, j))
    return cost
TimeO(n² log n)
SpaceO(n)
Problem 02 · What Holds It Together
Critical Connections in a Network
🔗 LC 1192 - Critical Connections in a Network
Hard Tarjan's Bridges Google · Amazon · Meta
›
Problem

Return every edge whose removal would disconnect the network — the bridges of the graph.

n = 4, connections = [[0,1],[1,2],[2,0],[1,3]] → [[1,3]]
Hints
▶Hint 1 — a nudge

Removing each edge and re-running DFS works but costs O(E·(V+E)). What does an edge inside a cycle have that a bridge does not?

▶Hint 2 — the key idea

A way around. Give each node a discovery time, and track the earliest node its subtree can reach by any other route — if a child cannot reach at or above the parent, that edge is a bridge.

Solution

Tarjan’s algorithm in its most useful form. One DFS assigns each node a discovery time, and each node reports back the lowest discovery time reachable from its subtree using at most one back-edge. The edge (u, v) is a bridge exactly when low[v] > disc[u]: v’s whole subtree has no alternative route back to u or earlier, so cutting that edge strands it. Skipping the edge you arrived on — but only that one — is the detail people get wrong.

▶Full solution
📐 Pseudocode · Discovery Time vs Low-Link 
function criticalConnections(n, connections):
    adj ← adjacency list
    disc ← array of -1;  low ← array of 0
    timer ← 0;  bridges ← empty list

    function dfs(u, parent):
        disc[u] ← low[u] ← timer;  timer ← timer + 1

        for v in adj[u]:
            if v = parent: continue       // skip the edge we came on

            if disc[v] = -1:               // tree edge
                dfs(v, u)
                low[u] ← min(low[u], low[v])
                if low[v] > disc[u]:
                    bridges.add((u, v))    // no way around → bridge
            else:                          // back edge: a way around
                low[u] ← min(low[u], disc[v])

    dfs(0, -1)
    return bridges
TimeO(V + E)
SpaceO(V)
Problem 03 · Two Colours
Is Graph Bipartite?
🔗 LC 785 - Is Graph Bipartite?
Medium BFS/DFS 2-Colouring Google · Amazon · Meta
›
Problem

Decide whether a graph’s nodes can be split into two sets so that every edge joins one set to the other.

graph = [[1,2,3],[0,2],[0,1,3],[0,2]] → false
Hints
▶Hint 1 — a nudge

Try colouring a node red and everything next to it blue. When does that go wrong?

▶Hint 2 — the key idea

When you reach a node that is already coloured the same as the one you came from. That happens exactly when the graph has an odd-length cycle.

Solution

Bipartite means two-colourable, and two-colourable means no odd cycle — three ways of saying the same thing, and saying that out loud is most of the answer. The traversal itself is ordinary BFS or DFS with a colour array instead of a visited array: neighbours get the opposite colour, and a neighbour already wearing your colour is the contradiction. The one thing people forget is that the graph may be disconnected, so the outer loop must restart from every uncoloured node.

▶Full solution
📐 Pseudocode · Colour, Then Check Neighbours 
function isBipartite(graph):
    colour ← array of n entries, all 0      // 0 = uncoloured, 1 / -1 = sides

    for start from 0 to n - 1:
        if colour[start] ≠ 0: continue   // graph may be disconnected

        colour[start] ← 1
        queue ← [start]
        while queue is not empty:
            u ← queue.popFront()
            for v in graph[u]:
                if colour[v] = colour[u]: return false   // odd cycle
                if colour[v] = 0:
                    colour[v] ← -colour[u]
                    queue.pushBack(v)

    return true
TimeO(V + E)
SpaceO(V)
