Trees II — BST, LCA & Construction

“An ordering rule turns a tree you can walk into a tree you can search.”

📚 Lecture 19 of 45 Phase 2 — Core Data Structures ⏱ 4 days 🎯 16 problems 💼 Google · Amazon · Meta · Microsoft
🌍
Why does this topic matter?
Lecture 18 taught you to walk a tree. This one adds the two things that make trees genuinely useful in interviews: an ordering rule that turns a tree into something you can search in O(height), and the ability to reason about two nodes at once rather than one. Think of a BST like a well-organised filing cabinet — every drawer you skip is half the cabinet you never open — and an LCA question like finding the most recent shared ancestor on a family tree.
By the end of this lecture you can
  • State the BST property exactly, and why a range check beats a local one
  • Use an in-order walk to get sorted order out of a BST
  • Find the lowest common ancestor of two nodes in one pass
  • Walk a tree in O(1) extra space with Morris traversal
  • Rebuild a tree from two of its traversals
🧠
The picture to keep in your head: a library with signposts at every shelf. In a binary search tree, every shelf has a sign: “smaller call numbers to the left, larger to the right”. Each sign you follow rules out half of what is left, just like binary search. The lowest common ancestor of two books is the last signpost where their routes from the entrance were still the same — the point where they split.

🆕 The BST Property

For every node in a BST, all values in its left subtree are strictly less, and all values in its right subtree are strictly greater.

📐 Pseudocode · BST Operations 
// The BST rule: everything in the left subtree < node < everything in the right
function search(node, val):
    while node ≠ null:
        if val = node.val: return node          // found
        if val < node.val: node ← node.left
        else: node ← node.right
    return null

// Insert:   same walk as search until null, place the new node there
// Validate: pass (min, max) bounds down; every node needs min < val < max
// Inorder:  always produces a sorted sequence ← the key BST insight
⚠️
Classic Mistake — Wrong BST validation: Checking only node.left.val < node.val < node.right.val at each node is wrong. You must pass a valid range [min, max] down the tree. Going left narrows the max; going right narrows the min. Start the bounds at ±∞ (in Java, use Long bounds) so a node holding the smallest or largest possible integer isn't wrongly rejected.
📐 Pseudocode · Validate BST + Kth Smallest 
// Validate BST — range propagation:
function isValidBST(root):
    return check(root, -∞, +∞)

function check(n, lo, hi):
    if n = null: return true
    if n.val ≤ lo or n.val ≥ hi: return false
    return check(n.left, lo, n.val) and check(n.right, n.val, hi)
    // going left narrows the max; going right narrows the min

// Kth Smallest — inorder = sorted, count as you go:
k ← the requested rank;  result ← none
function kth(n):
    if n = null or result is set: return
    kth(n.left)
    k ← k - 1
    if k = 0:
        result ← n.val
        return
    kth(n.right)

BST Insert & Delete

📐 Pseudocode · BST Insert (LC 701) + Delete (LC 450) 
// INSERT: navigate like search until a null spot, place the node there
function insertIntoBST(root, val):
    if root = null: return TreeNode(val)
    if val < root.val: root.left ← insertIntoBST(root.left, val)
    else: root.right ← insertIntoBST(root.right, val)
    return root                  // return root so the parent's pointer stays valid

// DELETE: 3 cases
// Case 1: leaf node    → return null
// Case 2: one child    → return that child
// Case 3: two children → copy the inorder successor up, delete the successor below
function deleteNode(root, key):
    if root = null: return null
    if key < root.val: root.left ← deleteNode(root.left, key)
    else if key > root.val: root.right ← deleteNode(root.right, key)
    else:
        if root.left = null: return root.right       // Cases 1 and 2
        if root.right = null: return root.left
        succ ← root.right
        while succ.left ≠ null: succ ← succ.left      // leftmost = successor
        root.val ← succ.val                           // copy value up
        root.right ← deleteNode(root.right, succ.val) // delete the old successor
    return root

// Time O(h): O(log n) for a balanced BST, O(n) worst case (skewed)

🌐 Lowest Common Ancestor (LCA)

The LCA of two nodes p and q is the deepest node that is an ancestor of both. It is the first node where they “split” in the tree.

📐 Pseudocode · LCA Binary Tree (LC 236) + BST (LC 235) 
// Binary Tree — works for any tree:
function lca(n, p, q):
    if n = null or n = p or n = q: return n
    l ← lca(n.left, p, q)
    r ← lca(n.right, p, q)
    if l ≠ null and r ≠ null: return n     // split here → this IS the LCA
    if l ≠ null: return l
    return r                               // whichever side found something

// BST — exploit the ordering (simpler):
function lcaBST(n, p, q):
    if p.val < n.val and q.val < n.val: return lcaBST(n.left, p, q)
    if p.val > n.val and q.val > n.val: return lcaBST(n.right, p, q)
    return n                               // split point → LCA
📌
Dry Run — LCA(root=3, p=5, q=1) on [3,5,1,6,2,0,8]:
3 / \ 5 1 / \ / \ 6 2 0 8 lca(3, p=5, q=1): left = lca(5, p=5, q=1) → node==p → return 5 ◄ found p right = lca(1, p=5, q=1) → node==q → return 1 ◄ found q both non-null → split point → return 3 ✓ Key: once both sides return non-null, the current node IS the LCA.

🧵 Morris Traversal — O(1) Space

Every traversal so far has cost O(h) memory — the call stack, or an explicit stack. Morris traversal gets in-order out of a tree in O(1) extra space by borrowing the null right pointers of leaf nodes as temporary threads back up the tree, then putting them back. Every node is visited at most twice, so it is still O(n) time.

📐 Pseudocode · Morris In-order Traversal 
// In-order traversal with NO recursion and NO stack.
// Idea: temporarily point each predecessor's right pointer back
// at its successor, so you can climb back up without a stack.
cur ← root

while cur ≠ null:
    if cur.left = null:
        visit(cur)
        cur ← cur.right
    else:
        // find the rightmost node of the left subtree
        pred ← cur.left
        while pred.right ≠ null and pred.right ≠ cur:
            pred ← pred.right

        if pred.right = null:
            pred.right ← cur      // 1st visit: thread it, go left
            cur ← cur.left
        else:
            pred.right ← null     // 2nd visit: unthread, restore tree
            visit(cur)
            cur ← cur.right
TimeO(n) — each edge walked at most twice
SpaceO(1)
⚠️
It mutates the tree while it runs
Between the threading and the unthreading, the tree is temporarily not a tree — it has cycles. The algorithm always restores it, but never run it concurrently with anything else reading the tree, and never on a structure you must not modify.

🏗️ Building a Tree from its Traversals

One traversal is never enough to rebuild a tree — but two are, as long as one of them is in-order. Preorder (or postorder) tells you which node is the root; in-order tells you where that root splits the remaining nodes into a left group and a right group. Recurse on the two groups.

📐 Pseudocode · Build from Preorder + Inorder 
// preorder tells you WHICH node is the root.
// inorder tells you WHERE that root splits left from right.
position ← map from value → index in inorder
p ← 0                     // cursor into preorder

function build(lo, hi):        // inorder range [lo, hi]
    if lo > hi: return null

    node ← Node(preorder[p])
    p ← p + 1
    mid ← position[node.value]

    node.left  ← build(lo, mid - 1)   // must come first: p is shared
    node.right ← build(mid + 1, hi)
    return node

return build(0, length(inorder) - 1)
TimeO(n) — the map removes the linear scan
SpaceO(n)
💡
The three variants
Preorder + inorder (LC 105) — take roots from the front. Postorder + inorder (LC 106) — take roots from the back and build right before left. Preorder + postorder (LC 889) — only works when every node has 0 or 2 children, and the answer is not unique.

⚠️ Complexity & Classic Bugs

The costs worth quoting in an interview first, then the mistakes that most often break code that looks correct. Every row in the second table is a bug someone has shipped.

Operation Cost Note
BST search, insert, delete O(h) O(log n) balanced, O(n) skewed
Validate a BST O(n)
LCA in any binary tree O(n)
LCA in a BST O(h) Walk down, no recursion into both sides
Build from pre-order + in-order O(n) with an index map O(n²) without
Morris traversal O(n) time, O(1) space
Bug Symptom Fix
Validating by comparing each node only with its parent A deeper node breaks the rule unnoticed Pass (min, max) bounds down
Using int bounds Fails on nodes holding the extreme values Use long or null for “no bound”
Deleting a node with two children Part of the tree disappears Replace it with its in-order successor, then delete that
Undefined handling of duplicates Inconsistent searches Decide: equal values go left, or are not allowed
Searching the in-order array for each root O(n²) build Precompute a value → index map
Building the right subtree before the left from pre-order The wrong tree Build left first — pre-order lists it first
Not removing Morris threads The tree is left modified Remove the thread on the second visit

💪 In-Lecture Practice Problems

Four problems: two on the ordering property, one on two-node reasoning, and one that rebuilds a tree from nothing but its traversals.

Problem 01 · LC 98
Validate Binary Search Tree
Medium Pattern 5: BST Property Amazon · Microsoft · Bloomberg · Meta LC 98
▶
Problem

Determine if a binary tree is a valid BST.

Input: [5,1,4,null,null,3,6] Output: false (root is 5 but right child is 4 which is less)
Hints
▶Hint 1 — a nudge

Checking only node vs its two children is the classic wrong answer.

▶Hint 2 — the key idea

Every node must fall inside an inherited (min, max) range: recurse left with max = node.val and right with min = node.val. Use long bounds for Integer.MIN/MAX values.

Solution

Pattern 5. Pass a valid range [lo, hi] down. Going left tightens the upper bound; going right tightens the lower bound. Use Long to avoid Integer.MIN/MAX_VALUE edge cases.

▶Full solution
📐 Pseudocode · LC 98 
function isValidBST(root):
    return check(root, -∞, +∞)

function check(n, lo, hi):
    if n = null: return true
    if n.val ≤ lo or n.val ≥ hi: return false
    return check(n.left, lo, n.val) and check(n.right, n.val, hi)
TimeO(n)
SpaceO(h)
Problem 02 · LC 236
Lowest Common Ancestor of a Binary Tree
Medium Pattern 6: LCA Amazon · Google · Meta · Microsoft LC 236
▶
Problem

Find the lowest common ancestor of two nodes p and q in a binary tree.

Input: root=[3,5,1,6,2,0,8], p=5, q=1 Output: 3
Hints
▶Hint 1 — a nudge

If both targets are in different subtrees, the current node is the answer.

▶Hint 2 — the key idea

Recurse both sides. If both return non-null, this node is the LCA; otherwise pass up whichever side is non-null. In a BST you can do better — walk down until the values straddle the node.

Solution

Pattern 6. Return node when null/p/q. If both left and right are non-null → split here → current node IS the LCA. Else bubble up the non-null side.

▶Full solution
📐 Pseudocode · LC 236 
function lca(n, p, q):
    if n = null or n = p or n = q: return n
    l ← lca(n.left, p, q)
    r ← lca(n.right, p, q)
    if l ≠ null and r ≠ null: return n
    if l ≠ null: return l
    return r
TimeO(n)
SpaceO(h)
Problem 03 · Rebuild
Construct Binary Tree from Preorder and Inorder Traversal
🔗 LC 105 - Construct Binary Tree from Preorder and Inorder Traversal
Medium Build from Traversals Google · Amazon · Meta
›
Problem

Given the pre-order and in-order traversals of a binary tree with unique values, rebuild the tree.

preorder = [3,9,20,15,7], inorder = [9,3,15,20,7] → the tree rooted at 3
Hints
▶Hint 1 — a nudge

Pre-order starts with the root. Where does that same value sit in the in-order list, and what does its position tell you?

▶Hint 2 — the key idea

Everything left of it in the in-order list is the left subtree, everything right is the right subtree. Recurse on those two slices.

Solution

Two facts do all the work: pre-order hands you the root first, and in-order splits the remaining values into the two subtrees once you know where the root is. Scanning the in-order array for the root each time costs O(n) and makes the whole thing O(n²); a value→index map fixes that. Keep a moving pointer into the pre-order array rather than slicing it, or the copying costs more than the algorithm.

▶Full solution
📐 Pseudocode · Root From Pre-order, Split With In-order 
function buildTree(preorder, inorder):
    pos ← map from value → index in inorder     // O(1) lookups
    i ← 0                                        // cursor into preorder

    function build(lo, hi):                  // inorder range [lo, hi]
        if lo > hi: return null

        rootVal ← preorder[i];  i ← i + 1
        node ← new TreeNode(rootVal)
        mid ← pos[rootVal]                       // where the root splits it

        node.left  ← build(lo, mid - 1)          // MUST be built first
        node.right ← build(mid + 1, hi)
        return node

    return build(0, length(inorder) - 1)

// The left call must run before the right one: pre-order lists the entire
// left subtree before the right, so the cursor has to consume it first.
TimeO(n)
SpaceO(n)
Problem 04 · Ordering
Kth Smallest Element in a BST
🔗 LC 230 - Kth Smallest Element in a BST
Medium BST Property Google · Amazon · Meta
›
Problem

Return the k-th smallest value in a binary search tree.

root = [3,1,4,null,2], k = 1 → 1
Hints
▶Hint 1 — a nudge

What order does an in-order walk visit a BST in? You do not need to sort anything.

▶Hint 2 — the key idea

In-order gives sorted order, so the k-th node visited is the answer. Count as you go and stop the moment you reach k.

Solution

This is the BST property doing all the work: in-order on a BST is the sorted sequence, so the problem reduces to “stop at the k-th step”. Collecting everything into a list and indexing works but reads the whole tree; counting during the walk and returning early is the answer they want. The classic follow-up — “what if the tree is modified often?” — wants each node to store its subtree size, which turns the query into O(height).

▶Full solution
📐 Pseudocode · In-order, Stop at k 
function kthSmallest(root, k):
    stack ← empty;  node ← root

    while node ≠ null or stack is not empty:
        while node ≠ null:                 // go as far left as possible
            stack.push(node)
            node ← node.left

        node ← stack.pop()                    // smallest unvisited
        k ← k - 1
        if k = 0: return node.val       // stop early

        node ← node.right

// Follow-up: store subtree sizes in each node and the query becomes
// O(height) — descend left or right by comparing k with leftSize + 1.
TimeO(height + k)
SpaceO(height)
