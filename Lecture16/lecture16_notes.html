Heaps & Priority Queues

“A heap is a complete binary tree stored in an array. Every parent is smaller than its children (min-heap) — and that one rule unlocks O(log n) insert & extract.”

📚 Lecture 16 of 38 Phase 2 — Core Data Structures ⏱ 5 days 🎯 20 problems 💼 Google · Amazon · Microsoft
🌍
Why does this topic matter?
Heaps appear in 15–20% of FAANG interviews. Three problem families dominate: Top-K (Kth largest, K closest points), Two Heaps (running median), and K-way Merge (merge K sorted lists). Master these three and you have a pattern for roughly 80% of all heap problems. Java's PriorityQueue is your primary tool — understand what it does internally so you never misuse it.
By the end of this lecture you can
  • Understand heap property (min-heap, max-heap) and heapify operation
  • Implement a heap from scratch using array representation
  • Solve Top-K problems efficiently with a size-K min-heap
  • Use two heaps for dynamic median computation in O(log n) per element
🔗
How it connects: A heap IS a complete binary tree (Lecture 15) stored in an array (Lecture 8). The parent-child formulas below come directly from BFS level-order indexing. After this lecture, heaps underpin Dijkstra's algorithm (Lecture 17 Graphs) and the median-of-medians approach in Sorting.

🏠 Heap Anatomy — The Array Representation

A complete binary tree can be stored perfectly in an array with no pointers needed. The structural rules are fixed by index arithmetic:

Array Representation

Array Representation — Index Formulas 
 Index:   0    1    2    3    4    5    6
 Array: [ 1,   3,   5,   7,   9,   8,   6 ]   ← min-heap

 Visualised as a tree:
            1          ← index 0  (root)
          /   \
         3     5       ← index 1, 2
        / \   / \
       7   9 8   6     ← index 3, 4, 5, 6

 Parent of i  → (i - 1) / 2
 Left child   → 2*i + 1
 Right child  → 2*i + 2

 Heap Property (min-heap): parent ≤ both children at EVERY node
 Max-heap: flip to parent ≥ both children

Min vs Max Heap

The only difference between a min-heap and a max-heap is the comparison in the heap property. Everything else — the index arithmetic, sift-up, sift-down — is identical. Flip ≤ to ≥ and a min-heap becomes a max-heap.

📌
Key complexity facts:
Insert (offer): O(log n) — sift UP  |  Extract-min (poll): O(log n) — sift DOWN  |  Peek-min: O(1) — always at index 0  |  Build heap from array: O(n) — not O(n log n)!

⚙ Core Operations

A heap only ever needs two repair routines. Sift-up walks a node towards the root while it is smaller than its parent; sift-down walks a node towards the leaves while it is bigger than its smallest child. Insert, delete and build are all written in terms of those two.

Insert & Sift-Up

📐 Pseudocode · Sift-Up, Sift-Down, Build 
// A heap is an array. parent(i) = (i-1)/2, children = 2i+1 and 2i+2.
function siftUp(i):          // after inserting at the end
    while i > 0 and heap[parent(i)] > heap[i]:
        swap(i, parent(i))
        i ← parent(i)

function siftDown(i):        // after moving the last element to the root
    while leftChild(i) < size:
        smallest ← index of the smaller existing child of i
        if heap[i] ≤ heap[smallest]: break
        swap(i, smallest)
        i ← smallest

function insert(x):  heap[size] ← x; size ← size + 1; siftUp(size - 1)
function extractMin():
    min ← heap[0]
    heap[0] ← heap[size-1]      // move the last leaf to the root
    size ← size - 1
    siftDown(0)
    return min

function build(array):       // O(n), NOT O(n log n)
    for i from size÷2 - 1 down to 0: siftDown(i)

// Why is build O(n)? Leaves need 0 work, and the bottom half of the array is all leaves.
// Formal proof: the sum of sift-down heights is a geometric series = O(n).

Delete & Sift-Down

poll() can't just remove index 0 — that would leave a hole. Instead move the last element into the root and sift it down. One O(log n) walk restores the whole heap.

Build Heap in O(n)

Inserting n elements one at a time costs O(n log n). Heapifying an existing array costs only O(n): half the nodes are leaves and need no work at all, and the number of nodes at height h shrinks geometrically while the work per node grows only linearly in h. The sum ∑ h · n/2h+1 converges to O(n).

Dry Run — Insert 2 into min-heap [1,3,5,7,9]:
Before: heap = [1, 3, 5, 7, 9] 1 / \ 3 5 / \ 7 9 Insert 2 at index 5: heap = [1, 3, 5, 7, 9, 2] i=5, parent=(5-1)/2=2, heap[2]=5 > heap[5]=2 → swap heap = [1, 3, 2, 7, 9, 5] i=2, parent=(2-1)/2=0, heap[0]=1 ≤ heap[2]=2 → STOP ✓ After: heap = [1, 3, 2, 7, 9, 5] 1 / \ 3 2 ← min-heap property restored / \ / 7 9 5

Java PriorityQueue

In an interview you almost never hand-roll a heap — you reach for PriorityQueue. Know its defaults cold: it is a min-heap, and it is not sorted when you iterate it.

💡
Java PriorityQueue cheatsheet:
PriorityQueue<Integer> minH = new PriorityQueue<>();    (default: min-heap)
PriorityQueue<Integer> maxH = new PriorityQueue<>(Collections.reverseOrder());
PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[0]-b[0]);  — sort by first element

Key methods: offer(x) O(log n)  |  poll() O(log n)  |  peek() O(1)  |  size() O(1)

📈 Pattern 1 — Single Heap (Kth Largest)

The simplest heap pattern. Use a size-K min-heap to track the K largest elements seen so far. The root (min of heap) is always the Kth largest. If a new element is larger than the root, pop root and push new element.

📐 Pseudocode · Kth Largest Element in Array (LC 215) 
// Maintain a min-heap of size K.
function findKthLargest(nums, k):
    minH ← empty min-heap
    for n in nums:
        minH.push(n)
        if minH.size > k: minH.popMin()    // evict the smallest; the top K survive
    return minH.peek()                      // min of the top K = Kth largest

// Why a size-K MIN-heap? The K largest elements survive, and
// their minimum (the heap root) is exactly the Kth largest.
// Time O(n log k)  Space O(k)
// Why NOT sort? Sort is O(n log n). If k is much smaller than n, the heap is much faster.
📊

🏆 Pattern 2 — Top K Elements

A generalisation of Pattern 1. Any problem asking for the K most/least something follows this shape. Key insight: use a min-heap of size K for top-K largest (counterintuitive — min-heap, not max-heap).

📐 Pseudocode · Top K Frequent Elements (LC 347) + K Closest Points (LC 973) 
// Top K Frequent Elements:
// 1. Count frequencies with a hash map
// 2. Push (freq, num) into a min-heap of size K
// 3. If heap size > K, pop (removes the least frequent)
// 4. The remaining K entries are the top-K frequent
function topKFrequent(nums, k):
    freq ← empty map
    for n in nums: freq[n] ← (freq[n] if n in freq, else 0) + 1
    minH ← empty min-heap of (freq, num), ordered by freq
    for (num, f) in freq:
        minH.push((f, num))
        if minH.size > k: minH.popMin()
    res ← array of length k
    for i from k - 1 down to 0: res[i] ← minH.popMin().num
    return res

// Why a MIN-heap? We want to EVICT the least frequent to keep the top K.
// The min is always at the root, so discarding it costs O(log k).
// Time O(n log k)  Space O(n) for the frequency map

// K Closest Points to Origin — same pattern, flipped heap:
function kClosest(pts, k):
    maxH ← empty max-heap ordered by x² + y²     // farthest point on top
    for p in pts:
        maxH.push(p)
        if maxH.size > k: maxH.popMax()          // evict the farthest
    return all points in maxH

// Note: compare SQUARED distances — no square root, no floating point

⚖ Pattern 3 — Two Heaps (Running Median)

Split the data stream into two halves: a max-heap for the lower half and a min-heap for the upper half. Keep their sizes balanced (differ by at most 1). The median is always at one of the two roots.

📐 Pseudocode · Find Median from Data Stream (LC 295) — Hard 
maxH ← empty max-heap        // lower half
minH ← empty min-heap        // upper half

function addNum(n):
    maxH.push(n)
    minH.push(maxH.popMax())         // push the max of the lower half up
    if minH.size > maxH.size:
        maxH.push(minH.popMin())     // rebalance: maxH keeps the extra element

function findMedian():
    if maxH.size = minH.size:
        return (maxH.peek() + minH.peek()) ÷ 2     // real division, e.g. 2.5
    return maxH.peek()               // maxH always has the extra element

// addNum: O(log n)  findMedian: O(1)
// Invariant: maxH.peek() ≤ minH.peek() always (the cross-push enforces this)
📊

🔁 Pattern 4 — K-way Merge

Given K sorted lists (or arrays), use a min-heap to efficiently pull the globally smallest element each time. Always keep exactly one element from each active list in the heap.

📐 Pseudocode · Merge K Sorted Lists (LC 23) 
// K-way merge: the heap holds at most one "front" node per list.
function mergeKLists(lists):
    pq ← empty min-heap ordered by node value
    for head in lists:
        if head ≠ null: pq.push(head)

    dummy ← ListNode(0)
    curr ← dummy
    while pq is not empty:
        curr.next ← pq.popMin()               // pull the globally smallest
        curr ← curr.next
        if curr.next ≠ null: pq.push(curr.next)   // push the next from the same list
    return dummy.next

// Key: the heap has at most K elements → each pop is O(log K), not O(log N)
// Time O(N log K) where N = total nodes, K = number of lists
// Space O(K) for the heap

⚡ Pattern 5 — Greedy Heap (Task Scheduler)

Use a max-heap to always process the most frequent/highest-priority task next. When a cooldown constraint exists, pair the heap with a wait queue.

📐 Pseudocode · Task Scheduler (LC 621) + Reorganize String (LC 767) 
// Task Scheduler — greedy: always run the most frequent available task
function leastInterval(tasks, n):
    cnt ← count of each task letter (26 slots)
    maxH ← max-heap of every non-zero count
    waitQ ← empty queue of (remaining count, available at time)
    time ← 0
    while maxH is not empty or waitQ is not empty:
        time ← time + 1
        if maxH is not empty:
            rem ← maxH.popMax() - 1
            if rem > 0: waitQ.enqueue((rem, time + n))     // cooling down
        if waitQ is not empty and waitQ.front().availableAt = time:
            maxH.push(waitQ.dequeue().rem)                  // cooled down — back in play
    return time
// Time O(T × 26) where T = total tasks  Space O(26) = O(1)

// Reorganize String — same greedy idea:
// always place the most frequent char that differs from the previous one
function reorganizeString(s):
    maxH ← max-heap of (count, char) for every char in s
    out ← empty string
    while maxH.size ≥ 2:
        a ← maxH.popMax();  b ← maxH.popMax()    // two DIFFERENT chars
        append a.char, then b.char to out
        a.count ← a.count - 1;  if a.count > 0: maxH.push(a)
        b.count ← b.count - 1;  if b.count > 0: maxH.push(b)
    if maxH is not empty:
        if maxH.peek().count > 1: return ""      // impossible
        append maxH.popMax().char to out
    return out
// Time O(n log 26) = O(n)  Space O(n) for the output

💪 In-Lecture Practice Problems

Problem 01 · LC 215
Kth Largest Element in an Array
Medium Pattern 1: Single Min-Heap Amazon · Google · Meta · Microsoft
▶
Problem

Given an integer array and integer k, return the kth largest element (not kth distinct).

Input: nums=[3,2,1,5,6,4] k=2 Output: 5
Hints
▶Hint 1 — a nudge

Sorting is O(n log n). You only need one element in its correct place.

▶Hint 2 — the key idea

A size-k min-heap gives O(n log k) — the root is the answer once every element has been offered. QuickSelect gives O(n) average.

Solution

Maintain a min-heap of size k. After processing all elements, the root is the Kth largest. The heap evicts smaller elements — only the K biggest survive.

▶
Solution
📐 Pseudocode · LC 215 
function findKthLargest(nums, k):
    minH ← empty min-heap
    for n in nums:
        minH.push(n)
        if minH.size > k: minH.popMin()
    return minH.peek()
TimeO(n log k)
SpaceO(k)
Problem 02 · LC 347
Top K Frequent Elements
Medium Pattern 2: Top K Amazon · Google · Meta
▶
Problem

Given an array and integer k, return the k most frequent elements.

Input: [1,1,1,2,2,3] k=2 Output: [1,2]
Hints
▶Hint 1 — a nudge

Count first; then pick the k biggest counts.

▶Hint 2 — the key idea

Size-k min-heap ordered by frequency for O(n log k), or bucket sort by count for O(n).

Solution

Count frequencies in a HashMap, then maintain a size-K min-heap by frequency. The min-heap evicts the least frequent, so only top-K frequent remain.

▶
Solution
📐 Pseudocode · LC 347 
function topKFrequent(nums, k):
    freq ← count of each value in nums
    pq ← empty min-heap of (freq, num), ordered by freq
    for (num, f) in freq:
        pq.push((f, num))
        if pq.size > k: pq.popMin()
    res ← array of length k
    for i from k - 1 down to 0: res[i] ← pq.popMin().num
    return res
TimeO(n log k)
SpaceO(n)
Problem 03 · LC 295
Find Median from Data Stream
Hard Pattern 3: Two Heaps Amazon · Google · Microsoft · Meta
▶
Problem

Design a data structure supporting addNum(int) and findMedian() with the stream arriving one number at a time.

addNum(1), addNum(2), findMedian()=1.5, addNum(3), findMedian()=2.0
Hints
▶Hint 1 — a nudge

The median sits between the smaller half and the larger half. Keep those two halves separate.

▶Hint 2 — the key idea

A max-heap for the low half and a min-heap for the high half, sizes kept within one of each other. The median is the top of the bigger heap, or the average of both tops.

Solution

Two heaps: maxH holds the lower half, minH holds the upper half. Always push to maxH first, then rebalance. Median lives at one or both roots.

▶
Solution
📐 Pseudocode · LC 295 
maxH ← empty max-heap;  minH ← empty min-heap

function addNum(n):
    maxH.push(n)
    minH.push(maxH.popMax())
    if minH.size > maxH.size: maxH.push(minH.popMin())

function findMedian():
    if maxH.size = minH.size: return (maxH.peek() + minH.peek()) ÷ 2
    return maxH.peek()
addNumO(log n)
findMedianO(1)
Problem 04 · LC 23
Merge K Sorted Lists
Hard Pattern 4: K-way Merge Amazon · Google · Microsoft · Uber
▶
Problem

Merge K sorted linked lists and return the sorted linked list.

Input: [[1,4,5],[1,3,4],[2,6]] Output: [1,1,2,3,4,4,5,6]
Hints
▶Hint 1 — a nudge

The next node in the answer is always the smallest current head among k lists.

▶Hint 2 — the key idea

Min-heap holding one node from each list. Pop the smallest, append it, then push its successor. O(N log k).

Solution

Push all K heads into a min-heap. Each poll gives the globally smallest node. Then push the next node from that list. Heap size stays ≤ K throughout.

▶
Solution
📐 Pseudocode · LC 23 
function mergeKLists(lists):
    pq ← min-heap (by value) of every non-null head
    dummy ← ListNode(0);  cur ← dummy
    while pq is not empty:
        cur.next ← pq.popMin()
        cur ← cur.next
        if cur.next ≠ null: pq.push(cur.next)
    return dummy.next
TimeO(N log K)
SpaceO(K)
Problem 05 · LC 621
Task Scheduler
Medium Pattern 5: Greedy Heap Amazon · Meta · Google
▶
Problem

Given tasks with a cooldown n, return the minimum time to finish all tasks. Same-letter tasks must be separated by n intervals.

Input: tasks=["A","A","A","B","B","B"] n=2 Output: 8 (ABAB_A_B or similar)
Hints
▶Hint 1 — a nudge

The most frequent task is the bottleneck — it dictates the skeleton of the schedule.

▶Hint 2 — the key idea

With maxCount occurrences of the most frequent task there are maxCount-1 gaps of size n. Answer = max(len, (maxCount-1)×(n+1) + numberOfTasksTiedForMax).

Solution

Greedy: always do the most-frequent available task. Max-heap gives the most frequent. If none available, idle. A wait queue tracks when each task becomes available again.

▶
Solution
📐 Pseudocode · LC 621 
function leastInterval(tasks, n):
    maxH ← max-heap of every non-zero task count
    waitQ ← empty queue of (remaining, availableAt)
    time ← 0
    while maxH is not empty or waitQ is not empty:
        time ← time + 1
        if maxH is not empty:
            r ← maxH.popMax() - 1
            if r > 0: waitQ.enqueue((r, time + n))
        if waitQ is not empty and waitQ.front().availableAt = time:
            maxH.push(waitQ.dequeue().remaining)
    return time
TimeO(T)
SpaceO(1)
