Recursion — The Mental Model

“To understand recursion, you must first understand recursion.”

📚 Lecture 8 of 45 Phase 1 — Foundations ⏱ 4 days 🎯 16 problems 💼 Amazon · Google · Microsoft
🌍
Why does this topic matter?
Every significant algorithm in the second half of this course — Trees, Graphs, Dynamic Programming, Divide & Conquer — is built on top of recursion. If recursion feels magical and confusing, those topics will feel impossible. But here's the secret: recursion is just a function that trusts itself to solve a smaller version of the same problem. Once that mental click happens, it unlocks everything else.
By the end of this lecture you can
  • Understand the recursive leap of faith — trust the function
  • Visualize recursion as a tree of calls
  • Master the 3 steps: base case, recursive relation, combine results
  • Read the cost of a recursion from the shape of its call tree
  • Identify when to use memoisation to avoid recomputation

📖 Before We Start — The Big Picture

Imagine you're asked to open the smallest of 5 nested Matryoshka dolls. You don't think about all 5 at once — you open the outermost one, set it aside, and repeat the same action. Eventually you reach the smallest doll (the base case) — it has nothing inside. Then you stop. That's recursion.

The call stack is the "pile of dolls you set aside." Each time your function calls itself, a new stack frame is added to the top of the pile. When the base case is reached, frames are removed one by one, in the reverse order they were added (LIFO — Last In, First Out). StackOverflowError means you never found the smallest doll — you kept opening forever.

🔗
How it connects: Lecture 7 (Java 8+) introduced functional thinking — input → output, no side effects. Recursion is the same mindset applied to algorithms. Lecture 12 (Sorting — Merge Sort, Quick Sort), Lectures 18–19 (Trees — every traversal) and Lecture 24 (Backtracking) are almost entirely built on the recursive thinking you learn here.

🧠 The Mental Model — Think, Trust, Induct

💡
Golden Rule for Recursion:
  1. Think: What is the smallest version of this problem I can solve?
  2. Trust: Assume the recursive call WORKS correctly for smaller input.
  3. Induct: Use that trusted result to build the answer for the current input.

Never try to trace the full recursion tree in your head. Trust the math.

Recursion is a function calling itself on a smaller version of the same problem, until it hits a base case (the simplest possible answer). It is the backbone of Trees, Graphs, DP, Divide & Conquer, and Backtracking — mastering it here pays dividends for the rest of the course.

⚙️ How Recursion Works — The Anatomy

Every recursive function has exactly two parts:

Part Purpose Consequence if missing
Base Case The terminating condition — returns without a recursive call Infinite recursion → StackOverflowError
Recursive Case Calls itself with a strictly simpler input (smaller, shorter, fewer) Infinite recursion if input never shrinks
📐 Pseudocode · The Recursion Skeleton 
// Every recursive function follows this shape
function solve(problem):

    // ① BASE CASE — the smallest problem you can answer directly
    if problem is simplest:
        return knownAnswer

    // ② RECURSIVE CASE — shrink the problem and trust the call
    smaller ← shrink(problem)         // make the problem smaller
    subResult ← solve(smaller)        // TRUST this works ✓
    return combine(subResult, current) // build the answer from it

Concrete Example: Factorial

📐 Pseudocode · Factorial 
function factorial(n):
    // BASE CASE: 0! = 1  (we know this cold)
    if n = 0: return 1

    // TRUST: factorial(n-1) gives (n-1)! correctly
    // INDUCT: n! = n × (n-1)!
    return n × factorial(n - 1)
factorial(4) ├── calls factorial(3) │ ├── calls factorial(2) │ │ ├── calls factorial(1) │ │ │ ├── calls factorial(0) │ │ │ │ └── returns 1 ← BASE CASE │ │ │ └── returns 1 × 1 = 1 │ │ └── returns 2 × 1 = 2 │ └── returns 3 × 2 = 6 └── returns 4 × 6 = 24 ← FINAL ANSWER
TimeO(n)
SpaceO(n) call stack

📚 The Call Stack — What Actually Happens in Memory

Each recursive call pushes a new stack frame onto the call stack. It holds: local variables, parameters, and the return address. When a base case is reached, frames are popped off in LIFO order.

⚠️
StackOverflowError — The JVM has a default stack size (~512KB–1MB). Deep recursion without a base case (or with n ≈ 10,000+) will crash. For very deep recursion, consider: (a) iterative rewrite, (b) tail recursion (compiler optimisation), or (c) increasing JVM stack size with -Xss.
Stack for factorial(3)
factorial(0) → 1  BASE
factorial(1) → 1×1
factorial(2) → 2×1
factorial(3) → 3×2  ← TOP
↑ Each box = one stack frame in memory
✅
Space = depth of recursion tree
factorial(n) → depth n → O(n) space
Binary search → depth log n → O(log n) space
Fibonacci (naive) → depth n → O(n) space

🛑 Base Cases — The Foundation of Correctness

Types of Base Cases

Type When to use Example
Empty / null check Working on arrays, strings, linked lists if (arr.length == 0) return;
Single element Arrays or lists that bottom out at size 1 if (lo == hi) return arr[lo];
Index out of bounds Grid/string traversal problems if (i < 0 || i >= n) return 0;
Counter reaches 0 Countdown problems, power, multiply if (exp == 0) return 1;
Target found / exceeded Search, sum, path problems if (target == 0) return true;
⚠️
Common Pitfall — Missing edge in base case:
For fibonacci(n), beginners write if (n == 0) return 0; but forget if (n == 1) return 1;. Without it, fib(-1) recursion never terminates. Always ask: what are ALL the trivial inputs?

🌿 Types of Recursion

1. Linear Recursion — One call per frame

Makes exactly one recursive call per invocation. The recursion tree is a straight line (depth = n).

📐 Pseudocode · Linear Recursion 
// Sum of array: sum(a, n) = a[n-1] + sum(a, n-1)
function arraySum(a, n):
    if n = 0: return 0                     // base case
    return a[n-1] + arraySum(a, n-1)       // linear: ONE call per frame

// String reversal: reverse(s) = reverse(s without first char) + first char
function reverse(s):
    if length(s) ≤ 1: return s
    return reverse(s[1 ..]) + s[0]

2. Tail Recursion — Call is the LAST thing

The recursive call is the very last operation — no work done after it returns. Some languages/compilers optimise this to avoid stack growth (tail-call optimisation). Java does NOT do TCO by default, but the pattern is worth knowing.

📐 Pseudocode · Tail Recursion 
// NOT tail recursive: the multiply happens AFTER the call returns
function factorial(n):
    if n = 0: return 1
    return n × factorial(n-1)

// Tail recursive: an accumulator carries the result down
function factTail(n, acc):
    if n = 0: return acc                   // acc already holds the answer
    return factTail(n-1, n × acc)          // the call IS the last operation
// Call: factTail(5, 1)

3. Tree Recursion — Multiple calls per frame

Makes more than one recursive call. The call tree branches — this is what creates exponential complexity in naive implementations.

📐 Pseudocode · Tree Recursion 
// Fibonacci: TWO recursive calls per frame → tree recursion
function fib(n):
    if n ≤ 1: return n                     // base cases: fib(0)=0, fib(1)=1
    return fib(n-1) + fib(n-2)             // TWO calls → branching!
// Time: O(2ⁿ) — the same subproblems are recomputed.
// Fix: memoisation brings it to O(n).
fib(4) ├── fib(3) │ ├── fib(2) │ │ ├── fib(1) → 1 │ │ └── fib(0) → 0 │ └── fib(1) → 1 └── fib(2) ← fib(2) computed AGAIN! Wasteful. ├── fib(1) → 1 └── fib(0) → 0 Total nodes: 9 for fib(4). For fib(40) → ~2 BILLION nodes!

4. Mutual Recursion — Functions calling each other

📐 Pseudocode · Mutual Recursion 
// is n even? → if n = 0: yes. Otherwise ask: is n-1 odd?
function isEven(n):
    if n = 0: return true
    return isOdd(n - 1)        // delegates to isOdd

function isOdd(n):
    if n = 0: return false
    return isEven(n - 1)       // delegates back to isEven

🚀 Fixing Tree Recursion: Memoisation

💡
Memoisation = Recursion + Caching. The key insight: in tree recursion, the same subproblems are solved repeatedly. Cache the answer the first time, return it from cache thereafter. This turns O(2ⁿ) → O(n).
📐 Pseudocode · Memoisation Pattern 
// Without memoisation: O(2ⁿ) — fib(2), fib(3) recomputed many times
function fib(n):
    if n ≤ 1: return n
    return fib(n-1) + fib(n-2)

// WITH memoisation: O(n) — each n is solved exactly once
memo ← array of size n+1, all set to UNKNOWN

function fibMemo(n):
    if n ≤ 1: return n
    if memo[n] ≠ UNKNOWN: return memo[n]    // ✔ cache hit — skip the work
    memo[n] ← fibMemo(n-1) + fibMemo(n-2)
    return memo[n]                          // store before returning

// When the state isn't a small integer, key the cache by the state itself:
cache ← empty map
function solve(state):
    if state in cache: return cache[state]
    result ← … compute from smaller states …
    cache[state] ← result
    return result
Approach Time Space When to use
Naive recursion O(2ⁿ) or worse O(n) stack Understanding / tiny inputs
Memoisation (top-down DP) O(n × states) O(n) stack + cache Overlapping subproblems, natural recursion structure
Tabulation (bottom-up DP) O(n × states) O(n) array No stack overflow risk, slightly faster in practice

🔷 Core Recursion Patterns

🎯
Pattern Recognition Guide
These patterns appear in 80% of recursion interview questions. Learn to identify which one applies before writing code.

Pattern 1 — Parameterized Recursion (carry state forward)

Pass extra parameters to carry accumulated state downward through the call tree. The base case uses the accumulated state as the answer.

📐 Pseudocode · Parameterized 
// Print 1 to n (no return value — the work is a side effect)
function print1toN(i, n):
    if i > n: return          // base case: done
    print(i)                  // print BEFORE the call → 1, 2, 3, …, n
    print1toN(i + 1, n)       // carry state: i grows each call
// Call: print1toN(1, n)

// Print n to 1 — just move the print AFTER the call
function printNto1(i, n):
    if i > n: return
    printNto1(i + 1, n)       // go all the way down first
    print(i)                  // print on the WAY BACK → n, n-1, …, 1

// KEY INSIGHT: work BEFORE the call happens going in (top-down)
//              work AFTER  the call happens coming back (bottom-up)
🔑
The Before/After Insight — Critical for Trees!
Code written before the recursive call executes while going deeper (pre-order).
Code written after the recursive call executes while returning (post-order).
This single insight explains Pre/In/Post-order tree traversals entirely.

Pattern 2 — Functional Recursion (return the answer)

The function returns a value that is built up from smaller sub-answers. Classic mathematical recursion style.

📐 Pseudocode · Functional 
// Power: xⁿ
function power(x, n):
    if n = 0: return 1                       // x⁰ = 1
    if n < 0: return power(1/x, -n)          // handle negative exponents
    return x × power(x, n-1)                 // naive: O(n)

// Fast power (binary exponentiation) — O(log n)
function fastPower(x, n):
    if n = 0: return 1
    if n < 0: return fastPower(1/x, -n)
    half ← fastPower(x, n ÷ 2)               // solve HALF, not n-1
    if n is even: return half × half         // xⁿ = (x^(n/2))²
    else:         return x × half × half     // xⁿ = x · (x^(n/2))²
// fastPower(2, 10): 10 → 5 → 2 → 1 → 0  (4 levels deep instead of 10)
👀
Preview — covered fully in Lecture 24. Two more recursion shapes show up constantly: include or exclude each item (every subset, 2ⁿ of them) and arrange everything (every ordering, n! of them). Both need one extra step this lecture has not taught yet — undoing a choice after exploring it — and that step is called backtracking. It gets its own lecture after trees and graphs, where you will have seen enough recursion for it to feel natural. For now, notice the shape in the complexity table below: two choices per level gives 2ⁿ, n choices per level gives n!.

⏱ Complexity Analysis for Recursive Algorithms

📐
Master Theorem (simplified): For T(n) = a·T(n/b) + O(nᵈ):
  • If d > log_b(a) → O(nᵈ)
  • If d = log_b(a) → O(nᵈ log n)
  • If d < log_b(a) → O(n^log_b(a))
Algorithm Recurrence Time Space (stack) Why
Factorial / Linear T(n)=T(n-1)+O(1) O(n) O(n) n levels, O(1) work each
Binary Search T(n)=T(n/2)+O(1) O(log n) O(log n) halves each time
Merge Sort T(n)=2T(n/2)+O(n) O(n log n) O(n) log n levels × O(n) merge
Fibonacci (naive) T(n)=T(n-1)+T(n-2) O(2ⁿ) O(n) exponential tree, depth n
Subsets T(n)=2T(n-1)+O(1) O(2ⁿ) O(n) 2 choices per element
Permutations T(n)=n·T(n-1)+O(1) O(n!) O(n) n! leaves
Fast Power T(n)=T(n/2)+O(1) O(log n) O(log n) halves exponent each time

The Subsets and Permutations rows are a preview: they are the two backtracking shapes taught fully in Lecture 24. The pattern to take away now is that the number of calls per level decides everything — one call gives O(n), two give O(2ⁿ), and n give O(n!).

Problem 01 · Linear Recursion Warmup
Sum of Digits of a Number
🔗 LC 1837 - Sum of Digits in Base K
Easy Linear Recursion Amazon · Adobe · Microsoft Linear Recursion
›
Problem

Given a non-negative integer n, return the sum of its digits using recursion.

Input: 1234 → Output: 10 (1+2+3+4) Input: 9875 → Output: 29 Input: 0 → Output: 0
Hints
▶Hint 1 — a nudge

n % 10 gives you the last digit; n / 10 removes it.

▶Hint 2 — the key idea

sumDigits(n) = n % 10 + sumDigits(n / 10), with base case n == 0 returning 0.

Solution

What is the smallest version? A single-digit number — its digit sum is itself.
How do you extract the last digit? n % 10.
How do you remove the last digit? n / 10.

▶Full solution
📐 Pseudocode · Sum of Digits 
function digitSum(n):
    if n = 0: return 0                       // base case
    return (n mod 10) + digitSum(n ÷ 10)     // last digit + the rest

// Dry run: digitSum(1234)
// = 4 + digitSum(123)
//   = 4 + 3 + digitSum(12)
//     = 4 + 3 + 2 + digitSum(1)
//       = 4 + 3 + 2 + 1 + digitSum(0)
//         = 10 ✓
TimeO(log n)
SpaceO(log n)
Problem 02 · Fibonacci + Memoisation
Fibonacci Number (3 ways — Naive → Memo → DP)
🔗 LC 509 - Fibonacci Number
Easy → Medium Google · Amazon · Meta Tree RecursionMemoisation Preview LC #509
›
Problem

Compute the nth Fibonacci number. fib(0)=0, fib(1)=1, fib(n)=fib(n-1)+fib(n-2).

fib(0)=0, fib(1)=1, fib(2)=1, fib(3)=2, fib(4)=3, fib(5)=5, fib(10)=55
Hints
▶Hint 1 — a nudge

Draw the recursion tree for fib(5). Count how many times fib(2) is computed.

▶Hint 2 — the key idea

Naive is O(2ⁿ) because subproblems repeat. Cache by n to get O(n), then notice you only ever need the last two values — O(1) space.

Solution
▶Full solution
📐 Pseudocode · Approach 1: Naive Recursion 
function fib(n):
    if n ≤ 1: return n
    return fib(n-1) + fib(n-2)     // O(2ⁿ) — recomputes the same values
📐 Pseudocode · Approach 2: Memoisation (Top-Down DP) 
memo ← array of size n+1, all set to UNKNOWN

function fib(n):
    if n ≤ 1: return n
    if memo[n] ≠ UNKNOWN: return memo[n]    // already computed
    memo[n] ← fib(n-1) + fib(n-2)
    return memo[n]
// Time O(n) — each subproblem solved once
// Space O(n) — the memo plus the call stack
📐 Pseudocode · Approach 3: Iterative (O(1) space) 
function fib(n):
    if n ≤ 1: return n
    a ← 0;  b ← 1
    for i from 2 to n:
        c ← a + b
        a ← b;  b ← c          // slide the two-value window forward
    return b
// Time O(n), space O(1) — the best version
🎓
Lesson: Memoisation (Approach 2) is the gateway to Dynamic Programming. Every DP problem starts as a recursive solution that you memoise. You'll use this exact pattern in Lecture 32 (Dynamic Programming).
Problem 03 · Fibonacci in Disguise
Climbing Stairs
🔗 LC 70 - Climbing Stairs
Easy Google · Amazon · Adobe Tree Recursion → DP
›
Problem

You are climbing a staircase. It takes n steps to reach the top. Each time you can climb 1 or 2 steps. In how many distinct ways can you reach the top?

Input: n = 2 → Output: 2 (1+1, 2) Input: n = 3 → Output: 3 (1+1+1, 1+2, 2+1) Input: n = 5 → Output: 8
Hints
▶Hint 1 — a nudge

To reach step n you arrived from step n-1 or step n-2.

▶Hint 2 — the key idea

It is Fibonacci in disguise: ways(n) = ways(n-1) + ways(n-2). Two rolling variables give O(1) space.

Solution

Key insight: To reach step n, you either came from step n-1 (took 1 step) or step n-2 (took 2 steps). So ways(n) = ways(n-1) + ways(n-2). That's Fibonacci!

This is the most common "recursion in disguise" interview question. The interviewer wants to see you:

  1. Recognise the recurrence relation
  2. Implement naive recursion (show you understand)
  3. Optimise with memoisation (show you can improve)
  4. Convert to iterative DP (show you're production-ready)
▶Full solution
📐 Pseudocode · 3 Approaches 
// Approach 1: naive recursion — O(2ⁿ), times out for large n
function climbNaive(n):
    if n ≤ 1: return 1
    return climbNaive(n - 1) + climbNaive(n - 2)

// Approach 2: memoisation — O(n) time, O(n) space
function climbMemo(n, memo):
    if n ≤ 1: return 1
    if memo[n] is known: return memo[n]          // cache hit
    memo[n] ← climbMemo(n-1, memo) + climbMemo(n-2, memo)
    return memo[n]

// Approach 3: iterative — O(n) time, O(1) space ✅
function climbStairs(n):
    if n ≤ 1: return 1
    prev2 ← 1;  prev1 ← 1
    for i from 2 to n:
        curr ← prev1 + prev2
        prev2 ← prev1
        prev1 ← curr
    return prev1

// Dry run: climbStairs(5)
// i=2: curr=1+1=2, prev2=1, prev1=2
// i=3: curr=2+1=3, prev2=2, prev1=3
// i=4: curr=3+2=5, prev2=3, prev1=5
// i=5: curr=5+3=8, prev2=5, prev1=8
// return 8 ✓
NaiveO(2ⁿ)
MemoO(n)
DP SpaceO(1)
💡
Pattern Recognition: Whenever you see "count the number of ways to reach X from Y with choices A or B", think Fibonacci recurrence. Variants: LC 746 Min Cost Climbing Stairs, LC 91 Decode Ways, LC 198 House Robber
Problem 04 · Tree Recursion → Memo
Target Sum
🔗 LC 494 - Target Sum
Medium Tree Recursion + Memoisation Google · Amazon · Meta
›
Problem

Put a + or − in front of every number so the expression equals target. Count the ways.

nums = [1, 1, 1, 1, 1], target = 3 → 5
Hints
▶Hint 1 — a nudge

Every number has exactly two choices. Draw the call tree for three numbers — how many leaves does it have?

▶Hint 2 — the key idea

2ⁿ leaves, but many calls repeat the same (index, running sum) pair. Cache on that pair and each one is solved once.

Solution

This problem is the whole lecture in one place. The plain recursion is two calls per level, so O(2ⁿ) — exactly the tree-recursion shape from the Fibonacci example. Then notice that the answer depends only on where you are and what the sum is so far, not how you got there: different paths reach the same (index, sum) state. Caching on that pair turns the exponential tree into at most n × (range of sums) distinct calls. That move — spot the repeated state, remember its answer — is the doorway to dynamic programming in Lecture 31.

▶Full solution
📐 Pseudocode · Two Calls, Then a Cache 
function findTargetSumWays(nums, target):
    memo ← empty map                          // (i, sum) → ways

    function ways(i, sum):
        if i = length(nums):                   // base case: used every number
            return 1 if sum = target else 0
        if (i, sum) in memo: return memo[(i, sum)]

        plus  ← ways(i + 1, sum + nums[i])     // choice 1
        minus ← ways(i + 1, sum - nums[i])     // choice 2
        memo[(i, sum)] ← plus + minus
        return memo[(i, sum)]

    return ways(0, 0)

// Without the two memo lines: O(2ⁿ). With them: each (i, sum) pair once.
TimeO(n · S) with memo
SpaceO(n · S)
