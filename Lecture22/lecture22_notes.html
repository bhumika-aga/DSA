Graphs II — Topological Sort & Shortest Paths

“Order the work, then price the route.”

📚 Lecture 22 of 45 Phase 2 — Core Data Structures ⏱ 5 days 🎯 16 problems 💼 Google · Amazon · Meta · Microsoft
🌍
Why does this topic matter?
Two questions dominate weighted-graph interviews. The first is “in what order may I do these tasks?” — course prerequisites, build dependencies, recipes — and topological sort answers all of them. The second is “what is the cheapest route?”, and there are three different answers depending on whether weights can be negative and whether you need one source or all of them. Knowing which to reach for is the skill being tested; each algorithm itself is about fifteen lines.
By the end of this lecture you can
  • Produce a topological order with Kahn's algorithm and detect impossibility
  • Run Dijkstra with a priority queue and state its assumption
  • Say exactly when Dijkstra breaks and Bellman-Ford is needed
  • Use Floyd-Warshall for all-pairs shortest paths and know its cost
  • Pick the right one from the constraints in under a minute
🧠
The picture to keep in your head: Getting dressed, and water in pipes. A topological order is any order of getting dressed that respects the rules: socks before shoes, shirt before jacket. Dijkstra’s algorithm is water spreading from a tap through pipes of different lengths: it reaches nearer junctions first, and the first time water arrives at a junction, it got there by the shortest route.

▶ Topological Sort

A topological order of a DAG lists every node before all nodes it points to. Only valid on Directed Acyclic Graphs. If a cycle exists, no topological order exists. Use case: course prerequisites, build dependency order, task scheduling.

Kahn's Algorithm (BFS-based) — Recommended

💡
Intuition: A node with in-degree 0 has no dependencies — process it first. After removing it, some neighbours lose a dependency (in-degree drops). If their in-degree reaches 0, they're ready. Repeat. If the output order has fewer than V nodes, there was a cycle.
📐 Pseudocode · Topological Sort (Kahn's) 
// Repeatedly take a node nothing depends on. If you can't empty
// the graph, what is left is a cycle.
indeg ← count of incoming edges for every node
queue ← every node with indeg = 0
order ← empty list

while queue not empty:
    node ← queue.popFront()
    order.append(node)

    for nb in adj[node]:
        indeg[nb] ← indeg[nb] - 1
        if indeg[nb] = 0: queue.pushBack(nb)

if length(order) ≠ V: return CYCLE_DETECTED
return order

// Time: O(V + E)  Space: O(V)

DFS-based Topological Sort

After fully processing a node (all descendants done), push it onto a stack. Reverse the stack for the order. Equivalent to Kahn's but DFS-native — useful when you already have DFS in the solution.

📐 Pseudocode · DFS Topo Sort (post-order + stack) 
stack ← empty stack
visited ← array of V, all false

function dfs(node):
    visited[node] ← true
    for nei in adj[node]:
        if not visited[nei]: dfs(nei)
    stack.push(node)                 // push AFTER all neighbours are done

// Call dfs(i) for every unvisited i, then read the stack top-to-bottom

⚙ Dijkstra's Algorithm

Dijkstra finds the shortest path in a weighted graph with non-negative edges. It is essentially BFS with a min-heap instead of a plain queue, always processing the node with the currently known shortest distance.

🎯 Dijkstra Recognition Signal

"Shortest path", "minimum cost/time/effort" and edges have non-negative weights → Dijkstra. Weights are negative? → Bellman-Ford. K-stops constraint? → Modified Bellman-Ford (DP with relaxation limit).

📐 Pseudocode · Dijkstra's Shortest Path 
// Weighted, non-negative edges. Always expand the closest unfinished
// node — a min-heap keeps that cheap.
dist ← array of infinity, length V
dist[src] ← 0
heap ← min-heap holding (0, src) ordered by distance

while heap not empty:
    (d, node) ← heap.extractMin()
    if d > dist[node]: continue     // a stale copy — skip it

    for (nb, w) in adj[node]:
        if d + w < dist[nb]:
            dist[nb] ← d + w
            heap.insert((dist[nb], nb))

return dist

// Negative edges? Dijkstra is WRONG — use Bellman-Ford.
// All weights 0 or 1? A deque beats the heap (0-1 BFS).

// Time: O((V + E) log V)  Space: O(V)
📌
The “stale entry” check is critical. Java's PriorityQueue does not support decrease-key, so when you find a shorter path you push a new entry rather than updating the old one. Old (larger) entries remain in the heap. The check if (d > dist[node]) continue discards them when they eventually pop.
TimeO((V+E) log V)
SpaceO(V + E)
ConstraintNon-negative weights only

🔴 Bellman-Ford

Bellman-Ford relaxes all edges V−1 times. Works with negative weights. A V-th relaxation pass that still improves a distance indicates a negative cycle. Slower than Dijkstra but more general.

📐 Pseudocode · Bellman-Ford 
function bellmanFord(edges, V, src):
    dist ← array of V, all ∞
    dist[src] ← 0

    repeat V - 1 times:                    // V-1 rounds
        for (u, v, w) in edges:
            if dist[u] ≠ ∞ and dist[u] + w < dist[v]:
                dist[v] ← dist[u] + w

    // Optional V-th pass: anything that still improves means a negative cycle
    for (u, v, w) in edges:
        if dist[u] ≠ ∞ and dist[u] + w < dist[v]:
            report "negative cycle reachable from src"
    return dist

// Time: O(V × E)  Space: O(V)
// In fixed-width integers use a large finite INF (e.g. MAX ÷ 2) so dist[u] + w can't overflow
💡
LC 787 “Cheapest Flights Within K Stops”: Use Bellman-Ford limited to K+1 rounds instead of V−1. Copy dist at the start of each round to avoid using the same round's updates within the same round (the “temp array” trick).
TimeO(V × E)
SpaceO(V)
HandlesNegative weights

🔳 Floyd-Warshall

Floyd-Warshall computes all-pairs shortest paths in O(V3) time. Works with negative weights (no negative cycles). Use only when V is small (≤ 300) and you need distances between every pair of nodes.

🎯 Floyd-Warshall Recognition Signal

"Shortest path between all pairs", "transitive closure", "can i reach j?" for every pair, or small V (≤ 300) with negative weights → Floyd-Warshall. Single source? Use Dijkstra or Bellman-Ford instead.

📐 Pseudocode · Floyd-Warshall All-Pairs Shortest Path 
// dist[i][j] = shortest distance from i to j
dist ← V × V matrix, all ∞
for i from 0 to V - 1: dist[i][i] ← 0
for (u, v, w) in edges: dist[u][v] ← w

// Try every intermediate node k
for k from 0 to V - 1:
    for i from 0 to V - 1:
        for j from 0 to V - 1:
            if dist[i][k] < ∞ and dist[k][j] < ∞:
                dist[i][j] ← min(dist[i][j], dist[i][k] + dist[k][j])

// Negative cycle: if dist[i][i] < 0 for any i, a negative cycle exists
// Time: O(V³)  Space: O(V²)
⚠
Overflow guard: Use INF = 1e9 (not Integer.MAX_VALUE) to avoid overflow when computing dist[i][k] + dist[k][j]. The guard if (dist[i][k] < INF) also protects you.
TimeO(V³)
SpaceO(V²)
HandlesNegative weights

⚠️ Complexity & Classic Bugs

The costs worth quoting in an interview first, then the mistakes that most often break code that looks correct. Every row in the second table is a bug someone has shipped.

Operation Cost Note
Topological sort (Kahn) O(V + E)
Dijkstra with a binary heap O((V + E) log V)
Bellman-Ford O(V · E)
Floyd-Warshall O(V³) time, O(V²) space Only for small V
0-1 BFS O(V + E) Weights of 0 and 1 only
Bug Symptom Fix
Dijkstra with negative edges Wrong distances, no error Use Bellman-Ford
Not skipping stale heap entries Extra work, occasionally wrong results if d > dist[u]: continue
Topological sort ignoring leftovers An “order” for a graph that has a cycle Check that every node was output
Hop-limited Bellman-Ford without a snapshot Uses more hops than allowed Relax from a copy of the previous round
Floyd-Warshall with k as the inner loop Wrong distances k must be the outermost loop
Infinity plus a weight Overflow into a negative “shortest” path Only relax when dist[u] is finite
Plain BFS on a weighted graph Wrong shortest paths Dijkstra, or 0-1 BFS for 0/1 weights

Problem 01 · LC 207
Course Schedule
Medium Topological Sort / Cycle Detection Amazon · Google · Meta · Microsoft
▶
Problem

There are n courses (0 to n-1). prerequisites[i] = [a, b] means you must take b before a. Return true if it is possible to finish all courses.

Input: n=2, prerequisites=[[1,0]] Output: true Input: n=2, prerequisites=[[1,0],[0,1]] Output: false (cycle)
Hints
▶Hint 1 — a nudge

'Can I finish?' is really asking whether the prerequisite graph has a cycle.

▶Hint 2 — the key idea

Kahn's algorithm: repeatedly remove nodes with in-degree 0. If you cannot process all V nodes, the leftovers form a cycle.

Solution

Build a directed graph. A cycle means a course depends on itself (directly or indirectly) — impossible. Run Kahn's BFS: if the number of processed nodes equals n, no cycle.

▶Full solution
📐 Pseudocode · LC 207 
function canFinish(n, prerequisites):
    adj ← n empty lists;  indeg ← array of n, all 0
    for (course, pre) in prerequisites:
        adj[pre].append(course)             // pre must come before course
        indeg[course] ← indeg[course] + 1
    q ← every node with indeg = 0
    done ← 0
    while q is not empty:
        node ← q.dequeue()
        done ← done + 1
        for nei in adj[node]:
            indeg[nei] ← indeg[nei] - 1
            if indeg[nei] = 0: q.enqueue(nei)
    return done = n                          // anything left is stuck in a cycle
TimeO(V+E)
SpaceO(V+E)
Problem 02 · LC 743
Network Delay Time
Medium Dijkstra Google · Amazon · Uber
▶
Problem

Weighted directed graph with n nodes. Signal starts from node k. Return the time for all nodes to receive the signal, or -1 if any node is unreachable.

Input: times=[[2,1,1],[2,3,1],[3,4,1]], n=4, k=2 Output: 2
Hints
▶Hint 1 — a nudge

Edges have weights, so BFS is wrong. All weights are positive, so you have a choice.

▶Hint 2 — the key idea

Dijkstra with a min-heap. The answer is the maximum over all shortest distances; if any node is unreachable, return -1.

Solution

Dijkstra from node k. Answer = max(dist[]). If any dist remains infinity, return -1. Classic single-source shortest path on a weighted graph.

▶Full solution
📐 Pseudocode · LC 743 
function networkDelayTime(times, n, k):
    adj ← n + 1 empty lists                 // nodes are 1-indexed
    for (u, v, w) in times: adj[u].append((v, w))
    dist ← array of n + 1, all ∞;  dist[k] ← 0
    pq ← min-heap of (distance, node), starting with (0, k)
    while pq is not empty:
        (d, node) ← pq.popMin()
        if d > dist[node]: continue          // stale
        for (nei, w) in adj[node]:
            if dist[node] + w < dist[nei]:
                dist[nei] ← dist[node] + w
                pq.push((dist[nei], nei))
    ans ← 0
    for i from 1 to n:
        if dist[i] = ∞: return -1            // some node never hears the signal
        ans ← max(ans, dist[i])
    return ans
TimeO((V+E) log V)
SpaceO(V+E)
Problem 03 · When Dijkstra Fails
Cheapest Flights Within K Stops
🔗 LC 787 - Cheapest Flights Within K Stops
Medium Bellman-Ford (bounded relaxations) Google · Amazon · Meta
›
Problem

Find the cheapest price from src to dst using at most k stops, or −1 if there is no such route.

n = 4, flights = [[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]], src = 0, dst = 3, k = 1 → 700
Hints
▶Hint 1 — a nudge

Dijkstra locks in a node the first time it pops it. Why is that wrong when a stop limit exists?

▶Hint 2 — the key idea

A more expensive route with fewer stops can still be the only legal one. Bound the work by rounds, not by cost: after i rounds of Bellman-Ford you know the best price using at most i edges.

Solution

This is the cleanest illustration of when to abandon Dijkstra. Its greedy guarantee assumes the cheapest way to reach a node is always the best way to continue — false here, because a cheap route may burn too many stops. Bellman-Ford’s structure fits exactly: run k + 1 relaxation rounds and the answer is the best price reachable within that many edges. The one detail that catches people is relaxing from a snapshot of the previous round, so a single round cannot chain two flights.

▶Full solution
📐 Pseudocode · k + 1 Rounds of Relaxation 
function findCheapestPrice(n, flights, src, dst, k):
    dist ← array of n entries, all infinity
    dist[src] ← 0

    repeat k + 1 times:                 // at most k stops = k+1 edges
        prev ← copy of dist                   // snapshot: no chaining
        for (u, v, price) in flights:
            if prev[u] ≠ infinity:
                dist[v] ← min(dist[v], prev[u] + price)

    return -1 if dist[dst] = infinity else dist[dst]

// Without the snapshot, one round could relax u→v then v→w, spending two
// flights in a round that is only allowed to spend one.
TimeO(k · E)
SpaceO(V)
