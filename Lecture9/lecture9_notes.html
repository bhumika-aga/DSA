Sorting Algorithms

"Sorting is the physics of search. Master the trade-offs between stability, memory, and raw speed."

📚 Lecture 9 of 38 Phase 2 — Core Data Structures ⏱ 4 days 🎯 25 problems 💼 Google · Amazon · Directi
🌍
Why does this topic matter?
Sorting is the physics of search. Once data is sorted, binary search, two-pointer, and sliding-window techniques become unlocked. Almost every data-processing pipeline in the real world begins with a sort. Interviewers test sorting to see if you understand trade-offs: stability vs. speed, memory vs. in-place, worst-case guarantees vs. average-case performance. Knowing when to use Merge Sort vs. Quick Sort vs. Counting Sort is the difference between an O(N log N) solution and a TLE.
By the end of this lecture you can
  • Implement all major sorting algorithms from scratch
  • Know stability, in-place, and worst-case trade-offs for each sort
  • Apply sort as preprocessing to unlock faster algorithms
  • Understand counting/radix sort for O(n) on bounded-range inputs

📖 Before We Start — The Big Picture

Sorting is the problem of rearranging N items so they are in a defined order (ascending, descending, or by some key). There are fundamentally two families of sorting algorithms:

  • Comparison-based sorts: These compare pairs of elements to decide their relative order. The theoretical minimum time for any comparison-based sort is O(N log N) — this is a mathematical proof, not just an observation. Algorithms in this family: Bubble, Selection, Insertion, Merge, Quick, Heap Sort.
  • Non-comparison sorts: These exploit additional knowledge about the data (e.g., all values are integers in a known range). They can beat O(N log N). Examples: Counting Sort, Radix Sort, Bucket Sort.

A sort is called stable if equal elements maintain their original relative order. This matters when sorting objects by multiple keys (e.g., sort employees by salary, then by name — you first sort by name stably, then sort by salary stably).

🔗
How it connects: Lecture 5 (Recursion) is the backbone of Merge Sort and Quick Sort — both use divide and conquer recursion. Lecture 10 (Searching) requires sorted input to work — Binary Search only works on sorted arrays. Many DSA problems say "sort first, then..." — this lecture teaches you why and how.

🌐 Sorting Overview

Sorting mechanics generally divide into heavily nested loops for smaller caches ($O(N^2)$ bounds) and recursive Divide & Conquer structures ($O(N \log N)$ limits).

  • $O(N^2)$ Baseline: Bubble, Selection, and Insertion Sorts. Best for tiny datasets or nearly perfectly sorted data.
  • $O(N \log N)$ Divide & Conquer: Merge Sort and Quick Sort. The industry standards for generalized scaling.
  • $O(N)$ Non-Comparison: Counting Sort and Radix Sort. Requires strict bounded constraints on dataset properties (like integers bounding).
  • $O(N \log N)$ Native: Heap Sort. In-place mapping without recursion.
💡
Stable Sort property: If two elements exhibit the same sorting key, their initial relative order is preserved. Essential for cascaded object sorting by multiple sequential criteria.

🔬 Algorithms Deep Dive

O(N²) Baseline Sorts

Bubble Sort: Propagates maximum values to the end iteratively via pair swaps. Often optimized to break early if no swaps occur.

📐 Pseudocode · Bubble Sort (Optimized) 
function bubbleSort(a):
    for i from 0 to length(a) - 1:
        swapped ← false

        for j from 1 to length(a) - i - 1:
            if a[j] < a[j-1]:
                swap(a, j, j-1)
                swapped ← true

        if not swapped: break        // nothing moved — it is already sorted

Selection Sort: Locates absolute current minimum and injects it upfront. Always performs exact $O(N)$ swaps.

📐 Pseudocode · Selection Sort 
function selectionSort(a):
    for i from 0 to length(a) - 2:
        minIdx ← i

        for j from i+1 to length(a) - 1:
            if a[j] < a[minIdx]: minIdx ← j

        swap(a, i, minIdx)           // exactly one swap per pass, always

Insertion Sort: Builds the output string progressively. Highly adaptive and routinely utilized inside complex frameworks (like Timsort) natively for handling $N < 64$ sub-chunks due to strict $O(N)$ speed on nearly sorted vectors.

📐 Pseudocode · Insertion Sort 
function insertionSort(a):
    for i from 1 to length(a) - 1:
        key ← a[i]
        j ← i - 1

        while j ≥ 0 and a[j] > key:  // shift everything bigger one slot right
            a[j+1] ← a[j]
            j ← j - 1

        a[j+1] ← key                 // drop key into the hole that opened up

Merge Sort (Divide & Conquer)

Splits cleanly down to base elements and merges components together recursively upward guaranteeing stable sorted arrays natively in $O(N \log N)$ constraints.

Caveat - The $O(N)$ Space Limit: The merge phase strictly enforces allocating external memory to preserve stability cleanly. It is the gold standard for Native Objects and Linked Lists precisely due to this stability factor.

📐 Pseudocode · Merge Sort 
function mergeSort(a, lo, hi):
    if lo ≥ hi: return            // 0 or 1 element is already sorted
    mid ← lo + (hi - lo) ÷ 2
    mergeSort(a, lo, mid)
    mergeSort(a, mid + 1, hi)
    merge(a, lo, mid, hi)

function merge(a, lo, mid, hi):
    left  ← copy of a[lo .. mid]
    right ← copy of a[mid+1 .. hi]
    i ← 0; j ← 0; k ← lo

    while i < size(left) and j < size(right):
        if left[i] ≤ right[j]:    // '<=' keeps it STABLE
            a[k] ← left[i];  i ← i + 1
        else:
            a[k] ← right[j]; j ← j + 1
        k ← k + 1

    copy any remainder of left, then of right, into a[k..]

Quick Sort

An in-place paradigm separating the domain physically into domains left recursively smaller than a central Pivot and physically greater.

The $O(N^2)$ Adversary Hazard: Standard Quick Sort choosing the exact highest element dynamically breaks out if data is aggressively inverse-sorted natively. We enforce randomized pivoting immediately to sustain average $O(N \log N)$ bounds strictly!

📐 Pseudocode · Quick Sort & Partition 
function quickSort(a, lo, hi):
    if lo ≥ hi: return
    p ← partition(a, lo, hi)
    quickSort(a, lo, p - 1)
    quickSort(a, p + 1, hi)

function partition(a, lo, hi):     // Lomuto scheme
    swap(a, random(lo, hi), hi)     // randomise: kills the O(n^2) worst case
    pivot ← a[hi]
    i ← lo                         // a[lo..i-1] are < pivot

    for j from lo to hi - 1:
        if a[j] < pivot:
            swap(a, i, j)
            i ← i + 1

    swap(a, i, hi)                  // pivot lands at its final index
    return i

Non-Comparison Sorts & Heap

Algorithms mapping domains directly to index spaces or structural constraints.

Counting Sort: Hashes bounding integers optimally, heavily consuming memory dynamically proportional to the highest integer natively.

📐 Pseudocode · Counting Sort Baseline 
function countingSort(a):
    max ← maximum value in a
    count ← array of 0, size max + 1

    for v in a: count[v] ← count[v] + 1

    j ← 0
    for v from 0 to max:
        while count[v] > 0:
            a[j] ← v
            j ← j + 1
            count[v] ← count[v] - 1

// Only viable when the value range is small — space is O(max).

Radix Sort: Cascades Counting Sort digit by digit safely preventing space exhaustion reaching $O(d \cdot (N+K))$ outputs perfectly.

📐 Pseudocode · Radix Sort Cascade 
function radixSort(a):
    if a is empty: return
    max ← maximum value in a

    exp ← 1                          // digit place: 1, 10, 100 ...
    while max ÷ exp > 0:
        countingSortByDigit(a, exp)  // MUST be stable, or earlier digits are undone
        exp ← exp × 10

Heap Sort: Forces elements into a Max/Min Binary Heap. Reaches strictly $O(N \log N)$ time natively with an optimal $O(1)$ embedded space boundary dynamically but lacks the sequential mapping speeds Merge Sort has.

📐 Pseudocode · In-Place Heap Sort 
function heapSort(a):
    n ← length(a)

    for i from n÷2 - 1 down to 0:    // build a max-heap, O(n)
        heapify(a, n, i)

    for i from n-1 down to 1:        // swap the max to the back, then repair
        swap(a, 0, i)
        heapify(a, i, 0)             // heap shrinks by one each round

🔄 Algorithm Variations

Cyclic Sort

Given parameters constraining elements rigidly inside $1$ to $N$, you assign targets manually by calculating targetIdx = nums[i] - 1 strictly bypassing comparison logic for direct index containment bounded strictly to $O(N)$.

📐 Pseudocode · Cyclic Sorting Logic 
// Values are 1..n, so value v belongs at index v-1.
i ← 0
while i < length(a):
    correct ← a[i] - 1

    if 1 ≤ a[i] ≤ length(a) and a[i] ≠ a[correct]:
        swap(a, i, correct)          // do NOT advance — the new a[i] may also be wrong
    else:
        i ← i + 1

Dutch National Flag (3-Way Partitioning)

When domains heavily replicate properties (e.g. 0s, 1s, and 2s purely). Using 3 pivot limits natively organizes elements centrally without mapping auxiliary constraints natively dynamically sorting in a single $O(N)$ pass structurally.

📐 Pseudocode · 3-Way Partition Bounds 
// low = end of the 0s, high = start of the 2s, mid = the scanner
low ← 0;  mid ← 0;  high ← length(a) - 1

while mid ≤ high:
    if a[mid] = 0:
        swap(a, low, mid);  low ← low + 1;  mid ← mid + 1
    else if a[mid] = 1:
        mid ← mid + 1
    else:
        swap(a, mid, high);  high ← high - 1   // mid does NOT advance here

QuickSelect

A Quick Sort recursion tree cut fundamentally in half. Instead of sorting both pivot sides, you analyze if the exact Kth pivot sits bounded dynamically processing strictly in amortized $O(N)$ time finding structural Medians optimally natively!

📐 Pseudocode · QuickSelect (Kth Largest) 
// The k-th largest sits at index length(a) - k once partitioned.
function quickSelect(a, lo, hi, target):
    p ← partition(a, lo, hi)

    if p = target: return a[p]
    if p < target: return quickSelect(a, p+1, hi, target)
    else:          return quickSelect(a, lo, p-1, target)

// Recursing into ONE side only is what makes this O(n) on average.

⏱️ Complexity Analysis

Algorithm Time (Best) Time (Avg / Worst) Space Constraints Stability
Insertion Sort $O(N)$ $O(N^2)$ $O(1)$ Stable
Merge Sort $O(N \log N)$ $O(N \log N)$ $O(N)$ Stable
Quick Sort $O(N \log N)$ $O(N^2)$ $O(\log N)$ Unstable
Heap Sort $O(N \log N)$ $O(N \log N)$ $O(1)$ Unstable
Counting Sort $O(N+K)$ $O(N+K)$ $O(K)$ Max Stable

🗺️ 2D Sorting Constraints

Interviewers reliably ask candidates to organize unstructured 2D domains dynamically mapping arrays (e.g. Time Intervals).

📐 Pseudocode · Interval Lambda Filtering 
// Sort by start time, breaking ties with the earlier end time.
sort(intervals) by comparator (x, y):
    if x.start ≠ y.start: return compare(x.start, y.start)
    else:                 return compare(x.end,   y.end)

// Two keys, in priority order — the second only decides when the first ties.

💪 In-Lecture Practice Problems

Problem 01 · In-Place Merge
Merge Sorted Array
🔗 LC 88 - Merge Sorted Array
Easy Amazon · Microsoft · Meta
›
Problem

Merge two sorted arrays in-place into the larger array. You must start merging from the back to avoid overwriting elements.

Hints
▶Hint 1 — a nudge

Filling from the front means shifting elements. Which end is free?

▶Hint 2 — the key idea

Merge backwards from index m+n-1. The tail of nums1 is empty space, so nothing ever gets overwritten before it is read.

Solution
Full solution with complexity
📐 Pseudocode · Backward Merge 
function merge(a, m, b, n):
    p1 ← m - 1                       // last real element of a
    p2 ← n - 1                       // last element of b
    write ← m + n - 1                // last slot of a

    while p2 ≥ 0:
        if p1 ≥ 0 and a[p1] > b[p2]:
            a[write] ← a[p1];  p1 ← p1 - 1
        else:
            a[write] ← b[p2];  p2 ← p2 - 1
        write ← write - 1

// Filling from the back means nothing is overwritten before it is read.
TimeO(m+n)
SpaceO(1)
Problem 02 · Three-Way Partition
Sort Colors (Dutch National Flag)
🔗 LC 75 - Sort Colors
Medium Microsoft · Amazon · Meta
›
Problem

Sort an array of 0s, 1s, and 2s in-place in $O(N)$ time and $O(1)$ space using three pointers tracking bounds.

Hints
▶Hint 1 — a nudge

Counting sort works in two passes. One pass needs three regions instead of two.

▶Hint 2 — the key idea

Dutch National Flag: pointers low, mid, high. 0 → swap with low and advance both; 1 → advance mid; 2 → swap with high and do not advance mid.

Solution
▶Full solution with complexity
📐 Pseudocode · Dutch National Flag 
function sortColors(a):
    low ← 0;  mid ← 0;  high ← length(a) - 1

    while mid ≤ high:
        if a[mid] = 0:
            swap(a, low, mid);  low ← low + 1;  mid ← mid + 1
        else if a[mid] = 1:
            mid ← mid + 1
        else:
            swap(a, mid, high);  high ← high - 1   // the swapped-in value is unseen
TimeO(N)
SpaceO(1)
Problem 03 · Cyclic Sort Secret
First Missing Positive
🔗 LC 41 - First Missing Positive
Hard Google · Amazon · Meta · Microsoft Cyclic Sort
›
Problem

Find the smallest positive integer missing from an unsorted array using $O(N)$ time and strict $O(1)$ space constraints.

Hints
▶Hint 1 — a nudge

The answer must lie in 1..n+1. That is a strong constraint.

▶Hint 2 — the key idea

Cyclic sort: put each value v in index v-1 by swapping. Then the first index where nums[i] != i+1 gives the answer.

Solution

Treat the array as a hash set where a value k maps optimally to index k-1. Swap elements into their correct positions greedily, then execute a final linear scan to find the first position mismatch.

▶Full solution with complexity
📐 Pseudocode · Cyclic Sort 
function firstMissingPositive(a):
    n ← length(a)

    i ← 0
    while i < n:
        correct ← a[i] - 1
        if 1 ≤ a[i] ≤ n and a[i] ≠ a[correct]:
            swap(a, i, correct)
        else:
            i ← i + 1

    for i from 0 to n - 1:
        if a[i] ≠ i + 1: return i + 1    // first slot holding the wrong value

    return n + 1                          // 1..n all present
TimeO(N)
SpaceO(1)
Problem 04 · Optimization Variants
Kth Largest Element in an Array
🔗 LC 215 - Kth Largest Element
Medium Meta · Amazon · Google · Microsoft QuickSelect / Heap
›
Problem

Find the $k$-th largest element in an unsorted array efficiently $O(N)$ average using QuickSelect partitioning, or optimally using Min-Heaps for stream capability.

Hints
▶Hint 1 — a nudge

A full sort is O(n log n). You only need one position to be correct.

▶Hint 2 — the key idea

QuickSelect: partition, then recurse only into the side containing k. O(n) average. A size-k min-heap is the safer O(n log k) fallback.

Solution
▶Full solution with complexity
📐 Pseudocode · Min Heap 
function findKthLargest(a, k):
    heap ← empty min-heap

    for v in a:
        heap.push(v)
        if size(heap) > k: heap.popMin()  // evict the smallest; the top k survive

    return heap.min                       // smallest of the top k = k-th largest
TimeO(N log k)
SpaceO(k)
Problem 05 · Radical Performance
Maximum Gap
🔗 LC 164 - Maximum Gap
Medium Apple · Amazon · Google Radix / Bucket Sort
›
Problem

Given an unsorted array, find the maximum difference between successive elements in sorted form. You must solve it in linear time and space $O(N)$ without deploying comparison bounds.

Hints
▶Hint 1 — a nudge

The requirement of linear time rules out comparison sorting entirely.

▶Hint 2 — the key idea

Pigeonhole: with n numbers spread over the range, some bucket of width (max-min)/(n-1) must be empty. The maximum gap spans a gap between buckets, so only bucket min/max matter.

Solution
▶Full solution with complexity
📐 Pseudocode · Pigeonhole Bucket Sort 
function maximumGap(a):
    if length(a) < 2: return 0

    min ← minimum of a
    max ← maximum of a
    gap ← max(1, (max - min) ÷ (length(a) - 1))

    // Pigeonhole: with n numbers spread across that range, at least one bucket
    // of width `gap` must be empty — so the largest gap spans BETWEEN buckets,
    // never inside one. Only each bucket's own min and max can matter.
    return maxGapAcrossBuckets(a, gap, min, max)
Problem 06 · Bucket Sort Approach
Top K Frequent Elements
🔗 LC 347 - Top K Frequent Elements
Medium Amazon · Meta · Google Bucket Sort
›
Problem

Given an integer array nums and an integer k, return the k most frequent elements. The algorithm must be better than $O(N \log N)$.

Hints
▶Hint 1 — a nudge

Count first; the rest is choosing the k largest counts.

▶Hint 2 — the key idea

Bucket by frequency — index = count, value = the numbers with that count — then read buckets from the top. O(n).

Solution
▶Full solution with complexity
📐 Pseudocode · Bucket Sort 
function topKFrequent(a, k):
    count ← empty map                     // value → how many times it appears
    for v in a: count[v] ← count[v] + 1

    // bucket[f] holds every value appearing exactly f times.
    // A value can appear at most length(a) times, so that many buckets suffice.
    bucket ← array of empty lists, size length(a) + 1
    for (value, freq) in count:
        bucket[freq].append(value)

    result ← empty list
    for f from length(bucket) - 1 down to 0:   // walk down from most frequent
        for v in bucket[f]:
            result.append(v)
            if length(result) = k: return result

    return result
TimeO(N)
SpaceO(N)
Problem 07 · Greedy Reordering
Wiggle Sort
🔗 LC 280 - Wiggle Sort 🔒 Premium
Medium Google · Amazon · Meta Greedy Sort
›
Problem

Given an integer array nums, reorder it such that $nums[0] \leq nums[1] \geq nums[2] \leq nums[3] \dots$ Optimal approach requires only a single $O(N)$ pass.

Hints
▶Hint 1 — a nudge

You need a local property, not a global order.

▶Hint 2 — the key idea

Walk the array; whenever the pair (i, i+1) violates the wanted up/down alternation, swap them. One pass, and the swap never breaks the pair before it.

Solution
▶Full solution with complexity
📐 Pseudocode · Greedy Swap Array 
function wiggleSort(a):
    for i from 0 to length(a) - 2:
        if i is even:
            if a[i] > a[i+1]: swap(a, i, i+1)   // want a[i] ≤ a[i+1]
        else:
            if a[i] < a[i+1]: swap(a, i, i+1)   // want a[i] ≥ a[i+1]

// One pass is enough: fixing pair i can never break pair i-1.
TimeO(N)
SpaceO(1)
Problem 08 · Sort + Min-Heap
Meeting Rooms II
🔗 LC 253 🔒 Premium
Medium Google · Amazon · Meta · Uber Sort + Heap
›
Problem

Given an array of meeting intervals [start, end], find the minimum number of conference rooms required to hold all meetings.

intervals = [[0,30],[5,10],[15,20]] Time: 0----5---10---15---20---30 Room1: [====0 30=======] Room2: [===5 10==] Room3: [=15 20==] → 2 rooms needed (room 2 ends at 10, room 3 reuses it from 15)
Hints
▶Hint 1 — a nudge

You need to know how many meetings are live at once.

▶Hint 2 — the key idea

Sort by start time and keep a min-heap of end times. Before adding a meeting, pop every room whose end time is ≤ the new start. Heap size is the answer.

Solution

Sort by start time, then use a min-heap of end times. For each meeting, check if the earliest-ending room (heap top) is free. If yes, pop and (conceptually) reuse that room — push the new end time. If no, we need a new room. The heap size at the end = rooms needed.

▶ Solution + Dry Run
📐 Pseudocode · Sort + PriorityQueue (Min-Heap) 
function minMeetingRooms(meetings):
    sort meetings by start time
    heap ← empty min-heap of end times

    for m in meetings:
        // If the earliest-finishing room is already free, reuse it.
        if heap is not empty and heap.min ≤ m.start: heap.popMin()
        heap.push(m.end)

    return size(heap)                // rooms in use at the busiest moment

// [[0,30],[5,10],[15,20]]
//   [0,30]  : heap empty     → new room   heap = [30]
//   [5,10]  : min 30 > 5     → new room   heap = [10, 30]
//   [15,20] : min 10 ≤ 15    → reuse      heap = [20, 30]
//   answer = 2
TimeO(N log N)
SpaceO(N)
