Prefix Sums & Difference Arrays

“Pay once, answer forever. Precompute the totals and every range question becomes one subtraction.”

📚 Lecture 26 of 45 Phase 3 — Core Patterns ⏱ 4 days 🎯 20 problems 💼 Google · Amazon · Meta · Microsoft
🌍
Why does this topic matter?
Lecture 25 ended on a warning: the moment negative numbers appear, a sliding window stops working, because adding an element can make an invalid window valid again. Prefix sums have no such rule. They answer “what is the total between i and j?” in constant time for any numbers at all, and their mirror image — the difference array — applies a range update in constant time too. Between them they turn a whole family of O(n²) and O(n·q) solutions into O(n). You met the basic idea as a preview in Lecture 11; this is the full treatment.
By the end of this lecture you can
  • Build a prefix-sum array and answer any range-sum query in O(1)
  • Combine prefix sums with a HashMap to count subarrays matching a target
  • Apply many range updates in O(1) each using a difference array
  • Extend both ideas to 2D grids with inclusion–exclusion
  • Recognise prefix-XOR as the same trick, and say which operations can never be prefixed
🧠
The picture to keep in your head: A car’s odometer. To know how far it is between two towns, read the odometer at each and subtract. You never re-drive the road. A prefix sum is an odometer for an array. A difference array is the reverse trick: instead of writing “rented” on every day of a booking, mark a start and an end on the calendar and fill the days in one sweep at the end.

🧱 Building a Prefix Sum

A prefix sum answers one question in advance: how much is there before this point? Store that for every index and you never add the same element twice again.

📐 Pseudocode · Build (the n+1 convention) 
// prefix[i] = sum of the first i elements = nums[0] + ... + nums[i-1]
// The extra leading 0 is what removes every edge case later.
prefix ← array of length n + 1
prefix[0] ← 0

for i from 0 to n - 1:
    prefix[i + 1] ← prefix[i] + nums[i]

// nums   = [ 3,  1,  4,  1,  5]
// prefix = [0, 3,  4,  8,  9, 14]
//           ^ nothing taken yet
⚠️
The off-by-one discipline. Decide once and never waver: prefix has n + 1 slots, and prefix[i] excludes nums[i]. The alternative (same length as nums, including the current element) forces an if (l == 0) check into every single query. One extra slot buys you a body of code with no special cases.

⚡ O(1) Range Queries

Everything before r + 1, minus everything before l, leaves exactly the window [l, r]. That is the whole idea.

📐 Pseudocode · Range Sum in O(1) 
function rangeSum(l, r):            // inclusive on both ends
    return prefix[r + 1] - prefix[l]

// nums   = [ 3,  1,  4,  1,  5]
// prefix = [0, 3,  4,  8,  9, 14]
// sum(1..3) = prefix[4] - prefix[1] = 9 - 3 = 6   (1 + 4 + 1) ✓
// sum(0..4) = prefix[5] - prefix[0] = 14 - 0 = 14 ✓
Approach Build One query q queries Update an element
Loop over the range each time — O(n) O(n · q) O(1)
Prefix sum array O(n) O(1) O(n + q) O(n) — rebuild the tail
Fenwick / Segment tree (Lecture 37) O(n) O(log n) O(q log n) O(log n)
🛑
When a prefix sum is the wrong tool. It assumes the array never changes. One update invalidates every prefix after it, so a problem with interleaved updates and queries wants a Fenwick tree or a segment tree instead — that is exactly the gap Lecture 37 fills.

🔑 Prefix + HashMap

The second use of a prefix sum is not about queries at all. If two prefixes are equal, the elements between them sum to zero; if they differ by k, the elements between them sum to k. So instead of storing prefixes in an array, store how often each prefix value has been seen — in a HashMap.

Counting Subarrays That Sum to K

📐 Pseudocode · Subarray Sum Equals K 
function countSubarrays(nums, k):
    seen ← {0: 1}              // the empty prefix has sum 0, once
    sum ← 0;  count ← 0

    for x in nums:
        sum ← sum + x
        if (sum - k) in seen:
            count ← count + seen[sum - k]    // every earlier prefix that closes a window
        seen[sum] ← (seen[sum] if sum in seen, else 0) + 1
    return count

// nums = [1, 2, 3], k = 3
// x=1: sum=1, need -2 → no.  seen = {0:1, 1:1}
// x=2: sum=3, need  0 → yes (×1) → count = 1.  seen = {0:1, 1:1, 3:1}
// x=3: sum=6, need  3 → yes (×1) → count = 2.  ✓ [1,2] and [3]
🧠
Why seed the map with {0: 1}? Without it, a subarray that starts at index 0 is never counted — because closing it needs a prefix of 0 that was never recorded. The seed says “before I read anything, I had a running total of zero, and that happened once.”
⚠️
Count, then record. Look up sum - k before you insert the current prefix. Do it the other way round and, when k = 0, every element cheerfully pairs with itself.

Divisible by K, and Longest Zero-Sum

Two variations reuse the same skeleton with a different key and a different stored value:

Question Map key Map value Why
How many subarrays sum to k? prefix sum count every earlier match is one more subarray
How many are divisible by k? prefix mod k count equal remainders cancel
Longest subarray summing to k? prefix sum first index earliest match gives the longest span
Longest with equal 0s and 1s? prefix with 0 read as −1 first index balance returning to a value means equal counts
⚠️
Negative remainders. In most languages -7 mod 3 is -1, not 2. Normalise with ((sum mod k) + k) mod k or the two halves of the same remainder never meet.

📋 Difference Arrays — The Mirror Image

A prefix sum turns many reads into one subtraction. A difference array turns many writes into two. Use it when the problem says “add v to every element from l to r”, many times over, and only asks for the final array.

📐 Pseudocode · Range Update in O(1) 
diff ← array of length n + 1, all 0

function update(l, r, v):        // add v to every index in [l, r]
    diff[l] ← diff[l] + v            // switch the change on
    diff[r + 1] ← diff[r + 1] - v    // switch it off again

function build():                 // run once, at the very end
    running ← 0
    for i from 0 to n - 1:
        running ← running + diff[i]
        result[i] ← running
    return result

// update(1, 3, +5) on n = 5
// diff   = [0, +5, 0, 0, -5, 0]
// build  = [0,  5, 5, 5,  0]      ← the +5 lives exactly on [1, 3] ✓
🧠
They are inverses. Prefix-summing a difference array gives back the original updates, and taking the differences of a prefix-sum array gives back the original elements. That is why the r + 1 slot exists: it is the same extra cell as the leading 0, seen from the other side.

The pattern hides in problems that never mention arrays. “Each booking adds seats to flights l through r”, “each passenger occupies the car from stop l to stop r”, “each person is alive from birth to death” — all the same two writes and one sweep.

2D Difference Arrays

📐 Pseudocode · Rectangle Update in O(1) 
// Add v to every cell in the rectangle (r1, c1) .. (r2, c2).
function update(r1, c1, r2, c2, v):
    diff[r1][c1]         ← diff[r1][c1] + v
    diff[r1][c2 + 1]     ← diff[r1][c2 + 1] - v
    diff[r2 + 1][c1]     ← diff[r2 + 1][c1] - v
    diff[r2 + 1][c2 + 1] ← diff[r2 + 1][c2 + 1] + v   // added back: it was removed twice

// Then prefix-sum the whole grid once (rows, then columns).

🧮 2D Prefix Sums

The same idea in two dimensions is called an integral image: P[r][c] is the sum of the whole rectangle from the top-left corner down to (r-1, c-1). Any sub-rectangle is then four lookups.

A | B ----+---- C | D    want D = whole − (A+B) − (A+C) + A    the corner A is subtracted twice, so add it back once
📐 Pseudocode · Build and Query a 2D Prefix 
// P has one extra row and one extra column of zeros.
for r from 1 to m:
    for c from 1 to n:
        P[r][c] ← grid[r-1][c-1] + P[r-1][c] + P[r][c-1] - P[r-1][c-1]

function regionSum(r1, c1, r2, c2):        // inclusive corners
    return P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]

// grid = [[1, 2],        P = [[0, 0, 0],
//         [3, 4]]             [0, 1, 3],
//                             [0, 4, 10]]
// regionSum(1,0, 1,1) = P[2][2] - P[1][2] - P[2][0] + P[1][0]
//                     = 10 - 3 - 0 + 0 = 7   (3 + 4) ✓
🧠
Inclusion–exclusion, in one sentence. Take the big rectangle, remove the strip above and the strip to the left, then add back the corner you just removed twice. The build formula is the same four terms rearranged.

✖️ Prefix XOR & Friends

Prefix sums work because addition has an inverse: subtraction. Any operation with an inverse can be prefixed the same way.

Operation Undo with Range formula Safe?
Sum (+) − P[r+1] - P[l] ✅ always
XOR (^) XOR itself P[r+1] ^ P[l] ✅ always
Product (×) ÷ P[r+1] / P[l] ⚠️ breaks on a zero
Min / Max nothing — ❌ use a sparse table or segment tree
📐 Pseudocode · Prefix XOR 
// x XOR x = 0, so XOR is its own inverse — no subtraction needed.
px ← array of length n + 1;  px[0] ← 0
for i from 0 to n - 1:
    px[i + 1] ← px[i] XOR nums[i]

function rangeXor(l, r):
    return px[r + 1] XOR px[l]

// A pair of equal prefix-XORs means the range between them XORs to 0 —
// the same "equal prefixes cancel" idea, one operator over.

⏱ Complexity & The Classic Bugs

Technique Preprocess Per query / update Extra space
1D prefix sum O(n) O(1) query O(n)
Prefix + HashMap — O(1) average per element O(n)
Difference array — O(1) update, O(n) once to build O(n)
2D prefix sum O(m · n) O(1) region query O(m · n)
Bug Symptom Fix
Forgetting the seed {0: 1} Subarrays starting at index 0 are missed Insert the empty prefix before the loop
Recording before counting Elements pair with themselves when k = 0 Look up sum - k first, then store
Off-by-one in the query One element too many or too few P[r+1] - P[l], always, with the extra leading slot
Difference array too short Crash when r is the last index Allocate n + 1 slots for the “off” mark
Negative remainders Divisible-by-k counts come out low ((sum mod k) + k) mod k
Overflow Sums wrap to negative numbers Accumulate in 64-bit (long)
💡
How to spot it in an interview. “Range sum”, “how many subarrays”, “many updates, one final read”, or a sliding window that breaks because the numbers can be negative. Any of those four, and a prefix or difference array is the first thing to try.

Problem 01 · Build & Query
Find the Middle Index in Array
🔗 LC 1991 - Find the Middle Index in Array
Easy Prefix Sum Amazon · Google · Meta
›
Problem

Return the leftmost index where the sum of everything strictly to its left equals the sum of everything strictly to its right. Return −1 if no such index exists.

nums = [2, 3, -1, 8, 4] → 3  (2+3-1 = 4 = 4)  |   nums = [1, -1, 4] → 2
Hints
▶Hint 1 — a nudge

You know the total of the whole array before you start walking it. What else do you need?

▶Hint 2 — the key idea

Keep a running left. The right side is total - left - nums[i] — the pivot itself belongs to neither side.

Solution

One pass over a running total replaces the inner loop. Compare before adding nums[i] to left, because the pivot is excluded from both sides. Negative numbers are no problem here: a prefix sum never assumes the values grow.

▶Full solution
📐 Pseudocode · Total Minus Left 
function findMiddleIndex(nums):
    total ← sum(nums)
    left ← 0
    for i from 0 to length(nums) - 1:
        right ← total - left - nums[i]      // pivot excluded from both sides
        if left = right: return i
        left ← left + nums[i]
    return -1

// [2,3,-1,8,4]: total = 16
// i=0 left=0  right=14   i=1 left=2 right=11
// i=2 left=5  right=12   i=3 left=4 right=4  ← answer 3 ✓
TimeO(n)
SpaceO(1)
Problem 02 · Prefix + HashMap
Binary Subarrays With Sum
🔗 LC 930 - Binary Subarrays With Sum
Medium Prefix + HashMap Amazon · Google · Meta
›
Problem

Given a binary array nums and an integer goal, return how many non-empty subarrays sum to exactly goal.

nums = [1, 0, 1, 0, 1], goal = 2 → 4
Hints
▶Hint 1 — a nudge

Two prefixes that differ by goal bound a subarray that sums to goal.

▶Hint 2 — the key idea

Walk the array keeping a running sum and a map of how often each earlier prefix appeared. Add map[sum - goal] at each step. Seed the map with {0: 1}.

Solution

The array is binary, so a sliding window is tempting — but goal can be 0, and that breaks the “shrink while too big” rule. The prefix-map version does not care: it counts every earlier prefix that closes a valid window, in one pass. (The at-most trick from Lecture 25 also works: atMost(goal) − atMost(goal−1).)

▶Full solution
📐 Pseudocode · Count, Then Record 
function numSubarraysWithSum(nums, goal):
    seen ← {0: 1}
    sum ← 0;  count ← 0
    for x in nums:
        sum ← sum + x
        if (sum - goal) in seen:
            count ← count + seen[sum - goal]     // look up BEFORE storing
        seen[sum] ← (seen[sum] if sum in seen, else 0) + 1
    return count

// [1,0,1,0,1], goal = 2
// prefixes: 1, 1, 2, 2, 3 — matches at sum=2 (×1), sum=2 (×1), sum=3 (×2)
// count = 4 ✓
TimeO(n)
SpaceO(n)
Problem 03 · Difference Array
Corporate Flight Bookings
🔗 LC 1109 - Corporate Flight Bookings
Medium Difference Array Amazon · Google · Microsoft
›
Problem

There are n flights. Each booking [first, last, seats] reserves seats on every flight from first to last inclusive. Return the total seats booked on each flight.

bookings = [[1,2,10],[2,3,20],[2,5,25]], n = 5 → [10, 55, 45, 25, 25]
Hints
▶Hint 1 — a nudge

Applying each booking flight by flight is O(bookings × n). Can one booking cost O(1)?

▶Hint 2 — the key idea

Record only where each booking starts and where it stops: +seats at first, -seats just after last. One prefix sum at the end turns the marks into the answer.

Solution

This is the difference array with the labels changed. Each booking writes two cells regardless of how many flights it spans, and a single sweep expands the marks. Watch the indexing: flights are 1-based in the statement, so either shift by one or allocate n + 2 cells — the “off” mark for the last flight must have somewhere to live.

▶Full solution
📐 Pseudocode · Two Writes, One Sweep 
function corpFlightBookings(bookings, n):
    diff ← array of length n + 1, all 0        // 0-based flights

    for (first, last, seats) in bookings:
        diff[first - 1] ← diff[first - 1] + seats
        if last < n: diff[last] ← diff[last] - seats

    answer ← array of length n
    running ← 0
    for i from 0 to n - 1:
        running ← running + diff[i]
        answer[i] ← running
    return answer

// diff after all three bookings: [10, 45, -10, 0, 0]
// sweep: 10, 55, 45, 25, 25 ✓
TimeO(n + bookings)
SpaceO(n)
Problem 04 · 2D Prefix
Matrix Block Sum
🔗 LC 1314 - Matrix Block Sum
Medium 2D Prefix Sum Amazon · Google · Microsoft
›
Problem

Return a matrix answer where answer[i][j] is the sum of all cells within k rows and k columns of (i, j), clipped to the grid.

mat = [[1,2,3],[4,5,6],[7,8,9]], k = 1 → [[12,21,16],[27,45,33],[24,39,28]]
Hints
▶Hint 1 — a nudge

Every answer cell is the sum of a rectangle. How many lookups should one rectangle cost?

▶Hint 2 — the key idea

Build a 2D prefix sum once, then clamp the rectangle corners to the grid: rows max(0, i-k) to min(m-1, i+k), and the same for columns.

Solution

Without preprocessing this is O(m·n·k²). With one integral image it is O(m·n) total, because each answer cell costs four lookups. The only fiddly part is clamping: write the corner arithmetic once, in a helper, and the edges stop being a special case.

▶Full solution
📐 Pseudocode · Integral Image + Clamp 
function matrixBlockSum(mat, k):
    m ← rows(mat);  n ← cols(mat)
    P ← (m+1) × (n+1) matrix of zeros
    for r from 1 to m:
        for c from 1 to n:
            P[r][c] ← mat[r-1][c-1] + P[r-1][c] + P[r][c-1] - P[r-1][c-1]

    answer ← m × n matrix
    for i from 0 to m - 1:
        for j from 0 to n - 1:
            r1 ← max(0, i - k);  c1 ← max(0, j - k)
            r2 ← min(m - 1, i + k);  c2 ← min(n - 1, j + k)
            answer[i][j] ← P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]
    return answer
TimeO(m · n)
SpaceO(m · n)
Problem 05 · Prefix XOR
XOR Queries of a Subarray
🔗 LC 1310 - XOR Queries of a Subarray
Medium Prefix XOR Amazon · Google
›
Problem

For each query [l, r], return the XOR of arr[l] ^ arr[l+1] ^ ... ^ arr[r].

arr = [1, 3, 4, 8], queries = [[0,1],[1,2],[0,3],[3,3]] → [2, 7, 14, 8]
Hints
▶Hint 1 — a nudge

Answering each query directly is O(n) per query. Which property of XOR makes a prefix array work?

▶Hint 2 — the key idea

x ^ x = 0, so XOR undoes itself: rangeXor(l, r) = px[r+1] ^ px[l], with no subtraction anywhere.

Solution

Everything you know about prefix sums transfers, with + and − both replaced by ^. Build px with the same leading zero — XOR with 0 leaves a value unchanged, which is exactly the role the empty prefix plays for sums.

▶Full solution
📐 Pseudocode · Prefix XOR 
function xorQueries(arr, queries):
    n ← length(arr)
    px ← array of length n + 1;  px[0] ← 0
    for i from 0 to n - 1:
        px[i + 1] ← px[i] XOR arr[i]

    out ← empty list
    for (l, r) in queries:
        append px[r + 1] XOR px[l] to out
    return out

// arr = [1,3,4,8] → px = [0, 1, 2, 6, 14]
// query [1,2] = px[3] XOR px[1] = 6 XOR 1 = 7 ✓
TimeO(n + q)
SpaceO(n)
Problem 06 · Prefix + Monotonic Deque
Shortest Subarray with Sum at Least K
🔗 LC 862 - Shortest Subarray with Sum at Least K
Hard Prefix + Deque Google · Amazon · Meta
›
Problem

Return the length of the shortest non-empty subarray with a sum of at least k. The array may contain negative numbers. Return −1 if none exists.

nums = [2, -1, 2], k = 3 → 3   |   nums = [84, -37, 32, 40, 95], k = 167 → 3
Hints
▶Hint 1 — a nudge

A sliding window fails here. Why? And what does the problem look like once you write it in prefix sums?

▶Hint 2 — the key idea

You need the shortest j - i with P[j] - P[i] ≥ k. Keep candidate is in a deque with increasing prefix values; pop from the front when a window qualifies, and from the back when a new prefix is no larger.

Solution

Negatives break windows because growing the window can lower the sum, so shrinking is no longer safe. In prefix form the question becomes a search over earlier prefixes. Two rules keep the deque honest: a front entry that already satisfies P[j] - P[front] ≥ k can be answered and discarded (no later j gives a shorter window), and a back entry with P[back] ≥ P[j] is useless (j is both later and smaller). Each index enters and leaves once: O(n).

▶Full solution
📐 Pseudocode · Monotonic Deque over Prefixes 
function shortestSubarray(nums, k):
    n ← length(nums)
    P ← array of length n + 1;  P[0] ← 0
    for i from 0 to n - 1: P[i + 1] ← P[i] + nums[i]      // use 64-bit

    dq ← empty deque of indices        // prefix values increase front → back
    best ← +infinity

    for j from 0 to n:
        while dq is not empty and P[j] - P[dq.front()] ≥ k:
            best ← min(best, j - dq.popFront())     // answered — never needed again
        while dq is not empty and P[dq.back()] ≥ P[j]:
            dq.popBack()                            // j is later AND smaller
        dq.pushBack(j)

    if best = +infinity: return -1
    return best
TimeO(n)
SpaceO(n)
