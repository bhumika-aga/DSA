Advanced Math & Game Theory

“Count without listing, jump a billion steps ahead, and know who wins before the first move.”

📚 Lecture 42 of 45 Phase 5 — Advanced Structures ⏱ 4 days 🎯 18 problems 💼 Google · Goldman Sachs · Amazon · Adobe
🌍
Why does this topic matter?
Some problems are impossible to brute-force not because the logic is hard but because the numbers are huge: the billionth term of a sequence, the number of ways to arrange a hundred thousand items, the chance of an outcome after endless random draws. Others ask who wins a game “if both players play perfectly”. Each of these has a small, reusable mathematical tool. None needs advanced maths — just multiplication, a little counting, and one clear definition of winning and losing.
By the end of this lecture you can
  • Turn a linear recurrence into a matrix and compute its n-th term in O(log n) steps
  • Compute nCr modulo a prime with factorials and inverse factorials
  • Count with inclusion–exclusion without double counting
  • Use linearity of expectation, reservoir sampling and rejection sampling
  • Label game positions as winning or losing, and use XOR and Grundy numbers for Nim-like games
🧠
The picture to keep in your head: a vending machine and a chessboard. A recurrence is a vending machine: put today’s numbers in, get tomorrow’s out, always by the same rule. Write the rule as a matrix and “press the button a billion times” becomes “square the matrix thirty times”. A game is a chessboard read backwards: start from the finished positions, where you already know who won, and label every earlier position by looking one move ahead.
↩️
Built on Lectures 10, 32 and 35. Lecture 10 taught modular arithmetic and fast power (repeated squaring) and named nCr and modular inverses in passing; this lecture teaches them in full. Lecture 32’s recurrences are what the matrices speed up, and Lecture 35 already solved Stone Game and Predict the Winner as interval DP — here you get the general theory of games behind them.

🔢 Matrix Exponentiation

Fibonacci says F(n) = F(n − 1) + F(n − 2). A loop gets F(n) in O(n) steps, which is fine for n = 10⁶ and hopeless for n = 10¹⁸. The trick is to see one step of the recurrence as a matrix multiplication: a fixed matrix M turns the pair (F(n), F(n − 1)) into (F(n + 1), F(n)).

| F(n+1) | | 1 1 | | F(n) | | | = | | · | | so (F(n+1), F(n)) = Mⁿ · (F(1), F(0)) | F(n) | | 1 0 | | F(n-1) | M

Doing n steps means multiplying by M n times, which is Mⁿ — and fast power from Lecture 10 computes any power with about log₂ n squarings. The same works for any recurrence where the next values are a fixed weighted sum of the last few: put the weights in the matrix.

📐 Pseudocode · Matrix Fast Power 
function multiply(A, B):                      // k × k matrices, mod MOD
    C ← k × k zeros
    for i, j, t from 0 to k - 1:
        C[i][j] ← (C[i][j] + A[i][t] · B[t][j]) mod MOD
    return C

function power(M, n):
    result ← identity matrix                     // plays the role of 1
    while n > 0:
        if n is odd: result ← multiply(result, M)
        M ← multiply(M, M)                       // M, M², M⁴, M⁸, ...
        n ← n / 2                                // integer division
    return result
// Cost: O(k³ log n). With k = 2 that is about 8 · 60 multiplications for n = 10¹⁸.
💡
How to build the matrix. List the numbers you need to know at each step — the state. Row i of the matrix says how the new value of state i is made from the old states. Counting walks works the same way: if state j can move to state i, put a 1 in row i, column j. Then Mⁿ counts every walk of length n.

🎲 Counting Without Listing

Two rules do most of the work. Multiply when choices happen one after another (3 shirts and 4 trousers make 3 × 4 = 12 outfits). Add when you pick one case or another and the cases cannot overlap. Everything else is built from these.

Question Count Example
Orders of n different items n! (n factorial) ABC: 3! = 6 orders
Choose r of n, order does not matter C(n, r) = n! / (r! · (n − r)!) 2 of {A, B, C, D}: C(4, 2) = 6
Choose r of n, order matters n! / (n − r)! Gold and silver from 4 runners: 12

nCr modulo a prime

The answer is usually wanted “modulo 10⁹ + 7”, and modular arithmetic has no division. It has something just as good: because 10⁹ + 7 is prime, dividing by a is the same as multiplying by ap − 2 (Fermat’s little theorem), which fast power computes. Precompute every factorial and every inverse factorial once; then each C(n, r) is two multiplications.

📐 Pseudocode · Factorials and Inverse Factorials 
function precompute(N):                     // P = 10⁹ + 7
    fact[0] ← 1
    for i from 1 to N: fact[i] ← fact[i - 1] · i mod P
    invFact[N] ← modPow(fact[N], P - 2, P)       // ONE inverse, by Fermat
    for i from N down to 1:
        invFact[i - 1] ← invFact[i] · i mod P    // 1/(i-1)! = i · 1/i!

function nCr(n, r):
    if r < 0 or r > n: return 0
    return fact[n] · invFact[r] mod P · invFact[n - r] mod P
// For small n (up to ~1000) Pascal's rule also works: C(n, r) = C(n-1, r-1) + C(n-1, r).

Inclusion–exclusion

How many numbers from 1 to 100 are divisible by 4 or 6? Adding 25 (fours) and 16 (sixes) counts the multiples of 12 twice, so subtract them once: 25 + 16 − 8 = 33. With three sets you add the singles, subtract the pairs, and add back the triple, which was subtracted once too often. In general: odd-sized groups add, even-sized groups subtract.

📐 Pseudocode · Count Multiples of Any Divisor 
function countDivisibleByAny(x, divisors):     // numbers in 1..x
    total ← 0;  m ← length(divisors)
    for mask from 1 to 2^m - 1:                 // every non-empty group
        l ← lcm of the divisors whose bits are set in mask
        if popcount(mask) is odd: total ← total + x / l
        else:                     total ← total - x / l
    return total
// Use the lcm, not the product: multiples of both 4 and 6 are multiples of 12, not 24.

🍀 Probability & Expectation

A probability is a number from 0 to 1: favourable outcomes divided by all outcomes, when they are equally likely. The expected value is the average result over many repeats: each outcome times its probability, added up. A fair die expects (1 + 2 + … + 6) / 6 = 3.5.

The most useful fact is linearity of expectation: the expected value of a sum is the sum of the expected values — always, even when the parts depend on each other. It turns scary questions into small ones. n people throw their hats in a pile and each takes one at random; how many expect their own hat back? Each person has a 1/n chance, so the answer is n × 1/n = 1, however large n is.

💡
Probability DP. When a process moves between states at random, dp[state] = the chance of ending well from that state = the average of dp over the states it can move to. It is ordinary DP from Lecture 32 with averages instead of minimums — New 21 Game and Soup Servings are both this shape.

Random sampling

Two interview favourites. Reservoir sampling picks one item uniformly from a stream whose length you do not know: keep the i-th item with probability 1/i. Rejection sampling builds one random range from another: generate a bigger uniform range, keep the part that splits evenly, and retry on the rest.

📐 Pseudocode · Reservoir and Rejection Sampling 
function pickUniform(stream):
    choice ← none;  i ← 0
    for item in stream:
        i ← i + 1
        if randomInt(1, i) = 1: choice ← item     // probability 1/i
    return choice
// Item i survives if picked (1/i) and never replaced: 1/i · i/(i+1) · ... · (n-1)/n = 1/n.

function rand10():                              // from rand7()
    repeat:
        x ← (rand7() - 1) · 7 + rand7()          // uniform on 1..49
        if x ≤ 40: return (x - 1) mod 10 + 1   // 40 = four full copies of 1..10

♟️ Game Theory

Interview games are between two players who take turns, see everything, and play perfectly; there is no luck. Every position is then either winning (the player to move can force a win) or losing. The two rules that decide it:

  • A position is winning if some move leads to a losing position (for the opponent).
  • A position is losing if every move leads to a winning position — including having no moves at all.
📐 Pseudocode · Label Every Position 
function firstPlayerWins(n):                 // positions 0..n, moves shrink the position
    win ← array of n + 1 false                   // win[0] = false: no move possible
    for pos from 1 to n:
        for each legal move m from pos:
            if not win[pos - m]:                 // hand the opponent a losing spot
                win[pos] ← true;  break
    return win[n]
// Nim Game (take 1–3): win[pos] is false exactly when pos is a multiple of 4.
💡
Print the table, spot the pattern. Many easy game problems have a one-line answer (n % 4 ≠ 0, “n is even”). Fill the win array for n = 1 to 20 on paper; the pattern is usually obvious, and the DP proves it.

Nim and Grundy numbers

In Nim, there are several piles, and a move takes any number of stones from one pile. The player to move loses exactly when the XOR of all pile sizes is 0. (From XOR 0, every move changes one pile and makes the XOR non-zero; from non-zero, there is always a move back to 0.)

The Sprague–Grundy theorem extends this to any game that splits into independent parts. Give each position a Grundy number: the smallest non-negative number not among the Grundy numbers of the positions you can move to (the mex). A position with Grundy number 0 is losing; for several independent games, XOR their Grundy numbers exactly like Nim piles.

📐 Pseudocode · Grundy Numbers by mex 
function grundy(n):
    g ← array of n + 1
    for pos from 0 to n:
        reachable ← { g[pos - m] for each legal move m from pos }
        v ← 0
        while v in reachable: v ← v + 1           // mex: smallest missing value
        g[pos] ← v
    return g
// Several independent games: the player to move wins iff g[a] XOR g[b] XOR ... ≠ 0.

Score games: best difference

When the question is by how much a player wins, store the best score difference “(mine − theirs) for the player to move”. Because the opponent then faces the same question from their side, one function covers both players: best(state) = max over moves of (gain − best(next state)). Lecture 35 used exactly this for Stone Game and Predict the Winner. And when every item is taken by someone, look for a greedy rule first: in Stone Game VI, taking an item is worth your value plus the value you deny the other player.

⚠️ Complexity & Classic Bugs

Technique Time
Matrix power, k × k matrix O(k³ log n)
Factorials + inverse factorials up to N O(N) once, then O(1) per nCr
Inclusion–exclusion over m sets O(2ᵐ)
Reservoir sampling O(n) time, O(1) space
Win / lose or Grundy table up to n, with up to m moves each O(n · m)
Bug Symptom Fix
Multiplying two ints near 10⁹ before taking mod Overflow, wrong answers Use long for every product
Dividing under a modulus Nonsense results Multiply by the modular inverse instead
Subtracting under a modulus Negative answers Write (a - b + MOD) % MOD
Using a · b instead of lcm(a, b) Inclusion–exclusion over-subtracts lcm(a, b) = a / gcd(a, b) · b
Matrix built transposed Correct for Fibonacci, wrong for other tables Row = new state, column = old state; test n = 2 by hand
Forgetting that “no moves” is losing Game DP wrong from the base case Set the terminal positions first
Comparing doubles with == Probability checks fail by 10⁻¹⁶ Compare with a tolerance
🔍
How to spot it. “Modulo 10⁹ + 7”, a limit like n ≤ 10⁹, “how many ways”, “probability”, “expected”, “uniformly at random”, “both players play optimally”.

Problem 01 · Matrix Exponentiation
Count Vowels Permutation
🔗 LC 1220 - Count Vowels Permutation
Hard 5 × 5 transition matrix Amazon · Google
›
Problem

Count strings of length n made of the vowels a, e, i, o, u where a is only followed by e; e by a or i; i by anything except i; o by i or u; and u by a. Return the count modulo 10⁹ + 7.

n = 1 → 5, n = 2 → 10, n = 5 → 68
Hints
▶Hint 1 — a nudge

What is the only thing you need to know about a string so far to decide how it can be extended?

▶Hint 2 — the key idea

Its last vowel. Keep five counts, one per last vowel. One extra letter maps the five counts to five new counts by a fixed rule — a 5 × 5 matrix.

Solution

Let count[v] be the number of valid strings ending in vowel v. Adding a letter gives new[j] = the sum of count[i] over every vowel i that may be followed by j. With n ≤ 2 × 10⁴ a loop of n − 1 such steps already passes. The lecture version writes the rule as a matrix T with T[j][i] = 1 when i may be followed by j, so the counts after n − 1 steps are Tn−1 times the starting vector of all ones. Matrix fast power makes that O(5³ log n) — fast even if n were 10¹⁸. Checking by hand: for n = 2 the allowed pairs are ae, ea, ei, ia, ie, io, iu, oi, ou, ua — 10.

▶Full solution
📐 Pseudocode · Transition Matrix to the Power n − 1 
function countVowelPermutation(n):
    // index 0..4 = a, e, i, o, u;  follows[v] = vowels allowed after v
    follows ← { a: [e],  e: [a, i],  i: [a, e, o, u],  o: [i, u],  u: [a] }
    T ← 5 × 5 zeros
    for each vowel i, for each j in follows[i]:
        T[j][i] ← 1                              // row = new last vowel, column = old
    P ← power(T, n - 1)                          // matrix fast power, mod 10⁹ + 7
    return (sum of every entry of P) mod (10⁹ + 7)   // P times a vector of all ones
TimeO(5³ log n)
SpaceO(1)
Problem 02 · nCr Modulo a Prime
Number of Ways to Reach a Position After Exactly k Steps
🔗 LC 2400 - Number of Ways to Reach a Position After Exactly k Steps
Medium Choose which steps go right Google · Amazon
›
Problem

Starting at startPos on an infinite number line, take exactly k steps, each one to the left or right. Count the different step sequences that end at endPos, modulo 10⁹ + 7.

startPos = 1, endPos = 2, k = 3 → 3 (RRL, RLR, LRR) startPos = 2, endPos = 5, k = 10 → 0
Hints
▶Hint 1 — a nudge

Does the order of the steps change where you finish? What does, then?

▶Hint 2 — the key idea

Only how many steps go towards the target. If r do, then r − (k − r) = distance, so r = (k + distance) / 2. Choosing which r of the k steps they are: C(k, r).

Solution

A DP over (position, steps left) works, but counting is shorter. The finish depends only on how many steps go towards endPos. With distance d = |endPos − startPos|, the r steps towards and k − r away must satisfy r − (k − r) = d. If d > k, or k − d is odd, no whole-number r exists and the answer is 0. Otherwise any choice of which r steps go towards the target works, and there are C(k, r) such choices — computed with factorials and inverse factorials.

▶Full solution
📐 Pseudocode · C(k, r) With Inverse Factorials 
function numberOfWays(startPos, endPos, k):
    d ← |endPos - startPos|
    if d > k or (k - d) is odd: return 0
    r ← (k + d) / 2                              // steps towards the target
    precompute(k)                                // fact and invFact up to k
    return nCr(k, r)
TimeO(k)
SpaceO(k)
Problem 03 · Inclusion–Exclusion
Ugly Number III
🔗 LC 1201 - Ugly Number III
Medium Count ≤ x, then binary search x Amazon · Google
›
Problem

An ugly number here is a positive integer divisible by a, b or c. Return the n-th ugly number. n, a, b and c are up to 10⁹; the answer is guaranteed to be at most 2 × 10⁹.

n = 3, a = 2, b = 3, c = 5 → 4 (2, 3, 4, 5, 6, ...) n = 4, a = 2, b = 3, c = 4 → 6 (2, 3, 4, 6, 8, ...)
Hints
▶Hint 1 — a nudge

Listing the numbers one by one is far too slow. Could you instead count how many ugly numbers are ≤ some x?

▶Hint 2 — the key idea

Inclusion–exclusion over the three divisors gives that count in O(1). The count only grows with x, so binary search for the smallest x whose count reaches n.

Solution

Two tools combine. Inclusion–exclusion counts the numbers up to x divisible by a, b or c: add x/a, x/b and x/c, subtract the three pairs using their lcm, and add back the triple. That count never decreases as x grows, which is exactly the condition for “binary search on the answer” from Lecture 13: the n-th ugly number is the smallest x whose count is at least n. Use long for the lcms — the product of two numbers near 10⁹ overflows an int.

▶Full solution
📐 Pseudocode · Count, Then Search 
function nthUglyNumber(n, a, b, c):
    ab ← lcm(a, b);  bc ← lcm(b, c);  ac ← lcm(a, c);  abc ← lcm(ab, c)   // long
    function count(x):
        return x/a + x/b + x/c - x/ab - x/bc - x/ac + x/abc
    lo ← 1;  hi ← 2 · 10⁹
    while lo < hi:
        mid ← lo + (hi - lo) / 2
        if count(mid) ≥ n: hi ← mid                // mid might be the answer
        else:              lo ← mid + 1
    return lo
TimeO(log(2 · 10⁹))
SpaceO(1)
Problem 04 · Probability DP
New 21 Game
🔗 LC 837 - New 21 Game
Medium Average over a sliding window Google · Amazon
›
Problem

Alice starts with 0 points and keeps drawing while she has fewer than k. Each draw adds a whole number from 1 to maxPts, all equally likely. Return the probability that she finishes with at most n points.

n = 10, k = 1, maxPts = 10 → 1.00000 n = 6, k = 1, maxPts = 10 → 0.60000 n = 21, k = 17, maxPts = 10 → 0.73278
Hints
▶Hint 1 — a nudge

Let dp[i] be the probability of ever holding exactly i points. Which earlier scores can jump to i in one draw?

▶Hint 2 — the key idea

The previous maxPts scores — but only those still drawing (below k). dp[i] is their sum divided by maxPts. Keep the sum as a sliding window instead of re-adding it.

Solution

This is the lecture’s probability DP. Score i is reached from score j with a single draw of i − j, which happens with probability 1/maxPts, and only if j < k (at k or above she has stopped). So dp[i] = (sum of dp[j] for j in [i − maxPts, i − 1] with j < k) / maxPts. Summing that range each time costs O(n · maxPts); a running window sum, adding dp[i] while i < k and dropping dp[i − maxPts], makes it O(n). The answer adds dp[i] for the final scores k ≤ i ≤ n. The shortcut at the top handles k = 0 and the case where she cannot possibly exceed n.

▶Full solution
📐 Pseudocode · dp With a Running Window Sum 
function new21Game(n, k, maxPts):
    if k = 0 or n ≥ k - 1 + maxPts: return 1.0      // she can never go over n
    dp ← array of n + 1 zeros;  dp[0] ← 1.0
    window ← 1.0;  answer ← 0.0                 // window = dp sum of the last maxPts drawing scores
    for i from 1 to n:
        dp[i] ← window / maxPts
        if i < k: window ← window + dp[i]       // still drawing: feeds later scores
        else:     answer ← answer + dp[i]       // stopped here, and i ≤ n
        if i - maxPts ≥ 0 and i - maxPts < k:
            window ← window - dp[i - maxPts]     // too far back to reach i + 1
    return answer
TimeO(n)
SpaceO(n)
Problem 05 · Win / Lose Positions
Stone Game IV
🔗 LC 1510 - Stone Game IV
Hard Label positions 0..n Amazon · Google
›
Problem

There are n stones. Alice and Bob take turns, Alice first; a move removes any non-zero square number of stones (1, 4, 9, …). The player who cannot move loses. Return true if Alice wins with perfect play.

n = 1 → true (take 1) n = 2 → false (take 1, Bob takes the last) n = 4 → true (take all 4)
Hints
▶Hint 1 — a nudge

Who wins with 0 stones left, from the point of view of the player whose turn it is? Build up from there.

▶Hint 2 — the key idea

win[i] is true if some square j² ≤ i leaves a losing position: win[i − j²] is false.

Solution

This is the lecture’s win/lose labelling with “remove a square” as the move. Position 0 is losing — the player to move has no move. For each i from 1 to n, try every square j² ≤ i; if one of them hands the opponent a losing position, i is winning, and you can stop trying. There are about √i squares to try for each i, so the table costs O(n √n) — about 3 × 10⁷ steps for n = 10⁵. Unlike Nim, there is no neat formula here: the DP is the solution.

▶Full solution
📐 Pseudocode · Winning If Some Move Hands Over a Loss 
function winnerSquareGame(n):
    win ← array of n + 1 false                   // win[0] = false
    for i from 1 to n:
        j ← 1
        while j · j ≤ i:
            if not win[i - j · j]:
                win[i] ← true;  break
            j ← j + 1
    return win[n]
TimeO(n √n)
SpaceO(n)
