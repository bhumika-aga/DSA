Sorting Algorithms

"Sorting is the physics of search. Master the trade-offs between stability, memory, and raw speed."

📚 Lecture 12 of 45 Phase 2 — Core Data Structures ⏱ 4 days 🎯 25 problems 💼 Google · Amazon · Directi
🌍
Why does this topic matter?
Sorting is the physics of search. Once data is sorted, binary search, two-pointer, and sliding-window techniques become unlocked. Almost every data-processing pipeline in the real world begins with a sort. Interviewers test sorting to see if you understand trade-offs: stability vs. speed, memory vs. in-place, worst-case guarantees vs. average-case performance. Knowing when to use Merge Sort vs. Quick Sort vs. Counting Sort is the difference between an O(N log N) solution and a TLE.
By the end of this lecture you can
  • Implement all major sorting algorithms from scratch
  • Know stability, in-place, and worst-case trade-offs for each sort
  • Apply sort as preprocessing to unlock faster algorithms
  • Understand counting/radix sort for O(n) on bounded-range inputs
🧠
The picture to keep in your head: Sorting a hand of cards. Most people already know insertion sort: pick up cards one at a time and slide each into place among the ones you hold. Merge sort is splitting the deck with a friend, each of you sorting half, then merging by repeatedly taking the smaller of the two top cards. The slow methods compare cards again and again; the fast ones never compare the same pair twice.

📖 Before We Start — The Big Picture

Sorting is the problem of rearranging N items so they are in a defined order (ascending, descending, or by some key). There are fundamentally two families of sorting algorithms:

  • Comparison-based sorts: These compare pairs of elements to decide their relative order. The theoretical minimum time for any comparison-based sort is O(N log N) — this is a mathematical proof, not just an observation. Algorithms in this family: Bubble, Selection, Insertion, Merge, Quick, Heap Sort.
  • Non-comparison sorts: These exploit additional knowledge about the data (e.g., all values are integers in a known range). They can beat O(N log N). Examples: Counting Sort, Radix Sort, Bucket Sort.

A sort is called stable if equal elements maintain their original relative order. This matters when sorting objects by multiple keys (e.g., sort employees by salary, then by name — you first sort by name stably, then sort by salary stably).

🔗
How it connects: Lecture 8 (Recursion) is the backbone of Merge Sort and Quick Sort — both use divide and conquer recursion. Lecture 13 (Searching) requires sorted input to work — Binary Search only works on sorted arrays. Many DSA problems say "sort first, then..." — this lecture teaches you why and how.

🌐 Sorting Overview

Every sorting algorithm falls into one of three groups, and the group tells you the speed. Two of them work by comparing pairs of elements; the third refuses to compare at all, which is how it beats them.

  • O(n²) — compare everything with everything: Bubble, Selection and Insertion Sort. Each one walks the list again for every element, so doubling the input makes them four times slower. Useful only for tiny lists, or for data that is already almost sorted.
  • O(n log n) — split, sort, merge: Merge Sort and Quick Sort. They halve the problem instead of rescanning it. This is as fast as comparison sorting can possibly get, and it is what every language’s built-in sort uses.
  • O(n log n) — sort with a heap: Heap Sort. Same speed as the group above, but it sorts inside the original array instead of allocating a second one, and it uses no recursion.
  • O(n) — don’t compare, count: Counting Sort and Radix Sort. Instead of asking “is a bigger than b?” they use each value as an index into a tally. That only works when the values are small whole numbers in a known range — ages 0–120, say, but not arbitrary decimals.
💡
What “stable” means: when two items tie, a stable sort leaves them in the order they were already in. That matters when you sort twice — sort employees by name first, then by salary, and a stable sort keeps each salary group in alphabetical order. An unstable sort would scramble it.

🔬 Algorithms Deep Dive

O(N²) Baseline Sorts

Bubble Sort: Propagates maximum values to the end iteratively via pair swaps. Often optimised to break early if no swaps occur.

📐 Pseudocode · Bubble Sort (Optimised) 
function bubbleSort(a):
    for i from 0 to length(a) - 1:
        swapped ← false

        for j from 1 to length(a) - i - 1:
            if a[j] < a[j-1]:
                swap(a, j, j-1)
                swapped ← true

        if not swapped: break        // nothing moved — it is already sorted

Selection Sort: Locates absolute current minimum and injects it upfront. Always performs exact O(n) swaps.

📐 Pseudocode · Selection Sort 
function selectionSort(a):
    for i from 0 to length(a) - 2:
        minIdx ← i

        for j from i+1 to length(a) - 1:
            if a[j] < a[minIdx]: minIdx ← j

        swap(a, i, minIdx)           // exactly one swap per pass, always

Insertion Sort: Builds the output string progressively. Highly adaptive and routinely utilized inside complex frameworks (like Timsort) natively for handling n < 64 sub-chunks due to strict O(n) speed on nearly sorted vectors.

📐 Pseudocode · Insertion Sort 
function insertionSort(a):
    for i from 1 to length(a) - 1:
        key ← a[i]
        j ← i - 1

        while j ≥ 0 and a[j] > key:  // shift everything bigger one slot right
            a[j+1] ← a[j]
            j ← j - 1

        a[j+1] ← key                 // drop key into the hole that opened up

Merge Sort (Divide & Conquer)

Splits cleanly down to base elements and merges components together recursively upward guaranteeing stable sorted arrays natively in O(n log n) constraints.

Caveat - The O(n) Space Limit: The merge phase strictly enforces allocating external memory to preserve stability cleanly. It is the gold standard for Native Objects and Linked Lists precisely due to this stability factor.

📐 Pseudocode · Merge Sort 
function mergeSort(a, lo, hi):
    if lo ≥ hi: return            // 0 or 1 element is already sorted
    mid ← lo + (hi - lo) ÷ 2
    mergeSort(a, lo, mid)
    mergeSort(a, mid + 1, hi)
    merge(a, lo, mid, hi)

function merge(a, lo, mid, hi):
    left  ← copy of a[lo .. mid]
    right ← copy of a[mid+1 .. hi]
    i ← 0; j ← 0; k ← lo

    while i < size(left) and j < size(right):
        if left[i] ≤ right[j]:    // '<=' keeps it STABLE
            a[k] ← left[i];  i ← i + 1
        else:
            a[k] ← right[j]; j ← j + 1
        k ← k + 1

    copy any remainder of left, then of right, into a[k..]

Quick Sort

An in-place paradigm separating the domain physically into domains left recursively smaller than a central Pivot and physically greater.

The O(n²) Adversary Hazard: Standard Quick Sort choosing the exact highest element dynamically breaks out if data is aggressively inverse-sorted natively. We enforce randomized pivoting immediately to sustain average O(n log n) bounds strictly!

📐 Pseudocode · Quick Sort & Partition 
function quickSort(a, lo, hi):
    if lo ≥ hi: return
    p ← partition(a, lo, hi)
    quickSort(a, lo, p - 1)
    quickSort(a, p + 1, hi)

function partition(a, lo, hi):     // Lomuto scheme
    swap(a, random(lo, hi), hi)     // randomise: kills the O(n^2) worst case
    pivot ← a[hi]
    i ← lo                         // a[lo..i-1] are < pivot

    for j from lo to hi - 1:
        if a[j] < pivot:
            swap(a, i, j)
            i ← i + 1

    swap(a, i, hi)                  // pivot lands at its final index
    return i

Non-Comparison Sorts & Heap

Algorithms mapping domains directly to index spaces or structural constraints.

Counting Sort: Hashes bounding integers optimally, heavily consuming memory dynamically proportional to the highest integer natively.

📐 Pseudocode · Counting Sort Baseline 
function countingSort(a):
    max ← maximum value in a
    count ← array of 0, size max + 1

    for v in a: count[v] ← count[v] + 1

    j ← 0
    for v from 0 to max:
        while count[v] > 0:
            a[j] ← v
            j ← j + 1
            count[v] ← count[v] - 1

// Only viable when the value range is small — space is O(max).

Radix Sort: Cascades Counting Sort digit by digit safely preventing space exhaustion reaching O(d · (n + k)) outputs perfectly.

📐 Pseudocode · Radix Sort Cascade 
function radixSort(a):
    if a is empty: return
    max ← maximum value in a

    exp ← 1                          // digit place: 1, 10, 100 ...
    while max ÷ exp > 0:
        countingSortByDigit(a, exp)  // MUST be stable, or earlier digits are undone
        exp ← exp × 10

Heap Sort: Forces elements into a Max/Min Binary Heap. Reaches strictly O(n log n) time natively with an optimal O(1) embedded space boundary dynamically but lacks the sequential mapping speeds Merge Sort has.

📐 Pseudocode · In-Place Heap Sort 
function heapSort(a):
    n ← length(a)

    for i from n÷2 - 1 down to 0:    // build a max-heap, O(n)
        heapify(a, n, i)

    for i from n-1 down to 1:        // swap the max to the back, then repair
        swap(a, 0, i)
        heapify(a, i, 0)             // heap shrinks by one each round

🔄 Algorithm Variations

Cyclic Sort

Given parameters constraining elements rigidly inside 1 to n, you assign targets manually by calculating targetIdx = nums[i] - 1 strictly bypassing comparison logic for direct index containment bounded strictly to O(n).

📐 Pseudocode · Cyclic Sorting Logic 
// Values are 1..n, so value v belongs at index v-1.
i ← 0
while i < length(a):
    correct ← a[i] - 1

    if 1 ≤ a[i] ≤ length(a) and a[i] ≠ a[correct]:
        swap(a, i, correct)          // do NOT advance — the new a[i] may also be wrong
    else:
        i ← i + 1

Dutch National Flag (3-Way Partitioning)

When domains heavily replicate properties (e.g. 0s, 1s, and 2s purely). Using 3 pivot limits natively organizes elements centrally without mapping auxiliary constraints natively dynamically sorting in a single O(n) pass structurally.

📐 Pseudocode · 3-Way Partition Bounds 
// low = end of the 0s, high = start of the 2s, mid = the scanner
low ← 0;  mid ← 0;  high ← length(a) - 1

while mid ≤ high:
    if a[mid] = 0:
        swap(a, low, mid);  low ← low + 1;  mid ← mid + 1
    else if a[mid] = 1:
        mid ← mid + 1
    else:
        swap(a, mid, high);  high ← high - 1   // mid does NOT advance here

QuickSelect

A Quick Sort recursion tree cut fundamentally in half. Instead of sorting both pivot sides, you analyse if the exact Kth pivot sits bounded dynamically processing strictly in amortised O(n) time finding structural Medians optimally natively!

📐 Pseudocode · QuickSelect (Kth Largest) 
// The k-th largest sits at index length(a) - k once partitioned.
function quickSelect(a, lo, hi, target):
    p ← partition(a, lo, hi)

    if p = target: return a[p]
    if p < target: return quickSelect(a, p+1, hi, target)
    else:          return quickSelect(a, lo, p-1, target)

// Recursing into ONE side only is what makes this O(n) on average.

⏱️ Complexity Analysis

Algorithm Time (Best) Time (Avg / Worst) Space Constraints Stability
Insertion Sort O(n) O(n²) O(1) Stable
Merge Sort O(n log n) O(n log n) O(n) Stable
Quick Sort O(n log n) O(n²) O(log n) Unstable
Heap Sort O(n log n) O(n log n) O(1) Unstable
Counting Sort O(n + k) O(n + k) O(k) Max Stable

🗺️ 2D Sorting Constraints

Interviewers reliably ask candidates to organize unstructured 2D domains dynamically mapping arrays (e.g. Time Intervals).

📐 Pseudocode · Interval Lambda Filtering 
// Sort by start time, breaking ties with the earlier end time.
sort(intervals) by comparator (x, y):
    if x.start ≠ y.start: return compare(x.start, y.start)
    else:                 return compare(x.end,   y.end)

// Two keys, in priority order — the second only decides when the first ties.

⚠️ Classic Bugs

The complexity section above covers the costs. These are the mistakes that most often break code that looks correct — check your solution against every row before calling it done.

Bug Symptom Fix
Comparator written as a - b Wrong order for large or negative values Integer.compare(a, b)
Assuming ties keep their order A second sort scrambles the first Use a stable sort, or sort on all keys at once
Quick sort with the first element as pivot O(n²) and a stack overflow on sorted input Pick a random pivot
Merge sort allocating new arrays in every call Slow, and heavy on memory Allocate one temporary array and reuse it
Counting sort with negative values Index out of bounds Offset every value by the minimum
Sorting everything to find the k-th element O(n log n) where O(n) was possible Quickselect, or a heap of size k
Forgetting that sorting changes the input The caller's array is reordered Copy it first if the original order matters

💪 In-Lecture Practice Problems

Problem 01 · In-Place Merge
Merge Sorted Array
🔗 LC 88 - Merge Sorted Array
Easy Amazon · Microsoft · Meta
›
Problem

Merge two sorted arrays in-place into the larger array. You must start merging from the back to avoid overwriting elements.

Hints
▶Hint 1 — a nudge

Filling from the front means shifting elements. Which end is free?

▶Hint 2 — the key idea

Merge backwards from index m+n-1. The tail of nums1 is empty space, so nothing ever gets overwritten before it is read.

Solution
▶Full solution
📐 Pseudocode · Backward Merge 
function merge(a, m, b, n):
    p1 ← m - 1                       // last real element of a
    p2 ← n - 1                       // last element of b
    write ← m + n - 1                // last slot of a

    while p2 ≥ 0:
        if p1 ≥ 0 and a[p1] > b[p2]:
            a[write] ← a[p1];  p1 ← p1 - 1
        else:
            a[write] ← b[p2];  p2 ← p2 - 1
        write ← write - 1

// Filling from the back means nothing is overwritten before it is read.
TimeO(m+n)
SpaceO(1)
Problem 02 · Three-Way Partition
Sort Colors (Dutch National Flag)
🔗 LC 75 - Sort Colors
Medium Microsoft · Amazon · Meta
›
Problem

Sort an array of 0s, 1s, and 2s in-place in O(n) time and O(1) space using three pointers tracking bounds.

Hints
▶Hint 1 — a nudge

Counting sort works in two passes. One pass needs three regions instead of two.

▶Hint 2 — the key idea

Dutch National Flag: pointers low, mid, high. 0 → swap with low and advance both; 1 → advance mid; 2 → swap with high and do not advance mid.

Solution
▶Full solution
📐 Pseudocode · Dutch National Flag 
function sortColors(a):
    low ← 0;  mid ← 0;  high ← length(a) - 1

    while mid ≤ high:
        if a[mid] = 0:
            swap(a, low, mid);  low ← low + 1;  mid ← mid + 1
        else if a[mid] = 1:
            mid ← mid + 1
        else:
            swap(a, mid, high);  high ← high - 1   // the swapped-in value is unseen
TimeO(N)
SpaceO(1)
Problem 03 · Cyclic Sort Secret
First Missing Positive
🔗 LC 41 - First Missing Positive
Hard Google · Amazon · Meta · Microsoft Cyclic Sort
›
Problem

Find the smallest positive integer missing from an unsorted array using O(n) time and strict O(1) space constraints.

Hints
▶Hint 1 — a nudge

The answer must lie in 1..n+1. That is a strong constraint.

▶Hint 2 — the key idea

Cyclic sort: put each value v in index v-1 by swapping. Then the first index where nums[i] != i+1 gives the answer.

Solution

Treat the array as a hash set where a value k maps optimally to index k-1. Swap elements into their correct positions greedily, then execute a final linear scan to find the first position mismatch.

▶Full solution
📐 Pseudocode · Cyclic Sort 
function firstMissingPositive(a):
    n ← length(a)

    i ← 0
    while i < n:
        correct ← a[i] - 1
        if 1 ≤ a[i] ≤ n and a[i] ≠ a[correct]:
            swap(a, i, correct)
        else:
            i ← i + 1

    for i from 0 to n - 1:
        if a[i] ≠ i + 1: return i + 1    // first slot holding the wrong value

    return n + 1                          // 1..n all present
TimeO(N)
SpaceO(1)
Problem 04 · QuickSelect
Find the Kth Largest Integer in the Array
🔗 LC 1985 - Find the Kth Largest Integer in the Array
Medium Partition Around a Pivot Amazon · Google · Meta
›
Problem

Given an array of numeric strings (up to 100 digits each) and an integer k, return the k-th largest of them. Duplicates count separately.

nums = ["3","6","7","10"], k = 4 → "3"  |  nums = ["2","21","12","1"], k = 3 → "2"
Hints
▶Hint 1 — a nudge

You cannot parse these into a 64-bit integer. How do you compare two numeric strings without converting them?

▶Hint 2 — the key idea

Longer string wins; same length compares lexicographically. With that comparator, QuickSelect partitions around a random pivot and recurses into one side only.

Solution

Sorting everything is O(n log n), but you only need one position. QuickSelect partitions around a pivot and then throws away the side that cannot contain the k-th element, giving O(n) on average (O(n²) worst case, tamed by picking the pivot at random). A size-k min-heap is the O(n log k) alternative when the data streams in.

▶Full solution
📐 Pseudocode · QuickSelect 
function compare(a, b):                     // numeric strings
    if length(a) ≠ length(b): return length(a) - length(b)
    return lexicographic compare of a and b

function kthLargestNumber(nums, k):
    target ← length(nums) - k               // k-th largest = this index when sorted
    lo ← 0;  hi ← length(nums) - 1
    while lo < hi:
        p ← partition(nums, lo, hi)         // random pivot, Lomuto or Hoare
        if p = target: return nums[p]
        if p < target: lo ← p + 1           // answer is to the right
        else: hi ← p - 1
    return nums[lo]

// Average O(n): each pass halves the range, n + n/2 + n/4 + ... = 2n
TimeO(n) average
SpaceO(1)
Problem 05 · Radical Performance
Maximum Gap
🔗 LC 164 - Maximum Gap
Medium Apple · Amazon · Google Radix / Bucket Sort
›
Problem

Given an unsorted array, find the maximum difference between successive elements in sorted form. You must solve it in linear time and space O(n) without deploying comparison bounds.

Hints
▶Hint 1 — a nudge

The requirement of linear time rules out comparison sorting entirely.

▶Hint 2 — the key idea

Pigeonhole: with n numbers spread over the range, some bucket of width (max-min)/(n-1) must be empty. The maximum gap spans a gap between buckets, so only bucket min/max matter.

Solution
▶Full solution
📐 Pseudocode · Pigeonhole Bucket Sort 
function maximumGap(a):
    if length(a) < 2: return 0

    min ← minimum of a
    max ← maximum of a
    gap ← max(1, (max - min) ÷ (length(a) - 1))

    // Pigeonhole: with n numbers spread across that range, at least one bucket
    // of width `gap` must be empty — so the largest gap spans BETWEEN buckets,
    // never inside one. Only each bucket's own min and max can matter.
    return maxGapAcrossBuckets(a, gap, min, max)
Problem 06 · Counting / Bucket Sort
H-Index
🔗 LC 274 - H-Index
Medium Bucket by Value Google · Amazon · Meta
›
Problem

Given citations, return the h-index: the largest h such that at least h papers have h or more citations.

citations = [3, 0, 6, 1, 5] → 3
Hints
▶Hint 1 — a nudge

Sorting makes it easy — but citations above n can never raise the answer above n.

▶Hint 2 — the key idea

Bucket the papers by citation count, clamping anything above n into the last bucket. Then walk from the highest bucket down, accumulating papers until the running total reaches the bucket index.

Solution

This is counting sort in disguise. Values are unbounded, but the answer is capped at n, so n + 1 buckets are enough. Sweeping from the top keeps a running count of papers with at least that many citations, and the first index where the count catches up is the h-index — O(n) instead of O(n log n).

▶Full solution
📐 Pseudocode · Buckets, Then Sweep Down 
function hIndex(citations):
    n ← length(citations)
    buckets ← array of n + 1 zeros
    for c in citations:
        buckets[min(c, n)] ← buckets[min(c, n)] + 1   // clamp: h can never exceed n

    papers ← 0
    for h from n down to 0:
        papers ← papers + buckets[h]        // papers with at least h citations
        if papers ≥ h: return h
    return 0

// [3,0,6,1,5], n = 5 -> buckets: 0:1, 1:1, 3:1, 5:2
// h=5: 2 papers (2 < 5). h=4: 2. h=3: 3 >= 3 -> answer 3
TimeO(n)
SpaceO(n)
Problem 07 · Sort + Interleave
Wiggle Sort II
🔗 LC 324 - Wiggle Sort II
Medium Virtual Indexing Google · Amazon · Meta
›
Problem

Reorder nums so that nums[0] < nums[1] > nums[2] < nums[3] ..., strictly alternating. Duplicates make this harder than it looks.

nums = [1, 5, 1, 1, 6, 4] → [1, 6, 1, 5, 1, 4]
Hints
▶Hint 1 — a nudge

Sort first. Which half should go into the even positions, and which into the odd ones?

▶Hint 2 — the key idea

Fill the even positions from the end of the smaller half and the odd positions from the end of the larger half. Taking them from the back keeps equal values apart.

Solution

Sorting and then placing the small half at even indices and the large half at odd indices almost works — but equal values land next to each other. Reading each half backwards pushes duplicates as far apart as possible, which fixes it. That is O(n log n); the O(n) version finds the median by QuickSelect and does a three-way partition with virtual indexing.

▶Full solution
📐 Pseudocode · Sort Then Interleave 
function wiggleSort(nums):
    sorted ← sort(copy of nums)
    n ← length(nums)
    mid ← (n + 1) ÷ 2                    // size of the smaller half

    j ← mid - 1                          // last of the small half
    for i from 0 to n - 1 step 2:        // even positions = valleys
        nums[i] ← sorted[j];  j ← j - 1

    j ← n - 1                            // last of the large half
    for i from 1 to n - 1 step 2:        // odd positions = peaks
        nums[i] ← sorted[j];  j ← j - 1

// [1,1,1,4,5,6]: valleys take 1,1,1 (from index 2 down)
// peaks take 6,5,4 -> [1,6,1,5,1,4]
TimeO(n log n)
SpaceO(n)
Problem 08 · Sort + Min-Heap
Divide Intervals Into Minimum Number of Groups
🔗 LC 2406 - Divide Intervals Into Minimum Number of Groups
Medium Interval Overlap Google · Amazon · Microsoft
›
Problem

Given intervals, split them into the fewest groups such that no two intervals in the same group overlap. Return the number of groups.

intervals = [[5,10],[6,8],[1,5],[2,3],[1,10]] → 3
Hints
▶Hint 1 — a nudge

Sort by start time. When a new interval begins, which existing group could possibly take it?

▶Hint 2 — the key idea

Keep a min-heap of the groups' end times. If the smallest end is before the new start, reuse that group (pop it); otherwise open a new group. Push the new end either way.

Solution

This is “meeting rooms” with a new name: the answer is the maximum number of intervals overlapping at any instant. The heap holds one end time per open group, so its size is the number of groups. Only the earliest-finishing group can ever be reused, which is exactly what peek gives you in O(1).

▶Full solution
📐 Pseudocode · Heap of End Times 
function minGroups(intervals):
    sort intervals by start ascending
    heap ← empty min-heap of end times

    for (start, end) in intervals:
        if heap is not empty and heap.peek() < start:
            heap.popMin()                 // that group is free again — reuse it
        heap.push(end)                    // this interval joins a group
    return heap.size                      // groups still open = groups needed

// A sweep line works too: +1 at each start, -1 just after each end,
// and the answer is the highest running total.
TimeO(n log n)
SpaceO(n)
