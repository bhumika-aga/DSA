String Algorithms — KMP, Z, Rabin-Karp & Manacher

“Never re-read what you already know.”

📚 Lecture 39 of 45 Phase 5 — Advanced Structures ⏱ 5 days 🎯 20 problems 💼 Google · Amazon · Meta · Microsoft
🌍
Why does this topic matter?
Finding a pattern inside a text sounds like a solved problem — every language has a search function. But the obvious method re-reads the same characters over and over, and on unlucky inputs it is quadratic. The four algorithms here are linear, and each stores a different kind of memory about the text: KMP remembers how the pattern overlaps itself, a rolling hash turns windows into numbers, the Z-array records where the start reappears, and Manacher reuses the mirror image inside a palindrome. Hard string questions are almost always one of these in disguise.
By the end of this lecture you can
  • Build the KMP failure table and use it to search in O(n + m)
  • Roll a hash across a string and handle collisions safely
  • Build the Z-array and use it for matching and prefix questions
  • Find palindromes in O(n) with Manacher, and know when O(n²) is enough
  • Choose between the four from the wording of a problem
🧠
The picture to keep in your head: never re-read what you already know. Imagine hunting for the phrase “abcabd” in a long text. You have matched “abcab” and the next letter is wrong. The slow way is to go back and start again one letter later. But you already know the last two letters you read were “ab” — which is exactly how the phrase begins. So you carry on as if you had matched “ab”, without re-reading anything. Every algorithm in this lecture is a different way of remembering what you have already seen.

🐢 Why the Obvious Method Is Slow

To find a pattern of length m in a text of length n, the obvious method tries every starting position and compares character by character. That is correct, and usually fine — but on text like aaaa…ab searching for aaab, each attempt gets almost to the end before failing, and the next attempt re-reads nearly all the same characters. Worst case: O(n × m). The algorithms below all reach O(n + m) by refusing to re-read.

🧩 KMP — The Failure Table

KMP (Knuth–Morris–Pratt) first studies the pattern alone. For every prefix of the pattern it records one number: the length of the longest proper prefix that is also a suffix — the part that “starts the way it ends”. This is called the failure table (or LPS, for longest prefix-suffix). When a mismatch happens, the table says how much of the match you can keep.

i 0 1 2 3 4 5 6
p[i] a b a b a c a
lps[i] 0 0 1 2 3 0 1

Read lps[4] = 3 as: “ababa ends with aba, which is also how it starts.” If the text matched ababa and then failed, you continue as if aba were already matched.

📐 Pseudocode · Build the Failure Table 
function buildLps(p):
    lps ← array of zeros, length(p)
    len ← 0                                  // length of the current prefix-suffix
    for i from 1 to length(p) - 1:
        while len > 0 and p[i] ≠ p[len]:
            len ← lps[len - 1]               // fall back to a shorter one
        if p[i] = p[len]:
            len ← len + 1
        lps[i] ← len
    return lps
📐 Pseudocode · Search With It 
function kmpSearch(text, p):
    lps ← buildLps(p)
    j ← 0                                    // characters of p matched so far
    for i from 0 to length(text) - 1:
        while j > 0 and text[i] ≠ p[j]:
            j ← lps[j - 1]                   // keep what still matches; never move i back
        if text[i] = p[j]: j ← j + 1
        if j = length(p):
            record a match starting at i - j + 1
            j ← lps[j - 1]                   // allow overlapping matches
// i only ever moves forward, and j can only fall back as far as it has
// climbed, so the total work is O(n + m).
💡
The table answers questions on its own. Many problems never search a text at all. “Is this string made of a repeated block?” and “what is the longest prefix that is also a suffix?” are read straight off lps for the last position.

🔑 Rabin-Karp — Fingerprints

You met the rolling hash as a preview in Lecture 11; this is the full treatment. Turn each window of m characters into a number — a fingerprint — by treating it as an m-digit number in some base B. Sliding one step right removes the leftmost digit and adds a new one, in O(1). Numbers get huge, so everything is taken modulo a large prime M.

📐 Pseudocode · Rabin-Karp With a Modulus 
function rabinKarp(text, p):
    n ← length(text);  m ← length(p)
    B ← 31;  M ← 1000000007
    power ← B^(m - 1) mod M                  // weight of the leftmost character
    hp ← hash of p;  ht ← hash of text[0..m-1]
    for i from 0 to n - m:
        if ht = hp and text[i..i+m-1] = p:   // equal hashes are only a hint: verify
            record a match at i
        if i + m < n:                        // roll the window one step right
            ht ← (ht - text[i] × power) mod M
            ht ← (ht × B + text[i + m]) mod M
            if ht < 0: ht ← ht + M
// hash of s = (s[0]·B^(m-1) + s[1]·B^(m-2) + … + s[m-1]) mod M
⚠️
Two different strings can share a fingerprint. That is called a collision. Either check the characters whenever the hashes match (as above), or use two different moduli and require both to agree. The real strength of rolling hashes is not single searches — KMP does those better — but comparing many substrings, such as “the longest substring that appears twice”.

🎬 The Z-Algorithm

The Z-array stores, for every position i, how many characters starting at i match the start of the string. It is another way of recording “where does the beginning reappear?”.

i 0 1 2 3 4 5 6
s[i] a a b x a a b
Z[i] — 1 0 0 3 1 0
📐 Pseudocode · Build the Z-Array in O(n) 
function zArray(s):
    n ← length(s);  Z ← array of zeros, length n
    l ← 0;  r ← 0                           // s[l..r-1] is the rightmost copy of a prefix
    for i from 1 to n - 1:
        if i < r:
            Z[i] ← min(r - i, Z[i - l])     // the box already proves this much
        while i + Z[i] < n and s[Z[i]] = s[i + Z[i]]:
            Z[i] ← Z[i] + 1                 // extend past what was proven
        if i + Z[i] > r:
            l ← i;  r ← i + Z[i]
    return Z
// To find p in text: build Z for  p + "$" + text  (with "$" in neither).
// Every position whose Z value equals length(p) is a match.

🮮 Palindromes and Manacher’s Algorithm

The simple way to find the longest palindrome is to try every centre and expand outwards while both sides match — O(n²), easy to write, and often good enough (it is covered in Lecture 33). Manacher’s algorithm reaches O(n) with the same “do not re-read” idea: inside a palindrome, the left half mirrors the right half, so a centre on the right can copy what its mirror image on the left already found.

📐 Pseudocode · Manacher’s Algorithm 
function longestPalindrome(s):
    t ← "#" + s with "#" between every character + "#"     // "aba" → "#a#b#a#"
    P ← array of zeros, length(t)        // P[i] = radius of the palindrome centred at i
    center ← 0;  right ← 0               // the palindrome reaching furthest right so far
    for i from 0 to length(t) - 1:
        if i < right:
            P[i] ← min(right - i, P[2 × center - i])      // copy from the mirror
        while i - P[i] - 1 ≥ 0 and i + P[i] + 1 < length(t)
              and t[i - P[i] - 1] = t[i + P[i] + 1]:
            P[i] ← P[i] + 1                               // expand beyond the copy
        if i + P[i] > right:
            center ← i;  right ← i + P[i]
    best ← the index with the largest P
    start ← (best - P[best]) ÷ 2
    return s from start, length P[best]
// The "#" separators make even- and odd-length palindromes look the same.

🧭 Which One When

The question Use Why
Find one pattern in one text KMP Guaranteed O(n + m), no hashing risk
Is the string one block repeated? Longest prefix that is also a suffix? KMP failure table Read the answer off the last entry
Compare many substrings against each other Rolling hash Each comparison is O(1)
Longest repeated substring Binary search on length + rolling hash A length that works means every shorter one does
How much of the start matches at every position Z-array Exactly what it stores
Longest palindrome, n ≤ 1000 Expand around centre O(n²) and hard to get wrong
Longest palindrome, n ≈ 10⁵ Manacher O(n)

⚠️ Complexity & Classic Bugs

Algorithm Time Space
Naive matching O(n · m) O(1)
KMP O(n + m) O(m)
Rabin-Karp O(n + m) expected O(1)
Z-algorithm O(n + m) O(n + m)

Manacher O(n) O(n)
Bug Symptom Fix
Letting lps[i] include the whole prefix Every value is its own index; the search loops forever The prefix-suffix must be proper: start i at 1
Moving the text pointer backwards in KMP Correct but back to O(n · m) Only j falls back; i never moves left
Trusting equal hashes Rare wrong answers you cannot reproduce Verify the characters, or use two moduli
Negative values after subtracting under a modulus Hashes never match Add M back when the result is negative
Overflow in hash × B Silently wrong hashes Use 64-bit arithmetic before taking the modulus
Using a separator that appears in the text False Z-array matches Pick a character outside the alphabet
Mixing up positions in t and in s for Manacher Off-by-one substring start = (best − P[best]) ÷ 2, length P[best]
🔍
How to spot it. “Find this pattern”, “repeated”, “prefix that is also a suffix”, “longest duplicate substring”, “shortest palindrome by adding characters” — and a string length of 10⁵, which rules out anything O(n²).

💪 In-Lecture Practice Problems

Five problems, one per algorithm: KMP to search, KMP’s table on its own, a rolling hash chosen to run the right way, the Z-array, and Manacher.

Problem 01 · KMP End to End
Find the Index of the First Occurrence in a String
🔗 LC 28 - Find the Index of the First Occurrence in a String
Easy KMP Google · Amazon · Microsoft
›
Problem

Return the index of the first occurrence of needle in haystack, or −1.

haystack = "sadbutsad", needle = "sad" → 0
Hints
▶Hint 1 — a nudge

The built-in search is fine here — but what does it cost on haystack "aaaa…ab" and needle "aaab"?

▶Hint 2 — the key idea

O(n · m), because every failed attempt re-reads almost the same characters. Build the failure table for the needle and never move backwards in the haystack.

Solution

An Easy label, but it is the cleanest place to write KMP once, completely. Build lps for the needle, then scan the haystack with a single forward pointer; on a mismatch only the needle pointer falls back, to lps[j − 1]. The first time j reaches the needle’s length, the match started at i − j + 1. Saying out loud why the naive method is O(n · m) is half of what the interviewer wants from this question.

▶Full solution
📐 Pseudocode · Failure Table, Then One Forward Pass 
function strStr(haystack, needle):
    m ← length(needle)
    lps ← array of zeros, length m;  len ← 0
    for i from 1 to m - 1:                         // build the failure table
        while len > 0 and needle[i] ≠ needle[len]: len ← lps[len - 1]
        if needle[i] = needle[len]: len ← len + 1
        lps[i] ← len
    j ← 0
    for i from 0 to length(haystack) - 1:          // search
        while j > 0 and haystack[i] ≠ needle[j]: j ← lps[j - 1]
        if haystack[i] = needle[j]: j ← j + 1
        if j = m: return i - m + 1
    return -1
TimeO(n + m)
SpaceO(m)
Problem 02 · The Table on Its Own
Longest Happy Prefix
🔗 LC 1392 - Longest Happy Prefix
Hard KMP failure table Google · Amazon
›
Problem

A happy prefix is a non-empty prefix that is also a suffix, excluding the whole string. Return the longest one, or an empty string.

s = "level" → "l"   |   s = "ababab" → "abab"
Hints
▶Hint 1 — a nudge

Checking every length from longest to shortest is O(n²) character comparisons. Which structure from this lecture stores exactly "longest proper prefix that is also a suffix"?

▶Hint 2 — the key idea

The KMP failure table. Its last entry, lps[n − 1], is the answer’s length.

Solution

A Hard label for a problem that is one line once you know the failure table: the definition of lps[n − 1] is the question. The lesson is that KMP’s table is useful by itself, with no text to search — for longest borders, for detecting repeated blocks, and for building shortest palindromes. A rolling hash comparing every prefix with its matching suffix also works in O(n), but it can collide, and the table cannot.

▶Full solution
📐 Pseudocode · Read the Last Entry 
function longestPrefix(s):
    n ← length(s)
    lps ← array of zeros, length n;  len ← 0
    for i from 1 to n - 1:
        while len > 0 and s[i] ≠ s[len]: len ← lps[len - 1]
        if s[i] = s[len]: len ← len + 1
        lps[i] ← len
    return s from 0, length lps[n - 1]
TimeO(n)
SpaceO(n)
Problem 03 · Roll the Other Way
Find Substring With Given Hash Value
🔗 LC 2156 - Find Substring With Given Hash Value
Hard Rolling hash, right to left Google · Amazon
›
Problem

The hash of a length-k string is (val(s[0])·p⁰ + val(s[1])·p¹ + … + val(s[k−1])·p^(k−1)) mod m, with val('a') = 1. Return the first length-k substring whose hash equals hashValue.

s = "leetcode", power = 7, modulo = 20, k = 2, hashValue = 0 → "ee"
Hints
▶Hint 1 — a nudge

Rolling left to right means the leftmost character (weight p⁰) leaves and every other weight drops by one power. How do you lower every power by one under a modulus?

▶Hint 2 — the key idea

You would have to divide by p — and m is not guaranteed prime, so the modular inverse may not exist. Roll from the right instead: the entering character gets p⁰ and everything else is multiplied by p.

Solution

This is the rolling hash with its direction chosen deliberately. The hash weights increase to the right, so a window moving leftwards updates by multiplying: h ← h × p + val(new), then subtract the character that fell off the right end, now carrying weight pᵏ. No division, so it works for any modulus. Walking right to left also means the last match you see is the leftmost one, which is the one the problem asks for.

▶Full solution
📐 Pseudocode · Multiply, Add, Subtract the Leaver 
function subStrHash(s, p, m, k, hashValue):
    n ← length(s)
    pk ← p^k mod m                                  // weight of the character leaving on the right
    h ← 0;  best ← 0
    for i from n - 1 down to 0:
        h ← (h × p + val(s[i])) mod m               // s[i] enters with weight p⁰
        if i + k < n:
            h ← (h - val(s[i + k]) × pk mod m + m) mod m      // s[i+k] leaves with weight pᵏ
        if i + k ≤ n and h = hashValue:
            best ← i                                // later iterations are further left
    return s from best, length k
TimeO(n)
SpaceO(1)
Problem 04 · The Z-Array Is the Answer
Sum of Scores of Built Strings
🔗 LC 2223 - Sum of Scores of Built Strings
Hard Z-algorithm Google · Amazon
›
Problem

A string is built by prepending characters, so the intermediate strings are the suffixes of the final string s. Each suffix scores the length of its longest common prefix with s. Return the total score.

s = "babab" → 9   (scores 1, 0, 3, 0, 5)
Hints
▶Hint 1 — a nudge

Write down what "longest common prefix of the suffix starting at i with the whole string" means. Have you seen an array that stores exactly that?

▶Hint 2 — the key idea

It is Z[i]. The full string scores n, so the answer is n plus the sum of the Z-array.

Solution

Once the question is restated — “for every suffix, how far does it match the start of the string?” — it is the definition of the Z-array, and the O(n) construction from this lecture solves it directly. Computing each common prefix separately would be O(n²) on a string like “aaaa…”. Restating a problem in terms of a known array is a skill worth practising: many Hard string problems are one well-chosen array plus a loop.

▶Full solution
📐 Pseudocode · n + Sum of Z 
function sumScores(s):
    n ← length(s);  Z ← array of zeros, length n
    l ← 0;  r ← 0
    for i from 1 to n - 1:
        if i < r: Z[i] ← min(r - i, Z[i - l])
        while i + Z[i] < n and s[Z[i]] = s[i + Z[i]]: Z[i] ← Z[i] + 1
        if i + Z[i] > r: l ← i;  r ← i + Z[i]
    total ← n                                       // the whole string matches itself
    for i from 1 to n - 1: total ← total + Z[i]
    return total
TimeO(n)
SpaceO(n)
Problem 05 · Manacher at Work
Maximum Product of the Length of Two Palindromic Substrings
🔗 LC 1960 - Maximum Product of the Length of Two Palindromic Substrings
Hard Manacher + best-before / best-after Google · Amazon
›
Problem

Choose two non-overlapping palindromic substrings of odd length, the first ending before the second starts. Maximise the product of their lengths.

s = "ababbb" → 9   ("aba" and "bbb")
Hints
▶Hint 1 — a nudge

If you knew, for every position i, the longest odd palindrome ending at or before i and the longest starting at or after i + 1, how would you finish?

▶Hint 2 — the key idea

Multiply those two and take the maximum over every split point. Manacher gives every centre’s radius in O(n); two sweeps turn radii into the before/after arrays.

Solution

Two ideas stacked. Manacher (odd lengths only, so no # separators are needed) gives, for each centre, its longest palindrome. A palindrome ending at position e of length L also contains one ending at e − 1 of length L − 2 — strip a character from each side — so one right-to-left sweep spreads each value inward, and a prefix maximum turns “ending exactly at” into “ending at or before”. The mirror image gives the “starting at or after” array, and the answer is one final loop over split points.

▶Full solution
📐 Pseudocode · Radii, Then Two Sweeps, Then One Split 
function maxProduct(s):
    n ← length(s);  d ← array of zeros, length n     // odd palindrome at i has length 2·d[i] − 1
    c ← 0;  r ← -1                                    // rightmost palindrome: centre c, right edge r
    for i from 0 to n - 1:
        k ← 1 if i > r else min(d[2 × c - i], r - i + 1)      // copy from the mirror
        while i - k ≥ 0 and i + k < n and s[i - k] = s[i + k]: k ← k + 1
        d[i] ← k
        if i + k - 1 > r: c ← i;  r ← i + k - 1

    endAt ← zeros;  startAt ← zeros                   // longest odd palindrome ending / starting at i
    for i from 0 to n - 1:
        endAt[i + d[i] - 1] ← max(endAt[i + d[i] - 1], 2 × d[i] - 1)
        startAt[i - d[i] + 1] ← max(startAt[i - d[i] + 1], 2 × d[i] - 1)
    for i from n - 2 down to 0: endAt[i] ← max(endAt[i], endAt[i + 1] - 2)      // strip both ends
    for i from 1 to n - 1: startAt[i] ← max(startAt[i], startAt[i - 1] - 2)
    for i from 1 to n - 1: endAt[i] ← max(endAt[i], endAt[i - 1])               // ending at or before i
    for i from n - 2 down to 0: startAt[i] ← max(startAt[i], startAt[i + 1])    // starting at or after i

    best ← 0
    for i from 0 to n - 2: best ← max(best, endAt[i] × startAt[i + 1])
    return best
TimeO(n)
SpaceO(n)
