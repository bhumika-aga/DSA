Mathematics for DSA

"Mathematics is the language of the universe — and interviewers have written their hard problems in it."

🌍
Why does this topic matter?
Math is the hidden engine inside the most elegant algorithm solutions. Problems that look like they need O(N) brute-force often have O(log N) math-based shortcuts. Can you check if a number is prime in 17 steps instead of 1 million? Can you compute 21000 without overflow? Can you find GCD without a loop of a million iterations? The answer to all three is yes — and those answers appear directly in FAANG interviews at Google, Amazon, Microsoft, and Apple. You don't need a math degree. You need 6 patterns.
By the end of this lecture you can
  • Master GCD, LCM, prime factorization, and sieve algorithms
  • Apply modular arithmetic for large number problems
  • Use fast exponentiation to replace brute-force powers
  • Know where combinatorics fits: nCr, Pascal’s triangle and Catalan numbers are previewed here and taught in full in Lecture 42
🧠
The picture to keep in your head: A clock face. Modular arithmetic is clock arithmetic: 10 o’clock plus 5 hours is 3 o’clock, because everything wraps round at 12. Programs wrap round at a large prime like 1,000,000,007 instead, for the same reason — to keep numbers small enough to store. And the greatest common divisor is the largest square tile that exactly covers a rectangle with no cutting.

📖 Before We Start — The Big Picture

Mathematics gives algorithms their efficiency. Consider finding if a number N is prime. The naïve approach checks all divisors from 2 to N — that's O(N) steps. The mathematical observation that "factors come in pairs, and one is always ≤ √N" reduces it to O(√N). For N = 1,000,000 that's the difference between 1,000,000 checks and 1,000 checks.

Modular arithmetic is clock arithmetic — on a 12-hour clock, 11 + 3 = 2, not 14. This is how computers handle numbers larger than the maximum int value: instead of overflowing, we keep taking the remainder. The pattern "output mod 109+7" appears in almost every combinatorics or large-number problem on LeetCode.

🔵 Prime Numbers

A number n is prime if it is > 1 and divisible only by 1 and itself. Every integer > 1 is either prime or a unique product of primes (Fundamental Theorem of Arithmetic).

Trial Division — O(√n)

🔑
Key Insight: If n has a factor > √n, it must also have one < √n (factors come in pairs). So only check divisors up to √n.
📐 Pseudocode · isPrime O(√n) 
function isPrime(n):
    if n < 2: return false
    if n = 2: return true
    if n is even: return false
    i ← 3
    while i × i ≤ n:                  // a factor above √n pairs with one below it
        if n mod i = 0: return false
        i ← i + 2                     // only odd divisors
    return true
// isPrime(25): i=3 (9 ≤ 25, 25 mod 3 = 1), i=5 (25 ≤ 25, 25 mod 5 = 0) → false ✓
TimeO(√n)
SpaceO(1)

Sieve of Eratosthenes — O(n log log n)

Find all primes up to N. Mark each prime's multiples as composite. Start marking at i² (smaller multiples already marked by earlier primes).

📐 Pseudocode · Sieve of Eratosthenes 
// Every prime crosses out its own multiples. Start at p*p —
// smaller multiples were already crossed out by smaller primes.
isPrime ← array of true, length n + 1
isPrime[0] ← isPrime[1] ← false

for p from 2 while p × p ≤ n:
    if isPrime[p]:
        for m from p × p to n step p:
            isPrime[m] ← false

return every p with isPrime[p] = true
Sieve(10): step by step Start: 2 3 4 5 6 7 8 9 10 i=2: mark 4,6,8,10 → left: 2 3 5 7 9 i=3: mark 9 → left: 2 3 5 7 i=4: 4×4=16 > 10, stop. Primes ≤10: 2, 3, 5, 7 ✓
⚠
Memory: Sieve uses O(n) space. For n=107 that's ~10MB. Use a segmented sieve for n > 108.

⚙ GCD & LCM — Euclidean Algorithm

📐
Core Formula: gcd(a, b) = gcd(b, a % b)   Base case: gcd(a, 0) = a
LCM: lcm(a, b) = (a / gcd(a,b)) * b  ← divide first to prevent overflow
📐 Pseudocode · GCD & LCM 
function gcd(a, b):
    if b = 0: return a
    return gcd(b, a mod b)

function gcdIterative(a, b):          // same thing without recursion depth
    while b ≠ 0:
        t ← b
        b ← a mod b
        a ← t
    return a

function lcm(a, b):
    return (a ÷ gcd(a, b)) × b        // divide first to avoid overflow

// gcd(48, 18) → gcd(18, 12) → gcd(12, 6) → gcd(6, 0) = 6 ✓
// lcm(4, 6) = (4 ÷ 2) × 6 = 12 ✓
TimeO(log min(a,b))
SpaceO(1)

🔄 Modular Arithmetic

When results exceed long range (e.g. 21000), use modular arithmetic. Most FAANG problems that say "output mod 109+7" require this.

📐
Rules (mod m):
(a+b) % m = ((a%m)+(b%m)) % m
(a×b) % m = ((a%m)×(b%m)) % m
(a−b) % m = ((a%m)−(b%m)+m) % m  ← +m prevents negatives!
Division: use modular inverse (Fermat's little theorem when m is prime)

Binary Exponentiation (Fast Power) — O(log n)

xn = (xn/2)2 if n is even  |  x × xn-1 if n is odd. This halves the exponent each step.

📐 Pseudocode · Fast Power (Binary Exponentiation) 
// Square the base and halve the exponent: O(log e) multiplications.
result ← 1
base ← base mod m

while e > 0:
    if e is odd:
        result ← (result × base) mod m
    base ← (base × base) mod m
    e ← e ÷ 2                // integer division

return result

// Watch the overflow: base*base needs a 64-bit type when m is large.

// Dry run: fastPow(2, 10, 1000) — 10 = 1010 in binary
//   bit 0 = 0: skip           base → 4
//   bit 1 = 1: result = 4     base → 16
//   bit 2 = 0: skip           base → 256
//   bit 3 = 1: result = 4 × 256 = 1024 mod 1000 = 24 ✓
TimeO(log n)
SpaceO(1)

🧮 Prime Factorization — O(√n)

📐 Pseudocode · Prime Factorization 
function primeFactors(n):
    factors ← empty map                 // prime → exponent
    i ← 2
    while i × i ≤ n:
        while n mod i = 0:
            factors[i] ← factors[i] + 1 // default 0
            n ← n ÷ i
        i ← i + 1
    if n > 1: factors[n] ← 1            // whatever remains is itself prime
    return factors
// 360 = 2³ × 3² × 5 → {2: 3, 3: 2, 5: 1}
// Number of divisors = (3+1)(2+1)(1+1) = 24

🎲 Combinatorics — Counting Without Listing

📐
C(n,r) = n! / (r! × (n-r)!)   (n choose r)
Pascal's Rule: C(n,r) = C(n-1,r-1) + C(n-1,r)
Tip: C(n,r) = C(n,n-r)  ← always choose the smaller side to minimise computation
📐 Pseudocode · Pascal's Triangle 
function pascalTriangle(n):
    C ← (n+1) × (n+1) grid of 0
    for i from 0 to n:
        C[i][0] ← 1
        for j from 1 to i:
            C[i][j] ← C[i-1][j-1] + C[i-1][j]   // Pascal's rule
    return C
// C[4][2] = C(4, 2) = 6 ways to choose 2 from 4 ✓
Pascal's Triangle: Row 0: 1 Row 1: 1 1 Row 2: 1 2 1 Row 3: 1 3 3 1 Row 4: 1 4 6 4 1 ← C(4,2)=6 (paths in 4-step grid) Each number = sum of the two directly above (Pascal's Rule)

Problem 01 · Sieve
Count Primes
🔗 LC #204
Medium Google · Amazon · Microsoft Sieve
›
Problem

Count the number of prime numbers strictly less than n.

Input: n=10 → Output: 4   (primes: 2, 3, 5, 7) Input: n=0 → Output: 0 Input: n=1 → Output: 0
Hints
▶Hint 1 — a nudge

Testing each number for primality is O(n√n). Cross numbers out instead of testing them.

▶Hint 2 — the key idea

Sieve of Eratosthenes: for each prime p, mark multiples starting at p×p (smaller ones are already marked). O(n log log n).

Solution

A brute-force checks each number up to n with isPrime() — that's O(n√n). Can you do better?
Key insight: if p is prime, then 2p, 3p, 4p... are all composite. Mark them off in bulk (Sieve).
Why start inner loop at p²? Because all smaller multiples of p (e.g. 2p, 3p) were already marked by earlier primes.

▶Full solution
📐 Pseudocode · Sieve O(n log log n) 
function countPrimes(n):           // primes strictly below n
    if n ≤ 2: return 0
    composite ← array of false, size n
    composite[0] ← true;  composite[1] ← true

    i ← 2
    while i × i < n:
        if not composite[i]:
            for j from i × i to n - 1 step i:
                composite[j] ← true
        i ← i + 1

    count ← 0
    for i from 2 to n - 1:
        if not composite[i]: count ← count + 1
    return count
// n = 10: mark 4, 6, 8, 9 → primes left 2, 3, 5, 7 → 4 ✓
TimeO(n log log n)
SpaceO(n)
Problem 02 · GCD Pattern
GCD of Array
🔗 LC #1979
Easy Amazon · Google · Adobe GCD
›
Problem

Given an integer array nums, return the GCD of the smallest and largest element.

Input: [2,5,6,9,10] → Output: 2   (gcd(2,10)=2) Input: [7,5,6,8,3] → Output: 1   (gcd(3,8)=1) Input: [3,3] → Output: 3
Hints
▶Hint 1 — a nudge

GCD of a list is just GCD applied repeatedly.

▶Hint 2 — the key idea

gcd(a, b) = gcd(b, a % b), base case b == 0. Fold it across the array; you only need the min and max for the array variant.

Solution

You only need gcd(min, max) — not gcd of all elements.
Use the Euclidean algorithm: gcd(a, b) = gcd(b, a%b). Base case: gcd(a, 0) = a.

▶Full solution
📐 Pseudocode · GCD of Array 
function findGCD(nums):
    return gcd(minimum of nums, maximum of nums)

function gcd(a, b):
    if b = 0: return a
    return gcd(b, a mod b)
// [2, 5, 6, 9, 10]: min 2, max 10 → gcd(2, 10) → gcd(10, 2) → gcd(2, 0) = 2 ✓
TimeO(n + log max)
SpaceO(1)
Problem 03 · Fast Power
Pow(x, n)
🔗 LC #50
Medium Google · Amazon · Meta Binary Exp
›
Problem

Implement pow(x, n) — x raised to power n. n can be negative.

Input: x=2.0, n=10 → Output: 1024.0 Input: x=2.0, n=-2 → Output: 0.25 Input: x=2.1, n=3 → Output: 9.261
Hints
▶Hint 1 — a nudge

Multiplying n times is O(n). Halving the exponent is O(log n).

▶Hint 2 — the key idea

If n is even, xⁿ = (x²)^(n/2); if odd, peel one x off. Handle negative n by inverting, and watch Integer.MIN_VALUE.

Solution

Naive: multiply x by itself n times — O(n). Too slow for large n.
Key insight: x^n = (x²)^(n/2) if n is even. This halves the exponent each step.
Edge cases: negative n (flip x to 1/x), n = Integer.MIN_VALUE (use long to avoid overflow).

▶Full solution
📐 Pseudocode · Binary Exponentiation 
function myPow(x, n):
    N ← n                              // widen first: negating the smallest int overflows
    if N < 0:
        x ← 1 / x
        N ← -N
    result ← 1
    while N > 0:
        if N is odd: result ← result × x   // take one x
        x ← x × x                          // square the base
        N ← N ÷ 2                          // halve the exponent
    return result
// myPow(2, 10):
//   N=10 (even): x=4,    N=5
//   N=5  (odd):  res=4,  x=16,  N=2
//   N=2  (even): x=256,  N=1
//   N=1  (odd):  res=4 × 256 = 1024 ✓
TimeO(log n)
SpaceO(1)
Problem 04 · Digit Math
Happy Number
🔗 LC #202
Easy Amazon · Google · Uber Cycle Detection
›
Problem

Repeatedly replace n with the sum of squares of its digits. Is n "happy" (eventually reaches 1)?

Input: 19 → true (1²+9²=82 →68 →100 →1 ✓) Input: 2 → false (enters infinite cycle: 4→16→37→58→89→145→42→20→4...)
Hints
▶Hint 1 — a nudge

The sequence either reaches 1 or repeats forever. How do you detect 'forever'?

▶Hint 2 — the key idea

It is cycle detection. Use a HashSet of seen values, or Floyd's slow/fast pointers over the digit-square function for O(1) space.

Solution

How do you know when it's NOT happy? It cycles without reaching 1.
Two approaches: (1) Use a HashSet to detect if a number repeats.
(2) Use Floyd's cycle detection (fast + slow pointer) — same technique as Linked List cycle!

▶Full solution
📐 Pseudocode · HashSet approach 
function isHappy(n):
    seen ← empty set
    while n ≠ 1 and n not in seen:     // a repeat means we're in a loop
        add n to seen
        n ← sumOfSquares(n)
    return n = 1

function sumOfSquares(n):
    s ← 0
    while n > 0:
        d ← n mod 10
        s ← s + d × d
        n ← n ÷ 10
    return s
// isHappy(19): 82 → 68 → 100 → 1 → true ✓
TimeO(log n)
SpaceO(log n)
Problem 05 · Combinatorics
Unique Paths
🔗 LC #62
Medium Google · Amazon · Bloomberg Math / DP
›
Problem

Count unique paths from top-left to bottom-right of m×n grid. Only right or down moves allowed.

Input: m=3, n=7 → Output: 28 Input: m=3, n=2 → Output: 3 Input: m=1, n=1 → Output: 1
Hints
▶Hint 1 — a nudge

Every path is the same length — (m-1) downs and (n-1) rights, in some order.

▶Hint 2 — the key idea

The answer is C(m+n-2, m-1). Compute it multiplicatively to avoid overflow, or fill a DP grid where each cell sums the two above and left.

Solution

Total moves needed: (m-1) down + (n-1) right = m+n-2 total moves.
You just need to CHOOSE which (m-1) of those moves are "down" — the rest are "right".
Answer = C(m+n-2, m-1). This is O(min(m,n)) vs O(m×n) for DP.

▶Full solution
📐 Pseudocode · O(min(m,n)) Combinatorics 
// Every path is (m-1) downs and (n-1) rights in some order → C(m+n-2, m-1)
function uniquePaths(m, n):
    result ← 1
    r ← m - 1
    total ← m + n - 2
    for i from 0 to r - 1:
        result ← result × (total - i) ÷ (i + 1)   // build C(total, r) one factor at a time
    return result
// Multiply before dividing — each partial product is an exact binomial, so ÷ is exact.
// m=3, n=7: C(8, 2) = 8 × 7 ÷ 2 = 28 ✓
// m=3, n=2: C(3, 2) = 3 ✓
TimeO(min(m,n))
SpaceO(1)
Problem 06 · Pascal's Triangle
Pascal's Triangle Row (O(n) space)
🔗 LC #119
Easy Apple · Amazon · Microsoft Combinatorics
›
Problem

Return the rowIndex-th (0-indexed) row of Pascal's Triangle using only O(rowIndex) space.

Input: rowIndex=3 → [1, 3, 3, 1] Input: rowIndex=0 → [1] Input: rowIndex=1 → [1, 1]
Hints
▶Hint 1 — a nudge

Each entry comes from the one before it, via a simple ratio.

▶Hint 2 — the key idea

C(n, k) = C(n, k-1) × (n - k + 1) / k. Use a long accumulator; a single row needs only O(k) space.

Solution

Pascal's Rule: row[j] = row[j-1] + row[j] (from previous row).
Key trick for O(n) space: update right-to-left so you don't overwrite values you still need.
Why right-to-left? Because row[j] needs old row[j] and old row[j-1]. Updating left-to-right would corrupt row[j-1].

▶Full solution
📐 Pseudocode · Pascal's Triangle Row 
function getRow(n):
    row ← [1]
    for i from 1 to n:
        for j from i-1 down to 1:           // RIGHT TO LEFT, so row[j-1] is still old
            row[j] ← row[j-1] + row[j]
        row.append(1)
    return row
// n = 3: [1] → [1,1] → [1,2,1] → [1,3,3,1] ✓
TimeO(n²)
SpaceO(n)
Problem 07 · Base Conversion
Excel Sheet Column Title
🔗 LC #168
Easy Microsoft · Amazon · Google Math / Encoding
›
Problem

Convert column number to Excel title. A=1, Z=26, AA=27, AZ=52, ZY=701.

Input: 1 → "A" Input: 28 → "AB" Input: 701 → "ZY"
Hints
▶Hint 1 — a nudge

It is base-26 — but with a twist that breaks the usual modulo.

▶Hint 2 — the key idea

There is no zero digit: A is 1, not 0. Decrement n by 1 before each % 26 and / 26 step.

Solution

This is base-26 BUT with no zero digit (A=1, not A=0). That's the trick.
Before taking (n % 26) to get the current letter, you must subtract 1 from n to shift to 0-indexed.
Example: 26 should give "Z", not "Z" then "A". After n-- we get n%26=25='Z', n/26=0. Done.

▶Full solution
📐 Pseudocode · Excel Sheet Column Title 
function convertToTitle(n):
    title ← ""
    while n > 0:
        n ← n - 1                              // A is 1, not 0 — shift to 0-indexed
        title ← letter('A' + n mod 26) + title // prepend the current letter
        n ← n ÷ 26
    return title
// n = 28:  n=27, 27 mod 26 = 1 → 'B', n=1;  n=0, 0 → 'A'  → "AB" ✓
// n = 701: n=700, 700 mod 26 = 24 → 'Y', n=26;  n=25, 25 → 'Z' → "ZY" ✓
TimeO(log n)
SpaceO(log n)
Problem 08 · Prime Factorization
Ugly Number II — Smallest with only 2, 3, 5 as factors
🔗 LC #264
Medium Google · Amazon · Meta Three Pointers
›
Problem

An ugly number has only prime factors 2, 3, and 5. Find the n-th ugly number.

Ugly sequence: 1, 2, 3, 4, 5, 6, 8, 9, 10, 12, 15... Input: n=10 → Output: 12 Input: n=1 → Output: 1
Hints
▶Hint 1 — a nudge

Every ugly number is an earlier ugly number multiplied by 2, 3 or 5.

▶Hint 2 — the key idea

Keep three pointers into the answer list, one per factor. Take the smallest of the three candidates, then advance every pointer that produced it — that dedupes.

Solution

Every ugly number is generated by multiplying a previous ugly number by 2, 3 or 5.
Use 3 pointers (i2, i3, i5) tracking the "next" ugly number to multiply for each factor.
Always pick the minimum of ugly[i2]×2, ugly[i3]×3, ugly[i5]×5 as the next ugly number.

▶Full solution
📐 Pseudocode · Three Pointer DP 
function nthUglyNumber(n):
    ugly ← array of size n
    ugly[0] ← 1
    i2 ← 0;  i3 ← 0;  i5 ← 0
    for i from 1 to n - 1:
        next2 ← ugly[i2] × 2
        next3 ← ugly[i3] × 3
        next5 ← ugly[i5] × 5
        next ← min(next2, next3, next5)
        ugly[i] ← next
        // advance EVERY pointer that produced the minimum — this skips duplicates
        if next = next2: i2 ← i2 + 1
        if next = next3: i3 ← i3 + 1
        if next = next5: i5 ← i5 + 1
    return ugly[n-1]
// Sequence: 1, 2, 3, 4, 5, 6, 8, 9, 10, 12 → ugly[9] = 12 ✓
TimeO(n)
SpaceO(n)
