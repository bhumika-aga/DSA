Searching Algorithms

"From exhaustive scanning to logarithmic bounds. Searching is the art of eliminating the irrelevant."

📚 Lecture 10 of 38 Phase 2 — Core Data Structures ⏱ 5 days 🎯 28 problems 💼 Google · Uber · Facebook
🌍
Why does this topic matter?
Searching is how every large system finds things fast. Google indexes billions of pages and returns results in milliseconds because of binary search principles at every layer. Binary Search turns an O(N) problem into O(log N) — for N = 1 billion, that's the difference between 1 billion operations and just 30. Beyond simple element search, "Binary Search on Answer Space" is one of the most powerful interview tricks — it converts problems that look impossible into clean O(N log N) solutions.
By the end of this lecture you can
  • Understand the limits of O(N) Linear Search against O(log N) Binary Search scaling.
  • Implement Binary Search perfectly — get boundaries right every single time.
  • Recognize disguised binary search problems that aren't initially obvious.
  • Apply "binary search on answer space" for monotonic optimization scenarios.
  • Search in rotated arrays, 2D matrices, and infinite data streams.

📖 Before We Start — The Big Picture

Searching is the problem of finding a target element in a dataset. The strategy depends entirely on what you know about the data:

  • Unsorted data? You have no choice but Linear Search — O(N). No trick can help without first sorting.
  • Sorted data? Binary Search reduces the problem by half with every comparison — O(log N). This is the cornerstone of this lecture.
  • Sorted 2D matrix? You can flatten it to 1D or use Staircase search.
  • Answer-space search? You don't search for a value in an array — you binary search for the optimal answer to a minimization/maximization problem.

The key insight of Binary Search is the invariant: at every step, you maintain the guarantee that the target — if it exists — lies within [lo, hi]. By checking the midpoint, you eliminate half the remaining candidates. You only need 30 checks to find any element in a 1-billion element array.

🔗
How it connects: Lecture 9 (Sorting) is the prerequisite — Binary Search requires sorted data. Lecture 5 (Recursion) shows the elegant recursive formulation of Binary Search. Binary Search on answer space appears in later lectures on Graphs (finding minimum cost) and Dynamic Programming.

🚀 Exponential Search & Integer Square Root

Two variants that come up constantly and that plain binary search does not cover: searching a sequence whose length you don't know, and searching a range of answers rather than a range of indices.

Exponential (Galloping) Search

Double a bound until you overshoot the target, then binary search the last doubling window. Because the window is found in O(log i) steps where i is the target's index, this beats plain binary search when the answer sits near the front — and it is the only option for an unbounded or infinite stream.

📐 Pseudocode · Exponential Search 
// Use when the array has no known end (a stream), or when the
// target is expected near the front. Find a bound, then binary search it.
if arr[0] = target: return 0

bound ← 1
while bound < length(arr) and arr[bound] < target:
    bound ← bound × 2      // 1, 2, 4, 8, 16 …

// target now lies in (bound/2, min(bound, n-1)]
return binarySearch(arr, bound ÷ 2, min(bound, length(arr) - 1), target)
TimeO(log i) — i is the target index
SpaceO(1)

Integer Square Root

Math.sqrt is banned in this question for a reason: it is the cleanest small example of binary search on the answer space. The predicate “is mid×mid ≤ n?” is monotonic — true, true, true, then false forever — so you can binary search the boundary.

📐 Pseudocode · Integer Square Root 
// Largest integer r with r*r <= n. A binary search on the ANSWER,
// not on an array — the classic 'search space' shape.
if n < 2: return n
lo ← 1
hi ← n ÷ 2      // sqrt(n) never exceeds n/2 for n >= 4
ans ← 1

while lo ≤ hi:
    mid ← lo + (hi - lo) ÷ 2
    if mid × mid ≤ n:
        ans ← mid       // feasible — record it and reach higher
        lo  ← mid + 1
    else:
        hi ← mid - 1    // too big

return ans
TimeO(log n)
SpaceO(1)
⚠️
The overflow trap
mid * mid overflows a 32-bit int long before mid reaches √(231). Use long, or compare mid ≤ n / mid instead of multiplying at all.

🌐 Search Overview

The goal of searching algorithms is simply to locate a target element in a dataset. Optimization comes from leveraging the properties of the dataset:

  • Linear Search: The universal fallback. Scans one by one. Required when data is unsorted.
  • Binary Search: The divide-and-conquer king. Slices domains in half, but requires sorted data.
  • Ternary Search: Divides space into thirds. Specialized for finding peaks/valleys in unimodal functions.
  • Interpolation Search: Guesses the location based on values. Incredible speed, but requires uniformly distributed data.

🔬 Algorithms Deep Dive

Linear Search

While mathematically $O(N)$ is slow, it is paradoxically the fastest search for tiny arrays ($N < 100$) due to CPU contiguous memory caching avoiding pointer jumping overhead.

Caveat - The Recursion Trap: Writing Linear Search recursively occupies $O(N)$ Space due to the Call Stack. Always write Linear Search iteratively in Java!

📐 Pseudocode · Linear Search (Iterative vs Recursive) 
// Iterative: space O(1)
function linearSearch(nums, target):
    for i from 0 to length(nums) - 1:
        if nums[i] = target: return i
    return NOT_FOUND

// Recursive: space O(n) — one call-stack frame per element
function recursiveLinear(nums, target, index):
    if index ≥ length(nums): return NOT_FOUND
    if nums[index] = target: return index
    return recursiveLinear(nums, target, index + 1)

Binary Search

Systematically eliminates halves. Heavily vulnerable to infinite loops if boundaries (`low`, `high`) overlap incorrectly.

Caveat - The Overflow Bug: Calculating mid = (low + high) / 2 overflows the 32-bit integer limit if boundaries are massive. Always use: mid = low + (high - low) / 2.

📐 Pseudocode · Classic Binary Search 
function binarySearch(nums, target):
    lo ← 0;  hi ← length(nums) - 1
    while lo ≤ hi:                   // '≤' so a one-element range is still checked
        mid ← lo + (hi - lo) ÷ 2
        if nums[mid] = target: return mid
        if nums[mid] < target: lo ← mid + 1
        else:                  hi ← mid - 1
    return NOT_FOUND

Interpolation Search

Instead of blindly checking the middle, it estimates position: pos = lo + ((target - arr[lo]) * (hi - lo) / (arr[hi] - arr[lo])).

Good to Know: Outperforms Binary Search by reaching $O(\log(\log N))$, but only if data is linearly uniform (e.g., 10, 20, 30...). If clumped heavily, it crashes to $O(N)$.

📐 Pseudocode · Interpolation Search 
// Guess the position from the VALUE, like opening a dictionary near 'M' for "mango".
while lo ≤ hi and arr[lo] ≤ target ≤ arr[hi]:
    if arr[hi] = arr[lo]:                        // flat range — avoid dividing by zero
        if arr[lo] = target: return lo
        return NOT_FOUND

    // multiply BEFORE dividing: dividing first truncates to 0 and the probe collapses to lo
    pos ← lo + (target - arr[lo]) × (hi - lo) ÷ (arr[hi] - arr[lo])

    if arr[pos] = target: return pos
    if arr[pos] < target: lo ← pos + 1
    else:                 hi ← pos - 1
return NOT_FOUND
// O(log log n) on uniformly spread values; degrades to O(n) on skewed data.

Ternary Search

Calculates mid1 and mid2 to eliminate a third of the array per pass. It is mathematically slower than Binary Search (`2 * log_3(N) > log_2(N)`), so it is never used for exact targeting natively.

Primary Use Case: Finding the maximum/minimum point in a continuous Unimodal function (a curve that goes strictly up, then strictly down).

📐 Pseudocode · Ternary Search (Peak Finding) 
// Find the maximum of a function that rises then falls (unimodal)
while hi - lo > 2:
    mid1 ← lo + (hi - lo) ÷ 3
    mid2 ← hi - (hi - lo) ÷ 3
    if f(mid1) < f(mid2): lo ← mid1      // the peak is right of mid1
    else:                 hi ← mid2      // the peak is left of mid2
// then check the last ≤ 3 points directly

🔄 Algorithm Variations

Upper / Lower Bounds (Duplicates)

If finding the first occurrence of a duplicate, when `nums[mid] == target`, don't stop! Keep searching left: ans = mid; high = mid - 1; to capture the earliest index boundary.

📐 Pseudocode · First / Last Occurrence 
// Don't return on the first match — record it and keep shrinking
// towards the side you want.
lo ← 0; hi ← length(a) - 1; ans ← -1

while lo ≤ hi:
    mid ← lo + (hi - lo) ÷ 2
    if a[mid] = target:
        ans ← mid
        hi ← mid - 1        // FIRST occurrence: keep looking left
        // lo <- mid + 1     // LAST occurrence: keep looking right
    else if a[mid] < target: lo ← mid + 1
    else:                    hi ← mid - 1

return ans

Search in Rotated Sorted Array

If an array is shifted (`[4, 5, 6, 7, 0, 1, 2]`), you test which half is strictly monotonic. If `nums[lo] <= nums[mid]`, the left side is perfectly sorted, and you can evaluate containment safely.

📐 Pseudocode · Sorted Half Validation 
if nums[lo] ≤ nums[mid]:                     // left half is sorted
    if nums[lo] ≤ target < nums[mid]: hi ← mid - 1   // target is inside it
    else:                             lo ← mid + 1   // so it must be on the right
else:                                        // right half is sorted
    if nums[mid] < target ≤ nums[hi]: lo ← mid + 1   // target is inside it
    else:                             hi ← mid - 1   // so it must be on the left

Binary Search on Answer Space

Searching for an abstract minimum/maximum configuration instead of an array index.

  1. Domain: Establish `lo` = absolute min answer, `hi` = absolute max.
  2. isValid(mid): Write a secondary $O(N)$ function to test if `mid` properly satisfies all constraints.
  3. Optimize: If `isValid(mid)` is logically valid, try optimizing further by lowering requirements: `hi = mid`. Otherwise, `lo = mid + 1`.
📐 Pseudocode · Binary Search on the Answer 
// Use when you can't search the input, but you CAN ask
// 'is candidate answer x feasible?' — and that answer is
// monotonic: false, false, ..., false, true, true, ..., true.
lo ← smallest conceivable answer
hi ← largest conceivable answer
ans ← hi

while lo ≤ hi:
    mid ← lo + (hi - lo) ÷ 2
    if feasible(mid):
        ans ← mid            // works — try to do better
        hi  ← mid - 1
    else:
        lo ← mid + 1         // too tight — relax

return ans

// Koko eating bananas: feasible(speed) = hours needed <= H
// Ship packages in D days: feasible(cap)  = days needed <= D

// Equivalent form without `ans`: shrink the range until lo = hi.
// Here lo always points at the smallest answer not yet ruled out.
while lo < hi:
    mid ← lo + (hi - lo) ÷ 2
    if feasible(mid): hi ← mid         // mid works — keep it in range
    else:             lo ← mid + 1     // mid fails — discard it
return lo

🗺️ 2D Matrix Traversals

Perfectly Flattened Binary Search

If a matrix `M x C` is strictly sorted universally (the end of Row 1 is less than the start of Row 2), treat it like a 1D array of length `M * C`.

The Indexing Math:
Row Index = mid / C
Col Index = mid % C

📐 Pseudocode · 1D to 2D Mapping 
rows ← number of rows;  cols ← number of columns
lo ← 0;  hi ← rows × cols - 1          // treat the matrix as one sorted array
while lo ≤ hi:
    mid ← lo + (hi - lo) ÷ 2
    val ← matrix[mid ÷ cols][mid mod cols]
    if val = target: return true
    if val < target: lo ← mid + 1
    else:            hi ← mid - 1
return false

Staircase / Saddleback Search

If the array is only sorted horizontally per row and vertically per col (meaning Row 2 can start with a smaller number than the end of Row 1), you cannot flatten it. You start exclusively at the Top-Right coordinate, shrinking the domain leftwards or downwards in $O(M + N)$ combinations.

📐 Pseudocode · Top-Right Staircase 
row ← 0;  col ← last column index
while row < number of rows and col ≥ 0:
    if matrix[row][col] = target: return true
    if matrix[row][col] > target: col ← col - 1   // everything below is bigger → drop this column
    else:                         row ← row + 1   // everything left is smaller → drop this row
return false

💪 In-Lecture Practice Problems

Problem 01 · Rotated Shift
Search in Rotated Sorted Array
🔗 LC 33 - Rotated Sorted Array
Medium Google · Amazon · Meta · Microsoft
›
Problem

Search for a target in a rotated sorted array in $O(\log N)$ time.

Hints
▶Hint 1 — a nudge

It is not sorted — but at any split, one of the two halves always is.

▶Hint 2 — the key idea

Compare a[lo] with a[mid] to find the sorted half. Check whether the target lies inside that half's range; if it does, search there, otherwise the other side.

Solution
▶Full solution
📐 Pseudocode · Pivot Logic 
function search(nums, target):
    lo ← 0;  hi ← length(nums) - 1
    while lo ≤ hi:
        mid ← lo + (hi - lo) ÷ 2
        if nums[mid] = target: return mid

        if nums[lo] ≤ nums[mid]:                       // left half sorted
            if nums[lo] ≤ target < nums[mid]: hi ← mid - 1
            else:                             lo ← mid + 1
        else:                                          // right half sorted
            if nums[mid] < target ≤ nums[hi]: lo ← mid + 1
            else:                             hi ← mid - 1
    return NOT_FOUND
TimeO(log N)
SpaceO(1)
Problem 02 · Unsorted Array Bounds
Find Peak Element
🔗 LC 162 - Find Peak Element
Medium Uber · Google · Meta
›
Problem

Find a local maximum in an array where neighbors aren't equal. Implement strictly in $O(\log N)$ time.

Hints
▶Hint 1 — a nudge

You do not need the global maximum — any local peak counts. That makes it binary-searchable.

▶Hint 2 — the key idea

If a[mid] < a[mid+1] you are on an ascending slope, so a peak lies to the right; otherwise it lies at mid or to the left.

Solution
▶Full solution
📐 Pseudocode · Upward Slope 
function findPeakElement(nums):
    lo ← 0;  hi ← length(nums) - 1
    while lo < hi:
        mid ← lo + (hi - lo) ÷ 2
        if nums[mid] < nums[mid + 1]:
            lo ← mid + 1          // rising slope → a peak lies to the right
        else:
            hi ← mid              // falling slope → peak at mid or to the left
    return lo
TimeO(log N)
SpaceO(1)
Problem 03 · Dual Partition Arrays
Median of Two Sorted Arrays
🔗 LC 4 - Median of Two Arrays
Hard Apple · Google · Amazon · Adobe
›
Problem

Find the combined median in $O(\log(\min(M,N)))$ time. This relies heavily on precise array partitioning boundaries.

Hints
▶Hint 1 — a nudge

Merging is O(m+n). Log time means you must binary search the partition point, not the values.

▶Hint 2 — the key idea

Binary search the shorter array for how many of its elements go left. The partition is correct when maxLeftA ≤ minRightB and maxLeftB ≤ minRightA.

Solution
▶Full solution
📐 Pseudocode · Partition Search 
function findMedianSortedArrays(A, B):
    if length(A) > length(B): return findMedianSortedArrays(B, A)   // search the shorter one
    x ← length(A);  y ← length(B)
    lo ← 0;  hi ← x

    while lo ≤ hi:
        px ← (lo + hi) ÷ 2                  // how many of A go on the left
        py ← (x + y + 1) ÷ 2 - px           // the rest of the left half comes from B

        maxLeftA  ← A[px-1] if px > 0 else -INFINITY
        minRightA ← A[px]   if px < x else  INFINITY
        maxLeftB  ← B[py-1] if py > 0 else -INFINITY
        minRightB ← B[py]   if py < y else  INFINITY

        if maxLeftA ≤ minRightB and maxLeftB ≤ minRightA:     // correct split
            if (x + y) is even:
                return (max(maxLeftA, maxLeftB) + min(minRightA, minRightB)) / 2
            return max(maxLeftA, maxLeftB)
        else if maxLeftA > minRightB:
            hi ← px - 1                     // took too many from A
        else:
            lo ← px + 1                     // took too few from A
TimeO(log(min(M,N)))
SpaceO(1)
Problem 04 · Answer Space bounds
Koko Eating Bananas
🔗 LC 875 - Koko Eating Bananas
Medium Airbnb · Google · Amazon
›
Problem

Find the minimum eating speed K such that Koko can eat all the bananas within H hours.

Hints
▶Hint 1 — a nudge

You cannot search the array — but you can search the possible speeds.

▶Hint 2 — the key idea

Speeds run 1..max(piles), and 'finishes in time' is monotonic. Binary search the smallest feasible speed.

Solution
▶Full solution
📐 Pseudocode · Monotonic Search 
function minEatingSpeed(piles, h):
    lo ← 1;  hi ← maximum of piles          // eating faster than the biggest pile never helps
    while lo < hi:
        mid ← lo + (hi - lo) ÷ 2
        if canFinish(piles, h, mid): hi ← mid
        else:                        lo ← mid + 1
    return lo

function canFinish(piles, h, k):
    hours ← 0
    for pile in piles:
        hours ← hours + ceil(pile / k)      // = (pile + k - 1) ÷ k in integer arithmetic
    return hours ≤ h
TimeO(N log(MaxP))
SpaceO(1)
Problem 05 · Grid Flattening
Search a 2D Matrix
🔗 LC 74 - Search a 2D Matrix
Medium Amazon · Microsoft · Meta
›
Problem

Write an efficient algorithm that searches for a value inside an `M x N` matrix uniformly sorted perfectly across rows.

Hints
▶Hint 1 — a nudge

Every row starts after the previous row ends. What does that make the matrix?

▶Hint 2 — the key idea

One sorted array of length m×n. Binary search 0..m×n-1 and map mid to (mid / cols, mid % cols).

Solution
▶Full solution
📐 Pseudocode · Midpoint Mapping 
function searchMatrix(matrix, target):
    m ← number of rows;  n ← number of columns
    lo ← 0;  hi ← m × n - 1
    while lo ≤ hi:
        mid ← lo + (hi - lo) ÷ 2
        r ← mid ÷ n;  c ← mid mod n
        if matrix[r][c] = target: return true
        if matrix[r][c] < target: lo ← mid + 1
        else:                     hi ← mid - 1
    return false
TimeO(log(M * N))
SpaceO(1)
Problem 06 · Find Pivot
Minimum in Rotated Sorted Array
🔗 LC 153
Medium Microsoft · Amazon · Google Binary Search
›
Problem

Given a sorted array rotated at some unknown pivot, find the minimum element in O(log N) time.

Original: [1, 2, 3, 4, 5] Rotated: [3, 4, 5, 1, 2] ← pivot at index 3 Minimum = 1
Hints
▶Hint 1 — a nudge

The minimum is the single place where the order breaks.

▶Hint 2 — the key idea

Compare a[mid] with a[hi], not a[lo]. If a[mid] > a[hi] the pivot is to the right, so lo = mid + 1; otherwise hi = mid.

Solution

The minimum is at the rotation point. At each step, compare nums[mid] with nums[hi]. If nums[mid] > nums[hi], the minimum is to the RIGHT of mid (the right half is the "smaller" section). If nums[mid] ≤ nums[hi], the minimum is at mid or to the LEFT.

▶Full solution
📐 Pseudocode · Binary Search on Rotation Pivot 
function findMin(nums):
    lo ← 0;  hi ← length(nums) - 1
    while lo < hi:
        mid ← lo + (hi - lo) ÷ 2
        if nums[mid] > nums[hi]: lo ← mid + 1    // the drop is to the right
        else:                    hi ← mid        // min is at mid or to the left
    return nums[lo]
// [3,4,5,1,2]: lo=0 hi=4 mid=2, 5 > 2 → lo=3
//              lo=3 hi=4 mid=3, 1 ≤ 2 → hi=3
//              lo = hi = 3 → return 1 ✓
TimeO(log N)
SpaceO(1)
Problem 07 · Lower/Upper Bound
Find First and Last Position of Element
🔗 LC 34
Medium Meta · Amazon · Google · LinkedIn Binary Search Bounds
›
Problem

Given a sorted array with possible duplicates and target, return [firstIndex, lastIndex] of the target, or [-1, -1] if not found. Must run in O(log N).

nums=[5,7,7,8,8,10], target=8 First occurrence: index 3 Last occurrence: index 4 Output: [3, 4]
Hints
▶Hint 1 — a nudge

One binary search finds a match. You need the boundaries of the block.

▶Hint 2 — the key idea

Run it twice: once biased left (on a match set hi = mid - 1) and once biased right (set lo = mid + 1), recording the index each time.

Solution

Run binary search twice: once to find the leftmost (lower bound) — when nums[mid]==target, record mid and continue left (hi=mid-1). Once for the rightmost (upper bound) — when nums[mid]==target, record mid and continue right (lo=mid+1).

▶Full solution
📐 Pseudocode · Two Binary Searches (Lower + Upper Bound) 
function searchRange(nums, target):
    return (bound(nums, target, findFirst = true), bound(nums, target, findFirst = false))

function bound(nums, target, findFirst):
    lo ← 0;  hi ← length(nums) - 1;  ans ← -1
    while lo ≤ hi:
        mid ← lo + (hi - lo) ÷ 2
        if nums[mid] = target:
            ans ← mid
            if findFirst: hi ← mid - 1       // keep looking left
            else:         lo ← mid + 1       // keep looking right
        else if nums[mid] < target: lo ← mid + 1
        else:                       hi ← mid - 1
    return ans
TimeO(log N)
SpaceO(1)
