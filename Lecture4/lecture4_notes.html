📖 Before We Start — The Big Picture

Think of a computer program as a recipe. Variables are your ingredients, data types are the containers (you can't store a liquid in a bag or a powder in a bottle), control flow is the list of steps, and methods are reusable sub-recipes. The computer follows these instructions one at a time, storing and reading values from memory as it goes.

At the hardware level, everything is just 0s and 1s in memory. Java's type system gives those raw bits meaning — a 32-bit pattern means a very different thing when interpreted as an int vs a float. This lecture teaches you to pick the right container for the right data, every time.

🔗
How it connects: This is the starting point — no prerequisites. Lecture 5 builds directly on this by explaining where these variables physically live in memory (stack vs heap). Every later lecture assumes you are fluent in these fundamentals.

🧱 Data Types

1.1 — Primitive Types (8 total)

Stored directly on the stack. Fixed size, no null, ultra-fast access. These are the atoms of Java.

Type Bits Range Default DSA Usage
byte 8 −128 → 127 0 raw byte buffers, rarely in DSA
short 16 −32,768 → 32,767 0 rarely used
int ⭐ 32 −2.1B → 2.1B 0 default integer — use this always
long ⭐ 64 ±9.2 × 10¹⁸ 0L large products, timestamps, overflow-prone problems
float 32 ~6-7 sig. digits 0.0f avoid — precision issues
double ⭐ 64 ~15-16 sig. digits 0.0 default decimal
char ⭐ 16 0 → 65,535 (Unicode) \u0000 frequency arrays, char arithmetic
boolean 1 bit true / false false flags, visited arrays, conditions
💡
DSA Rule of Thumb for type choice:
• Default to int for all integers.
• Switch to long when result can exceed ~2.1 billion (e.g. n × m with n,m ≈ 10⁵).
• char - 'a' gives you an index 0–25 — this is how you build O(1) frequency arrays for lowercase letters.
• double for geometry, probabilities, averages.

1.2 — Reference (Non-Primitive) Types

A primitive variable holds the value itself — the number 7 is right there in the box. A reference variable holds an address: directions to where the real object lives. Think of cash in your hand versus a house address written on paper. Copying the paper does not copy the house, two papers can lead to the same house, and a blank paper is null. That is why a == b on two arrays asks “same address?”, not “same contents?”.

Variables hold a memory address (reference) pointing to an object on the heap. Can be null. Includes all classes, arrays, interfaces.

☕ Java
// Primitive — value lives IN the variable (stack)
int x = 42;           // x IS 42

// Reference — variable holds ADDRESS pointing to heap
String s = "hello";  // s holds address of "hello" object on heap
int[] arr = {1,2,3};  // arr holds address of the array on heap

// Consequence: == checks identity (same address), not equality!
String a = new String("hi");
String b = new String("hi");
System.out.println(a == b);       // false  (different addresses!)
System.out.println(a.equals(b));  // true   (same content) ← USE THIS

1.3 — Type Casting (Interview Gotchas)

☕ Java · Casting Traps
// Widening (implicit, safe) — smaller → larger
int i = 100;
long l = i;          // auto-widens: no data loss
double d = i;        // auto-widens to 100.0

// Narrowing (explicit, lossy) — larger → smaller
double pi = 3.99;
int truncated = (int) pi;   // → 3  (TRUNCATES, does NOT round!)

// ⚠️ GOTCHA 1: integer division truncates
double wrong   = 5 / 2;      // → 2.0  (int division first, THEN widened)
double correct = 5.0 / 2;    // → 2.5  (double division)
double correct2 = (double) 5 / 2; // → 2.5  (cast first)

// ⚠️ GOTCHA 2: int overflow — use long!
int n = 100000;
int overflow = n * n;         // → negative! (wraps around 2.1B limit)
long safe = (long) n * n;    // → 10000000000L ✓

// ⭐ char arithmetic — essential for DSA
int idx = 'e' - 'a';            // → 4  (freq array index)
char c = (char)('a' + 3);       // → 'd'
boolean isLower = (ch >= 'a' && ch <= 'z'); // char range check
char upper = (char)(ch - 32);   // lowercase → uppercase
⚠️
Autoboxing / Unboxing Trap — Common Interview Gotcha!
Java caches Integer values from −128 to 127 (the Integer cache). Outside this range each auto-boxing creates a new heap object.

Integer a = 127, b = 127; a == b → true (same cached object)
Integer c = 128, d = 128; c == d → false (two different heap objects!)

Rule: ALWAYS use .equals() to compare wrapper types — never ==.
Additional trap: Unboxing a null Integer to int silently throws NullPointerException!

🔁 Control Flow

2.1 — All Loop Types

🎯
Pattern Recognition: Which loop to use?
• for: When you know the exact iteration count upfront.
• while: When iteration count depends on a condition (unknown upfront). Classic for binary search, two-pointer, digit extraction.
• do-while: When the body must execute at least once. Classic for menu loops, digit extraction where n=0 is possible.
• for-each: Cleanest for read-only traversal of collections/arrays when you don't need the index.
☕ Java · All Loop Types + DSA Usage 
// ── FOR loop — use when count is known ───────────────────────
for (int i = 0; i < n; i++)          // forward: i goes 0..n-1
for (int i = n-1; i >= 0; i--)        // reverse: suffix processing
for (int i = 0; i < n; i += 2)        // step 2: even indices
for (int i = 0; i < n-1; i++)         // n-1 pairs: adj comparison

// ── WHILE loop — use when count is unknown ───────────────────
while (lo <= hi) { ... }              // binary search template
while (n > 0) { digit = n%10; n/=10;} // digit extraction
while (n > 1) { n /= 2; count++; }   // count divisions → O(log n)
while (fast != null && fast.next != null) // linked list traversal

// ── DO-WHILE — body runs at least once ───────────────────────
do {
    digit = n % 10;
    reversed = reversed * 10 + digit;
    n /= 10;
} while (n != 0);                    // handles n=0 correctly

// ── FOR-EACH — read-only traversal ───────────────────────────
for (int x : arr) sum += x;           // array
for (String s : list) process(s);    // collection
for (Map.Entry<K,V> e : map.entrySet()) // map iteration

// ── NESTED LOOPS — know the complexity! ──────────────────────
for (int i = 0; i < n; i++)          // ┐ O(n²) — all pairs
    for (int j = i+1; j < n; j++) {}  // ┘ j starts at i+1: n(n-1)/2 pairs

// ── BREAK / CONTINUE ─────────────────────────────────────────
break;    // exits the INNERMOST loop only
continue; // skips to NEXT iteration of innermost loop
// To break an outer loop: use labeled break
outer: for (...) {
    for (...) { if (found) break outer; } // exits outer loop!
}

2.2 — Conditionals & Short-Circuit Evaluation

An if … else if … else chain runs the first branch whose condition is true and skips the rest. The operators && (and) and || (or) are short-circuiting: Java stops evaluating as soon as the answer is known. In arr != null && arr.length > 0, when arr is null the right-hand side is never run — which is exactly what stops it crashing. Put the cheap, safe check first.

☕ Java · Conditionals
// Standard if-else
if (x > 0) { ... }
else if (x == 0) { ... }
else { ... }

// Ternary — for simple single-value selection
int max = (a > b) ? a : b;
int abs = (x < 0) ? -x : x;     // ternary absolute value

// Switch (Java 14+ — enhanced switch expression)
int days = switch (month) {
    case 1, 3, 5, 7, 8, 10, 12 -> 31;
    case 4, 6, 9, 11 -> 30;
    default -> 28;
};

// ⭐ Short-circuit evaluation — CRITICAL for null safety!
// && stops at first FALSE condition
if (node != null && node.val == target) { ... }
// if node==null, right side NEVER evaluates → no NullPointerException

// || stops at first TRUE condition
if (arr == null || arr.length == 0) return;
// if arr==null, second check NEVER runs → safe!

// ⚠️ Integer.MAX_VALUE and MIN_VALUE — essential constants
int max = Integer.MAX_VALUE;  // 2^31 - 1 = 2,147,483,647
int min = Integer.MIN_VALUE;  // -2^31  = -2,147,483,648
int res = Math.max(a, b);      // Math utility methods
int abs = Math.abs(x);
double sq = Math.sqrt(n);

🔧 Methods & Arrays

3.1 — Method Anatomy

A method is a named, reusable recipe. Its first line says what it hands back (the return type, or void for nothing), what it is called, and what it needs (the parameters). The body does the work and return hands the result back. On LeetCode you fill in a method inside a class called Solution; the judge calls it with test inputs and checks what it returns.

☕ Java · Method Anatomy
//  access    static   return   name          parameters
public static   int   binarySearch(int[] arr, int target) {
    // body
    return -1;  // must return int (matches return type)
}

// void methods — no return value (but can still return early!)
public static void swap(int[] arr, int i, int j) {
    int tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
}

// Method overloading — same name, different params
int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; } // different return type too

// Varargs — variable number of args (used in DSA for flexibility)
int sum(int... nums) {
    int total = 0;
    for (int n : nums) total += n;
    return total;
}
// call: sum(1), sum(1,2), sum(1,2,3,4,5) — all valid

3.2 — Pass-by-Value: The Most Misunderstood Thing in Java

⚠️
Java is ALWAYS pass-by-value. No exceptions.
The confusion: for objects and arrays, the VALUE being passed is the reference (address).
A copy of the address is passed → mutations through that address persist. But reassigning the reference inside the method doesn't affect the caller.
☕ Java · Pass-by-Value Illustrated 
// PRIMITIVE: copy of value — original unchanged
void tryChange(int x) { x = 99; }
int a = 5;
tryChange(a);
System.out.println(a);  // still 5 — x was a COPY

// ARRAY: copy of reference — mutations visible to caller!
void mutate(int[] arr) { arr[0] = 99; }
int[] arr = {1,2,3};
mutate(arr);
System.out.println(arr[0]);  // 99 — mutation persisted!

// REFERENCE REASSIGNMENT: doesn't affect caller
void reassign(int[] arr) { arr = new int[]{9,9,9}; }
reassign(arr);
System.out.println(arr[0]);  // still 99 — local arr was a copy of address

// ⭐ Consequence: swap(int a, int b) NEVER works
//   swap(int[] arr, int i, int j) DOES work (mutations on shared array)

3.3 — Arrays: Your #1 DSA Tool

An array is a fixed-length row of values of one type. Its length is decided when it is created and never changes; positions run from 0 to length − 1; and a new array is filled with default values (0, false or null). Note that arrays use a.length with no brackets, while strings use s.length() with them. And printing an array directly shows something like [I@1b6d3586 — a memory address — so use Arrays.toString(a) to see its contents.

☕ Java · Arrays — Complete Reference 
// ── Declaration & Initialization ─────────────────────────────
int[] a = new int[5];          // [0,0,0,0,0] — auto-initialised to 0
boolean[] vis = new boolean[n]; // [false,false,...] auto init
int[] b = {3, 1, 4, 1, 5};     // literal init
int[][] mat = new int[3][4];   // 3 rows, 4 cols — all 0
int[][] grid = {{1,2},{3,4}};  // 2D literal

// ── Access ────────────────────────────────────────────────────
a.length                        // FIELD (no parens!) — O(1)
mat.length                      // number of rows
mat[0].length                   // number of cols in row 0

// ── java.util.Arrays methods ──────────────────────────────────
Arrays.sort(a);                 // O(n log n) — dual-pivot quicksort
Arrays.sort(a, 0, 5);          // sort subarray [0,5)
Arrays.fill(a, -1);             // fill all with -1  O(n)
Arrays.fill(a, 2, 5, 0);       // fill range [2,5) with 0
Arrays.copyOf(a, a.length);    // full copy — O(n)
Arrays.copyOfRange(a, 1, 4);   // subarray copy — indices [1,4)
Arrays.equals(a, b);           // element-wise comparison
Arrays.binarySearch(a, target); // O(log n) — array must be sorted!
Arrays.toString(a);            // "[1, 2, 3]" for printing

// ── Custom sort with Comparator ───────────────────────────────
Integer[] arr = {3,1,4,1,5};
Arrays.sort(arr, (a, b) -> b - a); // descending — note: needs Integer[], not int[]
// Sort by absolute value:
Arrays.sort(arr, (a, b) -> Math.abs(a) - Math.abs(b));

4.2 — Interfaces, Comparators & Generics

An interface is a promise of abilities: anything that implements Comparable promises it can be compared. A Comparator is a small object that answers one question about two items — negative if the first goes first, positive if the second does, zero if they tie. Generics, the <Integer> in List<Integer>, tell the compiler what a collection holds, so putting a String in by mistake is caught before the program runs. Generics only hold objects, which is why you write Integer and not int.

☕ Java · Comparator Patterns for DSA 
// Custom sorting — appears in interval, scheduling, and K-th problems

// Sort intervals by start time
Arrays.sort(intervals, (a, b) -> a[0] - b[0]);

// Sort strings by length
Arrays.sort(words, (a, b) -> a.length() - b.length());

// Max-heap (reverse natural order) — used constantly!
PriorityQueue<Integer> maxHeap = new PriorityQueue<>((a,b) -> b-a);

// Min-heap by second element of pair
PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[1] - b[1]);

// Generics — type-safe collections
List<Integer> list = new ArrayList<>();
Map<String, List<Integer>> graph = new HashMap<>();
Set<Integer> visited = new HashSet<>();

4.3 — static & final Keywords

static means “belongs to the class, not to any one object” — there is a single shared copy. final means “cannot be reassigned”. Careful with the second: a final int[] cannot be pointed at a different array, but the numbers inside it can still change. In DSA code you will mostly see the two together for constants, such as static final int MOD = 1_000_000_007;.

☕ Java · static & final 
// static — belongs to the CLASS, shared across all instances
class Counter {
    static int count = 0;   // shared across ALL instances
    int id;                  // unique per instance
    Counter() { id = ++count; }
}

// static methods can't access instance fields (no 'this')
// Why main() is static: JVM calls it without creating an object

// final — prevents reassignment / inheritance / override
final int MAX = 100;        // constant; convention: ALL_CAPS
final String s = "hi"; s = "bye";  // ✗ COMPILE ERROR

// DSA constants you'll use constantly:
static final int INF = Integer.MAX_VALUE;  // Dijkstra, DP
static final int MOD = 1_000_000_007;       // modular arithmetic

4.4 — The equals() + hashCode() Contract

⚠️
The Contract: If a.equals(b) is true, then a.hashCode() == b.hashCode() MUST also be true.
Breaking this contract causes silent bugs in HashMap, HashSet, and every hash-based structure.
When using a custom object as a HashMap key, you MUST override both methods together.
☕ Java · Custom HashMap Key 
class Point {
    int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }

    @Override
    public boolean equals(Object o) {
        if (!(o instanceof Point)) return false;
        Point p = (Point) o;
        return x == p.x && y == p.y;
    }

    @Override
    public int hashCode() {
        return 31 * x + y;  // must be consistent with equals()
    }
}
// Without overriding: map.get(new Point(1,2)) → null even after put!
Map<Point, String> map = new HashMap<>();
map.put(new Point(1,2), "origin");
map.get(new Point(1,2));  // → "origin" ✓ (with both overrides)

⏱ Big-O — A Recap in Java Terms

↩️
Recap — taught fully in Lecture 1. The growth ladder, reading cost from loops, space, amortised cost and turning constraints into a target were all covered in Lecture 1. What is new now is that you write real Java — and a single innocent-looking line can hide a whole loop. This table is the Lecture 1 skill applied to the Java you will actually type.
This line of Java… Costs Because
a[i], s.charAt(i) O(1) Direct access by position
list.get(i) on an ArrayList O(1) Backed by an array
list.add(x) O(1) amortised Occasionally doubles its storage
list.add(0, x), list.remove(0) O(n) Everything after it shifts
list.contains(x), list.indexOf(x) O(n) Scans the list
set.contains(x), map.get(k) O(1) average Hashing (Lecture 16)

Arrays.sort(a), Collections.sort(list) O(n log n) A full sort
Integer.parseInt(s), String.valueOf(n) O(digits) One step per digit
⚠️
The most common hidden O(n²). if (list.contains(x)) inside a loop over the list looks like one step per item. It is n steps per item. Swap the list for a HashSet and the same loop becomes O(n).

TreeMap — Missing from Most Courses: When you need range or nearest-key queries in O(log n).
tm.floorKey(x) — largest key ≤ x  |  tm.ceilingKey(x) — smallest key ≥ x

☕ Java · Collections Quick Reference 
// ── ArrayList ─────────────────────────────────────────────────
List<Integer> list = new ArrayList<>();
list.add(5);               // append
list.add(0, 5);            // insert at index 0 — O(n)!
list.get(i);               // O(1)
list.remove(i);            // by index — O(n); shifts everything
list.remove(Integer.valueOf(5)); // by value — O(n)
list.size(); list.isEmpty(); list.contains(x);
Collections.sort(list);    // O(n log n)
Collections.reverse(list);

// ── HashMap ───────────────────────────────────────────────────
Map<String,Integer> map = new HashMap<>();
map.put("a", 1);
map.get("a");                        // returns null if absent
map.getOrDefault("a", 0);           // ← use this to avoid null checks!
map.containsKey("a"); map.containsValue(1);
map.put("a", map.getOrDefault("a",0)+1); // frequency count pattern
map.putIfAbsent("a", new ArrayList<>()); // graph adjacency list
for (var e : map.entrySet())          // iterate all entries
    System.out.println(e.getKey() + " → " + e.getValue());

// ── PriorityQueue ─────────────────────────────────────────────
PriorityQueue<Integer> minPQ = new PriorityQueue<>();    // min-heap
PriorityQueue<Integer> maxPQ = new PriorityQueue<>(Collections.reverseOrder());
minPQ.offer(5);  // add
minPQ.peek();    // view min without removing — O(1)
minPQ.poll();    // remove and return min — O(log n)

// ── ArrayDeque as Stack ──────────────────────────────────────
Deque<Integer> stack = new ArrayDeque<>();
stack.push(5);   // push to front
stack.pop();     // remove from front
stack.peek();    // view front without removing

// ── ArrayDeque as Queue ──────────────────────────────────────
Deque<Integer> queue = new ArrayDeque<>();
queue.offer(5);  // enqueue at back
queue.poll();    // dequeue from front
queue.peek();    // view front

🔤 String Essentials for DSA

Java strings are immutable — every modification creates a new string. This is the #1 interview trap for beginners.

🚨
DANGER: String concatenation in a loop is O(n²)!
String s = ""; for(int i=0; i<n; i++) s += "a";
Each += creates a new string and copies everything. Use StringBuilder instead.
StringBuilder sb = new StringBuilder(); for(...) sb.append("a"); return sb.toString();

String Operations You Must Know

Operation Code Time Notes
Length s.length() O(1) Note: () for String, not .length
Get char s.charAt(i) O(1) Returns char, not String
Substring s.substring(i, j) O(j-i) Creates new string [i, j)
Compare s.equals(t) O(n) NEVER use == for strings!
To char array s.toCharArray() O(n) Convert to mutable array
Split s.split(" ") O(n) Returns String[]
Trim s.trim() O(n) Remove leading/trailing spaces
Contains s.contains("ab") O(n×m) Naive search
Index of s.indexOf("ab") O(n×m) Returns -1 if not found
To lowercase s.toLowerCase() O(n) Creates new string
💡
StringBuilder Cheat Sheet:
StringBuilder sb = new StringBuilder();
sb.append("hello"); — O(1) amortised
sb.insert(0, "x"); — O(n) — shifts everything
sb.reverse(); — O(n)

Rule: If you're building a string character by character, ALWAYS use StringBuilder.

Integer compared with == 127 equals 127, but 128 does not equal 128 Use .equals() or compare int values
Reading a[a.length] ArrayIndexOutOfBoundsException The last index is length − 1
Building a string with + in a loop Time Limit Exceeded on large inputs Use StringBuilder
Arithmetic on char 'a' + 1 prints 98 Cast back: (char) ('a' + 1)
Removing from a list inside a for-each loop ConcurrentModificationException Use an Iterator and it.remove(), or build a new list

Problem 01 · Brute → Optimise
Check if a Number is Prime
🔗 Related: LC 3115 - Maximum Prime Difference
Easy Google · Amazon · Adobe O(√n) Optimisation
›
Problem

Given a positive integer n, return true if it is prime (divisible only by 1 and itself).

isPrime(2) → true isPrime(17) → true isPrime(15) → false (3 × 5 = 15) isPrime(1) → false (1 is NOT prime by definition)
Hints
▶Hint 1 — a nudge

You do not need to test every number below n. How far do the factors actually go?

▶Hint 2 — the key idea

If n has a factor larger than √n, it must also have one smaller than √n. So loop i from 2 while i×i ≤ n.

Solution

Factors come in pairs: if a × b = n, then min(a, b) ≤ √n. So we only need to check up to √n.

Additional: skip even numbers after checking 2 — halves the iterations.

▶Full solution
☕ Java · 3 Approaches 
// Approach 1: Brute Force — O(n)
boolean isPrime_brute(int n) {
    if (n < 2) return false;
    for (int i = 2; i < n; i++)       // checks all the way to n-1
        if (n % i == 0) return false;
    return true;
}

// Approach 2: Optimized — O(√n)
boolean isPrime(int n) {
    if (n < 2) return false;
    if (n == 2) return true;          // 2 is prime
    if (n % 2 == 0) return false;     // all evens > 2 are not prime
    for (int i = 3; i*i <= n; i += 2) { // only odd i, stop at √n
        if (n % i == 0) return false;
    }
    return true;
}

// Dry run: isPrime(37)
// n=37, not even. i=3: 9≤37, 37%3≠0 | i=5: 25≤37, 37%5≠0
// i=7: 49>37 → STOP → return true ✓
// Only 3 iterations vs 35 in brute force!
Brute TimeO(n)
Optimal TimeO(√n)
SpaceO(1)
Problem 02 · Two Pointers Preview
Reverse an Array In-Place
🔗 LC 344 - Reverse String
Easy Amazon · Microsoft · Apple Two Pointers
›
Problem

Reverse an array in-place using O(1) extra space. Do not create a new array.

Input: [1, 2, 3, 4, 5] → Output: [5, 4, 3, 2, 1] Input: [1, 2] → Output: [2, 1]
Hints
▶Hint 1 — a nudge

You do not need a second array. What if two pointers walked towards each other?

▶Hint 2 — the key idea

Put one pointer at 0 and one at n-1, swap, then move both inwards. Stop when they meet.

Solution
▶Full solution
☕ Java
void reverse(int[] arr) {
    int left = 0, right = arr.length - 1;
    while (left < right) {
        int tmp  = arr[left];  // 3-step swap
        arr[left]  = arr[right];
        arr[right] = tmp;
        left++;   right--;     // converge inward
    }
}
// Dry run: [1,2,3,4,5]
// left=0,right=4: swap(1,5) → [5,2,3,4,1]
// left=1,right=3: swap(2,4) → [5,4,3,2,1]
// left=2,right=2: left==right → stop ✓
// n/2 = 2 swaps for n=5. O(n) time, O(1) space.
TimeO(n)
SpaceO(1)
Problem 03 · Binary Search Template
Find Smallest Letter Greater Than Target
🔗 LC 744 - Find Smallest Letter Greater Than Target
Easy Upper Bound Amazon · Google · LinkedIn
›
Problem

Given a sorted array of lowercase letters and a character target, return the smallest letter strictly greater than target. If there is none, wrap around and return letters[0].

letters = ['c','f','j'], target = 'a' → 'c'  |  target = 'c' → 'f'  |  target = 'j' → 'c'
Hints
▶Hint 1 — a nudge

The array is sorted, so you never need to look at every letter. Which half can you throw away after one comparison?

▶Hint 2 — the key idea

Binary search for the first index whose letter is greater than the target. If that index runs past the end, wrap to index 0.

Solution

This is the upper bound template. Keep a half-open range [lo, hi). If letters[mid] > target, the answer is at mid or to its left, so hi = mid; otherwise lo = mid + 1. When the loop ends, lo is the first greater letter — or n, which wraps to 0 with a modulo.

▶Full solution
☕ Java · Upper Bound 
char nextGreatestLetter(char[] letters, char target) {
    int lo = 0, hi = letters.length;       // search space [lo, hi)
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;      // never overflows
        if (letters[mid] > target) hi = mid;
        else lo = mid + 1;
    }
    return letters[lo % letters.length];   // lo == n means wrap around
}

// Dry run: ['c','f','j'], target = 'c'
// lo=0 hi=3 -> mid=1 'f' > 'c'  -> hi=1
// lo=0 hi=1 -> mid=0 'c' > 'c'? no -> lo=1
// lo == hi == 1 -> letters[1] = 'f'
TimeO(log n)
SpaceO(1)
Problem 04 · Brute Force to Counting
How Many Numbers Are Smaller Than the Current Number
🔗 LC 1365 - How Many Numbers Are Smaller Than the Current Number
Easy Counting Array Amazon · Microsoft · Bloomberg
›
Problem

For every nums[i], count how many other elements are strictly smaller than it. Values are between 0 and 100.

nums = [8, 1, 2, 2, 3] → [4, 0, 1, 1, 3]
Hints
▶Hint 1 — a nudge

Two nested loops solve it. Count the comparisons — what is that in Big-O?

▶Hint 2 — the key idea

Values only go up to 100. Count how often each value appears, turn those counts into running totals, and the answer for x is the number of values at most x - 1.

Solution

Start with the brute force and name its cost: for each element you scan all the others, so O(n²). Then use the constraint. A int[101] frequency array plus a prefix sum turns every query into one array read, so the whole problem becomes O(n + 100). This trade — a little memory for a lot of speed — is the same idea behind counting sort in Lecture 9.

▶Full solution
☕ Java · Counting + Prefix 
int[] smallerNumbersThanCurrent(int[] nums) {
    int[] count = new int[101];
    for (int x : nums) count[x]++;              // how often each value appears

    for (int v = 1; v <= 100; v++)
        count[v] += count[v - 1];               // now: how many values <= v

    int[] ans = new int[nums.length];
    for (int i = 0; i < nums.length; i++)
        ans[i] = nums[i] == 0 ? 0 : count[nums[i] - 1];
    return ans;
}

// nums = [8,1,2,2,3] -> counts <=0:0, <=1:1, <=2:3, <=7:4
// 8 -> 4, 1 -> 0, 2 -> 1, 2 -> 1, 3 -> 3
TimeO(n + 100)
SpaceO(101)
Problem 05 · Complexity Analysis
Max Consecutive Ones
🔗 LC 485 - Max Consecutive Ones
Easy Running Count Google · Amazon · Microsoft
›
Problem

Given a binary array nums, return the maximum number of consecutive 1s.

nums = [1, 1, 0, 1, 1, 1] → 3
Hints
▶Hint 1 — a nudge

Trying every start and end is O(n²). What single fact about the current position is enough?

▶Hint 2 — the key idea

Track the length of the run of 1s that ends at the current index: a 1 extends it, a 0 resets it to zero. Remember the best length seen.

Solution

Two variables replace the nested loops. current is the run ending here and best is the answer so far. Each element is read once, so the pass is O(n) with O(1) memory. The same extend-or-reset shape reappears as Kadane's algorithm on sums in Lecture 11.

▶Full solution
☕ Java · One Pass
int findMaxConsecutiveOnes(int[] nums) {
    int current = 0, best = 0;
    for (int x : nums) {
        if (x == 1) current++;      // extend the run
        else current = 0;           // a zero breaks it
        best = Math.max(best, current);
    }
    return best;
}

// [1,1,0,1,1,1] -> current = 1,2,0,1,2,3 -> best = 3
TimeO(n)
SpaceO(1)
Problem 06 · Counting Pairs
Number of Good Pairs
🔗 LC 1512 - Number of Good Pairs
Easy Counting Array Amazon · Microsoft · Adobe
›
Problem

A pair (i, j) is good when nums[i] == nums[j] and i < j. Return the number of good pairs. Values are between 1 and 100.

nums = [1, 2, 3, 1, 1, 3] → 4   (pairs (0,3), (0,4), (3,4), (2,5))
Hints
▶Hint 1 — a nudge

Write the double loop first. How many comparisons does it make for n elements?

▶Hint 2 — the key idea

When you reach a value that has already appeared c times, it makes c new pairs. Add c to the answer, then increase the count.

Solution

The nested loop makes n(n−1)/2 comparisons. Counting does it in one pass: each new occurrence of a value pairs with every earlier occurrence, so add the running count before incrementing it. Same answer, O(n) instead of O(n²).

▶Full solution
☕ Java · Count Then Pair 
int numIdenticalPairs(int[] nums) {
    int[] count = new int[101];
    int pairs = 0;
    for (int x : nums) {
        pairs += count[x];   // x pairs with every earlier copy of itself
        count[x]++;
    }
    return pairs;
}

// [1,2,3,1,1,3]
// 1:+0   2:+0   3:+0   1:+1   1:+2   3:+1   -> 4
TimeO(n)
SpaceO(101)
Problem 07 · Character Counting
Determine if String Halves Are Alike
🔗 LC 1704 - Determine if String Halves Are Alike
Easy Single Counter Amazon · Microsoft
›
Problem

Split an even-length string s into two halves. Return true when both halves hold the same number of vowels (a, e, i, o, u, upper or lower case).

s = "book" → true (1 vowel each)  |  s = "textbook" → false (1 vs 2)
Hints
▶Hint 1 — a nudge

You do not care which vowels appear, only how many are on each side.

▶Hint 2 — the key idea

One loop over the index i: add 1 for a vowel in the first half, subtract 1 for a vowel in the second half. The halves match when the total is zero.

Solution

A single balance counter replaces two separate counts. "aeiouAEIOU".indexOf(c) >= 0 is a readable vowel test and a good reminder that char values work directly with String methods. One pass, no extra arrays.

▶Full solution
☕ Java · Balance Counter 
boolean halvesAreAlike(String s) {
    String vowels = "aeiouAEIOU";
    int n = s.length(), balance = 0;
    for (int i = 0; i < n; i++) {
        if (vowels.indexOf(s.charAt(i)) >= 0) {
            balance += (i < n / 2) ? 1 : -1;
        }
    }
    return balance == 0;
}

// "book": 'o' at i=1 -> +1, 'o' at i=2 -> -1, total 0 -> true
TimeO(n)
SpaceO(1)
Problem 08 · Prefix Sum Introduction
Running Sum of 1D Array
🔗 LC 1480 - Running Sum
Easy Amazon · Microsoft Prefix Sum
›
Problem

Given an array nums, return the running sum: runningSum[i] = sum(nums[0]...nums[i]).

Input: [1, 2, 3, 4] → Output: [1, 3, 6, 10] Input: [3, 1, 2, 10, 1] → Output: [3, 4, 6, 16, 17]
Hints
▶Hint 1 — a nudge

Each output entry is the previous output entry plus the current input.

▶Hint 2 — the key idea

Accumulate in place: nums[i] += nums[i-1] from i = 1. No extra array needed.

Solution
Why this matters (a lot)

This is your first encounter with the prefix sum pattern. Prefix sums allow you to compute the sum of ANY subarray in O(1). This technique appears in:

  • Range sum queries (LC 303)
  • Subarray sum equals K (LC 560) — uses prefix sum + HashMap
  • Product of array except self (LC 238)
  • Many DP problems that optimise with prefix/suffix arrays
▶Full solution
☕ Java · In-place 
int[] runningSum(int[] nums) {
    for (int i = 1; i < nums.length; i++) {
        nums[i] += nums[i - 1];  // accumulate
    }
    return nums;
}

// Dry run: [1, 2, 3, 4]
// i=1: nums[1] = 2 + 1 = 3   → [1, 3, 3, 4]
// i=2: nums[2] = 3 + 3 = 6   → [1, 3, 6, 4]
// i=3: nums[3] = 4 + 6 = 10  → [1, 3, 6, 10] ✓

// 🎯 Bonus: How to get sum of subarray [i..j]?
// sum(i, j) = prefix[j] - prefix[i-1]
// Example: sum of nums[1..2] = prefix[2] - prefix[0] = 6 - 1 = 5
// Verify: nums[1] + nums[2] = 2 + 3 = 5 ✓
TimeO(n)
SpaceO(1)
Problem 09 · Digit Extraction
Count the Digits That Divide a Number
🔗 LC 2520 - Count the Digits That Divide a Number
Easy % 10 and / 10 Amazon · Adobe
›
Problem

Return how many digits of num divide num evenly. The input has no zero digits.

num = 121 → 2   (1 divides 121 twice, 2 does not)  |  num = 1248 → 4
Hints
▶Hint 1 — a nudge

You need each digit in turn, and you still need the original number to test against.

▶Hint 2 — the key idea

Copy num into a working variable. While it is greater than zero, take n % 10 as the digit and then n /= 10. Always test num % digit, never the shrinking copy.

Solution

This is the digit-extraction loop from the lecture, and it hides the classic bug: if you test n % digit you are testing a number you have already chopped up. Keep the original in its own variable. The loop runs once per digit, so it costs O(log₁₀ num).

▶Full solution
☕ Java · Digit Loop 
int countDigits(int num) {
    int n = num, count = 0;
    while (n > 0) {
        int digit = n % 10;              // read the last digit
        if (num % digit == 0) count++;   // test against the ORIGINAL
        n /= 10;                         // drop it
    }
    return count;
}

// num = 121 -> digits 1, 2, 1
// 121 % 1 == 0 yes, 121 % 2 == 1 no, 121 % 1 == 0 yes -> 2
TimeO(log num)
SpaceO(1)
Problem 10 · Greedy / One-Pass
Maximum Ascending Subarray Sum
🔗 LC 1800 - Maximum Ascending Subarray Sum
Easy Extend or Restart Amazon · Google
›
Problem

An ascending subarray is one where every element is strictly larger than the one before it. Return the largest possible sum of an ascending subarray of nums.

nums = [10, 20, 30, 5, 10, 50] → 65   (from [5, 10, 50])
Hints
▶Hint 1 — a nudge

Where can an ascending run begin? Only where the step from the previous element was not an increase.

▶Hint 2 — the key idea

Keep the sum of the run ending here. If nums[i] > nums[i-1] add to it, otherwise start again from nums[i]. Track the best sum you have seen.

Solution

One pass, two variables. Each element either extends the current run or starts a new one, so you never need to look back more than a single step. Recognise the shape: it is the same decision Kadane's algorithm makes, and the same one sliding windows make when they shrink.

▶Full solution
☕ Java · Extend or Restart 
int maxAscendingSum(int[] nums) {
    int sum = nums[0], best = nums[0];
    for (int i = 1; i < nums.length; i++) {
        if (nums[i] > nums[i - 1]) sum += nums[i];   // extend the run
        else sum = nums[i];                          // restart here
        best = Math.max(best, sum);
    }
    return best;
}

// [10,20,30,5,10,50] -> sum = 10,30,60,5,15,65 -> best = 65
TimeO(n)
SpaceO(1)
