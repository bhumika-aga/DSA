Dynamic Programming I — Foundations & 1D

“Write the honest recursion first. Dynamic programming is what happens when you stop solving the same subproblem twice.”

📚 Lecture 32 of 45 Phase 4 — Dynamic Programming ⏱ 6 days 🎯 25 problems 💼 Google · Amazon · Meta · Microsoft
🌍
Why does this topic matter?
This is the topic candidates fear, and the reason is usually that they were taught the tables first. Dynamic programming is not a table. It is a recursion you already know how to write, plus the observation that it keeps recomputing the same things. Get that order right — recursion, then memo, then table — and most DP problems become mechanical.
By the end of this lecture you can
  • Spot the two signals: overlapping subproblems and optimal substructure
  • Turn any recursion into memoised DP without thinking hard
  • Convert top-down into bottom-up, and then into O(1) space
  • State in one sentence what dp[i] means — and know why that sentence is the whole problem
  • Recognise the 1D families: climbing, robbing, coins, state machines and LIS

🔍 The Two Signals

A problem is a DP problem when both of these hold. Miss either one and you should be reaching for something else.

Signal What it means How to check
Overlapping subproblems the same smaller question is asked many times draw the recursion tree and look for a repeated node
Optimal substructure the best answer is built from the best answers to smaller versions can you write the answer for n in terms of smaller n?
🧠
Compare with the neighbours. Divide and conquer (Lecture 30) has optimal substructure but no overlap — each half is solved once, so no memo is needed. Greedy (Lecture 29) has optimal substructure and does not even explore alternatives. DP is the case where the options genuinely interact and the same states keep coming back.

🥋 The Four-Step Ladder

Every problem in this lecture is solved the same way. Climb as far as you need and stop — step 2 is usually enough to pass, step 4 is what impresses.

Step 1 — The Honest Recursion

📐 Pseudocode · Brute Force, Written Deliberately 
// "How many ways to climb n stairs, taking 1 or 2 at a time?"
function ways(n):
    if n ≤ 1: return 1          // base case first, always
    return ways(n - 1) + ways(n - 2)

// ways(5) calls ways(3) twice, ways(2) three times, ways(1) five times.
// That repetition IS the signal. Time: O(2ⁿ).

Step 2 — Add a Memo

📐 Pseudocode · Top-Down with Memoisation 
memo ← empty map                  // or an array filled with "unknown"

function ways(n):
    if n ≤ 1: return 1
    if n in memo: return memo[n]       // ← the entire technique, one line
    memo[n] ← ways(n - 1) + ways(n - 2)
    return memo[n]

// Each state is computed once: O(n) time, O(n) memo + O(n) stack.
// Nothing about the logic changed — only how often it runs.

Step 3 — Turn It Inside Out

📐 Pseudocode · Bottom-Up Tabulation 
dp ← array of length n + 1
dp[0] ← 1;  dp[1] ← 1              // the same base cases, written as data

for i from 2 to n:
    dp[i] ← dp[i - 1] + dp[i - 2]  // the same recurrence, in dependency order

return dp[n]

// No recursion, no stack. The loop order must guarantee that everything
// dp[i] depends on is already filled in.

Step 4 — Keep Only What You Need

📐 Pseudocode · O(1) Space 
a ← 1;  b ← 1                      // dp[i-2] and dp[i-1]
for i from 2 to n:
    a, b ← b, a + b
return b

// The recurrence only ever looks back two steps, so only two numbers
// need to exist. Works whenever dp[i] depends on a fixed window.
Step Time Space When to stop here
1 · recursion exponential O(depth) never — but always write it first
2 · memoised O(states) O(states + depth) states are sparse, or the order is awkward
3 · tabulated O(states) O(states) deep recursion risks a stack overflow
4 · rolling O(states) O(window) the interviewer asks for better space

🏷️ Defining the State

The hardest part of DP is not the code. It is finishing this sentence honestly:

dp[i] = “the <best / number of / whether> … considering only the first i items, ending at i”

Two candidate meanings for the same problem give two different recurrences, and only one of them usually works.

dp[i] means Recurrence Answer is Used by
best over the first i items choose to use item i or not dp[n] House Robber, Coin Change
best ending exactly at i extend one of the earlier endings max(dp) LIS, Kadane, arithmetic slices
best starting at i fill backwards dp[0] jump games, Brainpower
best at i in state s a small machine of states per index max over s of dp[n][s] stock problems with cooldown or fees
⚠️
If the recurrence will not come, the state is wrong. Struggling to write dp[i] in terms of earlier entries almost always means the definition is missing something — usually a second dimension (how many transactions left, whether the previous item was taken, what the last difference was). Add it to the state rather than patching the loop.

🧩 The 1D Families

Nearly every one-dimensional DP problem is one of five shapes. Learn the shape and the problem writes itself.

📐 Pseudocode · Take or Skip (House Robber) 
// dp[i] = the most you can take from the first i houses
prev2 ← 0;  prev1 ← 0
for x in nums:
    take ← prev2 + x                // rob this one: skip the neighbour
    skip ← prev1                    // leave it: keep the best so far
    prev2, prev1 ← prev1, max(take, skip)
return prev1
📐 Pseudocode · Unbounded Choice (Coin Change) 
// dp[a] = fewest coins that make exactly a
dp ← array of amount + 1, filled with infinity
dp[0] ← 0                            // zero coins make zero

for a from 1 to amount:
    for coin in coins:
        if coin ≤ a and dp[a - coin] + 1 < dp[a]:
            dp[a] ← dp[a - coin] + 1

if dp[amount] = infinity: return -1
return dp[amount]

// Each coin may be reused, which is why the loop goes forward over a.
// Lecture 34 shows what changes when each item may be used only once.
📐 Pseudocode · State Machine (Stock with Cooldown) 
// Three states per day: holding, just sold, free to buy.
hold ← -infinity;  sold ← -infinity;  rest ← 0

for price in prices:
    prevSold ← sold
    sold ← hold + price              // sell today
    hold ← max(hold, rest - price)   // keep holding, or buy today
    rest ← max(rest, prevSold)       // cooldown finishes

return max(sold, rest)             // never end while holding

LIS — and the O(n log n) Upgrade

The longest increasing subsequence deserves its own section, because both of its solutions are worth knowing and the fast one is often mis-explained.

📐 Pseudocode · LIS, Two Ways 
// O(n²): dp[i] = length of the best subsequence ENDING at i
dp ← array of 1s
for i from 1 to n - 1:
    for j from 0 to i - 1:
        if nums[j] < nums[i]: dp[i] ← max(dp[i], dp[j] + 1)
return max(dp)

// O(n log n): tails[k] = smallest possible tail of a subsequence of length k+1
tails ← empty list
for x in nums:
    pos ← first index in tails with value ≥ x     // binary search
    if pos = length(tails): tails.append(x)
    else: tails[pos] ← x                          // a smaller tail is always better
return length(tails)
🛑
tails is not the answer. Its length is the length of the longest increasing subsequence, but its contents are usually not a valid subsequence of the input. If the problem asks you to reconstruct the actual sequence, keep parent pointers alongside — or use the O(n²) version, where the reconstruction is easy.
🧠
Where you have seen the trick before. Replacing a tail with a smaller value is the greedy exchange argument from Lecture 29, and the binary search is Lecture 13's lower bound. Russian Doll Envelopes then sorts by width ascending and height descending so that same-width envelopes cannot chain — a sort decision straight out of Lecture 28.

⚠️ Complexity & The Classic Bugs

Family States Work per state Total
Climbing / take-or-skip n O(1) O(n), O(1) space
Coin change / unbounded choice amount O(coins) O(amount · coins)
State machine (stocks) n × k states O(1) O(n · k)
LIS, quadratic n O(n) O(n²)
LIS, patience n O(log n) O(n log n)
Bug Symptom Fix
A vague state definition The recurrence refuses to come out Write the sentence first; add a dimension if needed
Memoising on an incomplete key Wrong answers that look almost right The key must include every value the result depends on
Filling the table in the wrong order Reads an entry that is still empty Loop in dependency order — draw the arrows
Missing or wrong base case Off-by-one everywhere, or infinite recursion Decide dp[0] before anything else
Using “unreachable” as a number Coin Change returns amount + 1 Sentinel of infinity, checked before returning
Rolling variables updated in the wrong order The new value is read as if it were the old one Save the previous value before overwriting it
💡
How to spot it in an interview. “Maximum / minimum / number of ways”, a sequence of choices where each one affects the next, and a brute force that visibly repeats work. Say “let me write the recursion first” out loud — it buys thinking time and gets you most of the marks even if you never reach the table.

Problem 01 · The Four-Step Ladder
Coin Change
🔗 LC 322 - Coin Change
Medium Unbounded Choice Amazon · Google · Meta
›
Problem

Given coin denominations and an amount, return the fewest coins that add up to it exactly, or −1 if it cannot be done. Coins may be reused.

coins = [1, 2, 5], amount = 11 → 3  (5 + 5 + 1)  |   coins = [2], amount = 3 → -1
Hints
▶Hint 1 — a nudge

Greedy fails here — try coins [1, 3, 4] and amount 6. So write the recursion: what is the answer for amount in terms of smaller amounts?

▶Hint 2 — the key idea

best(a) = 1 + min(best(a - coin)) over every usable coin. Memoise on a, then turn it into a loop from 0 upwards.

Solution

This is the whole lecture in one problem. The recursion is obvious and exponential; the memo makes it O(amount × coins); the bottom-up version removes the stack. Two details decide correctness: dp[0] = 0 (zero coins make zero), and treating “impossible” as infinity so an unreachable amount never looks like a real answer. The forward loop is what allows a coin to be reused — Lecture 34 flips that loop for 0/1 items.

▶Full solution
📐 Pseudocode · Bottom-Up over Amounts 
function coinChange(coins, amount):
    dp ← array of amount + 1, filled with infinity
    dp[0] ← 0                              // base case: zero coins make zero

    for a from 1 to amount:
        for coin in coins:
            if coin ≤ a and dp[a - coin] + 1 < dp[a]:
                dp[a] ← dp[a - coin] + 1

    if dp[amount] = infinity: return -1
    return dp[amount]

// coins [1,2,5], amount 11
// dp: 0,1,1,2,2,1,2,2,3,3,2,3 → answer 3 ✓
TimeO(amount × coins)
SpaceO(amount)
Problem 02 · Take or Skip
House Robber II
🔗 LC 213 - House Robber II
Medium Linear DP, Twice Amazon · Google · Microsoft
›
Problem

Houses are arranged in a circle, so the first and last are neighbours. You cannot rob two adjacent houses. Return the maximum you can take.

nums = [2, 3, 2] → 3   |   nums = [1, 2, 3, 1] → 4
Hints
▶Hint 1 — a nudge

The straight-line version is dp[i] = max(dp[i-1], dp[i-2] + nums[i]). What does the circle add?

▶Hint 2 — the key idea

Only one extra fact: the first and last house cannot both be robbed. So run the linear solution twice — once without the last house, once without the first — and take the better result.

Solution

The instinct is to invent a circular recurrence; the better move is to remove the circularity by case analysis. Either house 0 is robbed (so house n−1 is out) or it is not (so the rest of the row is free). Each case is the plain House Robber on a slice, and each runs in O(1) space. Watch the single-house input, where both slices are empty.

▶Full solution
📐 Pseudocode · Two Linear Passes 
function rob(nums):
    if length(nums) = 1: return nums[0]
    return max(robLine(nums, 0, n - 2),      // drop the last house
               robLine(nums, 1, n - 1))      // drop the first house

function robLine(nums, lo, hi):
    prev2 ← 0;  prev1 ← 0
    for i from lo to hi:
        take ← prev2 + nums[i]
        prev2, prev1 ← prev1, max(take, prev1)
    return prev1

// [1,2,3,1]: without last → 1,2,3 gives 4; without first → 2,3,1 gives 3 → 4 ✓
TimeO(n)
SpaceO(1)
Problem 03 · Ending Exactly Here
Longest Increasing Subsequence
🔗 LC 300 - Longest Increasing Subsequence
Medium LIS / Patience Amazon · Google · Meta · Microsoft
›
Problem

Return the length of the longest strictly increasing subsequence. Elements need not be contiguous.

nums = [10, 9, 2, 5, 3, 7, 101, 18] → 4  ([2, 3, 7, 101])
Hints
▶Hint 1 — a nudge

“Best over the first i” does not work here. What if dp[i] is the best subsequence ending at i?

▶Hint 2 — the key idea

Then dp[i] = 1 + max(dp[j]) over earlier j with a smaller value — O(n²). For O(n log n), keep a tails array and binary search each new value into it.

Solution

The state definition is the lesson: anchoring the subsequence at i makes the recurrence possible, and the answer becomes the maximum over the table rather than its last entry. The patience upgrade keeps tails[k] = the smallest tail of any length-(k+1) subsequence; a smaller tail is never worse, so each value either extends the array or replaces the first entry that is at least as large. Its length is the answer — its contents are not a real subsequence.

▶Full solution
📐 Pseudocode · Quadratic, Then Patience 
// O(n²) — easy to reconstruct from
dp ← array of 1s
for i from 1 to n - 1:
    for j from 0 to i - 1:
        if nums[j] < nums[i]:
            dp[i] ← max(dp[i], dp[j] + 1)
return max(dp)

// O(n log n) — patience sorting
tails ← empty list
for x in nums:
    pos ← lowerBound(tails, x)          // first index with value ≥ x
    if pos = length(tails): tails.append(x)
    else: tails[pos] ← x
return length(tails)
TimeO(n log n)
SpaceO(n)
Problem 04 · State Machine
Best Time to Buy and Sell Stock with Cooldown
🔗 LC 309 - Best Time to Buy and Sell Stock with Cooldown
Medium DP over States Google · Amazon · Meta
›
Problem

You may buy and sell many times, but after selling you must rest one day before buying again. Return the maximum profit.

prices = [1, 2, 3, 0, 2] → 3  (buy 1, sell 2, cooldown, buy 0, sell 2)
Hints
▶Hint 1 — a nudge

Each day you are in one of a few situations. List them: holding a share, having just sold, or free to act.

▶Hint 2 — the key idea

Write one variable per state and update all three from the previous day’s values. Hold comes from resting-then-buying; sold comes from holding-then-selling; rest comes from having sold earlier.

Solution

When a plain dp[i] cannot express the constraint, the missing piece belongs in the state. Three running values are enough, but the update order matters: sold must be computed from yesterday’s hold, and rest from yesterday’s sold, so save the old value before overwriting. Initialising hold to −infinity stops a sale that never had a purchase.

▶Full solution
📐 Pseudocode · Three Running States 
function maxProfit(prices):
    hold ← -infinity      // best profit while holding a share
    sold ← -infinity      // best profit having sold TODAY
    rest ← 0              // best profit while free to buy

    for price in prices:
        prevSold ← sold                      // yesterday's value
        sold ← hold + price                  // sell what we held
        hold ← max(hold, rest - price)       // keep holding, or buy today
        rest ← max(rest, prevSold)           // cooldown day finishes

    return max(sold, rest)                 // never finish holding
TimeO(n)
SpaceO(1)
Problem 05 · Fill Backwards
Solving Questions With Brainpower
🔗 LC 2140 - Solving Questions With Brainpower
Medium Suffix DP Google · Amazon
›
Problem

Each question gives points but costs brainpower, skipping that many questions after it. Return the maximum points obtainable.

questions = [[3,2],[4,3],[4,4],[2,5]] → 5  (solve question 0, skip 2, solve question 3)
Hints
▶Hint 1 — a nudge

Solving question i affects what comes after it. Which direction should the table be filled?

▶Hint 2 — the key idea

Let dp[i] be the best score obtainable from question i onwards, and fill from the end: solve it and jump to i + brainpower + 1, or skip to i + 1.

Solution

A forward table would need to know which earlier question locked this one out. Flipping the definition to “from here to the end” makes each choice depend only on entries already computed. Size the array n + 1 so a jump past the end lands on a defined zero, and use 64-bit totals — the points add up beyond 32 bits.

▶Full solution
📐 Pseudocode · Right to Left 
function mostPoints(questions):
    n ← length(questions)
    dp ← array of n + 1 zeros            // dp[n] = 0: nothing left to solve

    for i from n - 1 down to 0:
        (points, brainpower) ← questions[i]
        next ← min(n, i + brainpower + 1)      // clamp the jump
        solve ← points + dp[next]
        skip ← dp[i + 1]
        dp[i] ← max(solve, skip)

    return dp[0]

// [[3,2],[4,3],[4,4],[2,5]] → dp = [5, 4, 4, 2, 0] → 5 ✓
TimeO(n)
SpaceO(n)
Problem 06 · Two Dimensions
Best Time to Buy and Sell Stock IV
🔗 LC 188 - Best Time to Buy and Sell Stock IV
Hard DP over Transactions Google · Amazon · Meta
›
Problem

You may complete at most k transactions (buy then sell). Return the maximum profit.

k = 2, prices = [3, 2, 6, 5, 0, 3] → 7  (2→6 and 0→3)
Hints
▶Hint 1 — a nudge

The cooldown problem needed one extra state. What extra information does a transaction limit require?

▶Hint 2 — the key idea

How many transactions are left. Keep buy[t] and sell[t] for each t from 1 to k, and update them for every price.

Solution

Two dimensions — day and transactions used — but only the transaction axis needs to be stored, because each day depends on the day before. When k is at least n / 2 the limit is no limit at all, and the problem collapses to “take every rise”; handling that case separately keeps the array from being enormous. Initialise each buy[t] to −infinity so an unstarted transaction cannot be sold.

▶Full solution
📐 Pseudocode · Rolling over Transactions 
function maxProfit(k, prices):
    n ← length(prices)
    if k ≥ n ÷ 2:                        // effectively unlimited
        return sum of every positive price rise

    buy ← array of k + 1, filled with -infinity   // best profit while holding, t-th transaction
    sell ← array of k + 1 zeros                   // best profit after closing t transactions

    for price in prices:
        for t from 1 to k:
            buy[t] ← max(buy[t], sell[t - 1] - price)
            sell[t] ← max(sell[t], buy[t] + price)

    return sell[k]
TimeO(n × k)
SpaceO(k)
