Dynamic Programming IV — Interval, Tree, Bitmask & Digit

“When the state is no longer an index: a range, a node, a set, or a position in a number.”

📚 Lecture 28 of 38 Phase 4 — Dynamic Programming ⏱ 7 days 🎯 25 problems 💼 Google · Amazon · Meta
🌍
Why does this topic matter?
The last three lectures used indices and budgets as states. These four families use stranger ones, and each has a trick that makes it possible: interval DP asks which element is handled last, tree DP returns several numbers from a post-order walk, bitmask DP packs a whole subset into an integer, and digit DP counts numbers without visiting them. They are the hard tier of most interview loops, and they all reuse the machinery you already have.
By the end of this lecture you can
  • Write interval DP by looping over length and splitting at a pivot
  • Carry several values up a tree in one post-order pass
  • Encode a subset of up to about 20 items as a bitmask state
  • Count numbers with a property using a tight flag
  • Say which of the four a new problem needs, from its constraints

📏 Interval DP

The state is a range: dp[i][j] is the answer for arr[i..j]. You saw the shape with palindromes in Lecture 26; here it gains a pivot.

📐 Pseudocode · The Interval Template 
for len from 2 to n:                  // shortest ranges first
    for i from 0 to n - len:
        j ← i + len - 1
        dp[i][j] ← worst possible value
        for k from i to j:          // the pivot: what happens LAST
            candidate ← dp[i][k-1] + cost(i, k, j) + dp[k+1][j]
            dp[i][j] ← best(dp[i][j], candidate)

return dp[0][n-1]

// Three nested loops → O(n³). That is the normal price of interval DP.

Think Last, Not First

🧠
Burst Balloons is the lesson. Asking “which balloon do I burst first?” leaves two ranges whose neighbours have changed — the subproblems are not independent. Asking “which balloon bursts last in this range?” fixes its neighbours as the untouched boundaries, and the two sides become independent subproblems. Whenever a choice damages its neighbours, reverse the question.

Games on a Range

Two players taking turns from the ends of an array is interval DP with a sign flip. Define dp[i][j] as the current player's advantage over the other, and the opponent's best play is simply your loss.

📐 Pseudocode · Take From Either End 
// dp[i][j] = (current player's score − opponent's score) on arr[i..j]
for i from 0 to n - 1: dp[i][i] ← arr[i]

for len from 2 to n:
    for i from 0 to n - len:
        j ← i + len - 1
        dp[i][j] ← max(arr[i] - dp[i+1][j],     // take the left end
                       arr[j] - dp[i][j-1])     // take the right end

return dp[0][n-1] ≥ 0                        // first player at least ties

// The minus sign is the whole trick: after your move, the opponent faces
// the smaller range and their advantage counts against you.

🌳 Tree DP

The state is a node, and the recursion is the post-order traversal from Lecture 15. The only new idea is that a node may need to return more than one number.

📐 Pseudocode · Two Values per Node 
// Classic: the best you can take from a subtree, with and without its root.
function solve(node):
    if node = null: return (0, 0)          // (taken, skipped)

    (lTake, lSkip) ← solve(node.left)
    (rTake, rSkip) ← solve(node.right)

    take ← node.value + lSkip + rSkip         // children must be skipped
    skip ← max(lTake, lSkip) + max(rTake, rSkip)
    return (take, skip)

// The answer is max(take, skip) at the root. One walk, O(n).

Rerooting — Answers for Every Node

Some problems want the answer for every node as the root. Running the whole DP n times is O(n²); two passes are enough.

📐 Pseudocode · Two-Pass Rerooting 
// Pass 1 (post-order from node 0): subtree sizes and distances downward.
function down(u, parent):
    for v in adj[u] if v ≠ parent:
        down(v, u)
        size[u] ← size[u] + size[v]
        answer[u] ← answer[u] + answer[v] + size[v]

// Pass 2 (pre-order): move the root one edge and patch the answer.
function up(u, parent):
    for v in adj[u] if v ≠ parent:
        answer[v] ← answer[u] - size[v] + (n - size[v])
        // everything inside v got 1 closer; everything outside got 1 further
        up(v, u)

// Two O(n) walks answer n questions. Sum of Distances in Tree is exactly this.

🔢 Bitmask DP

When the state is “which of these items have I already used?”, and there are at most about twenty of them, the whole subset fits in one integer. Bit i set means item i is used.

📐 Pseudocode · Assignment over Subsets 
// dp[mask] = answer when exactly the items in mask are used.
// popcount(mask) tells you how many are placed, so position = popcount.
dp ← array of 2ⁿ, all zero (or -infinity)
dp[0] ← 1

for mask from 0 to 2ⁿ - 1:
    position ← popcount(mask)              // next slot to fill
    for i from 0 to n - 1:
        if mask AND (1 << i) ≠ 0: continue   // item i already used
        if item i is allowed at position:
            dp[mask OR (1 << i)] ← dp[mask OR (1 << i)] + dp[mask]

return dp[2ⁿ - 1]                        // everything used
Operation Expression
Is item i in the set? mask AND (1 << i) ≠ 0
Add item i mask OR (1 << i)
Remove item i mask AND NOT (1 << i)
Full set (1 << n) - 1
How many are used popcount(mask) — Lecture 6
Every submask of mask s = mask; while s > 0: s = (s - 1) AND mask
🛑
Read n before reaching for a bitmask. 2ⁿ states is fine for n ≤ 20 and hopeless by n = 30. A constraint like “n ≤ 12” or “at most 16 people” is the problem telling you which technique it wants — small, strange limits usually mean bitmask or meet in the middle.
🧠
Bitmask plus BFS. Shortest Path Visiting All Nodes needs the state (node, visitedMask) — the same node is worth revisiting with a different set of visited nodes. Once the state is a pair, it is ordinary BFS from Lecture 17 over n · 2ⁿ states.

🔢 Digit DP

“How many numbers below N have property P?” N can be 10¹⁸, so the numbers cannot be visited. Build them digit by digit instead, carrying one crucial flag.

📐 Pseudocode · The Digit DP Skeleton 
digits ← decimal digits of N

function count(pos, tight, started, state):
    // tight   = the prefix so far equals N's prefix, so this digit is capped
    // started = we have placed a non-zero digit (handles leading zeros)
    // state   = whatever the property needs (last digit, remainder, mask…)
    if pos = length(digits): return 1 if state is acceptable else 0
    if not tight and memo[pos][started][state] is known:
        return memo[pos][started][state]

    limit ← digits[pos] if tight else 9
    total ← 0
    for d from 0 to limit:
        total ← total + count(pos + 1,
                             tight and d = limit,
                             started or d > 0,
                             updated state)

    if not tight: memo[pos][started][state] ← total
    return total

// "Between A and B" = count(B) − count(A − 1). Always.
⚠️
Only memoise the loose states. A tight prefix happens once per position, so caching it would poison the table for every other prefix of the same length. Memoise when tight is false — that is where the reuse is, and it is what makes the whole thing O(digits × states × 10).

🧩 Choosing the State

All four families answer the same question differently: what is the smallest description of “where I am” that makes the future independent of the past?

The state is Family Typical size Constraint that hints at it
a range [i, j] Interval O(n²) states, O(n³) time n ≤ 500, and choices damage neighbours
a node Tree O(n) states the input is a tree or a rooted graph
a subset Bitmask O(2ⁿ) states n ≤ 20, “assign each to each”
a position in a number Digit O(digits × state) “count numbers up to 10¹⁸”
a node of a DAG DP on a DAG O(V + E) longest path, counting paths

⚠️ Complexity & The Classic Bugs

Family States Per state Total
Interval n² O(n) pivots O(n³)
Tree n O(children) O(n)
Rerooting n O(1) patch O(n), two passes
Bitmask 2ⁿ O(n) O(n · 2ⁿ)
Bitmask over submasks 2ⁿ submasks O(3ⁿ)
Digit digits × state 10 O(10 · digits · state)
Bug Symptom Fix
Interval loops by index instead of length Reads an inner range that is still empty Loop over length, or i downward and j upward
Choosing what happens first in Burst Balloons Subproblems are not independent; answers too low Pick what happens last in the range
Forgetting the sign flip in a game DP Both players appear to cooperate Store the advantage and subtract the opponent's
Returning one value per tree node Cannot express “with or without this node” Return a pair (or a small tuple) and combine both
Bitmask with n = 25 Out of memory or time Check n first — this needs another technique
Memoising tight states in digit DP Counts are wrong for some bounds only Cache only when tight is false
Ignoring leading zeros “007” counted as a three-digit number Carry a started flag in the state
💡
How to spot it in an interview. Read the constraints first. n ≤ 20 means bitmask; n ≤ 500 with merging or bursting means interval; a tree input with a “for every node” question means rerooting; and a bound like 10¹⁸ means you are counting digits, not numbers.

Problem 01 · Think Last
Burst Balloons
🔗 LC 312 - Burst Balloons
Hard Interval DP Google · Amazon · Meta
›
Problem

Bursting balloon i earns nums[left] × nums[i] × nums[right], where the neighbours are the balloons currently beside it. Return the maximum coins from bursting them all.

nums = [3, 1, 5, 8] → 167
Hints
▶Hint 1 — a nudge

Try choosing which balloon to burst first, and watch the two halves stop being independent — their neighbours change.

▶Hint 2 — the key idea

Choose which balloon bursts last in a range instead. Its neighbours are then the untouched boundaries, and the two sides never interact.

Solution

The reversal is the whole problem. Pad the array with virtual 1s at both ends, then let dp[i][j] be the best coins from bursting everything strictly inside (i, j). Choosing the last balloon k fixes its multipliers as nums[i] and nums[j] — both still present — so the answer is dp[i][k] + nums[i]·nums[k]·nums[j] + dp[k][j]. Loop over length so inner ranges are ready.

▶Full solution
📐 Pseudocode · Last Balloon in the Range 
function maxCoins(nums):
    a ← [1] + nums + [1]                    // virtual boundaries
    n ← length(a)
    dp ← n × n table of zeros                // dp[i][j]: strictly between i and j

    for len from 2 to n - 1:            // distance between the boundaries
        for i from 0 to n - 1 - len:
            j ← i + len
            for k from i + 1 to j - 1:   // k bursts LAST
                gain ← a[i] × a[k] × a[j]
                dp[i][j] ← max(dp[i][j], dp[i][k] + gain + dp[k][j])

    return dp[0][n-1]

// [3,1,5,8] → 167 ✓
TimeO(n³)
SpaceO(n²)
Problem 02 · Interval on Coordinates
Minimum Cost to Cut a Stick
🔗 LC 1547 - Minimum Cost to Cut a Stick
Hard Interval DP Google · Amazon
›
Problem

A stick of length n must be cut at the given positions, in any order. Each cut costs the length of the piece being cut. Return the minimum total cost.

n = 7, cuts = [1, 3, 4, 5] → 16
Hints
▶Hint 1 — a nudge

The state is not an index into the stick — it is a pair of cut positions. What should the array of cuts include?

▶Hint 2 — the key idea

Add 0 and n as sentinels and sort. Then dp[i][j] is the cost of cutting the piece between cut i and cut j, and you pick which cut happens first inside it.

Solution

Same template as Burst Balloons, with coordinates instead of values. Adding the two endpoints means every piece is described by a pair of cut indices, so the cost of a cut is cuts[j] − cuts[i] regardless of order. Here you may think “first” rather than “last”, because a cut splits the piece cleanly into two independent pieces — the damage that ruins Burst Balloons does not happen.

▶Full solution
📐 Pseudocode · Sentinels + Pivot 
function minCost(n, cuts):
    c ← sort([0] + cuts + [n])
    m ← length(c)
    dp ← m × m table of zeros

    for len from 2 to m - 1:
        for i from 0 to m - 1 - len:
            j ← i + len
            best ← infinity
            for k from i + 1 to j - 1:      // k cut first
                best ← min(best, dp[i][k] + dp[k][j])
            dp[i][j] ← best + (c[j] - c[i])          // this piece's length

    return dp[0][m-1]
TimeO(m³)
SpaceO(m²)
Problem 03 · Rerooting
Sum of Distances in Tree
🔗 LC 834 - Sum of Distances in Tree
Hard Tree DP (Two Passes) Google · Amazon · Meta
›
Problem

For every node of a tree, return the sum of the distances from it to all other nodes.

n = 6, edges = [[0,1],[0,2],[2,3],[2,4],[2,5]] → [8, 12, 6, 10, 10, 10]
Hints
▶Hint 1 — a nudge

Computing one node’s answer is an easy DFS. Doing that n times is O(n²) — what changes when the root moves one edge?

▶Hint 2 — the key idea

Everything inside the new root’s subtree gets one step closer, and everything else gets one step further: answer[child] = answer[parent] − size[child] + (n − size[child]).

Solution

Two passes. The first, post-order from node 0, computes subtree sizes and the distance sum within each subtree. The second, pre-order, moves the root down one edge at a time and patches the answer in O(1) using the size split. This rerooting pattern answers “for every node” questions in linear time, and it generalises far beyond distances.

▶Full solution
📐 Pseudocode · Down, Then Up 
function sumOfDistancesInTree(n, edges):
    adj ← adjacency list
    size ← array of 1s;  ans ← array of zeros

    function down(u, parent):                // post-order
        for v in adj[u] if v ≠ parent:
            down(v, u)
            size[u] ← size[u] + size[v]
            ans[u] ← ans[u] + ans[v] + size[v]

    function up(u, parent):                  // pre-order
        for v in adj[u] if v ≠ parent:
            ans[v] ← ans[u] - size[v] + (n - size[v])
            up(v, u)

    down(0, -1);  up(0, -1)
    return ans
TimeO(n)
SpaceO(n)
Problem 04 · Subset as a State
Beautiful Arrangement
🔗 LC 526 - Beautiful Arrangement
Medium Bitmask DP Google · Amazon
›
Problem

Count the permutations of 1..n where, at every position i (1-based), either the value divides i or i divides the value.

n = 2 → 2  ([1,2] and [2,1])  |   n = 3 → 3
Hints
▶Hint 1 — a nudge

Backtracking works but revisits the same situations. What actually distinguishes one partial arrangement from another?

▶Hint 2 — the key idea

Only the set of numbers already placed — not their order. Encode that set as a bitmask, and the next position is popcount(mask) + 1.

Solution

Two different partial arrangements using the same numbers have identical futures, which is exactly the overlapping-subproblems signal. With the set as a bitmask, the position is free (it is the popcount), so a single array of 2ⁿ entries suffices. n ≤ 15 in the constraints is the giveaway that a bitmask is intended.

▶Full solution
📐 Pseudocode · dp[mask] = ways to fill popcount(mask) slots 
function countArrangement(n):
    full ← (1 << n) - 1
    dp ← array of full + 1 zeros
    dp[0] ← 1

    for mask from 0 to full:
        if dp[mask] = 0: continue
        pos ← popcount(mask) + 1               // next slot, 1-based
        for v from 1 to n:
            bit ← 1 << (v - 1)
            if mask AND bit ≠ 0: continue      // already used
            if v mod pos = 0 or pos mod v = 0:
                dp[mask OR bit] ← dp[mask OR bit] + dp[mask]

    return dp[full]
TimeO(n · 2ⁿ)
SpaceO(2ⁿ)
Problem 05 · Bitmask + BFS
Shortest Path Visiting All Nodes
🔗 LC 847 - Shortest Path Visiting All Nodes
Hard State = (node, mask) Google · Amazon · Meta
›
Problem

Given a connected undirected graph, return the length of the shortest walk that visits every node. You may start anywhere and revisit nodes and edges.

graph = [[1,2,3],[0],[0],[0]] → 4
Hints
▶Hint 1 — a nudge

Plain BFS marks a node visited once. Why is that wrong here?

▶Hint 2 — the key idea

Because arriving at the same node with a different set of visited nodes is a genuinely different situation. Make the state (node, visitedMask) and BFS over that.

Solution

The lesson is that “visited” is part of the state, not a side effect. Start the queue with every node (each with only its own bit set), then expand: moving to a neighbour sets that neighbour’s bit. The first state whose mask is full gives the answer, since BFS explores by distance. There are n · 2ⁿ states, which is why n ≤ 12.

▶Full solution
📐 Pseudocode · BFS over n · 2ⁿ States 
function shortestPathLength(graph):
    n ← length(graph);  full ← (1 << n) - 1
    queue ← empty;  seen ← empty set

    for i from 0 to n - 1:
        queue.push((i, 1 << i));  seen.add((i, 1 << i))    // start anywhere

    steps ← 0
    while queue is not empty:
        repeat queue.size times:
            (node, mask) ← queue.popFront()
            if mask = full: return steps
            for nb in graph[node]:
                state ← (nb, mask OR (1 << nb))
                if state not in seen:
                    seen.add(state);  queue.pushBack(state)
        steps ← steps + 1
TimeO(n² · 2ⁿ)
SpaceO(n · 2ⁿ)
Problem 06 · Digit DP
Non-negative Integers without Consecutive Ones
🔗 LC 600 - Non-negative Integers without Consecutive Ones
Hard Digit DP (Binary) Google · Amazon
›
Problem

Count the integers in [0, n] whose binary representation contains no two adjacent 1s.

n = 5 → 5  (0, 1, 2, 4, 5 — but not 3)
Hints
▶Hint 1 — a nudge

n can be a billion, so the numbers cannot be enumerated. Build them bit by bit from the most significant end.

▶Hint 2 — the key idea

Carry two things: whether the prefix still matches n (tight), and the previous bit. Without tight, the count depends only on the position and the previous bit — so memoise those.

Solution

Digit DP in its smallest form, in base 2. Once the prefix is strictly below n, everything after it is free, and the number of valid suffixes is a Fibonacci count — which is why the closed-form solution people quote works. Writing the general skeleton is more useful than the shortcut: change the state and the same code counts numbers with no repeated digit, a digit sum divisible by k, and so on.

▶Full solution
📐 Pseudocode · Tight Flag + Previous Bit 
function findIntegers(n):
    bits ← binary digits of n, most significant first
    memo ← empty map

    function count(pos, prevOne, tight):
        if pos = length(bits): return 1        // a complete valid number
        if not tight and (pos, prevOne) in memo:
            return memo[(pos, prevOne)]

        limit ← bits[pos] if tight else 1
        total ← 0
        for d from 0 to limit:
            if d = 1 and prevOne: continue       // no two adjacent ones
            total ← total + count(pos + 1, d = 1, tight and d = limit)

        if not tight: memo[(pos, prevOne)] ← total
        return total

    return count(0, false, true)
TimeO(bits)
SpaceO(bits)
