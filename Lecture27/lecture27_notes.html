Monotonic Stack & Queue

“Throw away what can never be the answer. Whatever survives is sorted — and that is the whole algorithm.”

📚 Lecture 27 of 45 Phase 3 — Core Patterns ⏱ 5 days 🎯 29 problems 💼 Google · Amazon · Meta
🌍
Why does this topic matter?
Lecture 15 previewed the monotonic stack with Next Greater Element and Daily Temperatures, and Lecture 26 ended with a deque of prefix sums. Both were the same move: keep candidates in sorted order, and drop the ones a later element has made useless. This lecture names that move, gives it one template with four settings, and then uses it for the problems it was really invented for — counting each element's contribution, and building the best possible subsequence.
By the end of this lecture you can
  • Write one template and set it to next/previous × greater/smaller without re-deriving it
  • Say what a popped element means, and why the total work is O(n)
  • Use the contribution technique to sum a value over every subarray
  • Build lexicographically smallest subsequences with a stack and a budget
  • Choose a monotone deque over a heap, and say what each one costs
🧠
The picture to keep in your head: People looking for someone taller. Imagine a line of people, each looking right for the first person taller than them. When a tall person arrives, everyone shorter who is still waiting has found their answer and steps out of line. The ones left are always in decreasing height — that ordered line of waiting people is the monotonic stack.

🧩 One Template, Four Variants

Every monotonic stack problem asks the same question about each element: who is the first element to my left (or right) that is bigger (or smaller) than me? Four combinations, one piece of code.

📐 Pseudocode · The Template 
stack ← empty stack            // holds INDICES, not values
answer ← array of n, filled with the "none found" default

for i from 0 to n - 1:                     // ← direction lives here
    while stack is not empty and nums[stack.top()] < nums[i]:   // ← comparison lives here
        j ← stack.pop()
        answer[j] ← i          // i is j's answer: the first one that beat it
    stack.push(i)

// Anything still on the stack never found an answer — it keeps the default.

Direction & Sign

Two switches configure it. The loop direction decides whether you are looking forwards or backwards; the comparison decides greater or smaller.

You want Loop Pop while Stack ends up
Next greater element left → right nums[top] < nums[i] decreasing
Next smaller element left → right nums[top] > nums[i] increasing
Previous greater element right → left nums[top] < nums[i] decreasing
Previous smaller element right → left nums[top] > nums[i] increasing
🧠
Or keep one direction and read it twice. Walking left to right and popping on < also tells each surviving element who its previous greater element is — it is whatever sits below it on the stack at the moment it is pushed. One pass can fill both arrays.

Handling Ties

⚠️
Equal values decide whether you double-count. When duplicates exist, make one side strict and the other not: pop on ≤ going left, and on < going right (or the mirror). Then a run of equal values is claimed by exactly one of them, and totals come out right instead of doubled.

📏 What the Stack Really Stores

The stack is not a list of numbers; it is a list of unresolved candidates. An index stays on it while no later element has beaten it. The moment one does, that index's span is fixed forever — and the span is usually what the problem actually wants.

heights = [2, 1, 5, 6, 2, 3]    index 3 (value 6) is popped at index 4    previous smaller = index 2  |  next smaller = index 4    so 6 rules the open range (2, 4) — exactly one bar wide
🧠
Why it is O(n), not O(n²). The while loop looks nested, but each index is pushed once and popped once in the whole run. Amortised, that is two operations per element — the same argument as the two-stack queue in Lecture 15.

The most famous span problem deserves its own walk-through. You may have seen it named in Lecture 15; this is where it is taught.

Largest Rectangle in Histogram

Find the largest rectangle that fits inside a histogram. Each bar has width 1. This classic problem uses a stack to track left and right boundaries for each bar height.

Heights: [2, 1, 5, 6, 2, 3] ┌─┐ │6│ ┌─┼─┼─┐ │5│6│ │ │ │ │ │ ┌─┐ ┌─┐ │ │ │2│ │3│ │2│ │ │ │ │ │ │ ┗━┷━━┷━┷━┷━┷━━━┷━┛ Largest rectangle = 10 units (heights 5 and 6, width 2) Key insight: For bar at index i with height h[i], - Left boundary: first bar to the left that is SHORTER than h[i] - Right boundary: first bar to the right that is SHORTER than h[i] Stack maintains indices in INCREASING height order. When a shorter bar arrives, pop — each popped bar found its right boundary.
📐 Pseudocode · Largest Rectangle in Histogram — Monotonic Increasing Stack 
function largestRectangleArea(heights):
  n ← length(heights)
  stack ← empty stack            // indices, heights increasing from bottom to top
  maxArea ← 0

  for i from 0 to n:             // one extra step: i = n acts as a height-0 sentinel
      if i = n: curH ← 0 else: curH ← heights[i]
      while stack is not empty and curH < heights[stack.top()]:
          h ← heights[stack.pop()]          // this bar's rectangle ends here
          if stack is empty: w ← i
          else: w ← i - stack.top() - 1
          maxArea ← max(maxArea, h × w)
      stack.push(i)
  return maxArea

// [2,1,5,6,2,3]:
// i=0: push 0. stack=[0]
// i=1: h[1]=1 < h[0]=2 → pop 0, h=2, w=1 (stack empty), area=2
//      push 1. stack=[1]
// i=2,3: increasing → push. stack=[1,2,3]
// i=4: h=2 < h[3]=6 → pop 3, h=6, w=4-2-1=1, area=6
//      2 < h[2]=5 → pop 2, h=5, w=4-1-1=2, area=10 ← max!
// ... continues. Final maxArea = 10 ✓

🧮 The Contribution Technique

Some problems ask for a value summed over every subarray — the minimum of each, the range of each. There are O(n²) subarrays, so they cannot all be visited. Turn the question inside out: instead of asking “what is the minimum of this subarray?”, ask “how many subarrays does this element rule?”

📐 Pseudocode · Sum of Subarray Minimums 
// nums[i] is the minimum of every subarray that stays strictly inside
// (previous smaller, next smaller) and includes i.
left[i]  ← distance to the previous smaller element   // pop on ≥ going left
right[i] ← distance to the next smaller element       // pop on >  going right

total ← 0
for i from 0 to n - 1:
    count ← left[i] × right[i]        // choices on each side multiply
    total ← total + nums[i] × count
return total mod 1000000007

// nums = [3, 1, 2, 4], element 1 at index 1
// previous smaller: none → 2 choices of start (index 0 or 1)
// next smaller: none → 3 choices of end (index 1, 2 or 3)
// so 1 is the minimum of 2 × 3 = 6 subarrays
⚠️
The duplicate trap. With equal values, “the minimum” is ambiguous, and a symmetric rule counts some subarrays twice. Break the tie by direction: going left, stop at values ≥ this one; going right, stop only at values strictly <. Each subarray then belongs to the leftmost copy of its minimum, once.

The same counting answers a family of questions. Sum of subarray maximums flips every comparison. Sum of subarray ranges is the maximum total minus the minimum total. Maximum min-product weights each element's span by a prefix sum — the technique from Lecture 26, reused inside this one.

🔢 Building the Best Sequence

The third family uses the stack as the answer being built rather than a bookkeeping device. The rule is always the same: before pushing the current character, pop anything that makes the result worse — but only while you can still afford to.

📐 Pseudocode · Smallest Subsequence, k Removals 
function mostCompetitive(nums, k):        // keep k items, smallest sequence
    stack ← empty stack
    drops ← length(nums) - k                // how many we may throw away

    for x in nums:
        while stack is not empty and stack.top() > x and drops > 0:
            stack.pop()                     // a smaller value arrived — the bigger one must go
            drops ← drops - 1
        stack.push(x)

    return the first k items of the stack

// The budget is what makes it correct: without it, the stack would
// happily drop everything down to the single smallest element.
🧠
Same shape, different budget. Remove K Digits spends a fixed budget. Remove Duplicate Letters may only pop a letter that appears again later — the remaining-count array is its budget. Once you see the budget, the problems stop looking different.

🎚️ Monotone Deque — Windows That Move

A stack answers questions about a growing prefix. When the left end moves too, you need the same idea with a second door: a monotone deque. Indices leave from the back when a better candidate arrives, and from the front when they fall out of the window.

📐 Pseudocode · Window Maximum in O(n) 
dq ← empty deque of indices        // values decrease front → back

for i from 0 to n - 1:
    if dq is not empty and dq.front() ≤ i - k:
        dq.popFront()                  // expired: left the window

    while dq is not empty and nums[dq.back()] ≤ nums[i]:
        dq.popBack()                   // useless: later AND bigger

    dq.pushBack(i)
    if i ≥ k - 1: report nums[dq.front()]   // front is always the window max

The deque is the engine behind three different-looking problems: window extremes, DP where a state may only reach back k steps (Constrained Subsequence Sum), and pair problems where one term is fixed and the other must be maximised over a moving range (Max Value of Equation).

Deque vs Heap

Monotone deque Max-heap
Per element O(1) amortised O(log n)
Removing an expired item pop the front — it is right there lazy deletion, or a heap that supports removal
Answers one extreme, over a contiguous window any top-k, over any set
Use it when the window slides in one direction items arrive and leave arbitrarily
🛑
When a monotonic structure is the wrong tool. It only ever answers about the nearest qualifying element or the extreme of a contiguous window. “How many elements to my left are smaller?” is a counting question — that needs a Fenwick tree (Lecture 37), not a stack.

⏱ Complexity & The Classic Bugs

Technique Time Space Answers
Monotonic stack (one pass) O(n) O(n) nearest greater / smaller, on either side
Contribution technique O(n) O(n) a value summed over all O(n²) subarrays
Stack with a budget O(n) O(n) lexicographically best subsequence
Monotone deque O(n) O(k) extreme of a sliding window
Bug Symptom Fix
Storing values instead of indices You know what beat it, not where Push indices; read values through them
Both sides use the same comparison Duplicates counted twice; totals too large One side strict, the other not
Forgetting what is left on the stack Trailing elements get no answer Flush after the loop, or use a sentinel
No sentinel in area problems The last bars are never resolved Append a height of 0 (or −∞) at the end
Deque expiry checked after pushing A stale index is reported as the window extreme Drop the front before reading it
Overflow in contribution sums Negative totals on large inputs 64-bit accumulation, modulo as you go
💡
How to spot it in an interview. The words “next greater”, “nearest smaller”, “span”, “how many days until”, “sum over all subarrays”, “lexicographically smallest after removing k”, or “maximum of every window”. All seven are this lecture.

Problem 01 · The Template
Next Greater Node In Linked List
🔗 LC 1019 - Next Greater Node In Linked List
Medium Next Greater Element Amazon · Google · Microsoft
›
Problem

For every node of a linked list, return the value of the first later node with a strictly greater value, or 0 if there is none.

head = [2, 1, 5] → [5, 5, 0]   |   head = [2, 7, 4, 3, 5] → [7, 0, 5, 5, 0]
Hints
▶Hint 1 — a nudge

A linked list has no indices — but nothing stops you from copying the values into an array first.

▶Hint 2 — the key idea

Run the standard template over the array: keep a stack of indices whose answer is still unknown, and when a bigger value arrives, pop and fill them in.

Solution

Two structures from earlier lectures meet here. Walk the list once into an array (Lecture 14), then apply the monotonic template (this one). Anything still on the stack at the end never found a greater value, which is why the default of 0 is filled in first.

▶Full solution
📐 Pseudocode · Copy Out, Then Template 
function nextLargerNodes(head):
    nums ← values of the list, in order          // one walk
    answer ← array of length(nums), all 0        // "none found" default
    stack ← empty stack                          // indices, values decreasing

    for i from 0 to length(nums) - 1:
        while stack is not empty and nums[stack.top()] < nums[i]:
            answer[stack.pop()] ← nums[i]
        stack.push(i)
    return answer

// [2,7,4,3,5]: 7 pops 2 → ans[0]=7
// 5 pops 3 and 4 → ans[3]=5, ans[2]=5;  7 and 5 never popped → 0
TimeO(n)
SpaceO(n)
Problem 02 · Scan From the Right
132 Pattern
🔗 LC 456 - 132 Pattern
Medium Monotonic Stack + Best Popped Google · Amazon · Meta
›
Problem

Return true if there are indices i < j < k with nums[i] < nums[k] < nums[j] — a small value, then a big one, then a middle one.

nums = [3, 1, 4, 2] → true  (1, 4, 2)  |   nums = [1, 2, 3, 4] → false
Hints
▶Hint 1 — a nudge

Fix the middle value (the “2”) last. Scanning right to left, what is the best candidate for it?

▶Hint 2 — the key idea

Keep a decreasing stack from the right. Every popped value was smaller than the current one, so remember the largest popped value as third; if any later element is smaller than third, the pattern exists.

Solution

The clever part is what the popped values mean. Going right to left, popping happens when the current element is bigger — so a popped value is a candidate “2” with a known “3” to its right. Keep the largest such value, and the test for the remaining element is a single comparison.

▶Full solution
📐 Pseudocode · Track the Best Popped Value 
function find132pattern(nums):
    stack ← empty stack            // values, decreasing from bottom to top
    third ← -infinity              // best "2" seen so far, with a bigger "3" to its right

    for i from length(nums) - 1 down to 0:
        if nums[i] < third: return true      // found the "1"
        while stack is not empty and stack.top() < nums[i]:
            third ← max(third, stack.pop())       // popped < nums[i]: a valid middle
        stack.push(nums[i])
    return false

// [3,1,4,2]: push 2; at 4 → pop 2, third = 2; at 1 → 1 < 2 → true ✓
TimeO(n)
SpaceO(n)
Problem 03 · Contribution
Sum of Subarray Minimums
🔗 LC 907 - Sum of Subarray Minimums
Medium Contribution Technique Amazon · Google · Meta
›
Problem

Return the sum of the minimum of every contiguous subarray, modulo 109+7.

arr = [3, 1, 2, 4] → 17  (mins: 3,1,2,4,1,1,2,1,1,1)
Hints
▶Hint 1 — a nudge

There are O(n²) subarrays, so you cannot visit them. Turn it around: for one element, how many subarrays does it minimise?

▶Hint 2 — the key idea

Find the previous smaller and next smaller element. If the gaps are left and right, this element is the minimum of left × right subarrays — multiply by its value and add.

Solution

This is the lecture’s centrepiece. Each element rules the stretch between its two smaller neighbours; the number of subarrays containing it and staying inside that stretch is a simple product of the two gaps. Handle duplicates asymmetrically (stop at ≥ on one side, > on the other) or equal values will each claim the same subarray.

▶Full solution
📐 Pseudocode · Span Counting 
function sumSubarrayMins(arr):
    n ← length(arr);  MOD ← 1000000007
    left ← array of n;  right ← array of n

    stack ← empty stack                     // previous smaller, strict on the left
    for i from 0 to n - 1:
        while stack is not empty and arr[stack.top()] ≥ arr[i]: stack.pop()
        if stack is empty: left[i] ← i + 1 else: left[i] ← i - stack.top()
        stack.push(i)

    stack ← empty stack                     // next smaller, non-strict on the right
    for i from n - 1 down to 0:
        while stack is not empty and arr[stack.top()] > arr[i]: stack.pop()
        if stack is empty: right[i] ← n - i else: right[i] ← stack.top() - i
        stack.push(i)

    total ← 0
    for i from 0 to n - 1:
        total ← (total + arr[i] × left[i] × right[i]) mod MOD
    return total

// arr = [3,1,2,4]: element 1 → left=2, right=3 → rules 6 subarrays
TimeO(n)
SpaceO(n)
Problem 04 · Stack with a Budget
Remove Duplicate Letters
🔗 LC 316 - Remove Duplicate Letters
Medium Lexicographic Stack Google · Amazon · Meta
›
Problem

Remove letters so that every distinct letter appears exactly once, and the result is the lexicographically smallest such string.

s = "bcabc" → "abc"   |   s = "cbacdcbc" → "acdb"
Hints
▶Hint 1 — a nudge

Build the answer on a stack. When a smaller letter arrives, when is it safe to pop the bigger one already there?

▶Hint 2 — the key idea

Only when that letter appears again later — count the remaining occurrences first. Also skip any letter already in the answer.

Solution

The budget here is not a number but a pair of arrays: how many of each letter remain, and which letters are already used. Pop the top while it is bigger than the current letter and still available later. Each letter is pushed and popped at most once, so the pass is linear.

▶Full solution
📐 Pseudocode · Count Remaining + In-Stack Flags 
function removeDuplicateLetters(s):
    remaining ← count of each letter in s
    inStack ← 26 booleans, all false
    stack ← empty stack

    for c in s:
        remaining[c] ← remaining[c] - 1          // c is being consumed now
        if inStack[c]: continue                 // already placed — never twice

        while stack is not empty and stack.top() > c and remaining[stack.top()] > 0:
            inStack[stack.pop()] ← false         // safe: it comes back later

        stack.push(c);  inStack[c] ← true
    return the stack, bottom to top

// "cbacdcbc": c, then b pops c? c reappears → yes. a pops b and c → "a"
// then c, d; b pops d? d never returns → keep → "acdb" ✓
TimeO(n)
SpaceO(1) — 26 letters
Problem 05 · Monotone Deque
Max Value of Equation
🔗 LC 1499 - Max Value of Equation
Hard Monotone Deque Google · Amazon
›
Problem

Points are sorted by x. Maximise yi + yj + |xi − xj| over pairs with |xi − xj| ≤ k.

points = [[1,3],[2,0],[5,10],[6,-10]], k = 1 → 4  (points 0 and 1)
Hints
▶Hint 1 — a nudge

Points are sorted, so for a later point j the absolute value disappears. Rewrite the expression with i < j.

▶Hint 2 — the key idea

It becomes (yi − xi) + (xj + yj). For each j you want the largest y − x among points still within k — a sliding window maximum.

Solution

The algebra does the real work: once i < j, the expression splits into a part that depends only on i and a part that depends only on j. What remains is the window-maximum problem, so a deque keyed on y − x answers every j in O(1). Expiry is by x-distance, not by index count.

▶Full solution
📐 Pseudocode · Rewrite, Then Slide 
function findMaxValueOfEquation(points, k):
    dq ← empty deque of (y - x, x)     // y - x decreasing front → back
    best ← -infinity

    for (x, y) in points:
        while dq is not empty and x - dq.front().x > k:
            dq.popFront()                          // too far away now

        if dq is not empty:
            best ← max(best, dq.front().value + x + y)

        while dq is not empty and dq.back().value ≤ y - x:
            dq.popBack()                           // later AND no better

        dq.pushBack((y - x, x))
    return best
TimeO(n)
SpaceO(n)
Problem 06 · Deque + DP
Constrained Subsequence Sum
🔗 LC 1425 - Constrained Subsequence Sum
Hard Monotone Deque over DP Google · Amazon · Meta
›
Problem

Choose a non-empty subsequence where consecutive chosen indices are at most k apart, maximising the sum.

nums = [10, 2, -10, 5, 20], k = 2 → 37  (10 + 2 + 5 + 20)
Hints
▶Hint 1 — a nudge

Write the recurrence first: dp[i] = nums[i] + max(0, best dp in the last k positions).

▶Hint 2 — the key idea

Scanning that window for every i is O(n·k). The window only moves forward, so keep its maximum in a monotone deque instead.

Solution

This is the lecture applied to a DP table rather than to the input. The recurrence needs one number — the best dp value within the last k indices — and that is exactly a sliding window maximum. Note max(0, ...): starting fresh is always allowed, which is what makes an all-negative array return its largest element.

▶Full solution
📐 Pseudocode · Window Maximum over dp[] 
function constrainedSubsetSum(nums, k):
    dp ← array of length(nums)
    dq ← empty deque of indices         // dp values decreasing front → back
    best ← -infinity

    for i from 0 to length(nums) - 1:
        if dq is not empty and dq.front() < i - k:
            dq.popFront()                           // out of reach

        if dq is empty: dp[i] ← nums[i]
        else: dp[i] ← nums[i] + max(0, dp[dq.front()])

        best ← max(best, dp[i])

        while dq is not empty and dp[dq.back()] ≤ dp[i]:
            dq.popBack()
        dq.pushBack(i)
    return best
TimeO(n)
SpaceO(n)
Problem 07 · Monotonic Increasing Stack
Largest Rectangle in Histogram
🔗 LC 84
Hard Amazon · Google · Meta · Microsoft Monotonic Stack
›
Problem

Given an array of bar heights (each width = 1), find the area of the largest rectangle that can be formed within the histogram.

[2,1,5,6,2,3] → 10 (bars of height 5 and 6, width 2)
Hints
▶Hint 1 — a nudge

For each bar, how far left and right can it extend at its own height?

▶Hint 2 — the key idea

Monotonic increasing stack of indices. When a shorter bar arrives, pop and compute area = height × width, where width comes from the new stack top. Append a sentinel 0 so the stack always drains.

Solution

Maintain a monotonically increasing stack of bar indices. When a shorter bar arrives (the right boundary), pop the taller bar and compute its maximum rectangle. The width is determined by: left boundary = current stack top (after pop), right boundary = current index. Append a sentinel height 0 at the end to flush all remaining bars.

▶Full solution
📐 Pseudocode · Sentinel + Increasing Stack 
function largestRectangleArea(heights):
    n ← length(heights)
    stack ← empty stack;  maxArea ← 0
    for i from 0 to n:
        if i = n: curH ← 0 else: curH ← heights[i]     // sentinel flushes the stack
        while stack is not empty and curH < heights[stack.top()]:
            h ← heights[stack.pop()]
            if stack is empty: w ← i
            else: w ← i - stack.top() - 1
            maxArea ← max(maxArea, h × w)
        stack.push(i)
    return maxArea
TimeO(N)
SpaceO(N)
Problem 08 · Monotonic Deque
Sliding Window Maximum
🔗 LC 239
Hard Google · Amazon · Meta · Uber Monotonic Deque
›
Problem

You are given an array and a sliding window of size k moving from left to right. Return the maximum value in each window position.

nums=[1,3,-1,-3,5,3,6,7], k=3 → [3,3,5,5,6,7]
Hints
▶Hint 1 — a nudge

A heap gives O(n log k). O(n) needs something that discards losers permanently.

▶Hint 2 — the key idea

Monotonic decreasing deque of indices. Pop from the back anything smaller than the newcomer — it can never win again — and pop from the front once it falls out of the window.

Solution

Maintain a monotonically decreasing deque of indices. For each new element: ① Remove indices no longer in the window (from front). ② Remove indices with smaller values from the back (they can never be max while current is in window). ③ Add current index to back. ④ The front is always the window maximum. Each element is added/removed once → O(N).

▶Full solution
📐 Pseudocode · O(N) Deque 
function maxSlidingWindow(nums, k):
    res ← array of length(nums) - k + 1
    dq ← empty deque                        // indices, values decreasing front → back
    for i from 0 to length(nums) - 1:
        if dq is not empty and dq.front() < i - k + 1:
            dq.popFront()                   // expired
        while dq is not empty and nums[dq.back()] < nums[i]:
            dq.popBack()                    // smaller, useless
        dq.pushBack(i)
        if i ≥ k - 1: res[i - k + 1] ← nums[dq.front()]
    return res
TimeO(N)
SpaceO(K)
